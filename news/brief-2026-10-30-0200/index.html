头条

vLLM 的 Rust 前端补上了 PD 搬运账本 PD 就是 prefill/decode 解耦那套分工流水线。 UMBP 是 vLLM 里搬 KV 的连接器。 KV 就是解码用的草稿纸。 这次 Rust 前端把 UMBP 的传输指标导出来了。 跟 Python 侧对齐，搬了多少、丢了多少都有数。 你评估 PD 的时候，这类指标就是账本。 不过只是指标对齐，不是新功能。 来源：https://github.com/vllm-project/vllm/pull/64512

框架更新

正式版全平 vLLM 还是 0.32.0。 SGLang 还是 0.5.22。 LMDeploy 还是 0.18.0。 TGI 还是 v3.3.7。 llama.cpp 还是 v0.8.0。 FlashInfer 正式版还是 0.7.2.post1。 v0.5.23 的 tag 能打开了。 但 release notes 还是空的。 文档安装版已经升到 0.5.23。 正式版应该快了，继续等。 来源：https://github.com/sgl-project/sglang/releases/tag/v0.5.23

vLLM：Rust 前端开始管数据并行 三笔连发，都是 DP 负载均衡那套。 DP 就是数据并行，多卡分摊请求。

#64451 支持混合和外部 DP 负载均衡。

#64450 让握手 owner 负责一段 DP rank。

#64449 修了协同 DP 初始化的会合消息。

背景：vLLM 在把 Python 前端往 Rust 迁。 DP 相关能力也在一个个搬过去。 来源：https://github.com/vllm-project/vllm/pull/64451

vLLM 其余一句话带过 MoE prefill 的 tile 调整了。 1024 token 以上，tile 改用 32 行。 NVFP4 量化核加了个尺寸开关。 generate 响应信封跟 Python 对齐。 剩下是 CI 分片、XPU、编译缓存等杂活。 来源：https://github.com/vllm-project/vllm/pull/64467

SGLang：解码侧的拆词器提速两笔 detokenizer 就是把 token 翻回文字的部件。

#47415 把每步输出 id 压成一列发。

行偏移另算，通信量小了。

#47260 让每请求的解码输入只发一次。

两笔都是给 decode 减负。 来源：https://github.com/sgl-project/sglang/pull/47415
