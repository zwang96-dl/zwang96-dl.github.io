KVCacheWorkingSet：KV 缓存到底要配多大，一遍测量就算出来

原文：The KV Cache Working Set: Online Capacity Planning for LLM Inference Systems（arXiv:2609.27746，2026-09-23，金山云，9 页 4 图）
开源：llc-kc/kv_cache_capacity_estimator
一句话版本：前缀缓存是省钱利器，但"缓存留多大"全靠猜。
这篇教你用生产流量在线测一遍，直接算出"留多大最划算"。

人话解读

在线推理最怕的是什么。KV 缓存留小了，命中率垮掉，prefill 重新算一遍，吞吐暴跌。 留大了呢，显存和内存白白烧钱，谁都心疼。

以前的做法很笨。 想知道 1TB、2TB、5TB 分别什么命中率，就得真实部署三遍。 或者离线重放 trace，每种容量单独模拟一遍。 几十种候选容量，就是几十遍计算量。在线根本玩不了。

这篇做了一个工具叫 KVSET。 它只重放一遍请求，就把所有候选容量的命中率曲线全算出来。 然后告诉你：想保住目标命中率，最小配多少。

类比一下：KV cache 是模型的草稿纸。 prefix caching 就是备菜，重复的前缀只算一遍，不用每次重做。 这篇回答的是：草稿纸到底要买多大的，才能不耽误做菜又不浪费。

对你意味着什么：你正在 SGLang 上评估 P/D 解耦。 解耦之后 KV 池要单独配大小、单独做预算。 这篇就是现成的"配卡计算器"，开源可用。

核心方法

  • 底层依据：Mattson stack 算法。
  • 1970 年的老工具，专门给缓存容量做"体检"。
  • 它专为 LRU（最近没用的先踢走的淘汰策略）设计。
  • vLLM、SGLang、Mooncache 的 KV 池都在用 LRU。
  • 正好对口，直接能用。
  • 核心思想：每个缓存页有个"栈深度"。
  • stack distance 就是页被压在历史栈里有多深。
  • 某次访问时，如果深度 < 容量 C，说明这次能命中。
  • 深度 > 容量 C，说明已经被踢出去了，命中不了。
  • KVSET 的做法：对每个 KV 页，算它在当前请求里的栈深度。
  • 然后把深度跟每个候选容量比一遍，命中与否一次判完。
  • 聚合所有请求，就得到整条"容量-命中率"曲线。
  • 找最小容量：看目标命中率需要的最深栈深度。
  • 最深的那个深度，就是你要配的最小容量。
  • 工程加速：Fenwick 树（二叉索引树，快速数数的数据结构）。
  • 用它数"上次访问之后中间插了多少个不同页"，算栈深度。
  • 不维护真正的 LRU 栈，开销很小，可以挂在线上跟着流量跑。
  • 两用模式：在线接生产请求流，或者离线重放 trace。

关键数据

  • 实验环境：NVIDIA H20、GLM-5.2。
  • 模型用了 W4A8 量化，引擎是 SGLang。
  • 部署 Mooncache 配多档物理容量做对照，KV 缓存 FP8 量化。
  • 量化后每 token 约 60KB 的 KV 存储。
  • KVSET 预测的命中率，跟真实部署实测点几乎重合。
  • 说明它不用真部署，就能算准"容量-命中率"关系。
  • 命中率随容量先陡后平：容量小时加一点涨很多。
  • 过了拐点再加容量，收益微乎其微。
  • 99% 的请求保住理论命中率，大约需要 5 TiB。
  • 降到 95% 覆盖，只需要约 1 TiB，容量直接砍到五分之一。
  • 99.9% 覆盖的需求不收敛，一直往上长，别追求极致。
  • 分层配法建议：CPU 内存 1 TiB 保 95% 请求。
  • 磁盘 5 TiB 保 99% 请求，两层加起来单机可装下。
  • 动机数据：命中率接近 1 时，prefill 吞吐按 T=T̂/(1−r) 暴涨。
  • 所以"命中率涨几个点"值多少钱，可以直接换算。

关键图表

图 1 是什么：Mattson stack 算法的工作原理图解。 说明了什么：栈深度小于容量的页就是命中，一次算出所有容量下的命中情况。 不用每个容量单独重放，这是 KVSET 快的核心。

图 2 是什么：容量-命中率曲线，预测 vs 实测。 说明了什么：KVSET 的预测跟真实部署测出来的点几乎重合。 想先看到陡涨后趋平：超过约 800GiB 再加容量几乎没收益。

图 3 是什么：24,000 个生产请求的在线容量分析。 说明了什么："留住所有历史"这条蓝线是无底洞，一直涨。 定好覆盖目标，容量立刻收敛。95% 只需约 1TiB，99% 约 5TiB。

跟你的研究方向的关联

  • SGLang P/D 解耦评估：解耦后 KV 池独立配预算，这篇就是配预算的工具。
  • decode 侧吃 HBM 带宽，prefill 侧吃算力。
  • KV 池大小是第三个变量。
  • SARA 笔记算的是"几张卡"，这篇算的是"KV 池留多大"，拼在一起才完整。
  • 命中率公式 T=T̂/(1−r) 值得记：命中率从 0.9 提到 0.95。
  • 吞吐直接翻倍，配容量的钱花在陡坡上最划算。
  • 局限：目前只支持 LRU 淘汰策略的 full-attention 层。
  • 混合注意力模型（Mamba、滑窗）的那部分要另算。
  • 你做多模态时，视觉 encoder 侧的 KV 复用模式跟文本不一样。
  • 建议两边各跑一遍 KVSET 再拼总账，别混在一起测。

术语表

  • working set（缓存最少要留多大）。
  • prefix caching（重复前缀只算一遍的备菜机制）。
  • KV cache（模型算过的草稿纸）。
  • prefill（一次吃完输入、算出草稿的阶段）。
  • decode（一个字一个字往外吐的阶段）。
  • hit rate（缓存命中率，打中了几次）。
  • LRU（最近没用的先踢走）。
  • stack distance（页被压在历史栈里多深）。
  • Mattson stack（1970 年的老算法，给缓存做体检）。
  • Fenwick 树（二叉索引树，快速数数）。
  • coverage target（要保住多少请求的命中率）。
  • hierarchical storage（内存加硬盘分层放）。
  • MTP（多 token 并行预测，实验里关掉了）。
