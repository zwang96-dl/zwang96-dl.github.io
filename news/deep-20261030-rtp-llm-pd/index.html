阿里 RTP-LLM 的 P-D 分离：72B 线上实测，实例 -24%、P99 -78%

原文：InfoQ《大模型推理新突破：分布式推理技术探索与实践》
作者：阿里巴巴智能引擎 / TRE / 高性能网络团队
链接：https://www.infoq.cn/article/70zucQxBJc72NOWggR5u
收录日期：约 2026-10-28/29（页面未显示确切日期，此前各期简报未报过）

一句话人话

阿里把 prefill 和 decode 拆成两个集群跑。 72B 模型线上全量上线后，机器少了 24%。 平均时延降 48%，P99 时延降 78%。 这是一份生产级的 P-D 解耦成绩单。

核心数据

  • 场景 A（72B，Qwen-72B-Chat-Pro）：实例数 -24%。
  • 平均时延 -48%，P99 时延 -78%。
  • 场景 B（14B）：平均时延 -32%。
  • 单请求 prefill 产出的 KV cache 约 5GB。
  • prefill 单次执行 200ms 到 10s 不等。
  • 数据为作者自报，线上业务实测。

核心方法

为什么拆

  • prefill 是计算密集型，decode 是显存带宽瓶颈。
  • 混在一起跑，长 prefill 会把 decode 的时延拖出巨大波动。
  • chunked prefill 也救不了，prefill 长期占显存。
  • 干脆拆开，各自用最合适的卡和 batch。

KV 怎么传：按层边算边传

  • KV cache（prefill 算出的"草稿纸"）是 P 传给 D 的核心货物。
  • 单请求约 5GB，一次性传会形成洪峰，把 D 打爆。
  • 办法：每算完一层就发一层。
  • prefill 本来就要跑几百毫秒到几秒。
  • 发送代价摊进计算时间里，洪峰就没了。
  • 类比：别等整桌菜做好再上，一道一道上。

传输协议：RDMA 单边操作

  • TCP 要走内核协议栈，拷贝多、时延抖。
  • RDMA（高速网卡直通技术）让网卡直接读写对方内存。
  • 不经过内核，没有拷贝，没有上下文切换。
  • 他们用单边 Read/Write，不用双边 Send/Recv。
  • 单边不需要两边握手协调，控制流更简单。
  • 控制信息（传地址、长度、rkey）走 TCP/RPC。
  • 数据走 RDMA，控制走 TCP，分工明确。

通信库选型：ACCL

  • Gloo 和 MPI 在 GPU 直传（GDR）上不如 NCCL。
  • NCCL 要预建通信集合，不支持动态增删节点。
  • P-D 场景节点来来去去，NCCL 不合适。
  • 最终选了 ACCL：点对点、可动态建链。
  • 支持多网卡聚合带宽，GPU 和网卡按亲近性配对。

控制面：gRPC Stream

  • P-D 之间要多轮会话，TCP 太裸，ARPC 没 Stream 能力。
  • 选 gRPC Stream 传控制信息。
  • First Token 也要从 P 同步给 D。
  • D 可能还没收完 KV，只能先等。
  • 短消息走 RPC 很快，时延增加可接受。

降本三板斧

  • 第一，凑批：D 适合大 batch，多配 P、少配 D。
  • 第二，机型：P 用高算力卡，D 用大显存卡。
  • 第三，量化分开：P 跑 FP16/W8A8，D 跑 W4A16/W4A8。
  • 单部署做不到分开量化，P-D 分离天然可以。
  • 零碎小卡也能组织进集群，勤俭持家。

显存有效占用

  • P 开始执行时，D 才申请显存。
  • P 发完 KV 立刻释放显存给别的请求。
  • D 跑完才把 KV 回传给 P，减少 P 的占用时间。
  • 传输和计算 overlap，在时延和占用间取平衡。

四家实现对比（原文剖析）

  • vLLM：Connector 基类 + 双端队列，可插拔。
  • 但还在初级阶段：不支持按层发送、TP/PP、prefix cache。
  • Mooncake：工业界大规模 RDMA P-D 分离的标杆。
  • 支持 TCP/RDMA/NVMe/CXL，对象级传输。
  • TensorRT-LLM：MPI 启动，CacheTransceiver 基类。
  • 不支持按层发送，节点管理缺失，偏原始。
  • InfiniStore：轻量 KV Store，RDMA 读写异步。
  • 简单易用，适合快速验证。
  • 阿里自己的 CacheStore：支持 RDMA、异步接口。
  • 计算传输 overlap，可传任意 Tensor。

术语表

  • P-D 分离：prefill/decode disaggregation 的简称。把"读题"和"答题"拆到不同机器上跑。
  • prefill：读题阶段。处理全部输入 token，产出第一个输出 token 和 KV cache。
  • decode：答题阶段。用 KV cache 一个 token 一个 token 往外蹦。
  • KV cache：prefill 算出的"草稿纸"。存着注意力算过的中间结果，decode 复用它不用重算。
  • TTFT：首字时间。从请求发出到第一个 token 出来的时延。
  • TBT：字间时延。decode 阶段每两个 token 之间的间隔。
  • RDMA：高速网卡直通技术。网卡直接读写远端内存，不经过操作系统内核。
  • 单边操作：RDMA 的 Read/Write。发起方直接读写对方内存，对方 CPU 不参与。
  • rkey：RDMA 内存注册后发的"门禁卡"。拿着它才能读写那块内存。
  • GDR：GPU Direct RDMA。网卡直接读写显存，不经过主机内存。
  • ACCL：阿里选的 RDMA 通信库。支持点对点、动态建链、多网卡聚合。
  • gRPC Stream：谷歌的 RPC 框架的流式模式。适合 P-D 之间多轮会话。
  • chunked prefill：把 prefill 切成小块，多轮跟 decode 凑批跑。缓解但根治不了干扰。
  • TP：张量并行。把一层切到多张卡上并行算。
  • W4A16：权重 4 bit、激活 16 bit 的量化。省显存，decode 更快。
  • MaaS：Model as a Service。模型即服务，用户只调接口不管机器。
