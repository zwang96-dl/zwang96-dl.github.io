多模态大模型推理服务简报 · 2026-10-30（10点版）

10点版来了，这轮推理速度成了全场话题。 SGLang 的激进算子融合，让 DeepSeek-V4.1-Flash 逼近每用户 1000 tok/s。 本期有一篇值得深读：DeepSeek 官方的 KV 压缩论文。

头条

推理速度赛道：SGLang 激进融合打出新纪录 这是 swyx 的 Latent Space AI News 10/29 推理速度专题。 SGLang 的 megakernels（激进算子融合）在 GB300 NVL72 上跑 DeepSeek-V4.1-Flash。 每用户接近 1000 tok/s，数据引自 SemiAnalysis。 Cline 把 Nemotron 3.5 Super VL 在单张 GB300 上从 6,058 翻到 11,840 tok/s。 Mistral Large 4 首日就有 vLLM 支持。 FP8 和 NVFP4 检查点都能直接跑，NVFP4 是英伟达的 4 位浮点格式。 还内置 DSpark 草稿头，输出吞吐 1.92 到 2.23 倍。 DSpark 是 DeepSeek 自家的投机解码。 提醒一句：以上全是各家自报数字，没有独立实测。 来源：http://latent.space/p/ainews-building-aie-code-the-top-coding-agent-conference/

框架更新

SGLang #45328：PD 搬运去掉 host 同步 PD 解耦里，prefill 算完要把 KV 草稿纸搬给 decode。 这笔改动让 decode 侧发布 KV 目的地时不再等 host 同步。 搬运和计算重叠跑的工况下，延迟直接降。 跟你评估 PD 解耦的搬运账本直接相关。 来源：https://github.com/sgl-project/sglang/pull/45328

vLLM #64638：all-gather 和 norm 融成一个算子 给 Muse Spark hybrid MoE（混合专家模型）提速。 通信加归一化两步并一步，少一次 kernel 启动开销。 来源：https://github.com/vllm-project/vllm/pull/64638

vLLM #64612：GLM-5.3 草稿模型换 FP8 KV，省 2.85GB 投机解码是让小模型先打草稿、大模型改。 这笔把 GLM-5.3 草稿模型的 KV 缓存换成 dlfash fp8 格式。 每 rank 省 2.85 GB 显存。 你在 AMD 卡上跑 GLM-5.3，显存账本可以直接抄。 来源：https://github.com/vllm-project/vllm/pull/64612

新技术与论文

DeepSeek-V4.1-Flash：把 KV 压缩推到极限（值得深读） DeepSeek 官方的多模态 MoE，552B 参数，支持百万 token 上下文。 CED 架构（因果编码器-解码器）：读题每 token 只激活 8B 参数。 吐字阶段激活 16B，输入重的智能体负载最吃香。 KV 压缩两招：跨层 KV 复用（CSA2）加 FP4 KV 缓存。 HBM 里每 token 只要 890 字节，是 V4-Flash 的四分之一。 SWA Bounded Replay（滑动窗口有界重放）把持久化 KV 压到八分之一。 跟你研究的 KV 优化和多模态 serving 直接对口。 来源：https://arxiv.org/abs/2609.19969
