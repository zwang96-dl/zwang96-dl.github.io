新技术与论文

arXiv 10/8 批次本轮入库。 17:00 PDT 发布，8 篇新收录。

  • RaReCache：让小模型替大模型做 prefill。
  • KV cache（推理时的草稿纸）跨模型复用，不用重算。
  • 这解决级联 serving 的老大难。
  • 中途换大模型，提示词不用重算一遍。
  • 方法是 rank disagreement。
  • 给每个 token 打信息密度分。
  • 只重算最密的 30% 位置，大模型精度保住 95–99%。
  • Qwen3 0.6B→14B 上测的。
  • 23 倍参数差，prefill 快 3 倍。
  • 跟你评估的 P/D 解耦是亲戚：小模型干粗活，大模型只干精活。
  • 标「值得深读」，精读笔记单独出了。
  • https://arxiv.org/abs/2610.11358
  • Dual-QK：把 KV cache 压到 2 bit。
  • 还能动态剪掉 query 通道。
  • query（查询向量）通道剪掉后，读 KV cache 更快。
  • 128K 上下文下，KV cache 压缩 6.8 倍。
  • 读取量降 8.3 倍。
  • 作者在 SGLang 里实现了，decode 吞吐最高 3.75 倍。
  • 你手上正好有 SGLang，这篇可以直接对着代码看。
  • https://arxiv.org/abs/2610.09827
  • TokenRouter。
  • 给 token 级路由做的 serving 系统。
  • 背景：不同 token 分给不同模型跑，省钱又保质量。
  • 现有系统跑这种细粒度路由会步调失调、频繁卡顿。
  • 它给每个模型开一个子服务器，异步调度。
  • decode 吞吐比现有系统高 2–64 倍。
  • https://arxiv.org/abs/2610.12242
  • SparseDecoding：decode 阶段的训练无关剪枝法。
  • 校准不用自然文本，用模型自己生成的 token。
  • 这样避免分布偏移，decode 读内存更快。
  • https://arxiv.org/abs/2610.12327
  • Read What Matters。
  • 读 KV cache 时动态分精度。
  • 按每次 query 的需求来定。
  • 存下来的条目不动，每次按查询逐条分配 key 通道精度。
  • 少浪费显存带宽。
  • https://arxiv.org/abs/2610.11245
  • KV 量化与线性注意力的统一理论（RAM-Net）。
  • 把"逐条压缩"和"聚合压缩"统一成一个机制。
  • 理论味重，但指向低显存推理的权重迁移路径。
  • https://arxiv.org/abs/2610.11214
  • Exit-Guided Speculative Decoding。
  • 研究 draft 树哪里丢了 target 质量。
  • 从 target 分布视角看，给验证器设计划理论上限。
  • https://arxiv.org/abs/2610.11750
  • Speedbumps：投机解码的生产安全警告。
  • 攻击者在 prompt 里加点扰动。
  • draft 和 target 分歧变大。
  • 接受率一掉，推理反而比自回归还慢、还贵。
  • 14点版报过 Secure Speculative Decoding。
  • 这篇是它的攻击实证版。
  • https://arxiv.org/abs/2610.10929

补收一篇 P/D 强相关（9 月底的，往期漏了）：

  • MoSE：P/D 解耦下 KV 传输的网络层优化。
  • prefill 和 decode 节点间要传 KV。
  • 这跟训练的集合通信打架。
  • 它提出可切换拓扑的 expander，KV 通信开销降约 90%。
  • 跟你正在评估的 P/D 解耦直接相关。
  • https://arxiv.org/abs/2609.39138
