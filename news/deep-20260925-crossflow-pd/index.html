Crossflow：P/D 解耦的墙会"呼吸"了——decode 闲了就把算力租给 prefill

原文：Crossflow: Prefill–Decode Elasticity for Agentic LLM Serving，Meta Platforms，arXiv:2609.27085（2026-09-22）
原文链接：https://arxiv.org/abs/2609.27085

一句话人话版

P/D 解耦本来是两拨 GPU 各干各的，中间的墙是死的。 Crossflow 让这堵墙会呼吸：prefill 排起长队时，decode 闲着的算力临时租出去帮忙。 租约随时可撤销，decode 一忙立刻收回，不耽误正事。

为什么这事值得看

静态切分有个死结：prefill 和 decode 的忙闲节奏根本对不上。 Meta 实测了自家大集群：输入输出 token 的比例，分钟级峰值能冲到均值的 4.7 倍。 agent 流量更夸张：公开 trace 里一天之内，这个比例中位数跨度 24.5 倍。 想临时改配比？挪一个节点要几十分钟，期间 GPU 干停着不干活。 按 95 分位配卡，最多 17% 的集群算力白白闲置。 配少了就一边排队、一边空转，两头难受。

核心方法

三件套，层层递进。

1. 先发现 prefill 真的忙：压力检测

  • 光数排队人数不够用，突发来得比轮询快。
  • 请求一到就按"真正要算的 token"记账，缓存命中的部分不算钱。
  • 预估等待超过阈值，压力信号变真；回落到低阈值才解除，防抖动。

2. decode 敢不敢借：多资源 lease（租约）

  • 每个 decode 节点按实时状态发一张"租约"：能借多少算力、多少 KV、多少传输带宽，全写清。
  • 租约带版本号和过期时间，过期作废，不囤积。
  • 关键洞察：光看 GPU 利用率不够。同样的负载下，长上下文和短上下文能挤出的 prefill 算力差 11–34%。
  • 反馈闭环：借出去后 decode 延迟没涨，下次多借点；一碰 SLO 红线，下张租约直接归零。
  • decode 一忙，租约自动缩到零，系统退化成普通静态 P/D，安全兜底。

3. 借给谁最划算：shape 感知的准入

  • 不是谁排队久就借给谁，要算两条路谁更快。
  • 一条是老实等 prefill 池，另一条是去 decode 家"蹭算力"，只有后者严格更快才放行。
  • 新会话第一次来就定好 prefill 家和 decode 家，长上下文尽量凑一堆，batch 更均匀。

打个比方：像写字楼的会议室，平时各部门固定用，但前台支持"可撤销预定"。 你部门开大会人不够，隔壁空会议室临时借你；主人一回来，你立刻腾走。

关键数据

  • 实现：在 SGLang 上改的；模型 GPT-OSS-120B 和 GLM-5.2；硬件 NVIDIA GB300。
  • 评测：公开 trace + Meta 内部 trace，保时间戳回放。
  • 16 个负载点几何平均：请求吞吐 +16.6%，输入 token +17.4%，输出 token +16.2%。
  • 高负载点最高：输入 +42.7%，输出 +43.4%。
  • 平均首 token 时间（TTFT）每个点都降：GPT-OSS-120B 降 10–34%，GLM-5.2 降 32–57%。
  • 打其他基线（PPD、SMetric、CacheWise）：输出吞吐最高多 43.4%，平均 ITL 最低。
  • 代价：decode 侧有延迟开销，但有上界、可量化，不是无底洞。

跟你的研究方向哪里相关

  • 你在评估 SGLang 的 P/D 解耦：Crossflow 就是"解耦之后配比怎么动态调"的现成答案，而且直接在 SGLang 上实现。
  • 跟 SARA 那篇对照看：SARA 是静态配卡算公式，Crossflow 是运行时弹性借算力，一静一动。
  • 配比敏感度实验（1P5D 到 4P2D 全扫过）说明：即使静态配比选错了，弹性也能兜底。
  • 你的 AI 自动调参系统可以把"租约"当成一维可调参数，跟配比一起搜。
  • 注意：它的 ITL 在个别配置下会涨（GLM-5.2 TraceLab 上 +20.9–34.3%），借算力不是免费午餐。

术语表

  • P/D 解耦：prefill 和 decode 拆到两拨 GPU 上跑，各干各擅长的事。
  • TTFT：首 token 时间，敲完回车到第一个字蹦出来的等待。
  • ITL：token 间延迟，字和字之间蹦出来的间隔。
  • lease（租约）：decode 节点发布的"我能借多少算力"凭证，短命、可撤销。
  • spill（溢出）：prefill 池装不下，溢到 decode 节点上算的请求。
  • shape：请求的"体型"，prompt 多长、输出多长、KV 占多少。
