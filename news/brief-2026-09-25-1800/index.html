多模态大模型推理服务简报 · 2026-09-25（18点版）

傍晚这轮生态偏安静，框架六家都没发新版。 但有两条实用干货，是前几轮漏掉的补收。

业内新闻

  • Google 的 Antigravity SDK 现在能纯本地跑 Agent 了。
  • 9 月 23 日，Google 正式给 SDK 加上了本地模型路径。
  • 官方参考配置：Gemma 4 26B A4B 配 LiteRT-LM。
  • LiteRT-LM 是 Google 的端侧推理引擎，专门跑本地模型。
  • A4B 是 MoE 的写法：模型拆成小专家，总 26B 参数每次只激活 4B。
  • 要 24GB 以上显存或统一内存，上下文 64K。
  • 不用 API key，也不用联网，全在本地跑。
  • 更关键的是 LocalOpenAIAgentConfig，它能直连你本地起的 OpenAI 兼容服务。
  • 说白了：Agent 编排留在 Antigravity，推理走你自己的 vLLM。
  • 本地服务开好之后，base_url 指过去就行。
  • 原文：https://aicybr.com/blog/google-antigravity-sdk-local-gemma-4-offline-agents

新技术与论文

  • vLLM 也能跑 GGUF 文件了，但只在 GPU 上。
  • GGUF 是 llama.cpp 那套省显存的模型格式。
  • 用法是官方插件 vllm-gguf-plugin，写法是 repo:quant_type。
  • 硬件表很直白：NVIDIA、AMD 的 GPU 支持。
  • x86、Arm 的 CPU 明确不支持。
  • 说白了：它的 GGUF 路径是给批量 serving 写的 GPU 算子。
  • CPU 那边没有对应算子，因为它压根是 serving 引擎。
  • 官方原话：高度实验性、欠优化。
  • 能用的量化类型比 llama.cpp 窄，新模型家族也跟得慢。
  • 记住它是省显存的特性，不是提吞吐的，别指望 QPS 起飞。
  • 一句话规律：llama.cpp 拿 GGUF 当本命，vLLM 拿它当选项。
  • 原文：http://dev.to/mrsaynothing/can-vllm-run-gguf-yes-on-gpu-only-1hpj
