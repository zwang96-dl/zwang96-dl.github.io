新技术与论文

论文一："优化到底伤没伤质量"，终于有把标准尺子了

说白了，以前各家报的"快 3 倍、精度几乎不掉"，用的尺子都不一样。 没法横向比，谁吹得响谁赢。 Jerry Kaplan 这篇给了套校准过的测量方法。 核心招数：拿另一个大模型当裁判，给输出打分。 但裁判也可能有偏好，所以先给裁判做"体检"。 让它给同一模型跑两次分，看它有没有系统性偏心。 还加了个"空条件"对照组：分布跟原模型完全一样。 按理说它测出来差异必须是零，专治裁判"看走眼"。 这套方法跟你直接相关。 MI350 上选量化方案，它帮你避开 benchmark 幻觉。 你在评估 P/D 解耦时，也能拿它当裁判校准尺子。 深读笔记已生成：《给推理优化装一把"校准过的尺子"》，含原文 2 张关键图。 https://arxiv.org/abs/2609.18005

论文二：本地跑大模型，prompt 真的更"私密"吗？

很多人觉得：prompt 留在本地设备上，肯定比云上私密。 这篇论文说：未必。 作者扒了本地 LLM 服务栈四处漏 prompt 的地方。 模型加载、运行时内存、wrapper 持久化、服务接口，个个都可能漏。 作者还开源了检测框架 LLAnalyzer，自动测每道边界漏不漏。 偏安全工程方向，跟你的推理优化主线关系不大，知道有这事就行。 https://arxiv.org/abs/2609.18526

业内新闻

Arcfra 发了 Neutree 1.2：统一推理平台开始接非 LLM 模型了

Neutree 是个统一推理平台。 底层搭在 vLLM 和 SGLang 上。 这版新增了 Flex Engine，专接非 LLM 模型。 比如 MinerU、PaddleOCR 这种文档解析和 OCR 工具。 还加了 KV-cache 用量自动估算。 KV-cache 就是推理时的"草稿纸"，现在部署前能自动算出来。 部署前就知道要多少显存，少踩"爆显存"的坑。 消息来自 PR Newswire 通稿，厂商自报，看看就好。 https://hkbusinesswire.com/arcfra-releases-neutree-1-2-to-add-non-llm-model-support-and-simplify-ai-operations/
