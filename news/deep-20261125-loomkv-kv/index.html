LoomKV：KV 缓存无损压缩，硬盘和显存都变大

  • 原文：Wentao Zhu、Ziao Sheng 等，华东师范大学、中兴通讯
  • 文章：LoomKV: Lossless KV Cache Compression from GPU Memory to SSD for LLM Serving
  • 提交时间：2026-11-24
  • 原文链接：https://arxiv.org/abs/2611.32954
  • 说明：数字全是作者自报，没有独立复现

一句话

KV 缓存能无损压小三成。压完值一个不变。硬盘层和显存池都跟着变大。

人话解读

智能体每轮都重发整段对话。引擎把算过的部分存下来。存下来的就是 KV 缓存。它像一本草稿纸，复用就不用重算。

草稿纸很占地方。Qwen3-30B 每词占 96KB。32GB 显存只够五个长会话。引擎只好把缓存挪到内存和硬盘。用时再搬回来。

容量不够有两种疼法。第一种，硬盘层太小。旧缓存还没复用就被挤掉。只能重新算一遍。首字时间一下就涨上去。

第二种，显存池太小。缓存明明在硬盘里。请求却挤不进显存池。只能在门口排队。硬盘再大也帮不上忙。

以前的压缩多半有损。有损就是值会变。量化会改数值，逐出会扔词。输出可能跟着变。每个模型都得重新验精度。

LoomKV 走无损路线。无损就是一个值都不改。它发现一个规律。BF16 的高字节很集中。最常见的 7 个值占了 94%。这就是能压的地方。

图 1：三个观察。左图是容量悬崖。缓存层从 1200GB 缩到 1040GB。吞吐从 9.4 掉到 4.6。中图是显存池瓶颈。放行 16 个请求时更堵。右图是字节分布。高字节前 7 个值占 94%。

核心方法

方法有两种模式。两种共用同一套编码。

先看编码本身。每个数拆成高低两字节。低字节原样存着。高字节用 3 位码代替。码表按每个头单独标定。标定就是先数一遍频率。常见的字节给短码。

两种模式的区别在压哪里。

第一种叫 tier 模式。只压内存和硬盘层。显存里还是原样。用时解压回显存。引擎的注意力不用改。

第二种叫 pool 模式。显存池里也存压缩版。注意力算子边解压边算。它把解压融进计算里。不用先还原再算。

图 2：两种模式。上图是 tier 模式。压缩只发生在缓存层。下图是 pool 模式。显存池里也是压缩版。注意力算子直接读压缩数据。

还有三个配套设计。

一是按实际长度存。压完多长就占多长。不按固定格子对齐。对齐会把省下的空间吃回去。

二是并行解压。数据按类型分开存。解压时一瓦片一个线程组。还原的值直接写进显存页。不用先拼临时缓冲。

三是异步搬运。压缩在后台慢慢做。加载请求不用排队等。同步等待不挡正事。

关键数据

  • 测了 9 个模型，4B 到 72B。
  • BF16 缓存压到原来的 0.71。
  • FP8 缓存压到 0.85 到 0.87。
  • 硬件是 2 张 H800。
  • 引擎是没改过的 vLLM 0.30。
  • 缓存层用 LMCache 0.5.6。
  • 主负载是 AgentX 智能体回放。
  • 提示词中位 89K 词，最长 254K。
  • 压缩层等于 1.4 倍大的原层。
  • 悬崖处有效吞吐涨 2.7 到 3.6 倍。
  • 首字时间降到原来的三分之一上下。
  • 重复提示首字最多快 1.7 倍。
  • pool 模式多装 1.31 到 1.34 倍词。
  • 12 个长请求能跟 8 个一样顺。
  • 真实轨迹上吞吐涨 1.24 和 1.59 倍。
  • 容量够用时，代价至多 2.2%。
  • tier 模式跟原版逐位一致。
  • pool 模式精度对齐 FA3。
  • FA3 就是主流的注意力算子。

图 3：悬崖处的表现。左上蓝线是压缩版。红线是原版。640GB 处蓝线明显更高。左下是命中率拆分。压缩版命中率守在 0.90 附近。原版掉到 0.17。

跟研究方向的关联

跟你的缓存评估直接对口。

第一，它补了无损这一档。以前比的都是有损方案。无损不用重验精度。这条线值得单独列。

第二，容量要按等效值报。压完等于多大的原层。这篇给了换算办法。评估时可以照着报。

第三，悬崖位置值得测。容量够时收益很小。逼近悬崖时收益暴涨。评估要扫容量，别只测一档。

第四，它建在 vLLM 和 LMCache 上。引擎没改过。这点对落地很友好。SGLang 那边还没接。

第五，pool 模式要换算子。解压融进注意力里。跟你引擎选型有关。换算子就是换一条执行路径。

第六，数字要带条件看。2.7 倍只在悬崖处。容量够时只有 2% 代价。抄数字时要带上容量档。

术语表

  • KV 缓存：算过的上下文草稿，复用就不用重算。
  • 无损压缩：压完再还原，值一个不变。
  • 有损压缩：为了省空间，允许值变一点。
  • tier 模式：只压内存和硬盘层。
  • pool 模式：显存池里也存压缩版。
  • 容量悬崖：容量跌破某点，性能断崖式下跌。
  • 有效吞吐：满足延迟指标的请求数。
  • 首字时间：从发请求到第一个词的等待。
  • BF16：一种 16 位浮点格式。
  • FP8：一种 8 位浮点格式，更省但有损。
  • LMCache：给引擎管分层缓存的组件。
  • AgentX：智能体负载的回放评测。
