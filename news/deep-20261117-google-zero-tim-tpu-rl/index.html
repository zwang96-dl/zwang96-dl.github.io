Google Zero-TIM：训练和推理的数对不上，RL 悄悄变离线

  • 作者：Lin Chai 等，Google
  • 文章：Unlocking Stable On-Policy RL on TPU with Bitwise-Zero Train–Inference Mismatch
  • 发布时间：2026-11-16
  • 原文链接：https://developers.googleblog.com/unlocking-stable-on-policy-rl-on-tpu-with-bitwise-zero-traininference-mismatch/
  • 说明：数字全是 Google 自报，单种子测试，没有第三方实测

一句话

RL 训练里采样和训练各算各的数。同一权重下，两个数对不上，训练就悄悄变离线。Zero-TIM 让三条路按位对齐，200 步里差值全程是 0。

人话解读

RL 就是让模型自己试、自己改。模型先采样出一串动作，再按这些动作算梯度更新自己。真在轨训练要求采样和更新用同一个策略。现实里采样和训练走的是两条路。采样是 decode，一次吐一个词，边吐边记 logprob。logprob 就是动作的对数概率。训练是整批前向加反向，再算一遍 logprob。两条路用的权重一样，算出来的数却可能不一样。差得不多，但每步都差，越攒越偏。训练以为自己在轨，其实已经离线了。多轮对话里这个偏会越滚越大。Zero-TIM 就是把这个偏按到 0。它的办法不是合并两条路，而是让两条路的算术一模一样。

图 1：bfloat16 里加法顺序会改结果。2.0 附近，0.0078125 是半个间隔。逐个加会被舍掉，先分组加就能进到下一个值。浮点加法不满足结合律，换个加法顺序，舍入位置就变了。

核心方法

方法分四招，都围着一个问题转：三条路的算术怎么做到一模一样。

第一招：锁死单卡内的累加顺序。用 batch-invariant 的 Pallas 内核。batch-invariant 就是结果不随 batch 大小变。分块顺序固定，跟 token 行数无关。中间结果用 float32 累加，输出再转回原精度。注意力、MLP、LM head 都走这套。RMSNorm 和 SwiGLU 另有专用内核。已有的 Pallas 分页注意力前向保留。

第二招：跨卡规约排好队。行并行投影每张卡各出一份部分结果。先用 ppermute 传，再按同样的卡号顺序加。ppermute 是 JAX 里跨卡传数据的操作。顺序写在程序里，不交给集合通信自己选。

第三招：打分尾巴统一。decode、prefill、训练三条路用同一套采样变换。log-softmax 用同一个固定 Pallas 构造。prefill 和训练打的是 rollout 里已经采出来的动作，不另选。token ID 跨环境轮次保留下来。

第四招：训练复用 serving 的前向。自定义求导规则包住 serving 内核。前向走 serving 的 Pallas 内核，反向走可微分的复刻。编译时传 XLA_FLAGS，关掉多余精度。长轨迹按固定块切分，KV 缓存往下传。反向沿着缓存连回去，梯度汇总后再更新。

图 2：三条路都要按位比。decode 和 prefill 比 serving 内部。prefill 和训练比跨引擎边界。直接比采样和训练，只能发现有差。加 prefill 当中间站，才能定位差从哪进来的。

图 3：长轨迹切块算。KV 缓存连着前向的块，反向沿着缓存连回去。梯度汇总之后再交给优化器更新。

关键数据

  • 验证规模：64 张 TPU v5p，DP8×TP8。
  • 测试环境：FrozenLake 合成小环境，Qwen3-8B 公开权重。
  • 步数：200 步数值验证，GSPO-token 损失，leave-one-out 优势。
  • 对照组：标准训练、TIS、Zero-TIM 三组。
  • 核心结果：Zero-TIM 的采样和训练 logprob 平均绝对差全程是 0。
  • 解题率：Zero-TIM 的解题率往上涨，比另外两组高。
  • 标准组和 TIS 组：差值一直不是 0。
  • TIS 只调了更新权重，没去掉底层的差。
  • 单种子：只跑了一个种子，完整解题率数值文章没给全。
  • 适用面：正在扩展到线性注意力和 MoE 架构。

图 4：200 步实测。FrozenLake 从 2×2 到 9×9 的格子，最多五轮交互。Zero-TIM 的 logprob 差全程是 0。解题率也比标准组和 TIS 组高。

跟研究方向的关联

这篇跟 PD 解耦评估直接相关。

第一，RL 采样就是推理。sglang-miles 那条 RL 线里，rollout 全靠推理引擎采样。数不对齐，RL 就白跑。

第二，三路对账可以抄。decode 对 prefill，prefill 对训练。PD 评估里也可以加这一项。读题和吐词两条路的数先对上。

第三，确定性内核是前提。batch-invariant 内核不光为 RL 服务。评测复现也要它。

第四，传输也要进对账。PD 拆开跑，KV 要跨机器搬。搬完的数对不对，也值得验。

第五，注意适用面。这是 TPU 加 JAX 的配方。H100 和 MI350X 上要换一套内核。

第六，MoE 和线性注意力还没接。文章说正在扩展。等它落地再跟。

术语表

  • logprob：一个动作被选中的对数概率。RL 里拿它算更新。
  • on-policy：采样和更新用同一个策略。真在轨。
  • off-policy：采样和更新用的不是同一策略。有偏差。
  • bfloat16：16 位低精度浮点数。省显存，但舍入误差大。
  • Pallas：JAX 写 TPU 内核的语言。能定死累加顺序。
  • ppermute：JAX 里跨卡传数据的操作。点对点换部分结果。
  • custom VJP：自定义求导规则。前向走一套，反向走另一套。
  • GSPO：一种 RL 算法。按 token 分组算优势。
  • TIS：截断重要性采样。给离线样本加权重，截掉过大的。
  • TiTO：token 进出都保留原样。跨轮次不丢采样记录。
  • FrozenLake：一个合成小环境。格子世界里找路。
  • DP8×TP8：64 张卡，数据并行 8 路，张量并行 8 路。
