VideoMM：长视频理解"先粗看再细看"，推理快 6 倍精度还涨

原文：VideoMM: Adaptive Macro-Micro Inference for Efficient Video MLLMs（arXiv 2026-09-15；郭浩宇等，中国科学技术大学）
代码：https://github.com/adfh917k/VideoMM

人话解读

长视频喂给多模态模型，视觉 token 会爆炸。 举个例子：10 分钟 720p 视频，每秒取 1 帧。 在 Qwen3-VL 上能攒出超过 30 万个 token。 上下文窗口直接撑爆，算力账单也撑爆。

以前的解法是：找个辅助小模型先把 token 砍掉一截。 但这里有个两难。 轻量 encoder 砍得快，经常把关键语义一起砍掉。 重的 MLLM 砍得准，可它自己吃掉的算力比省下的还多。 等于请了个保洁，工资比省下的水电费还贵。

VideoMM 的洞察很妙：挑"哪块区域值得看"和"看清细节"是两件事。 挑区域不需要高清，粗看就行。 细节只在拿不准的时候才上高清。 用人话说：像侦探看监控。 先 16 倍速扫一遍，锁定可疑时间段。 再把可疑片段放慢逐帧看。 没人会从头到尾逐帧看完 10 小时监控。

核心方法

两阶段流水线。

Stage I：宏观代理做分组筛选

  • 先把视频空间降采样 k 倍（实验用 k=2）。
  • token 量直接除以 k²，得到 Macro Proxy。
  • Macro Proxy 就是视频的"粗看版"。
  • 把帧交错分成 G 组，每组都是全视频的稀疏采样。
  • 用 MLLM 自己的跨模态注意力打分。
  • 跨模态注意力就是"文字问题在看图片的哪里"。
  • 每组保留前 50% 的帧，再按 token 预算取 top-K。

Stage II：自适应宏观-微观推理

  • 先用 macro token 回答问题。
  • 共识投票机制：各组答案一致就直接输出。
  • 答案打架了，才把 Stage I 选出的区域映射回高清帧。
  • 提取 micro token（高清细节 token），再推理一遍。
  • 拿不准才上高清，拿得准直接走。

关键数据

LongVideoBench 上的 headline 数字。

  • 推理加速 6.13 倍，精度反涨 7.4%（相对全上下文基线）。
  • 对比当时最强方法 FlexSelect：加速 2.73 倍，精度不掉。
  • 三个模型全跑赢：Qwen2.5-VL-7B、GLM-4.1V-9B、Qwen3-VL-8B。

Qwen2.5-VL-7B 的细表（原文 Table 1）。

  • LongVideoBench 精度：57.67 → 64.70（涨 12.2%）。
  • 吞吐：0.77 → 5.16 样本/分钟（6.7 倍）。
  • 三个基准平均：精度涨 15.9%，吞吐 6.5 倍。

帧数扩展性（原文 Figure 4，Qwen3-VL-8B）。

  • 帧数从 128 涨到 512。
  • VideoMM 的精度和吞吐都跟着涨。
  • 基线方法帧数一多就掉，撑不住。

跟你的研究方向的关联

  • 这是 prefill/encoder 侧的降本思路。
  • 视觉 token 在进 LLM 之前就砍掉。
  • 进 decode 的 KV 量也跟着降，一石二鸟。
  • 跟 EPD 解耦同路：NVIDIA 9/9 博客那篇就是 encoder 单独部署。
  • 这篇是在 encoder 输入侧再砍一刀。
  • 跟 vLLM v0.29.0 的多模态性能专区互补。
  • vLLM 做的是加速 encoder kernel（ViT 全量 CUDA graph）。
  • VideoMM 做的是减少要算的 token 数。
  • 你在 SGLang 上做 P/D 解耦评估时。
  • 长视频场景的 prefill 成本是主要变量。
  • 这类"感知粒度"方法值得当对比基线。

术语表

  • MLLM 多模态大语言模型。能看图、看视频又能读文字的模型。
  • Macro Proxy 宏观代理。降采样帧做的"粗看版"视频。
  • Micro Token 微观 token。高清帧上选中区域的精细 token。
  • Grouped Selection 分组筛选。帧交错分组，组内按注意力打分选 token。
  • Consensus-based voting 共识投票。多组 macro 答案一致就直接输出。
  • Cross-modal attention 跨模态注意力。文字问题在看图片哪里的注意力权重。
  • LongVideoBench。长视频理解基准，测细粒度检索和复杂推理。
