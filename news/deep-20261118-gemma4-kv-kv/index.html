Gemma 4 的 K=V 缓存：只存一份，解码 KV 省三成

  • 作者：Kushagra Bainsla
  • 文章：Storing the Gemma 4 K=V Cache Once: Exact Global-KV Memory Savings in a Paged Serving Engine with Unchanged Attention Kernels
  • 提交时间：2026-11-17（arXiv:2611.23035v1）
  • 原文链接：https://arxiv.org/abs/2611.23035
  • 说明：数字全是作者自报，没有第三方复现。只测了一个模型、两张 A100。

一句话

Gemma 4 全局层里，K 和 V 是同一份数。

官方说这设计能省 37.5% 的 KV。

开源引擎却还在存两份。

这篇只存一份，解码 KV 省三成多。

人话解读

Gemma 4 31B 有两种层。

50 层滑窗层，只看最近 1024 个词。

10 层全局层，看整段上下文。

长上下文里，全局层占了 KV 的大头。

全局层有个特殊结构，叫 K=V。

它没有 V 投影这个矩阵。

V 就是归一化后的 K 投影。

K 是 V 乘一个固定权重，再转一下位置。

说白了，K 和 V 是同一份数换了件衣服。

官方报告说，这设计能省 37.5% 的 KV。

但 vLLM 这些开源引擎没吃到这口红利。

它们还在每个头每个 token 存 1024 个数。

这篇把 1024 砍到 640。

怎么做到的？一行只存 640 个数。

K 和 V 各从这行里开一扇窗读。

窗口就是带步长的视图，不用复制数据。

注意力核一个字都不用改，直接读。

key-norm 权重折进 query 里。

输出再按固定顺序排回来。

数学上是精确的，不是近似。

核心方法

一行 640 个数，分成三段。

开头 128 个，是旋转过的 K。

中间 384 个，是没旋转的 V。

末尾 128 个，是旋转过的 V。

K 视图读 0 到 511 号数。

V 视图读 128 到 639 号数。

两扇窗在中间 384 个数上重叠。

这就是省掉的那 384 个数。

query 的未旋转部分带上 key-norm 权重。

输出按固定置换排回模型顺序。

整个过程没有近似，没有精度损失。

作者还承认，这招不是全新发明。

MLA 解码也是从一行缓存里读 K 和 V。

这篇是把它用到 K 和 V 等宽的情形。

这样现成的注意力核不用改就能读。

关键数据

单请求解码 KV，32K 时 3.29 降到 2.46 GiB。

64K 时 5.79 降到 4.13 GiB。

省 1.34 倍到 1.40 倍。

块数上，32K 从 1349 降到 1008 块。

64K 从 2373 降到 1690 块。

全局层那部分，省 1.6 倍。

算上分页对齐，省 1.5 倍。

全层加起来，就是 1.34 到 1.40 倍。

读题高峰省得少一点。

32K 省 1.15 倍，64K 省 1.23 倍。

因为读题预约里还有滑窗层的固定开销。

32K 时，15 GiB 池子多装一个请求。

批从 3 涨到 4。

解码从 56.0 涨到 69.7 词每秒。

涨 1.24 倍。

64K 时批还是 2 个，没多装。

吞吐 36.3 降到 34.8 词每秒。

反而慢了 4%。

第三个请求差 181 块，没塞下。

同批对比，每步慢 4% 到 9%。

原因是权重占了每步读数的 85%。

KV 省了，步子没快多少。

PD 拆分实测，两张 A100。

读题一张，解码一张，NIXL 传 KV。

16K 提示词，每步解码 token 是原来的 1.38 倍。

8K 提示词，是 1.24 倍。

eager 模式吞吐涨 1.30 倍和 1.11 倍。

正确性上，432 道题只变 2 道答案。

都在来回跑的噪声里。

输出跟仿真版按位一致。

FP8 KV 还没叠加上。

只在核层面试过，默认刻度下有一层超差。

所以别急着把两份省法加在一起。

跟研究方向的关联

KV 优化线直接对口。

K=V 这类结构性省法，抄进清单。

不是所有模型都有这结构。

先查模型配置里有没有 attention_k_eq_v。

PD 拆分评估里，搬运量直接少三成。

NIXL 搬运加 CPU 卸载那路已经跑通。

省显存不等于省时间。

批上不去的时候，吞吐可能还掉。

评估里 KV 字节数和批大小要分开报。

同批步时慢 4% 到 9%，也要进账。

FP8 KV 别急着叠加。

默认刻度下有一层超差，等后续工作。

术语表

  • K=V：key 和 value 是同一份数，只差一个固定权重和位置旋转。
  • 全局层：看整段上下文的注意力层，长上下文里 KV 的大头。
  • 滑窗层：只看最近一小段的注意力层，KV 不随长度涨。
  • 分页 KV：把 KV 存在固定大小的块里，像操作系统分页。
  • NIXL：英伟达的 KV 传输库，PD 拆分里搬 KV 用。
  • RoPE：旋转位置编码，给 token 标位置的办法。
  • eager 模式：不抓 CUDA 图，一步步跑的执行模式。
  • 块：vLLM 管理 KV 的一页，论文里按 262144 字节算。
