ElasticKV：显存吃紧时，KV 缓存降半格照样跑——高并发下首字延迟降 4 倍

原文：Does Execution Require Target KV Fidelity? A Mixed-Fidelity KV Runtime for LLM Serving（arXiv:2609.33536，2026-09-27；作者 Jiantong Jiang 等；基于 vLLM 实现）

一句话人话

显存不够时，推理引擎以前只会二选一：要么让请求排队等，要么直接踢掉重来。

ElasticKV 给了第三条路：把 KV 缓存（模型的"草稿纸"）临时换成半精度的"简版"，先让请求跑起来，等显存宽裕再换回完整版。

换句话说：发烧 38 度先吃退烧药撑住，别非要住院打点滴。

核心问题：被忽视的"门槛"

现在的推理引擎有个隐形规矩：请求能不能跑，看的是完整精度的 KV 是否在显存里。

完整精度（TARGET，16 位）不在显存，就只能排队或抢占（preempt）。

但抢占代价极高：被踢的请求要重算 prefill，首字延迟（TTFT，指从发请求到看到第一个字的时间）直接爆炸。

论文指出：瓶颈不只是 KV 存多少、搬多快，更是"引擎只认完整精度"这个死规定。

核心方法：三件套

1. 成对打包布局（让省下来的显存真能用）

直接把 KV 压成 8 位没用。

因为显存按固定大小的块分配（PagedAttention 的页式管理），块里只用一半，另一半还是占着——省了等于没省。

做法：两个逻辑块凑成一对（pair），降精度后两份 8 位 BASE 塞进一个物理块，腾出的另一个物理块整块还给分配器。

类比：拼车。两个人各开一辆车浪费一半座位，拼成一辆，另一辆直接还车。

2. 双模式 attention 后端（简版直接能跑，不拖累完整版）

BASE 不只是存得下，还得能直接参与 attention 计算。

论文做了个弹性 attention 后端：BASE 走简版路径，TARGET 走原生路径。

关键保证：正常无压力时，TARGET 路径性能零损失——只在压力下才启用 BASE。

3. 压力感知的精度调度（降级果断、升级谨慎）

降级（TARGET→BASE）：果断，显存一紧就动手，先保住不抢占。

升级（BASE→TARGET）：谨慎，只有显存确实有余量才升回去。

还有保护规则：attention sink（每层开头几个"锚点" token）和最近的 token 不降级，保精度。

类比：退烧药只在发烧时吃，烧退了再停；但心脏病药（关键 token）一颗都不能停。

关键数据

  • 高并发下，平均 TTFT 是标准 vLLM 的 1/3.8–1/4.0，P90 TTFT（最慢的 10% 请求）是 1/9.1。
  • 对比带 host 内存 offload 的 vLLM：平均 TTFT 降 2.0–2.6 倍，P90 降 2.5–4.7 倍。
  • 吞吐是纯显存版 vLLM 的 2.45–2.63 倍。
  • 同等压力下，基线抢占 4989/579 个请求，ElasticKV 零抢占。
  • 精度：LongBench 21 个任务，BASE 暴露 5%/10%/20% 时平均分基本追平 FP16（50.06 vs 49.89），比全程固定 FP8 还好。
  • 跨平台：NVIDIA A100 和 AMD MI355X（8 卡）都验证过。
  • 真实 trace 回放（Mooncake 生产 trace）：同样零抢占、SLO 达标率全线提升。

跟你的研究方向的关联

  • KV 缓存优化：这是目前看到把"精度降级"做进 runtime 调度层的完整方案，不是单纯压缩算法。跟你之前看的量化（AWQ/GPTQ/FP8）是互补维度：那些是静态选精度，这个是运行时按压力动态选。
  • P/D 解耦评估：论文的压力场景就是 prefill 堆积 + decode 抢显存。SGLang 的 P/D 解耦里，decode 节点的 KV 压力同样存在，这套"降半格先跑"的思路可以直接借鉴到 decode 侧容量规划。
  • AI 自动调参系统：BASE 暴露比例是个天然的可调参数——压力阈值、降级粒度、升级余量，都是调参空间。以后做 autotuner 时，这类"压力-精度"旋钮值得收进参数表。

术语表

  • TTFT（time-to-first-token）：首字延迟，从发请求到吐出第一个 token 的时间。
  • TPOT（time-per-output-token）：每个输出 token 的平均耗时，衡量 decode 流畅度。
  • 抢占（preemption）：显存不够时，引擎把正在跑的请求踢掉、KV 丢掉，之后重算。
  • PagedAttention：vLLM 的显存管理，把 KV 按固定块分配，像操作系统管内存页。
  • attention sink：每层开头几个 token，attention 权重天然集中，丢了精度崩。
  • BASE / TARGET：本文的叫法。TARGET = 完整 16 位 KV；BASE = 保留高 8 位的简版，可无损还原回 TARGET。
  • P90：把所有请求按延迟排序，排在 90% 位置的那个值——看"慢请求有多慢"。
