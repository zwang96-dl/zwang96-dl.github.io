新技术与论文

  • arXiv 9/30 批次这轮终于进了 API 索引。
  • 上轮 18 点版查时还不可见，这轮补上。
  • 六篇跟推理 serving 相关的，逐篇确认往期没报过。
  • MoSE：给推理集群的网络装了个"换挡器"。
  • P/D 解耦会把 KV 搬运变成主干道流量。
  • 但集群网络多半按训练那套静态拓扑配的。
  • KV 得绕 2 到 3 跳，才能从 prefill 送到 decode。
  • MoSE 让网络跟着负载改道。
  • 推理忙就直连 prefill 和 decode，训练忙就切回均匀扩张器。
  • 靠光电路交换重配：用光开关重排链路，不加端口、不改路由。
  • 1024 组仿真，跑了 20 个随机种子。
  • KV 通信代价平均降 90.8%，P95 降 91.9%。
  • 直连比例从 0.4% 涨到 100%。
  • KV 平均跳数从 5.66 降到 1.00。
  • 「值得深读」：中文精读笔记已生成。
  • 含原文 Figure 1/2/3 和 Table I。
  • 论文：https://arxiv.org/abs/2609.39138
  • Herschel：生产环境的推理优化，改成"按需体检"。
  • 一直开全量 profiling（性能剖析）太贵。
  • 只采轻量数据，又不够定位问题。
  • Herschel 热插拔到运行中的进程上采证据。
  • 查完就走，不改引擎、不重启。
  • 定位到低效机制后，让 AI agent 动手改。
  • 动的是 engine 和 kernel。
  • 改动先在受控环境里验证。
  • 专家审核通过才上线，改动保留触发问题的负载。
  • 受控测试里主动采集对首字延迟的影响不到 0.5%。
  • 一句话：这就是你 autotuner 想做的"线上诊断+自动改参"。
  • 论文：https://arxiv.org/abs/2609.40247
  • Inference Auctions：算力不够分时，拿"拍卖"来排队。
  • 用户对延迟的容忍度不同，但现在的分级定价太粗。
  • 这篇设计了个拍卖机制：用户出价买更快服务。
  • 算法保证真实出价最划算，还配了个自动出价 agent。
  • 按预算自动调出价，追求效用最大。
  • 实测说不丢延迟，还保住了 SGLang 的缓存利用率优势。
  • 一句话：调度策略的经济学视角，排队论之外的另一种思路。
  • 论文：https://arxiv.org/abs/2609.40070
  • Vosti：给"推理确定性"立了个形式化规矩。
  • 9/10 的深读笔记讲过：temperature=0 也不可复现。
  • vLLM 的 batch-invariant 模式宣称输出稳定。
  • SGLang 的确定性模式也这么宣称。
  • 这篇一测，发现问题了。
  • 某些执行变化下，它们的 logits（模型输出的原始分数）真不一样。
  • Vosti 自己造了个引擎：kernel 选择不看运行时状态。
  • KV 缓存跟逻辑 token 前缀绑定，还用 Verus 做了归纳证明。
  • 一句话：厂商的"确定性模式"被形式化测试翻了车，这篇是修复版。
  • 论文：https://arxiv.org/abs/2609.38981
  • SparLeak：稀疏注意力在共享 GPU 上会"漏"隐私。
  • 稀疏注意力（只看部分 token 的注意力）的访存模式跟输入有关。
  • 同卡上的邻居能从 KV 缓存的访问痕迹反推你的问题和回答。
  • prefill 阶段能猜查询属性，decode 阶段能重建回答内容。
  • 一句话：长上下文都在上稀疏注意力，共享 GPU 的隔离假设要打问号了。
  • 论文：https://arxiv.org/abs/2609.38830
  • QATFactory：量化训练对齐部署的开源框架。
  • 痛点：激进的训练后量化掉精度，但训练时又没对应精度的硬件。
  • 它在 BF16 里模拟部署时的量化噪声。
  • 比如在 H100 上训 NVFP4。
  • NVFP4 是英伟达 4bit 浮点格式，H100 原生不支持。
  • 支持 NVFP4、MXFP4、llama.cpp 的 Q4_K。
  • 导出直给 vLLM 和 llama.cpp。
  • 8B 到 230B 都测过，导出没有额外转换损失。
  • 一句话：想上 FP4 又不想掉精度，这套工具链值得看一眼。
  • 论文：https://arxiv.org/abs/2609.39223
