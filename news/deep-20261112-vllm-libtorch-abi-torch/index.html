vLLM 换 torch 不用重编了：LibTorch 稳定 ABI 迁移全记录

  • 原文：vLLM 团队，官方博客
  • 发表：2026-11-06
  • 原文链接：https://vllm.ai/blog/2026-11-06-stable-abi-cuda
  • 说明：数字全是官方自报，没有第三方实测
  • 背景：v0.33.0 已发布稳定 ABI 的 CUDA 轮子
  • 本轮是 2026-11-12 13点版深读，之前几期漏报了这篇

一句话

以前 torch 一升级，vLLM 就得跟着重编。

现在 v0.33.0 的轮子锁了稳定 ABI。

换个兼容的新 torch，直接装上就能跑。

人话解读

vLLM 的 C++ 后端天天调 PyTorch。

调的是 LibTorch，就是 PyTorch 的 C++ 部分。

API 是源码层面的约定，函数名长什么样。

ABI 是编译层面的约定，编译好的代码怎么接线。

源码没变，ABI 也可能变。

一变，扩展就得重新编译。

以前就是这样。

torch 出新版，vLLM 得重编一遍再发版。

用户只能干等。

历史数据很扎眼。

四个 torch 大版本，vLLM 跟进用了 33、34、44、60 天。

torch 2.12.0 甚至一次都没跟上。

稳定 ABI 就是一份承诺。

这批二进制接口，以后版本都不变。

只用这批接口的扩展，换 torch 不用重编。

好比插座的尺寸定死了。

换个新插头，照样插得上。

核心方法

  • 第一步，先盘点。
  • 把 vLLM 调过的所有 PyTorch 接口列出来。
  • 看哪些已有稳定版，哪些还是缺口。
  • 缺口列成清单，去跟 PyTorch 社区要。
  • 盘点结果写进 RFC，路线先定下来。
  • 第二步，元函数和自动求导搬去 Python。
  • 稳定 ABI 现在没有稳定的 SymInt。
  • SymInt 是形状推导里的符号整数。
  • 元函数就是只算形状、不真算的函数。
  • 所以元函数只能写在 Python 里。
  • 自动求导的机器也不在稳定 ABI 里。
  • 反向函数同样只能写 Python。
  • 好在 vLLM 本来多数元函数就在 Python。
  • 推理引擎也很少写反向，影响不大。
  • 第三步，搭脚手架。
  • CUDA 构建里有 175 个以上的源文件。
  • 还有 120 多个头文件。
  • 一次全迁没法审。
  • 办法是另建一个稳定库。
  • 内核一批一批搬过去。
  • 构建开关 TORCH_TARGET_VERSION 会把关。
  • 一旦混进不稳定的头文件，编译直接失败。
  • 第四步，算子走分发器注册。
  • 注册要用 STABLE_TORCH_LIBRARY。
  • 跟常用的 TORCH_LIBRARY 很像。
  • 区别是实现要包一层 TORCH_BOX。
  • 这层把 C++ 类型装箱成通用类型。
  • 通用类型才能穿过稳定 ABI 的边界。
  • 用 pybind11 注册的算子得先转 TORCH_LIBRARY。
  • 第五步，逐个源文件换稳定接口。
  • 改动大多是机械替换。
  • torch::Tensor 换成 torch::stable::Tensor。
  • at::kInt 换成 headeronly 的 ScalarType::Int。
  • t.view 换成 torch::stable::view。
  • 只许用三处头文件。
  • 稳定 C++ 包装、headeronly 工具、C 垫片。
  • 团队还给 AI 助手写了迁移技能。
  • 自动把老接口映射到稳定版。
  • 还会标出跟迁移无关的改动。
  • 第六步，验。
  • 每个迁移 diff 逐行人工审。
  • 单元测试和性能测试都要跑。
  • 还要验轮子真的稳定。
  • 工具是 torch-abi-audit。
  • 它扫 .so 文件，给每个符号分类。
  • 没有不稳定符号，才算稳定。
  • 它还会报最低 torch 版本。
  • 现在 vLLM 的 CI 里就跑着它。
  • 轮子一退化，CI 就报警。

关键数据

  • 跟进延迟：33、34、44、60 天。
  • 对应四个 torch 大版本。
  • torch 2.12.0 从没被跟上。
  • 迁移起点：RFC 发在 2025-10-15。
  • 第一批迁移 PR 发在 2025-12-29。
  • 树内代码 2026 年 6 月稳定下来。
  • 最后一块 DeepGEMM 在 2026-10-15 完成。
  • 轮子审计结果：Torch ABI 是 STABLE。
  • 最低 torch 版本是 2.13.0。
  • 13 个扩展模块，0 个不稳定符号。
  • QuTLASS 把底线抬到 2.13.0。
  • 其他模块最低只要 2.10.0 或 2.11.0。
  • 依赖一共 7 个，都要跟着迁。
  • FlashMLA、DeepGEMM、FlashAttention-2、FlashAttention-3。
  • DeepSelect、FlashKDA、QuTLASS。
  • 上游状态不齐。
  • FlashMLA、FlashAttention-3、QuTLASS 已进上游。
  • DeepGEMM、FlashAttention-2、DeepSelect 还在走流程。
  • FlashKDA 上游还没接。
  • vLLM 先在自己的 fork 里迁完。
  • 实测演示：同一份 vLLM，不重编。
  • 先跑 torch 2.14.1，输出正常。
  • 升到 torch 2.15.0，再跑，输出一样。
  • 模型是 SmolLM2-135M-Instruct。
  • 提示词是 The capital of France is。
  • 输出是 Paris. Paris is a city known for。
  • 迁移成本：宿主端多了点开销。
  • C 垫片要做类型转换。
  • 分发器调用要查表加装箱。
  • 平时基本感觉不到。
  • CUDA 图热身后，开销就消失了。
  • 只有反复启动极快小内核的 eager 模式。
  • 那里才可能看出来。
  • 迁移过程没测出明显性能回退。

跟研究方向的关联

  • 你在 vLLM 和 SGLang 之间做评估。
  • 运维成本是评估的一块。
  • torch 升级不用等 vLLM 重编。
  • 这块成本基本被这篇抹掉了。
  • 以前每次等 33 到 60 天。
  • 现在直接换轮子就能试新 torch。
  • 你的 H100、MI350X、MI300X 都跑 vLLM。
  • 换 torch 试新特性，门槛低了很多。
  • PD 评估也有关系。
  • DeepGEMM、FlashMLA 这些依赖都迁了。
  • 它们正是 MoE 和注意力那条线的关键内核。
  • 评估清单里可以加一条。
  • vLLM 轮子换 torch 版本后，跑分还稳不稳。
  • torch-abi-audit 这个工具可以直接抄。
  • 验自己编译的轮子是不是真的稳定。
  • 报告最低 torch 版本，省得猜。
  • SGLang 那边也在推 Rust 重写关键路径。
  • 两家都在砍重编和重写的税。
  • 只是砍的税种不一样。
  • 但要注意，PyPI 的包元数据还没跟上。
  • v0.33.0 还锁着 torch==2.14.0。
  • 想换版本得手动装 torch。
  • 别以为 pip 一装就自动换。

局限与提醒

  • 稳定 ABI 只是 LibTorch 的一个子集。
  • 不是所有接口都有稳定版。
  • is_pinned 当时就没有，只能走分发器绕。
  • 2.14 才补了稳定的 C++ 版本。
  • SymInt 和自动求导现在还不支持。
  • 元函数和反向只能写 Python。
  • 宿主端多了类型转换和查表开销。
  • 极快小内核的 eager 模式可能看出来。
  • 迁移时没测出回退，但那是 vLLM 自己的测试。
  • CPU 和 ROCm 构建还没迁。
  • ROCm 共享了多数源文件，剩得不多。
  • 但没迁完之前，别默认 ROCm 也稳定。
  • PyPI 元数据还锁着 torch 2.14.0。
  • 想换 torch 得手动装，别走 pip 默认。
  • 数字全是 vLLM 官方自报。
  • 没有第三方复现。

术语表

  • ABI：二进制接口，编译好的代码怎么跟库接线。
  • API：源码接口，函数名和参数长什么样。
  • LibTorch：PyTorch 的 C++ 部分。
  • 稳定 ABI：一批承诺不变的二进制接口。
  • C 垫片：一层薄薄的 C 接口，把 LibTorch 接口包起来。
  • headeronly：只含头文件、不链接库的工具代码。
  • SymInt：形状推导里的符号整数，长度可以是变量。
  • 元函数：只算输出形状、不真算的函数。
  • 自动求导：反向传播算梯度的机器。
  • 分发器：按输入类型把算子派到对应实现的调度器。
  • TORCH_LIBRARY：PyTorch 注册自定义算子的宏。
  • TORCH_BOX：把 C++ 类型装箱成通用类型的包装。
  • pybind11：把 C++ 绑到 Python 的工具。
  • torch-abi-audit：扫 .so 文件、分类符号稳不稳定的工具。
  • eager 模式：算子一个一个立即执行的模式。
  • CUDA 图：把一串内核调用录下来、一次回放的加速手段。
  • 轮子：Python 的二进制安装包，.whl 文件。
  • fork：把别人的仓库复制一份自己改。
