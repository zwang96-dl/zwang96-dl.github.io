DeepInfer：DeepSeek 自家引擎开源精读

原文链接：https://github.com/deepseek-ai/DeepInfer 发布时间：2026-10-20 02:08 PDT（HN 首帖时间） 许可证：Apache 2.0

人话解读

  • DeepSeek 把自家引擎开源了。
  • 它就是线上服务的同款底座。
  • 现在只服务一个模型。
  • 模型是 V4.1-Flash。
  • 这次放出的是离线推理。
  • 在线服务还差三件套。
  • 草稿纸系统没有放出来。
  • 草稿纸就是 KV 缓存。
  • PD 解耦也没有放出来。
  • PD 解耦就是分工流水线。
  • 负载均衡同样没有放。
  • 先说清最关键的一条。
  • 你的三台机器都跑不了。
  • 它只认两种新硬件。
  • 一种是英伟达 SM100。
  • 那是 B200 那代芯片。
  • 另一种是华为昇腾 950。
  • H100 是上一代 SM90。
  • MI350X 和 MI300X 是 AMD。
  • 三台都不在名单里。
  • 所以这篇是看思路用的。
  • 不是拿来直接部署的。
  • 数字都是官方自报。
  • 没有独立复测，别当定论。

核心方法

  • 底子主要搭在 vLLM 上。
  • 它 README 里写得很清楚。
  • 还借鉴了 SGLang 等框架。
  • 内核是一整套自家货。
  • 有 FlashMLA 等五个库。
  • 都是 DeepSeek 之前开源的。
  • 并行这边给了三件套。
  • 注意力走数据并行加上下文并行。
  • 专家走专家并行加负载均衡。
  • 专家就是 MoE 的分工小组。
  • 投机解码叫 DSpark。
  • 像实习生先打一版草稿。
  • 专家再按信心决定验哪段。
  • 草稿最长默认是 5 个词元。
  • 解码还有个省活的招。
  • 叫有界重放，只补尾巴。
  • 默认只留最后 140 个词元。
  • 调度默认走异步模式。
  • 排队和计算同时进行。
  • 还有批次不变性这个开关。
  • 同一问题换批次结果不变。
  • 打开它还能做确定性采样。
  • 结构化输出也内置了。
  • 能按正则和 JSON 格式卡住。

关键数据

  • 仓库是 10 月 16 日建的。
  • 今早 09:12 UTC 推送更新。
  • HN 首帖冲到约 298 分。
  • 评论有一百多条。
  • 我核时星标约 4700 个。
  • prefill 图在 4 卡上测。
  • decode 图在 64 卡上测。
  • 两组都在一个互联域里。
  • 上下文长度都是 131072。
  • prefill 每卡约 6 万词元每秒。
  • 那是批次 4096 时的数。
  • 批次拉到 65536 时更高。
  • 每卡约 9 万词元每秒。
  • 代价是单步延迟涨十倍。
  • 从约 70 毫秒涨到 730 毫秒。
  • decode 每卡最高约 2.6 万。
  • 那是每人约 103 词元每秒时。
  • 想让每人跑到约 325 的话。
  • 每卡吞吐只剩约 2600。
  • 这就是吞吐和手感的交换。
  • 投机接受率图里写了 75%。
  • 平均一次能过 3.25 个词元。

跟你研究方向的关联

  • 你在评估 SGLang 的 PD 解耦。
  • 它偏偏没放解耦那部分。
  • README 说引擎功能已大半实现。
  • 但这次发布就是不带它。
  • 所以解耦细节还得看别家。
  • 能借的是它的投机做法。
  • 按信心排验证顺序这招。
  • 跟你看的 DSpark 线索同源。
  • 有界重放也值得抄思路。
  • 它能少重算解码前的活。
  • 对长上下文场景很实用。
  • 批次不变性对调参有用。
  • 自动调参最怕结果乱飘。
  • 结果稳定才好比参数好坏。
  • 它的性能图画法也值得学。
  • 吞吐永远配着延迟一起画。
  • 这正是 SLA 内比吞吐的画法。

术语表

  • SM100：英伟达 B200 那代架构。
  • SM90：英伟达 H100 那代架构。
  • KV 缓存：存好的中间结果草稿纸。
  • PD 解耦：读题和答题分开跑。
  • DSpark：DeepSeek 的投机解码。
  • 投机解码：先猜几词再一起验。
  • MoE：按题分给专家小组的模型。
  • 专家并行：专家拆到多卡上跑。
  • 有界重放：只重算最后一小段。
  • 批次不变性：换批次结果不变。
  • Pareto 图：吞吐延迟一起看的图。
