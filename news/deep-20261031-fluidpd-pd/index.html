FluidPD：PD 解耦里，读题吐字两拨人不够用了怎么办

原文：FluidPD: In-Place Elasticity for SLO-Aware Prefill-Decode Disaggregated LLM Serving 作者：Kartik Ramesh、Kaidi Fu、Zihan Zheng、Jiahuan Yu、Fabio Oliveira、Carlos Costa、Minjia Zhang（IBM Research） arXiv:2610.06917，2026-10-02 提交，2026-10-31 02点版深读 原文链接：https://arxiv.org/abs/2610.06917

一句话人话

PD 解耦把读题和吐字分到两拨机器，可真实流量的读题/吐字比例忽上忽下。配比写死了就会一边排长队、一边机器闲着，SLO 照样违约。这篇让 worker 不用重启、原地换角色，比例跟着流量走。

为什么值得读

  • 你正在评估 SGLang 的 PD 解耦，配比调不出是核心痛点之一
  • 这篇给了两个现成旋钮：瞬时借调（FluidToken）、持续换角（FluidRole）
  • 它的 PPI/DPI 压力指数，正是你 autotuner 缺的提前量信号
  • 跟之前深读的 DolphinRouting、AMPD 互补：那两个管请求去哪，这篇管 worker 演什么

核心方法

问题抓得很准：固定 P/D worker 配比下，读题/吐字需求比一漂移，配置立刻错配。加机器的 autoscaling 反应慢、还要备卡，治不了分钟级的不平衡。

两个机制，分治两种不平衡：

  • FluidToken（治瞬时）：读题侧突发排队、吐字侧还有余量时，把有界的一部分读题计算卸给吐字 worker
  • FluidRole（治持续）：把运行中的 worker 原地换角色。

读题切吐字、吐字切读题都行。 全程不用重载模型、不重启引擎

压力指数提前报警：两组轻量指标：PPI 管读题压力，DPI 管吐字压力。 在 SLO 违约前就暴露哪边吃紧。

换角不丢请求：要切角色的 worker 先 DRAIN。 没开工的排队请求转给同角色其他人。 手头的干到安全边界再切。换角代价跟方向有关，选代价最小的那台下手。

连续 N 个周期都说要换才真换：防止压力毛刺引发反复横跳。

关键数据

  • 生产 Azure trace 上回放。
  • 整体 SLO 达成率对静态 SGLang 最高提升 94.6 个百分点
  • 增益主要来自首字延迟（TTFT）达成率，吐字间隔（TPOT）双方都接近 100%
  • 6 张卡的 FluidPD，打赢了扩到 8 张卡的 Dynamo 自动扩缩
  • 消融：FluidRole 单独贡献大于 FluidToken，两者叠加最好
  • 评测模型：Llama-3.1-8B、Qwen3-14B、Qwen3-30B-A3B MoE
  • 全部为作者自报，无第三方复现。
  • SLO 口径是 TTFT 3000ms、TPOT 150ms

跟你研究方向的关联

  • 你的 PD 解耦评估清单里，P/D 配比最难调。
  • 这篇把配比做成了运行时自动的
  • PPI/DPI 这组压力指数可以直接借进你的 autotuner，当提前量信号用
  • FluidToken 的有界卸载，跟你已有的 KV 搬运账本是上下叠加：一个借计算、一个搬草稿纸
  • 注意口径差异：它的 SLO 是 3000ms 首字、150ms 吐字。
  • 你的短输入场景下阈值要重设
  • 它的评测是 Azure 对话 trace，不是智能体多轮负载。
  • 搬结论前先在你自己的负载上复测

术语表

  • PD 解耦：读题（prefill）和吐字（decode）分到不同机器跑的分工流水线
  • SLO：服务等级目标，这里指延迟达标线
  • PPI/DPI：读题压力指数/吐字压力指数，提前暴露哪边吃紧的轻量指标
  • FluidToken：瞬时借调，把一部分读题计算临时卸给有余量的吐字 worker
  • FluidRole：持续换角，worker 原地在读题/吐字角色间切换，不重启不重载模型
  • DRAIN：换角前的安全过渡，把没开工的请求转走、手头的干到安全边界
  • Autoscaling：自动扩缩容，流量大了加机器，小了减机器，反应慢还要备卡
  • TTFT/TPOT：首字延迟/吐字间隔，推理延迟的两个常用口径
  • CUDA Graph：把一串算子录成一张图反复回放，省掉每次调度的开销
