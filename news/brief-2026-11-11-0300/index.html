vLLM：6 条，懒卸载那条最值得看

先说 #61797，跟前缀缓存有关。

前缀缓存就是把算过的历史先存着。

下次遇到相同的开头，直接复用，不用重算。

这次加了懒卸载：GPU 空闲队列里的块。

挑出能复用的，慢慢挪到别处存着。

全注意力前缀链先合上，源块钉住不动。

传完了才放行，每秒只扫一次队列。

说白了，显存腾地方时，好草稿纸先搬走。

不是等到被踢出去，才想起来抢救。

来源：https://github.com/vllm-project/vllm/pull/61797

第二条 #66994，跟批量不变性有关。

批量不变性就是同一请求，不管怎么拼批。

结果逐位都一样，这是确定性评估的底线。

多模态 OCR 的抢占测试，以前跑不过。

因为某一步输出随批量大小变了半个数。

现在测试改成按批量不变的方式跑。

来源：https://github.com/vllm-project/vllm/pull/66994

第三条 #66196，跟 P/D 解耦测试有关。

P/D 解耦就是读题和生成分开跑。

NIXL 是英伟达的卡间传输库。

P/D 交接就靠它搬 KV 缓存。

这次把 NIXL 的精度 sweep 改成 pytest。

还能自动分片跑，原来是手写 bash 循环。

其余三条一句话带过。

#66489，空消息列表现在直接报 400。

以前会跑完一轮生成，才报 500 错。

#66781，Rust 前端多跑一批 Python 测试。

#65541，Rust 的压测结果文件跟 Python 对齐。

SGLang：8 条，Kimi-K3 那条最值得看

先说 #41794，跟 Kimi-K3 有关。

KDA 是一种新注意力，带状态递推。

AMD 卡上有融合的 KDA 解码核。

投影、卷积、状态更新、归一化一次跑完。

但部署的 Quark 权重一直没触发这条快路。

解码悄悄走没融合的老路，每步多几次启动。

现在 BF16 状态加 Quark 权重，融合核终于生效。

来源：https://github.com/sgl-project/sglang/pull/41794

第二条 #49567，也是 AMD 的提速。

注意力输出现在直接写进调用方给的 buffer。

以前先写临时 buffer，再拷一次。

拷贝省了，breakable 的读题图也少绕一圈。

第三条 #46830，跟 DSA 有关。

DSA 是 DeepSeek 的稀疏注意力。

rank 走岔路的 eager 路径上，host 同步删了。

host 同步就是 CPU 等 GPU 回话，越少越好。

第四条 #46820，KV 指标背压不再堵调度器。

指标就是监控用的数字，背压是下游顶住。

以前指标顶住了，调度器跟着停摆。

现在监控慢了，调度照常走。

其余四条一句话带过。

#49574，MiniMax-H3 扩散模型的加载修补。

公开的 H3-Image 快照之前起不来。

#47096，工具调用回放并进前一条评论消息。

#49787，文档里 AgentX 改名 InferenceX。

#49750，NPU 镜像 tag 升到 2026.11.0.post3。

TRT-LLM：5 条，DSA 索引器那条最值得看

先说 #21892，跟 DSA 读题有关。

DSA 读题时要给每个查询行挑 top-k 的键。

top-k 就是只留最相关的几个。

以前要先把整个 logits 矩阵算出来。

logits 就是每个词的打分。

现在融合索引器直接挑，不物化大矩阵。

还替换了 DeepGEMM 的那对核。

只在 SM100 和 SM103 上，默认关闭。

SM100 就是 Blackwell 架构的卡。

来源：https://github.com/NVIDIA/TensorRT-LLM/pull/21892

第二条 #22050，是个修补。

全上下文解码跟 PrimTS 的新接口对齐。

PrimTS 是 TRT-LLM 里的一套运行时。

其余三条都是基建。

#22101，Slurm runner 固定在各自并行分支。

#22094，pre-merge 豁免一个失败用例。

#22081，删了 Nemotron V3 的几条并行配置。

llama.cpp：6 条，CPU 精度那条最值得看

先说 #29810，跟 CPU 推理有关。

单块的 CPU 注意力核，V 的累加以前用 F16。

F16 就是 16 位浮点，精度低。

长上下文会丢精度，甚至溢出成无穷大。

现在改成 F32 累加，跟分块核保持一致。

来源：https://github.com/ggml-org/llama.cpp/pull/29810

第二条 #31526，Vulkan 的 KV 反量化优化。

反量化就是把压过的 KV 再展开算。

现在能跟 CM2 配合开了。

其余四条一句话带过。

#32060，安卓聊天编辑器打开虚拟键盘。

#32008，Vulkan 的设备故障 buffer 分配。

#31877，WebGPU 加了 PAD_REFLECT_1D 支持。

一篇实测：agent 跑起来，vLLM 和 SGLang 一半的活都在白干

这是昨晚的一篇实测，之前几期漏报了。

作者 Nahuel Nucera，自己写了个 Rust 引擎。

约 1700 行，专为 agent 会话设计。

思路很简单：会话的 KV 缓存留在显存里。

KV 缓存就是算过的历史草稿纸。

agent 每轮都把整段历史重发一遍。

中位数 60 轮，历史能长到几万个词。

工具一跑，历史就被 LRU 踢出显存。

LRU 就是最久没用的先踢掉。

回来又得全重算，等于白干一半活。

实测 24 个真实 coding agent 会话。

791 轮，Qwen3-8B，一张 L40S。

工具等 0.5 秒时，Rust 引擎比 SGLang 快 1.31 倍。

比 vLLM 快 1.45 倍，首字快约 5 倍。

vLLM 和 SGLang 有 51% 到 55% 的词是重算。

Rust 引擎只有 8% 到 16%。

工具等 5 秒时，优势缩到 1.13 倍。

等 60 秒时，基本打平，首字反而更慢。

说白了，agent 回来得快，留着草稿纸就赚。

回来得慢，留着也是占地方。

这篇跟你的前缀缓存研究直接撞上。

Agent 会话的草稿纸，留在显存里才划算

作者 Nahuel Nucera，dev.to 文章加同名论文。

2026-11-11 发布，代码和论文都开源了。

24 个真实 agent 会话、791 轮，同卡同模型同显存。

工具等 0.5 秒时，全程快 1.31 倍、首字快约 5 倍。

重算的历史从一半多，压到 8% 到 16%。

工具等 60 秒时，优势全没了。

三条固定策略全败，跨会话共享前缀才扳回平手。

这篇能帮你回答一个实际问题。

agent 场景下，前缀缓存到底该留多久。

留的判断标准、三个失败策略、复用率的算法。

都能直接进你的 PD 解耦评估清单。

但只测了一个模型、一张卡、一种负载。

CPU 卸载和 SGLang 流式会话都没测。
