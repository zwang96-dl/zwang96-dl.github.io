SGLang：GLM-5.3-Flash 的 PD 读题开 CP，H20 上 64k 读题快 1.51 倍

一句话

GLM-5.3-Flash 的 PD 读题节点。

以前开上下文并行只认 DFlash2。

现在原生 MTP 和不用投机解码也能开了。

64k 读题快了一半多，精度没掉。

人话解读

先讲 PD 解耦是什么。

它是读题和写答案分开跑。

读题那拨算完，把草稿纸传给解码那拨。

草稿纸就是 KV 缓存。

读题节点想算得快，可以开 CP。

CP 就是上下文并行。

它把一份长输入拆到多张卡上算。

GLM-5.3-Flash 是智谱的新旗舰模型。

它的 PD 读题节点以前有个硬性限制。

开 CP 必须配 DFlash2。

DFlash2 是一种投机解码的草稿验证机制。

投机解码就是先让小模型打草稿。

再让大模型一次验一堆。

原生 MTP 是另一种草稿姿势。

MTP 就是多词预测，一次多猜几个词。

官方菜谱用的就是原生 MTP。

但读题节点开 CP 时碰上它，启动直接报错。

不用投机解码也一样，照样报错。

这回把那条限制拆了。

三种姿势都能开 CP 了。

测试在两台机器上跑的。

一台是 8 张 B300。

一台是 8 张 H20。

读题和解码各占一半卡。

中间用 Mooncake 传草稿纸。

Mooncake 是开源 KV 缓存池。

结果是速度涨了，精度没动。

核心方法

1. 拆掉 DFLASH-only 的限制

改动集中在一个钩子文件里。

cp_tp_group_sharing_hook.py。

以前它在 GLM-5.3-Flash 的 PD 分支里写死。

只有 DFlash2 能走 CP。

这回把这条规则删了。

前面的投机检查还在。

它只放行 DFlash2 和原生 MTP。

原生 MTP 还要求 top-k 等于 1。

top-k 就是一次猜几个候选词。

解码节点、非 Mooncake 后端照样被拦。

并行度大于 1 的 PP、DP、EP 也照样被拦。

说白了，门从只开一扇改成开两扇。

但没资格进的还是进不去。

2. 草稿种子从 CP 汇总的张量里取

放行只是第一步。

种子要对得上，验证才不会翻车。

种子就是 MTP 第一轮验证用的草稿起点。

它由 top-k、隐藏状态和 DSA 种子拼成。

DSA 就是稀疏注意力，只算重要的部分。

读题节点开 CP 后，这些张量散在各路 rank 上。

这回在写种子前先汇总。

隐藏状态在算 logits 之前汇总。

索引 top-k 在写种子前汇总。

汇总完再拼种子，解码那边才能接着验。

3. 草稿层 KV 在每路 CP rank 上都存全量

目标模型的 CP 和 TP 位置要对齐。

CP rank r 就当 TP rank r 来注册。

目标的 MLA KV、KDA 状态和辅助 buffer。

都发到解码端对应的 TP rank 上。

MLA 就是多头隐注意力，KV 压得很扁。

KDA 是配套的状态分片。

草稿层跟目标层走同一套位置。

每路 CP rank 上都存一份完整草稿 KV。

各路发出去的都是完整拷贝。

跟不开 CP 的 PD 一个做法。

不用改传输逻辑。

4. 测试加了原生 MTP 的 PD 用例

新测试叫 TestGlm53CpBcgMtpPD。

它跑了三组旧测试。

填充分块加前缀重放。

不均匀批量填充重放。

GSM8K 数学题。

还加了一个新测试。

test_first_verify_uses_prefill_draft_seed。

它只让解码跑一次验证。

验证用的草稿必须来自读题节点发的种子。

做个反向对照能看出来。

种子换成全零，验证一次都过不了。

测试就挂，说明种子确实在起作用。

跟研究方向的关联

这篇直接撞上你的 PD 解耦评估。

五招能直接进评估清单。

第一招：读题池子的并行姿势要单列。

CP 以前只配 DFlash2。

现在 MTP 和不用投机解码也能配。

评估清单里要加一栏。

每种投机姿势配 CP 的收益各是多少。

第二招：首字要按分块和图上限分档报。

B300 默认设置下 CP 反而慢 2.9%。

图上限抬到 16384 才快 1.23 倍。

只报一个倍数会骗人。

第三招：DP attention 也要放进对照组。

H20 上它连 20 秒线都过不了。

B300 上它吞吐最高，但单请求首字最慢。

高并发和单请求是两个赛道。

第四招：种子对齐要进检查清单。

CP 汇总这一步漏了，验证就翻车。

新模型上线先对一遍种子来源。

第五招：精度对照要看三组数。

GSM8K、长针、接受长度都得看。

只看一组数，容易漏掉暗病。

还有一个方向值得跟。

EP 大于 1 和 NIXL 后端还没放行。

作者说 #44293 在跟 NIXL 和 EP。

放行之后要再核一遍。

术语表

  • PD 解耦：读题和解码分开跑，各用各的实例
  • 读题：prefill，把输入一次性算完
  • 解码：decode，一个词一个词往外吐
  • CP：上下文并行，把长输入拆到多张卡上算
  • TP：张量并行，把一层拆到多张卡上
  • DP attention：数据并行注意力，多路并行算注意力
  • EP：专家并行，MoE 的专家拆到多张卡上
  • PP：流水线并行，把模型层拆到多张卡上
  • MTP：多词预测，一次多猜几个词
  • EAGLE：一种投机解码的草稿模型
  • DFlash2：一种投机解码的草稿验证机制
  • 投机解码：先让小模型打草稿，再让大模型一次验一堆
  • top-k：一次猜几个候选词
  • KV 缓存：模型的草稿纸，记着每轮对话的上下文
  • Mooncake：开源 KV 缓存池，管显存内存和 SSD
  • MLA：多头隐注意力，KV 压得很扁的注意力
  • DSA：稀疏注意力，只算重要的部分
  • RoCE：基于以太网的远程直接内存访问
  • GSM8K：小学数学题测试集，常用精度对照
  • 长针测试：大海捞针，测长上下文找东西的能力
  • 接受长度：草稿一次被接受的平均词数
  • 首字：TTFT，第一个词吐出来要等多久
  • P95：95% 的请求都比这个数快
  • B300：英伟达 Blackwell 架构的数据中心 GPU
  • H20：英伟达 Hopper 架构的数据中心 GPU
  • 种子：MTP 第一轮验证用的草稿起点
  • 握手：两边实例建立连接时先对一遍条件
