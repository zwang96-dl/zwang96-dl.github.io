多模态大模型推理服务简报 · 2026-11-04（3点版）

3点版来了。凌晨小窗口，动静不大。vLLM 本轮挂零。SGLang 在昇腾 NPU 上补了一块投机解码。Dynamo 修了一个 PD 链路的取消传播。

框架更新

SGLang 1 笔

#38440：昇腾 NPU 上，DeepSeek-V4 的投机解码有了紧凑模式 投机解码就是小模型先打草稿、大模型再改。昇腾后端以前只能用统一的验证窗口，或者干脆退回后处理。两处冤枉开销：验证窗口按最长的算、收尾步骤不在计算图里。这笔 PR 把紧凑模式搬到 NPU 上。验证图按 token 层级回放，收尾步骤也融进图里。玩昇腾卡的同学可以期待。 来源：https://github.com/sgl-project/sglang/pull/38440

Dynamo 1 笔

#14775：客户端取消，能传到远端的 prefill 卡了 PD 解耦就是 prefill 和 decode 分开跑的分工流水线。以前客户端取消请求，prefill 端的远程 worker 可能还在干活。这笔让取消信号穿过路由器，传到远程 prefill worker。省掉的算力马上释放。 来源：https://github.com/ai-dynamo/dynamo/pull/14775

TRT-LLM 2 笔

#21503：Kimi K2 的工具解析器，流尾的参数不再丢 用 Kimi K2 / K2.5 做流式工具调用。如果最后一个数据包正好带完整个工具调用，旧参数会被吞掉。这笔把流尾的参数释放出来。agent 场景下值得升级。 来源：https://github.com/NVIDIA/TensorRT-LLM/pull/21503

#20650：KV 窗口检查先看开关再记日志 每步 decode 都要查 KV 窗口是否越界。日志级别的判断本身挺贵，还在栈里翻调用者。这笔先看容量、再看日志开关。小优化，略过不亏。 来源：https://github.com/NVIDIA/TensorRT-LLM/pull/20650

llama.cpp 3 笔

#31635：Gemma4 助手的 flash attention 跟进了。#31607：RISC-V 向量指令按目标扩展开关。其余 #31644 是 ggml 同步，略过。

来源：https://github.com/ggml-org/llama.cpp/pull/31635

FlashInfer 5 笔

全是 cake 内核微调。#8633 那笔动了 decode 合并的 TP4 行轮询。其余是梯度 kernel 的调优配置。跟训练沾边多，serving 略过。 来源：https://github.com/flashinfer-ai/flashinfer/pull/8633

新技术与论文

光交换给 decode 铺路：静态光路切换做 LLM 解码（2611.05104） decode 是逐个 token 吐字的阶段，最怕通信拖后腿。这篇用光路切换搭互联。光路事先按负载配好，不用动态调度。说白了：给卡和卡之间修一条光纤专用道。做长上下文 serving 的，可以看一眼思路。 来源：https://arxiv.org/abs/2611.05104（11/3 提交）

卸载式 MoE 推理：多请求交错打，显存和算力都不闲（2611.04794） MoE 就是每次只激活几个专家的模型。权重放不下显存时，要在 CPU 和 GPU 之间倒腾。倒腾的功夫 GPU 就闲着。这篇让多个请求的倒腾和计算交错开。一个在搬，一个在算。单机玩大 MoE 的，思路可借鉴。 来源：https://arxiv.org/abs/2611.04794（11/3 提交）

业内新闻

英国 ARIA 要实测光计算服务器：给 prefill 那步换光路（11/3） Lumai 是牛津分拆的光计算创业公司。它的 Iris 服务器把矩阵运算放在光束里做，主攻 prefill 那步。prefill 就是先读提示词、一次算完的阶段。ARIA 要把几台 Iris 搬进自家的推理实验室。实验室花了 5000 万英镑，专做推理规模化验证。目标是验证功耗降 90% 的说法。数字目前全是创业公司口径，没独立实测。跟上面那篇光路论文正好呼应。 来源：https://www.siliconreport.com/aria-will-test-lumai-servers-that-use-light-to-run-ai-models

Anthropic 开源 FlashProve：用密码学证明"真是这个模型答的你"（11/2） FlashProve 是一套零知识证明系统。模型方先对权重做一次承诺，每次回答附上一份短证明。用户不用看到权重，就能验证回答确实出自宣称的模型。代价不小：生成证明的 GPU 时间是跑 vLLM 推理的 70 到 95 倍。上下文目前只到 1024 token。防的是第三方路由偷换便宜模型那档事。 来源：https://pondero.ai/news/2026-11-04-anthropic-flashprove-provable-inference/

访谈与深度

DeepInfer 产品视角：DeepSeek 没开源的才是产品（11/3） DeepInfer 本体 10 月 20 日已报过，这里是新的产品分析。DeepSeek 把部署 Q&A 更新到了 0.2 版。披露了集群分工、缓存保留时长、单卡每小时收入。有个新料：vLLM 团队也报了个数，在 GB200 上。batch 从 8 到 256，decode 只慢 6% 以内。提醒一句：数字都是 DeepSeek 和 vLLM 各自口径，无独立复测。评估 serving 方案时，这篇可当方法论对照。 来源：https://medium.com/@saeed_themedaibiref/deepseek-open-sourced-its-inference-engine-what-it-kept-back-is-the-product-d05aa7b09f0c

KV 预留量其实是个定价问题：报童模型视角（11/3，LinkedIn） KV cache 就是解码时留的草稿纸，预留多了浪费显存、少了会被抢占。作者把这写成运筹学的报童问题。最优预留分位点，等于抢占成本和闲置成本的临界比。正好呼应 1点版那篇 cμ 调度论文。偏理论，但能帮你想明白调度器的天花板。 来源：https://www.linkedin.com/pulse/your-kv-reservation-quantile-price-you-never-wrote-down-jatasra-cfzqc

补漏：ElasticMM，多模态 serving 的新执行范式（HN） 这条是两天前的 Show HN，之前各版漏了。ElasticMM 是专为多模态大模型做的开源 serving 系统。NeurIPS 2025 的 Oral 论文。它提出一个新执行范式。英文名 Elastic Multimodal Parallelism。翻成中文：弹性多模态并行。按推理阶段和模态动态调并行度。论文口径：TTFT（首 token 延迟）降 4.2 倍。混合多模态负载吞吐涨 3.2 到 4.5 倍。正对你的多模态推理优化方向。开源地址在 GitHub。 来源：https://news.ycombinator.com/item?id=46269848
