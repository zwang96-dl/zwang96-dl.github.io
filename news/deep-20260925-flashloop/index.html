FlashLoop：循环模型的"懒人更新"，KV 缓存直接砍掉 6 倍

原文：FlashLoop: Fast and Memory-Efficient Looped Transformers via Lazy Updates（arXiv:2609.29812，2026-09-24，Wanqi Yang / Shiwei Liu，ELLIS Institute Tübingen；代码 https://github.com/Superone77/FlashLoop）
一句话版本：循环模型每轮都重复算、每轮都存一份 KV。
FlashLoop 发现后面的轮次基本在"摸鱼"，只更新变化的 token，剩下的复用。

人话解读

循环模型（Looped Transformer）是个省参数的思路。

同一组 Transformer 块反复跑 R 遍，计算深度上去了，参数不增加。

听着很美，实际部署是个坑。

每跑一遍，就要存一份新的 KV cache（推理草稿纸）。

R 遍就是 R 份，显存和计算量跟着轮数线性涨。

论文给的例子很扎心：Ouro-2.6B 跑 4 遍，32K prompt 在 A100 上 prefill 要 27 秒。

同级别的 LLaMA-3.1-8B 只要 3 秒。

KV cache 一个人吃 48 GiB，对面只要 4 GiB。

参数只有人家的三分之一，推理账单反而贵 10 倍。

FlashLoop 的核心发现：后面的轮次，大部分工作都是重复的。

状态变化越来越集中在少数 token 上。

注意力的变化被一小撮 key 列主导。

相邻两轮的 KV 差值（residual），比完整 KV 好量化得多。

于是三板斧，全部免训练、推理时直接用：

  • Token-Sparse Updates：只给"还没收敛"的 token 重算，其余的直接复用上一轮的状态和 KV。
  • Sparse Attention：按上一轮的注意力贡献统计，只挑重要的 key 列算，softmax 规模用缓存的全局概率质量保住。
  • KV-Residual Quantization：存一个量化后的基准态，各轮之间只存低比特的差值。

核心方法

  • 动机来自实测，不是凭空想的。
  • 循环 refinement 有个"偷懒"规律：轮次越往后，变化越稀疏、越可预测、越好压缩。
  • 三种冗余，一一对应三个组件。
  • Token 级冗余：轮间隐状态变化集中在少数 token。
  • 注意力列冗余：后一轮的注意力输出，用前一轮挑出的少量 key 列就能重建。
  • KV 存储冗余：相邻轮 KV 差值在同样量化配置下重建误差更低。
  • 三个组件是累加开启的，消融实验（原文 Figure 4）逐个验证贡献。
  • 硬件感知流水线 + 优化 kernel 落地 GPU，不是纯纸面方案。

关键数据

  • 端到端加速最高 1.64 倍，KV cache 显存最高省 6 倍，精度无损。
  • 8K 上下文（Ouro-2.6B R4）：KV cache 小 5.8 倍，8K prefill 计算量小 1.8 倍。
  • 32K 上下文：KV 省 20 GiB（降 82.8%），加速约 1.6 倍。
  • 上下文越长、轮数越多，收益越大（原文 Figure 6/7）。
  • 超参鲁棒性：第 3 轮留 25% token、第 4 轮留 10%，精度基本不动。
  • 4-bit KV 差值量化：相对 BF16 基准，KV 体积和 decode kernel 延迟大降，精度影响可忽略。
  • 2-bit 就不行了，精度明显掉。
  • 注意力列保留 5% 时精度才开始掉，之前都很稳。
  • 对比基线：H2O 每轮独立压 25% token，不懂利用跨轮冗余，精度掉得多。
  • Last-step KV Reuse 只留最后一轮 KV，丢了中间轮的信息，精度也掉。
  • FlashLoop 是唯一"跨轮信息保留 + 冗余压缩"兼得的。

跟你研究方向的关联

  • 这是 KV cache 优化的一个新维度：之前大家压的是"层间、token 间"的冗余，这篇压的是"轮次间"的冗余。
  • "存差值不存全量"的思想可以借鉴：KV-Residual Quantization 本质是增量编码，跟你做 KV 压缩是一个路数。
  • 如果你在评估的模型里有循环/权重共享结构（或 test-time compute 放大的推理模型），这篇是直接可用的推理加速方案。
  • 免训练是最大卖点：不用重训、不用改权重，推理框架侧就能接。

术语表

  • Looped Transformer（循环 Transformer）：同一组 Transformer 块反复跑多遍的模型，用少量参数换更深的计算。类比：同一道菜谱炒三遍，锅还是那口锅。
  • Lazy Updates（懒人更新）：变化小的部分就不重算，直接复用。类比：文档只改了两段，就没必要全文重印。
  • KV residual（KV 差值）：相邻两轮 KV 的差。差值小而集中，比完整 KV 好压缩。
  • Token-Sparse Updates：只更新活跃 token，其余复用。
  • Ouro / Huginn：论文里用的循环模型。Ouro-2.6B 是主力测试对象。
  • H2O：一种 KV 驱逐基线，按注意力分数只留 25% token。这里被当反面教材。

局限与提醒

  • 只在循环模型上验证过：Ouro、Huginn 等。普通 Transformer 没有"轮次"这个维度，用不上这套。
  • 1.64 倍加速是端到端上限，32K 长上下文下约 1.6 倍，短上下文收益会小。
  • decode 侧的稀疏更新有调度开销，单加 Token-Sparse 时 decode 延迟反而涨，三个组件要配套用。
  • 实验在单张 A100-SXM4-40GB 上，多卡/大 batch 下的表现论文没给。
