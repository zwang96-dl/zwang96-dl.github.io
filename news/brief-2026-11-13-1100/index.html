11点版来了，头条是 vLLM 给视觉编码器提速。

框架更新

头条：vLLM 给 Muse 视觉编码器提速

Muse 是个多模态模型系列。 它的视觉编码器以前每张图都要等 GPU 回话。 等一次，就卡一次，视频一多就慢。 这回 #64822 把布局挪到 host 上算。 GPU 和 CPU 之间不再来回同步。 两个编码器的同步都从 800 多次降到 0。 32 帧视频编码快了 1.15 到 1.22 倍。 输出跟原来逐位一致，没变味。 图片和正常服务不受影响。 来源：https://github.com/vllm-project/vllm/pull/64822

vLLM：9 条，量化那两条值得看

先说 #61815。 没量化的输出头，现在能在线压成 FP8。 输出头就是最后那层，负责吐词。 小激活参数的 MoE 模型上，它是大头。 每吐一个词，都要读它一遍。 压完，验证和解码都能快一点。 这是可选项，输出会变，自己选。 来源：https://github.com/vllm-project/vllm/pull/61815

再说 #62515。 推测解码的自适应验证，接上了新后端。 针对 GLM-5.3-Flash，在 Hopper 卡上跑。 推测解码就是先让实习生打草稿再让专家改。 来源：https://github.com/vllm-project/vllm/pull/62515

再说 #67041。 HiSparse 那边撤回了一个改动。 之前它强行换了 FlashInfer 的集合通信后端。 这回撤了，回到原来的做法。 来源：https://github.com/vllm-project/vllm/pull/67041

SGLang：2 条，都是 AMD 卡上的小修

先说 #43136。 DCP 就是把上下文拆开算。 收集前缀时，改用 host 侧偏移量。 GPU 同步又少了一处。 来源：https://github.com/sgl-project/sglang/pull/43136

再说 #47645。 CUDA 图回放时，草稿 token 的分片规划修了。 来源：https://github.com/sgl-project/sglang/pull/47645

TRT-LLM：5 条，Cosmos 那条值得看

先说 #21572。 Cosmos3-Edge 的 FP8 版能加载了。 这是个视频生成模型。 去噪的前 3 步和后 3 步用 W8A16。 中间步骤用 W8A8。 W8A16 就是权重 8 位、激活 16 位。 这样精度和速度能兼顾。 来源：https://github.com/NVIDIA/TensorRT-LLM/pull/21572

再说 #22209 和 #22202。 推测解码那边的两个编译修补。 草稿提交核和门控归一化核，提前把变体编好。 来源：https://github.com/NVIDIA/TensorRT-LLM/pull/22209 来源：https://github.com/NVIDIA/TensorRT-LLM/pull/22202

再说 #22191。 Mooncake 升到 0.3.14。 Mooncake 是 KV 传输用的缓存层。 来源：https://github.com/NVIDIA/TensorRT-LLM/pull/22191

#22060 是流水线基建，跳过。

llama.cpp：1 条小修，快照动了

#30021，AMD 显卡的矩阵乘配置调优。

来源：https://github.com/ggml-org/llama.cpp/pull/30021

补记一条 1.0 的细节。 Medium 的深挖补了几个点。 1.0 还带了 FP8 的 KV 缓存。 草稿纸也能用 8 位记，更省显存。 MoE 模型多了 host 侧专家缓存。 不常用的专家放内存里，用时再取。 新支持的模型里有 Kimi-K3.1-Pro。 来源：https://medium.com/data-science-in-your-pocket/llama-cpp-v1-0-0-local-ai-finally-gets-a-stable-foundation-8587fb5619ba

FlashInfer：2 条

先说 #9453。 H100 的分页注意力，FP16 也能走自动分发。 大活儿走 cuDNN，小活儿还留给 FA2 和 FA3。 来源：https://github.com/flashinfer-ai/flashinfer/pull/9453

再说 #9020。 MXFP8 的矩阵乘调优器，现在会排 CuTe-DSL 和 cuDNN。 跑在 SM107 的卡上。 来源：https://github.com/flashinfer-ai/flashinfer/pull/9020

Dynamo：1 条，两行代码的提速

#18703，只删了两行。

前端到 worker 的 TCP 缓冲，之前写死了 2MB。 系统上限只有 208KB，反而关了内核自调。 大 prompt 一多，请求要在前端等 0.1 到 0.4 秒。 现在交给内核自己调，等待没了。 来源：https://github.com/ai-dynamo/dynamo/pull/18703
