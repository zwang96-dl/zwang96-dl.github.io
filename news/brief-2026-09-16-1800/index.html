新技术与论文

看视频的模型也有了"省电模式"。 VideoMM 专门给长视频理解省 token。 思路是"先粗看，再细看"。 粗看用降采样帧找语义相关区域。 只有相关区域才送去高清细看。 其他方法都把整片视觉 token 一股脑塞进去。 实测 LongVideoBench 上快 6.13 倍。 精度反涨 7.4%，比现有最快的方法快 2.73 倍。 说白了：视觉 token 不再按吨收费。 「值得深读」：多模态推理优化正是你的研究方向。 encoder/prefill 阶段怎么砍视觉冗余。 这篇是现成的参考答案。 来源：arXiv 9/15 http://arxiv.org/abs/2609.16722v1

一个基座、多个 LoRA 专家，草稿纸只写一次。 多 LoRA 部署常见：一个底座挂几个专家。 它们往往看的是同一份上下文。 这篇问了个实在问题：底座的 prefill KV 只算一次。 然后分给所有专家复用，质量亏多少。 prefill 是模型"第一遍读题"的阶段。 实验用 Qwen3-1.7B 挂了两个专家。 结论：普通训练好的 LoRA 直接复用，质量基本保住。 对你意味着：LoRA 混跑时，prefill 成本可以摊薄。 来源：arXiv 9/15 http://arxiv.org/abs/2609.17109v1

循环 Transformer 的投机解码来了。 Looped Transformer 是把同一组层反复用的模型。 循环 Transformer 就是省参数，但解码慢。 LoopSpec 让它自己给自己当草稿。 每轮循环的中间状态直接猜下一个 token。 不用另训练草稿模型。 说白了：自己给自己打下手。 来源：arXiv 9/15 http://arxiv.org/abs/2609.17184v1

访谈与深度

一台 GPU 干两份活，生产级 LoRA 混跑实战。 Swayam 的团队在 Azure 上跑的真架构。 一个 vLLM 实例，底座是开源视觉语言模型。 微调的 LoRA 适配器按需加载。 请求指定 domain-adapter 就走微调版。 不指定就走底座，零适配器开销。 另一路是多 agent 系统，直接连底座。 他们的原话：两台服务器两份账单太亏了。 一个实例、两个客户端，全搞定。 对你意味着：vLLM 有热切换适配器的官方姿势。 /v1/load_lora_adapter 接口，不用重启。 来源：Medium（今日） https://medium.com/@swayampatil7918/serving-two-llm-workloads-from-one-gpu-a-practical-mlops-architecture-on-azure-1ef290b32389

多 token 预测到底在干嘛，一篇讲透了。 temperature2 写了篇 MTP 的深挖。 MTP 是多 token 预测，一次猜好几个 token。 它不是预训练的玄学。 它是投机解码的草稿，从模型自己身上长出来的。 关键数据：DeepSeek-V3 的 MTP 模块在 15.7B 规模上。 HumanEval 从 20.7 涨到 26.8。 GSM8K 从 25.4 涨到 31.4。 还提到：vLLM 9/14 的文档里，mtp 已经是原生方法。 跟 EAGLE 并列，不再是外挂。 来源：temperature2 9/15 https://temperature2.com/p/2026-09-15-did-you-know-multi-token-prediction/
