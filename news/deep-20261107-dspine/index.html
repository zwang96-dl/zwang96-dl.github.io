DSpine：并行草稿一边写一边递话，接受长度涨 27.8%

  • 原文：https://arxiv.org/abs/2609.36173
  • 标题：Draft in Parallel, Condition Through Depth: Adjacent Causal Injection for Speculative Decoding
  • 作者：Haohui Zhang、Keyu Chen 等（上海交大、腾讯优图实验室、厦门大学）
  • 提交：2026-09-28（v1），2026-10-10 修订（v2）
  • 深读：13点版（2026-11-07，Reddit LocalLLaMA 当日转帖）
  • 含原文 Figure 1/3/5/6

人话解读

一句话：并行草稿各写各的词，前后接不上就白写。 投机解码就是先让小模型打草稿。 再让大模型一次批量验完。 验的时候只认前缀。 第一个对不上的词一出现，后面全作废。 并行草稿一次出整段，速度快。 但每个位置下笔时，还不知道前一个位置写了啥。 各自合理的词拼在一起，可能前后矛盾。 DFlash 干脆不补，各位置独立选词。 Domino、DSpark、DFlash2 事后才补关系。 在主干算完后加个小模块调分布。 信息进得太晚，补不全。 DSpine 把递话搬进主干内部。 每过一层，前一个位置就把预测递给后一个。 像接力赛边跑边递棒。 因果链顺着网络深度自己长出来。 各位置还是并行更新，不用等。 Qwen3-8B 上平均接受长度从 3.77 涨到 4.82。 SGLang 实测吞吐比 DFlash 高 23.3%。 多出来的接受长度直接变成吞吐。 这篇的价值不在 27.8% 这个数。 它证明了依赖关系可以在层内长出来。

核心方法

1. 先看清病根：两个实验证据

第一，浅层就能读出靠谱预测。 早期位置在浅层已经形成可恢复的预测信息。 所以前缀不必等算完，早就能去影响后继位置。 第二，递得越早越管用。 只换掉紧邻前驱，准确率就掉一大截。 哪怕更早的历史全对也补不回来。 同样正确的预测，递得越早，后继越准。 结论就两句。 要递就递紧邻前驱。 要递就从第一层开始递。

2. 统一传递空间：预测和定稿走同一条路

目标模型的输出头天然会给词打分。 它的每一行就是一个词的向量。 DSpine 把输出头拿来做传递空间。 先归一化，再做 PCA 白化。 白化去掉所有词共有的成分。 剩下的方向才分得清词。 没定稿的前驱递的是预测特征。 每层把状态投影到这个空间。 不用先解码成词。 已定稿的词直接递词向量。 预测和定稿长得一样。 同一条路能传两种东西。 这就是主干内递话和选词时递话能共用一套机制的原因。

3. 逐层注入：门控决定收多少

每过一层 Transformer，每个位置只收紧邻前驱的消息。 收多少由门控定。 接收方和前驱的特征一起算门。 浅层的前驱还不稳，门就关小点。 消息先投影，再按门缩放，写回残差流。 所有位置在同一层内并行递话。 锚点位置不动。 注意力也改成块内因果。 位置 t 只看目标上下文和块内 0 到 t 号位置。 注意力与注入方向一致。

4. 转移缓存：把串行选词变成并行算分

最后一层之后，要从左到右逐个选词。 每个词的选法取决于前一个选了啥。 串行选词会拖慢解码。 DSpine 先把所有相邻候选对的分数并行算好。 存进转移缓存。 选词时直接查表，不用再算。 串行过程变成并行查表。 加上融合内核，整套东西在 SGLang 里并行跑。

5. 逐层监督：逼浅层早点长出预测

训练时每层都加余弦对齐损失。 逼每层的预测特征贴近目标词向量。 有一定概率把前驱特征换成真词向量。 让模型学会在两种输入下都稳。 逐层全词表交叉熵反而有害。 逼中间层去分类，会打断后面的上下文计算。

关键数据

  • 接受长度，7 个数学、代码、聊天 benchmark 平均。
  • Qwen3-8B 温度 0：DFlash 3.77。
  • Domino 4.18，DSpark 4.32。
  • DFlash2 4.39，DSpine 4.82。
  • Qwen3-8B 温度 1：DFlash 3.39。
  • DSpark 3.92，DSpine 4.42。
  • Qwen3-4B 温度 0：DFlash 3.71。
  • DFlash2 4.50，DSpine 4.75。
  • 8B 上比最强基线高 10.0%。
  • 温度 1 时高 12.8%。
  • 4B 上比最强基线高 5.4% 和 10.1%。
  • 吞吐在 SGLang 里测，温度 0，并发 2 到 32。
  • 8B 平均比 DFlash2 高 11.1%。
  • 4B 平均比 DFlash2 高 6.5%。
  • 相对不投机解码的原始速度，最高快 4.0 倍。
  • 每个任务、每个并发下都是最高。
  • 耗时拆解，Qwen3-8B，SGLang。
  • 验证占每轮 72% 到 76%，各家差不多。
  • 逐层注入 5 层总共最多加 0.15 毫秒。
  • 转移缓存解码比 DSpark、Domino 的事后模块便宜一半还多。
  • DSpine 每轮 7.14 毫秒。
  • DFlash2 是 7.19 毫秒。
  • 每生成一个词，DSpine 比 DFlash2 少花 10.9% 的时间。
  • 消融：去掉末尾精修，接受长度掉 6.6% 到 7.1%。
  • 再去掉逐层注入，掉 8.8% 到 10.7%。
  • 两招互补，不是重复。
  • 实验口径：草稿主干 5 层，块大小 16。
  • 所有草稿器在同一份 ShareGPT 数据上重训 6 轮。
  • 目标回答由目标模型自己重新生成。
  • 温度 0 和 1 都测，7 个 benchmark 全覆盖。
  • 数字均为作者自报，无第三方复现。

跟研究方向的关联

  • 投机解码是 PD 解耦评估里 decode 侧的加速手段。
  • DSpine 是 DFlash 家族最新的一员。
  • DSpark、DFlash2 都已在 SGLang 里。
  • SGLang 刚合入了 #48375。
  • 它让 prefill 和 decode 先对一下草稿排布。
  • 两边排布不一样就直接报错。
  • 评 DSpine 时可直接套同一套口径。
  • 温度 0 和 1 都测，并发 2 到 32 分档。
  • 接受长度只看平均不够。
  • 聊天类 benchmark 绝对值低，要分任务看。
  • 成本账要看每生成一个词的时间。
  • 光看每轮耗时会漏掉接受长度的收益。
  • 注意实验只测了 Qwen3-4B 和 8B。
  • 更大模型、更长上下文还没测。
  • Qwen3.8-27B 的草稿权重还没放出。
  • 草稿器要重训才能用。
  • 不是开箱即用的开关。
  • 数字全是作者自报。
  • SGLang 里的实测口径写得很清楚，可以复现。

术语表

  • 投机解码：小模型先打草稿，大模型一次批量验完的加速办法。
  • 接受长度：每轮平均能往前推进几个词，越高越快。
  • 并行草稿器：一次前向同时猜出整段候选的草稿器。
  • DFlash：用块扩散一次猜整段的并行草稿器。
  • Domino、DSpark、DFlash2 是 DFlash 的三个后继。
  • 它们都在事后补因果关系。
  • 块大小：一次猜多少个词，论文里是 16。
  • 转移缓存：预先算好所有相邻候选对分数的表。
  • PCA 白化：去掉向量共有成分、让方向分得更开的处理。
  • 余弦对齐损失：逼预测特征贴近目标词向量的训练目标。
  • 门控：由输入自己决定收多少消息的开关。
  • 块内因果注意力：块里每个位置只看自己和之前的位置。
  • 温度：采样时的随机程度，0 是贪心，1 是正常采样。
  • TPOT：每输出一个词的时间，越小越快。
