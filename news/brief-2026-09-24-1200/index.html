新技术与论文

1. Medium 万字长文：2026 年的推理栈全盘点。

今天刚出炉，作者把四大引擎、两大架构变化一次讲透。

还给了选型框架。

通用 serving 用 vLLM，前缀复用重的活给 SGLang。

前缀复用重的流量，SGLang 比 vLLM 快 29%。

但作者也泼了冷水：这 29% 全靠前缀缓存。

前缀缓存（算过的 KV 下次直接复用），省掉重复计算。

prompt 各不相同、没有公共前缀，两家基本打平。

P/D 解耦（读题和答题分两拨 GPU 跑）已经从研究进生产。

投机解码（小模型先打草稿、大模型验算）延迟能压到一半以下。

不过它只降延迟不涨吞吐，别指望它多卖 token。

FP8 存 KV（KV 缓存用 8 位存），显存直接省一半。

作者建议当默认配置开。

  • 原文：https://medium.com/@charan.panthangi/the-llm-inference-stack-in-2026-vllm-sglang-tensorrt-llm-semantic-routing-and-the-combination-d9df1a16f93f

2. GLM-5.3 实测：8 张 H20 上 SGLang 和 vLLM 硬碰硬。

中文社区的一份实测，54 组结果、7680 个请求，零失败。

短请求 SGLang 全胜：吞吐高 9% 到 57%。

首 token（第一个字出来的延迟）也快一半以上。

长输入画风突变：vLLM 首 token 更快，4K 输入 1.9 秒对 5.9 秒。

但 SGLang decode 快，整请求反而先完成。

吞吐还高 7% 到 11%，长尾场景别只看首字。

注意这是裸配基线：加速优化全关了。

MTP（一次多猜几个 token）、前缀缓存都没开。

开优化之后排名可能变，别当终局结论。

  • 实测报告：https://github.com/runzhliu/aik8s/blob/HEAD/articles/wechat/glm53-h20-sglang-vllm.md

3. 「值得深读」SGLang P/D 解耦惊现静默 corrupt：mooncake 传输竞态。

这条跟你手里的活直接相关，先说结论。

AMD 的 infera 项目给 SGLang 的 P/D 解耦打了个关键补丁。

mooncake 是 P/D 之间搬运 KV 的传输层。

bug 是：非尾块的 KV 还没写完，就被提前传走了。

decode 拿到半成品，长 prompt 的输出悄悄变错。

不报错也不崩，最阴的那种。

症状很好认：大海捞针（长文本里找数字的测试）只捞出前几位。

后面全是乱码。

根因很打脸：mooncake 根本没实现 event 等待。

barrier 形同虚设，注释写了等于白写。

修复就三处：给传输块加 wait_event，传之前先等前向算完。

在 2×8 卡 MI325X 上验证：大海捞针 5/9 涨到 9/9。

划重点：补丁还没提交上游，自己搭 PD 环境得手动打。

推荐理由：帮你避开 PD 评估里最阴的坑。

静默 corrupt 会污染 benchmark，数字正常但答案是错的。

验证环境是 MI325X + ROCm，跟你的卡是同门。

  • 补丁文档：https://github.com/amd-agi/infera/blob/HEAD/deploy/docker/patches/sglang_disagg/README.md

访谈与深度

1. RohitAI：vLLM 0.30 的生产视角解读。

作者把 0.30 的两个新特性翻译成了运维语言。

Fast Start（权重常驻显存、重启秒起）：重启不丢热状态。

但它不恢复进行中的请求和 KV，期望别放错地方。

HiSparse（稀疏 KV 页溢出到主机内存）：拿内存换 GPU 容量。

注意 HiSparse 是 CUDA 独占，ROCm 不支持，跟你没关系。

升级坑：GPTQ 激活顺序路径被删，YaRN 上下文限制被修正。

核心警告：俩特性别当全局开关，得按模型逐个配。

  • 原文：https://rohitai.com/blog/vllm-0-30-open-model-serving-runtime-upgrade

2. 中文深度：SGLang 26.08 与 NVFP4 的精度账。

一篇中文拆解，把 Blackwell 这轮量化升级掰开揉碎了。

NVFP4（英伟达 4-bit 浮点格式）是 Blackwell 独占。

Hopper 想省显存，只能用 FP8，没有平替。

MTP 在 GB300 上要显式开启，迁移配置得重调。

精度这笔账被低估了。

DeepSeek-V4 跑 GSM8K，NVFP4 比 FP8 低 0.3%。

论文里不算啥，生产环境每千次错 3 次，可就不低了。

作者观点：SGLang 押注吞吐，vLLM 押注调度可靠性。

  • 原文：http://blog.hubianluanma.com/posts/sglang-26-nvfp4-blackwell-inference/
