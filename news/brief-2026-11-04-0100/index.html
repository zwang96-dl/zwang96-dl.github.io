框架更新

FlashInfer v0.7.3 正式版（11/4 05:57Z，上一轮窗口内漏报，补上） FlashInfer 是 vLLM、SGLang 底层用的注意力内核库。 MLA 后端收拢成一套，还自带自动调优。 cuDNN 分组 GEMM 也接进了统一的 MoE 接口。 Rubin（SM107）支持继续加码。 DeepSeek-V4 的 NVFP4 解码上了车。 Kimi-K3、MiniMax-H3 的专用内核，也打包了。 简单说：Blackwell 和 Rubin 用户，升级吃得到。 来源：https://github.com/flashinfer-ai/flashinfer/releases/tag/v0.7.3

vLLM 9 笔

#64182：AWQ/GPTQ 的 Marlin 权重缓存支持重启 11点版报过 FP8 版，这轮是 INT4 版。 权重缓存守护进程能把打包好的 Marlin 权重留着。 引擎重启后不用重新转格式，开工更快。 来源：https://github.com/vllm-project/vllm/pull/64182

#63921：DeepSeek-V4.1 在英伟达卡上 decode 提速 实测一块 GB300 托盘，batch 1 到 32。 decode 那步快 5.9% 到 17%。 agent 场景的 P90 交互性高 4% 到 26%。 来源：https://github.com/vllm-project/vllm/pull/63921

#65498：MoE 的 combine 少一次显存拷贝 MoE 的 combine 就是把各专家的输出拼回来。 B200 上 EP4、Qwen3.5-397B 的尺寸。 每层省 163 微秒，约等于半 GB 的显存读写。 来源：https://github.com/vllm-project/vllm/pull/65498

#65076：Mooncake 的 KV 搬运认得每张卡了 KV 搬运就是 PD 解耦里的搬运活。 草稿纸从 prefill 卡传到 decode 卡。 Mooncake 连接器现在能按 GPU 取设备名。 多卡环境下寻址更准。 来源：https://github.com/vllm-project/vllm/pull/65076

其余 5 笔略过。音频解析的张量转换修准了（#65579）。XPU 升到 torch 2.15。run-batch 的 JSON 修补。DeepSeek-V4.1 的 tokenizer 修正。UMBP 的恢复测试。

新技术与论文

对抗性投机推理：投机解码会改变 agent 的行为（2611.05345） 投机解码就是小模型先打草稿、大模型再改。 以前大家只当它是纯加速手段。 这篇说：在长链条 agent 任务里。 草稿被接受还是被拒，会改变推理链的输出分布。 换句话说，验证窗口里的数值噪声会悄悄改写 agent 的"想法"。 跟你的投机解码方向相关，角度很新。 来源：https://arxiv.org/abs/2611.05345（11/3 提交）

循环模型跑 serving，瓶颈到底在哪（2611.05150） 循环模型就是同一组层反复用很多遍，Ouro、Huginn 是代表。 作者在开源引擎里实测。 每个 token 要跑 5689 个小 kernel。 把它们融起来，吞吐涨 1.11 到 1.59 倍。 而且 1014 个请求逐位一致，精度没动。 跟 LoopVQ 是姊妹篇，23点版报过。 一个压 KV，一个压 kernel。 来源：https://arxiv.org/abs/2611.05150（11/3 提交）

LiquidCP：把注意力任务从通信和内核边界里解放出来（2611.04401） 上下文并行就是把长序列切开、让多张卡各算一段。 老办法是环形执行，每步都等通信，GPU 经常闲着。 这篇把任务拆成传输、计算、归约三类，按 tile 级依赖调度。 训练和推理走同一套模型，decode 的长尾也不再堵路。 做长上下文 serving 的，可以看一眼思路。 来源：https://arxiv.org/abs/2611.04401（11/3 提交）

cμ 规则：显存受限下的最优调度理论（2611.04807） 偏理论的一篇。把 LLM 推理调度写成排队论问题。 结论是：在 KV 显存受限时，cμ 规则渐近最优。 工程上直接抄不了，但能帮你想明白调度器的天花板在哪。 来源：https://arxiv.org/abs/2611.04807（11/3 提交）
