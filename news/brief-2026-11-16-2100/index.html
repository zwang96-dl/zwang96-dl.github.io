vLLM：Nemotron 看图那步搬上 GPU

#65941 是本轮最值得看的一条。

它把 Nemotron VL 的缩放搬上 GPU。

以前图片和视频帧在 CPU 上缩放。

uint8 双三次缩放是预处理里最贵的 CPU 活。

Perception Test 一个视频，单核要花约 350 毫秒。

这回改走 CV-CUDA 在 GPU 上缩放。

CV-CUDA 是英伟达的图像处理库。

图像和视频任务的首字时间降 40% 到 50%。

首字时间就是从发请求到第一个词出来。

覆盖 NemotronH_Nano_VL_V2。

服务 Nemotron 3 Nano Omni。

还有 Nemotron 3.5 Super VL。

还有 Nemotron Nano VL v2 的视频。

默认不开，需要手动打开。

#67136 修的是在线 NVFP4 量化。

NVFP4 是一种 4 位量化格式。

在线量化就是加载时现算压缩权重。

配上 CPU offload 以前会直接崩溃。

原因是量化权重还在 meta 设备上。

meta 设备就是只占位、不存数的状态。

现在 offload 会跳过这些参数。

MoE 的专家层也能先在 CPU 上物化。

再逐个搬上 GPU 量化。

这是 #64552 的前置拆分。

#67058 是个小修补。

聊天模板格式扩展到 cross-encoder。

cross-encoder 是给两个文本打分的模型。

剩下四条是 XPU 的测试清理。

#68052、#67877、#67243、#67188。

业内新闻

Google Zero-TIM：训练和推理的数对不上（值得深读）

RL 训练里，采样和训练走两条路。

采样是 decode，一次吐一个词。

训练是整批前向加反向。

同一权重、同一 token，两边算出的数可能不一样。

差一点点不要紧，攒多了训练就飘了。

Zero-TIM 是 Google 在 Tunix 里的一套配方。

它让三条路的数按位对齐。

64 张 TPU v5p 上验证过。

200 步里，采样和训练的数差全程是 0。

解题率也涨了。

这事跟 sglang-miles 那条 RL 线直接相关。

RL 采样就是推理，数不对齐就是白跑。

深读笔记已经写好，见本轮「值得深入学」。

来源：https://developers.googleblog.com/unlocking-stable-on-policy-rl-on-tpu-with-bitwise-zero-traininference-mismatch/
