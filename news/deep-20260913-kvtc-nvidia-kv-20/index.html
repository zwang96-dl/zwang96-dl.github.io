KVTC：NVIDIA 给 KV 缓存做的"20 倍无损压缩"

原文：KV Cache Transform Coding for Compact Storage in LLM Inference
作者：Konrad Staniszewski、Adrian Łańcucki（NVIDIA / 华沙大学）
链接：https://arxiv.org/abs/2511.01815（arXiv:2511.01815，ICLR 2026；v2 修订于 2026-03-11）
另见：VentureBeat 对 Adrian Łańcucki 的专访 https://venturebeat.com/orchestration/nvidia-shrinks-llm-memory-20x-without-changing-model-weights

一句话人话版

KV 缓存（推理时存上下文的草稿纸）是长对话 serving 里最烧显存的东西。

KVTC 不碰模型权重，只压这张草稿纸：20 倍压缩，精度几乎不掉。

划重点：长上下文多轮场景的显存救星，短对话别用。

核心方法

第一招：PCA 解相关（主成分分析，把重复信息摊平）

  • 不同 attention 头的 KV 特征高度相关，藏着大量冗余。
  • KVTC 用 PCA 把特征线性解相关，变成互相独立的系数。
  • PCA 基矩阵 V 只在校准集上算一次。
  • 之后所有请求的缓存都复用这一个 V。
  • 说白了：先给草稿纸"去重"，再压就轻松多了。

第二招：自适应量化（动态规划分比特，重要的多给）

  • 解相关后的系数按方差排好队。
  • 动态规划（DP，一种最优分配算法）给每个坐标分比特预算。
  • 方差大的多给比特，方差小的少给。
  • 排在后面的成分经常直接分 0 比特。
  • 0 比特等于提前降维，又省空间又省算力。

第三招：熵编码打包（DEFLATE，用 GPU 并行压）

  • 量化后的符号用 DEFLATE 算法再压一遍。
  • 走 nvCOMP 库，压缩解压都在 GPU 上并行做。
  • 三招叠满：名义 64 倍配置，实测能到 64–88 倍。

两处"碰不得"：

  • 最老的 4 个 token（attention sink，注意力锚点）不压。
  • 最近的 128 个 token（滑动窗口）不压。
  • 消融实验：压了这两类，高压缩比下精度直接崩。

关键数据

压缩比 vs 精度（论文主结果）

  • 最高 20 倍压缩，推理和长上下文精度损失不到 1 个百分点。
  • 特定场景能到 40 倍以上。
  • 测了 Llama 3、Mistral NeMo、R1-Qwen 2.5 三个模型家族。
  • 基准：AIME25、GSM8K、LiveCodeBench、LongBench、MATH-500、MMLU、Qasper、RULER。
  • 全程压过三类基线：token 驱逐、量化、SVD 方法。

VentureBeat 专访里的工程数字

  • 8 倍压缩档：Qwen2.5-1.5B 每 token 从 29KB 压到 3.2KB。
  • 代码任务精度只掉 0.3 个百分点。
  • 8000 token 的 prompt：从头重算要 3 秒，解压 KVTC 缓存只要 380 毫秒。
  • 首字延迟（TTFT）直接快 8 倍。
  • 测试条件：12B 模型、单张 H100。

跟 DMS 的关系

  • DMS（动态记忆稀疏化）是另一种思路：沿时间轴删不重要的 token。
  • KVTC 是在每个位置上压数据，两者维度正交。
  • 作者说理论上互补，但叠起来的压缩比还没实测过。

跟你的研究方向的关联

  • 你正在 SGLang 上评估 P/D 解耦（prefill/decode 分离）。
  • P/D 解耦最大的成本就是 KV 缓存的搬运：prefill 算完要把 KV 运到 decode 节点。
  • NIXL 负责"搬得快"，KVTC 负责"搬得少"，两条腿走路。
  • 优化版 KVTC 会进 Dynamo 的 KVBM（KV 块管理器），兼容 vLLM。
  • SGLang 这边如果要跟进，大概率也是先落在 KV 传输/存储层。
  • 多模态长上下文（encoder 输出进 KV）是 KVTC 的天然主场。
  • 跟本系列的《DeepSeek-V4.1-Flash：KV 压到 890 字节/token》是姊妹篇：一个改架构，一个不碰权重。

术语表

  • KV 缓存：推理时存的上下文"草稿纸"，避免每轮重算。
  • PCA：主成分分析，把相关特征变成独立成分的数学工具。
  • 熵编码：按出现频率给符号编短码的无损压缩，DEFLATE 是代表。
  • TTFT：首字延迟，从发 prompt 到第一个 token 出来的时间。
  • Attention sink：序列最开头的几个 token，attention 特别依赖它们。
  • NIXL：NVIDIA 的推理传输库，管 GPU 之间搬数据。
  • Dynamo：NVIDIA 的推理 serving 框架，KVBM 是它的 KV 缓存管理模块。

关键图表

图 1：KVTC 三段式流水线

图里是什么：KV 缓存从左进，先过"线性投影"（PCA 解相关，基矩阵在校准集上一次性算好），再过"自适应量化"（动态规划分配比特），最后"熵编码"（DEFLATE，用 nvCOMP 在 GPU 上并行），进存储。 说明了什么：整个方法不碰模型权重，是纯粹的缓存后处理；三步各管一段压缩比，模块化很好。

图 2：三段各自贡献了多少压缩比（Llama 3.1 8B）

图里是什么：四根堆叠柱，对应 8×/16×/32× 四档配置。蓝色是 PCA 的贡献，橙色是量化，绿色斜纹是 DEFLATE。纵轴是 log2(压缩比)。 说明了什么：配置越激进，PCA 的份额越大（64× 档近一半来自 PCA）；DEFLATE 是"添头"，但让实际压缩比稳定超过名义值（8× 配置实测 9–10×）。
