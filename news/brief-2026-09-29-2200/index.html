新技术与论文

  • Agent 服务里 KV 复用有个痛点：缓存换个位置就得重算。
  • ATTUNER 找到了病根：位置对不上其实影响不大。
  • 真伤精度的是多段缓存之间"选谁"的注意力分数。
  • 它在 query 侧做适配，补回分数，不用逐个 token 重算。
  • 跟 prefix caching 一个家族，Agent 场景值得看一眼。
  • 论文：https://arxiv.org/abs/2609.36722
  • DScale 玩的是扩散式投机解码，在验证环节动刀。
  • 高并发下，验证 padding 和被拒的草稿是主要浪费。
  • 它用一个 11 万参数的小预测器动态定验证长度。
  • A100 上 Qwen3-8B、并发 8–32 测过。
  • 跟 SEED（20点版那篇）是投机解码的两种不同打法。
  • 论文：https://arxiv.org/abs/2609.37532
  • LongSpark 盯着投机解码里的 drafter 成本。
  • 上下文越长 drafter 越贵，省的算力被吃回去。
  • 它从验证流程里只取固定大小的视图，成本不随上下文涨。
  • 像实习生只看专家批注的要点页，不看全本。
  • 论文：https://arxiv.org/abs/2609.37029

业内新闻

  • SGLang 曝了个安全漏洞，跟你评估的方向直接相关。
  • CVE-2026-102634：PD 解耦 + Mooncake 后端时有校验缺失。
  • /generate 里重复的 bootstrap_room（KV 传输配对用的会话号）没人拦。
  • 没登录的攻击者发两个相同值的请求，能搞崩调度进程。
  • 还能把别人的请求 hang 住，直到传输超时。
  • CVSS 7.5，官方 issue #40125 还开着，没确认修复。
  • CVE 是今天（9/29）公开的。
  • 划重点：你测 PD 解耦时，把 bootstrap_room 校验列进测试项。
  • 顺手把服务放内网，别裸奔到公网。
  • 漏洞详情：https://www.thehackerwire.com/vulnerability/CVE-2026-102634/
  • 官方 issue：https://github.com/sgl-project/sglang/issues/40125
