MCF：prefill 攒副本，decode 只传问题

  • 原文：MCF: A Memory- and Communication-Aware Co-Designed Framework for Long-Context LLM Inference
  • 出处：arXiv:2610.34731，2026-10-26 提交
  • 作者：Huaizhi Zhang、Jiacheng Zhu 等
  • 投稿目标：EuroSys '27
  • 链接：https://arxiv.org/abs/2610.34731

人话解读

  • 长文章读题时，草稿纸要跨机器传。
  • 草稿纸就是 KV cache（存好的注意力中间结果）。
  • 传草稿纸这件事，常常比计算还慢。
  • MCF 的办法分两段走。
  • 读题阶段，先给热门草稿多备几份。
  • 哪台机器要用，近处就有副本。
  • 读完题，副本全部撤掉。
  • 只留每块草稿的正本，分片放好。
  • 吐字阶段，草稿纸一步都不动。
  • 只把当前问题送到各台机器。
  • 问题比草稿纸小得多。
  • 说白了，搬问题不搬仓库。

核心方法

  • 读题按块切开，一块块算。
  • 这叫 chunked prefill（分块预填充）。
  • 每块草稿一出生就定好正本主人。
  • 调度器叫 MARS，管副本怎么发。
  • 它看三件事再决定发几份。
  • 一看显存还剩多少。
  • 二看这块以后会被用多少次。
  • 三看跨机器传一次有多贵。
  • 越靠前的草稿，被复用越多。
  • 所以早期草稿副本发得最多。
  • 读题越往后，显存越紧张。
  • 副本就一份份撤掉。
  • 到吐字开始，布局已经收干净。
  • 不用在交界处整体搬家换布局。
  • 吐字时每台机器只算本地那片。
  • 各算一半，再把结果拼起来。
  • 路由和拼接交给网卡里的 FPGA。
  • FPGA 是可编程的硬件加速芯片。
  • 主机不用插手传草稿这件事。

关键数据

  • 均为作者自报，没有独立复现。
  • 先说最大的那笔账。
  • 16K 长度读题，机器从 2 台加到 16 台。
  • 首字延迟从 1.68 秒降到 0.62 秒。
  • TTFT 就是等第一个字的延迟。
  • 16 台时对手 Ring 要 1.91 秒。
  • 换算下来 MCF 快约 3.1 倍。
  • 对手 Zigzag 要 1.81 秒。
  • MCF 快约 2.9 倍。
  • 8K 以内那组曲线更夸张。
  • MCF 的延迟几乎是一条平线。
  • 对手和 PD 解耦都随长度猛涨。
  • 代价是总传输量略高一点。
  • 16 台时它传 5.12 GiB。
  • 对手只传约 4.40 GiB。
  • 它买的是关键路径上不等待。
  • 不是总搬运量最省。
  • 它也老实交代了会输的场合。
  • 短提示只有 1K 时，它反而最慢。
  • 副本的固定开销摊不回来。
  • 分块越大，延迟和传输都越低。
  • 这是它给的分块大小实验。

口径提醒

  • 这组数字不能直接搬进 GPU 集群。
  • 实验跑在 FPGA 计算网卡上。
  • 权重和草稿纸都量化到 INT4。
  • INT4 是 4 比特的低精度存法。
  • 三个对手也不是原装系统。
  • 是作者按同样数据流复刻的版本。
  • 所以它赢的是通信模式之争。
  • 不是赢了 vLLM 或 SGLang。
  • 真实 GPU 上的差距要自己测。

跟你研究方向的关联

  • 你正在评估 SGLang 的 PD 解耦。
  • 这篇正好治 PD 的交界处。
  • 交界处最贵的就是换布局和搬草稿。
  • 它把换布局摊进读题全程。
  • 交界那一刻反而不搬家。
  • 这招在 GPU 上也能借。
  • 读题早期显存空，可以先多备副本。
  • 你的 autotuner 能多两个旋钮。
  • 一个是副本份数随进度的曲线。
  • 一个是读题的分块大小。
  • 但你的输入只有约 250 词元。
  • 它自己承认短提示会亏。
  • 你的场景大概率在亏损区。
  • 真正能借的是布局渐变这个思路。
  • 不是它的 FPGA 那套硬件。

术语表

  • KV cache：草稿纸，存好的注意力中间结果。
  • prefill：读题阶段，算完整个输入。
  • decode：吐字阶段，一个个往外蹦词。
  • PD 解耦：读题和吐字拆到不同机器。
  • TTFT：首字延迟，等第一个字的时间。
  • chunked prefill：把读题切成小块算。
  • Ring Attention：草稿沿环形在机器间流传。
  • FPGA：可编程硬件芯片，这里做智能网卡。
  • INT4：4 比特低精度，省显存但掉精度。
