SGLang v0.5.19：统一 Radix Tree 转正 + EPD 重构 + mxfp8 KV 传输

原文：Release v0.5.19 · sgl-project/sglang（786 个 PR，214 位贡献者）
原文：https://github.com/sgl-project/sglang/releases/tag/v0.5.19
说明：GitHub release 页是纯文本，没有配图；本篇为要点精读，无原文图表。

一句话人话版

SGLang 这版把缓存和解耦两条线都推了一大步：unified radix tree 成为所有模型的默认缓存，PD 解耦的 KV 传输开始支持 mxfp8，外加一次 EPD 架构重构——正好跟 NVIDIA 那篇"什么时候该拆 EPD"博客前后脚，SGLang 这是在把解耦的路铺好。

跟你最相关的四个变化

1. Unified radix tree 默认开启（Breaking Change）

SGLANG_ENABLE_UNIFIED_RADIX_TREE 环境变量被废弃——统一树现在是所有配置的默认缓存，不再只是混合模型的专属。

顺带的三件事：

  • PD decode 侧也能复用缓存前缀了（SWA 混合模型如 gpt-oss，#27770）——解耦部署里 decode worker 不再是"无缓存裸奔"；
  • 运行中的 server 可以动态挂载/卸载 L3 存储（#35269）；
  • PP + HiCache L3 在各 rank 间保持一致（#27010）。

人话：prefix caching 的覆盖面从"部分模型、部分 worker"扩大到"全部"。你以后测多轮对话/多图复用的命中率，基线直接按这个算。

2. EPD 重构（#30398）

release 里只有一行 [Refactor] New EPD，但信号很明确：SGLang 在重写 EPD 的实现。结合 NVIDIA 博客（Dynamo 先交卷、vLLM/SGLang 在 roadmap 上），可以认为EPD 正在从"实验性开关"变成"正式架构"。建议：等 EPD 文档更新后，对照 NVIDIA 博客的四维决策表（图像量/OSL/模型大小精度/混合流量）在你这边复测一遍。

3. mxfp8 KV cache 进 PD 传输（#35718、#35888）

  • PD 传输支持 mxfp8 KV cache；
  • mxfp8 KV cache 支持 CPU offload。

人话：解耦部署里 prefill→decode 传 KV 的带宽瓶颈，可以用更低精度的 KV 来压。配合这版另一个优化——PD KV 传输打包成目标端连续的 RDMA 块（Kimi-Linear-48B 上传输时间 -28%~-39%，#35762），SGLang 的 P/D 解耦传输正在系统性地减负。

4. 多模态专项优化

  • PaddleOCR-VL：页面预处理重叠 + ViT 打包 + prefill CUDA graph，1080p 页面 TTFT 从 235ms → 120ms，req/s 1.84×（H200，#35318）——文档/OCR 类多模态负载的典型调优三板斧，值得抄作业；
  • 多模态 embedding 改用 index_copy_ 代替 masked_scatter_ 做 scatter，削 transient GPU 显存（#37070）；
  • 修了缓存 miss 后多模态 embedding 的重编码逻辑（#36595）；
  • Qwen3-VL MoE 推理的 deepstack 顺序修复（#34690）——如果你跑 Qwen3-VL，这版再测。

其他值得扫一眼的

  • Beam search：传 beam_width 就能拿 n 条最优序列，暂不支持跟投机解码/解耦/DP attention/HiCache 混用（#31626）；
  • DeepEP v2：ElasticBuffer 引擎，buffer 定长，跨节点 decode 也能跑 CUDA graph（#35634）；
  • W4A8 MoE on Hopper：MXFP4 expert 配 FP8 activation，DeepSeek-V4-Flash 输出吞吐 +12%，GSM8K 精度不变（#34967）；
  • LayerNorm 序列并行（--enable-layernorm-sp）：Qwen3-8B prefill 在 H100 -3.5%、B200 -5.6%，TP 越大越赚（#30915）；
  • DCP 登陆默认 Blackwell MLA 后端：128K 输入下 8×B200，纯 TP 在 ~680 tok/s 就不涨了，DCP 继续随并发涨（#33926）。

跟你研究方向的关联

  • 升级建议：unified radix tree 转正是 breaking change，升 v0.5.19 后 prefix caching 行为会变，benchmark 记得重跑基线；
  • EPD + mxfp8 KV 传输：正是 NVIDIA 博客里"NIXL 传 embedding"的 SGLang 对应物。等 EPD 文档齐了，可以在单机上先试 PD 解耦 + mxfp8 KV，对比聚合部署的 TTFT；
  • PaddleOCR-VL 的三板斧（预处理重叠/ViT 打包/prefill CUDA graph）是多模态 TTFT 优化的通用配方，跟 EPD 解耦正交，可以叠加；
  • 量化线（W4A8 MoE、NVFP4 相关）继续加码，跟你"量化放大解耦收益"的思路一致。

术语表

  • Radix tree / prefix caching：前缀缓存。把已算过的 prompt 前缀的 KV 存成树结构，相同前缀的请求直接复用，不用重算。
  • Unified radix tree：统一基数树，SGLang 新一代缓存结构，统一管理多种模型的 KV。
  • PD disaggregation：prefill/decode 解耦，prefill 和 decode 跑在不同 worker 上。
  • EPD：encode-prefill-decode 解耦，再往前多拆了一个 vision encoder 阶段。
  • mxfp8：8-bit microscaling 浮点格式，比 FP8 精度更好。
  • DCP：decode context parallelism，decode 阶段的上下文并行。
  • DeepEP：DeepSeek 开源的 MoE expert 并行通信库。
  • HiCache：SGLang 的分层 KV 缓存（GPU→CPU→存储）。
