vLLM：多模态直连不再干等 60 秒

#69366 修了 Mooncake 消费端的等待。

消费端就是接收编码结果的那台机器。

以前图片直连消费端会一直等推送。

等满 60 秒就报错。

现在没人推送就本地自己编码。

作者实测从 60 秒报错变成 0.7 秒成功。

已经有推送副本时还是走老路。

#68357 让 Mooncake 能用 RDMA 传缓存。

RDMA 就是网卡直达显存的高速通道。

以前可扩展缓存会被启动检查拦下。

现在支持的卡可以直接放行。

不支持的卡会明确报错。

这跟 P/D 解耦传缓存直接相关。

#69814 简化了 KV 缓存规划。

KV cache 就是存中间结果的草稿纸。

删掉了一批没人用的死代码。

块数现在按精确值走。

#69640 给 Rust 前端加了排队上限。

排队请求或 token 超限就直接拒绝。

返回 503，不再硬塞进引擎。

#69428、#69664、#66926 是小修补和测试。

来源：https://github.com/vllm-project/vllm/pull/69366、https://github.com/vllm-project/vllm/pull/68357、https://github.com/vllm-project/vllm/pull/69814 和 https://github.com/vllm-project/vllm/pull/69640

SGLang：小分组解码也能走快路

#53024 让 DCP 小分组用上合并核。

DCP 就是分布式上下文并行。

以前只有 8 卡分组能走快路。

2 卡和 4 卡只能走慢的回退路。

现在小分组也能直接合并候选。

作者在 GB300 上测了 K3 解码。

每步快了 4% 到 7%。

数字是作者自报，没独立复现。

#52897 给扩散模型融合了归一化。

单卡实测端到端快了约 3.7%。

剩下 5 条是文档、CI 和镜像更新。

来源：https://github.com/sgl-project/sglang/pull/53024 和 https://github.com/sgl-project/sglang/pull/52897

TRT-LLM：多模态解码改了默认格式

#22334 是个破坏性变更。

图片默认解成 PIL 格式。

视频默认解成 uint8 数组。

uint8 就是每像素只占一个字节。

8 帧 1080p 视频的存储少了 75%。

数 token 的耗时也大幅下降。

但有个代价要知道。

大图预处理在 Grace CPU 上慢了约 5 毫秒。

旧的 format 和 device 参数现在会报错。

#22619 把循环状态检查搬进了缓存管理器。

#22765 补了 Rubin 的 NVFP4 缓存说明。

NVFP4 是英伟达的 4 位浮点格式。

剩下 9 条是文档、测试和 infra。

来源：https://github.com/NVIDIA/TensorRT-LLM/pull/22334、https://github.com/NVIDIA/TensorRT-LLM/pull/22619 和 https://github.com/NVIDIA/TensorRT-LLM/pull/22765

llama.cpp：长上下文少搬一次数据

#32795 让量化索引键原地读取。

以前每轮都要先转成 F32 再算。

现在融合路径直接读量化数据。

作者测了 DeepSeek V4.1 Flash。

48K 上下文时快了约 15%。

上下文越长，收益越大。

但这不是逐位等价的改动。

计算路径变了，末位结果可能差一点。

#30685 让输入拷贝改成异步。

作者测的一个配置快了 12.1%。

其他配置基本没变。

#31898、#31871 是内存预留和 SYCL 支持。

剩下几条是界面和工具调用。

快照到了 b12721，见版本水位。

来源：https://github.com/ggml-org/llama.cpp/pull/32795 和 https://github.com/ggml-org/llama.cpp/pull/30685

补报：语法本身也能当草稿

这篇之前漏了，这轮补上。

Grammar-as-a-Drafter 11 月 24 日更新了 v2。

结构化输出有语法约束。

比如 JSON 的键名和括号位置。

语法引擎其实早就知道下一步。

这篇让语法直接参与打草稿。

草稿模型猜错的地方被语法填上。

作者在 TPU 上测了 JSON 任务。

每步保留的 token 从 2.06 涨到 5.43。

解码快了 2.66 到 2.81 倍。

但有两点要注意。

实测只在 TPU 上，没有 GPU 数据。

输出分布也可能跟老办法有偏移。

数字是作者自报，没独立复现。

来源：https://arxiv.org/abs/2611.28349

补报：循环模型并发时别乱投机

PackLoop 是 11 月 23 日提交的。

循环模型每 token 要重复算很多轮。

投机解码在单请求时很快。

请求一多，收益就被摊薄了。

这篇说问题出在排布，不在投机本身。

只在本来就要读的行里投机。

164 个负载点里赢了 161 个。

中位快 1.25 倍，最高 1.76 倍。

但只测了 Ouro 系列循环模型。

跟主流模型的关系还要再看。

数字是作者自报，没独立复现。

来源：https://arxiv.org/abs/2611.30205
