MTP 自蒸馏：把 3 倍加速"烤"进模型权重，不用投机解码

原文：Multi-Token Prediction via Self-Distillation（arXiv:2602.06019；John Kirchenbauer 等，UMD / LLNL / Columbia / TogetherAI；2026-02-05 提交，04-23 修订 v2）
今日由 VentureBeat 深度报道（2026-09-10，含一作访谈）
代码：https://github.com/jwkirchenbauer/mtp-lm ｜ 权重：hf.co/collections/tomg-group-umd/mtp-lm

人话解读

投机解码的思路是"雇个小跟班先猜、大模型再验"——但小跟班本身也要训练、部署、运维，多一套系统就多一份麻烦。这篇论文走了另一条路：直接训练模型"一次说好几个词"（多 token 预测，MTP），把加速能力"烤"进权重里，推理时不需要任何辅助模型。

为什么以前这条路走不通？因为传统训练是拿标准答案"对作业"：模型独立地猜第 1 个词、第 2 个词……各猜各的，结果可能拼出"lion bamboo"（狮子竹子）这种语法崩坏的组合。这篇的妙处是换了个"判卷老师"：让一个强大的标准模型（teacher）当裁判，学生模型一次吐出一整串词，老师只管打分"这串词整体通不通顺"。这就像学外语时不再逐词查字典，而是直接整句说给母语者听、对了就记住——学的是"整句的感觉"，不是"每个词的概率"。

关键设计只有一处：在词表里加一个特殊的 <MTP> mask token，架构其余部分（MoE、滑动窗口注意力、SSM 层等）原封不动。任何标准模型都能这样"无痛改造"。

核心方法

1. Student-Forced 在线自蒸馏（on-policy distillation）

训练时把输入切成多个 MTP 区域（region），每个区域由前缀 + k 个 <MTP> mask 组成：

  • 学生（待训练的 MTP 模型）一次前向生成一整段 k 个 token（deterministic argmax rollout）；
  • 老师（同一个 checkpoint 初始化的强 NTP 模型）用链式法则给这整段打分：$P_{teacher}(y'|x) = \prod_j P_{teacher}(y'_j \mid y'_{<j}, x)$；
  • 优化目标是两者分布的 KL 散度（式 3），外加"hard teacher"变体（老师也用 argmax，熵降到零，监督信号更清晰）。

类比：学生交"整段作文"，老师不逐字改红笔，只给整段打一个"通顺分"——学生为了高分，自己学会"整段通顺"的写法。这跟 RL 很像（on-policy rollout + reward），但 reward 来自老师模型的打分，不需要人工标注。

2. 并行训练的 masking 技巧（Blocked Attention）

为了"一次训练、多个区域并行学"，设计了特殊的 attention mask（Figure 3）：

  • 非 MTP 区域的 token：标准因果 mask；
  • 每个 MTP 区域内的 mask token：只能看本区域之前的 prefix，不能看其他区域；
  • MTP span 的位置和长度 k 在训练中随机化（k ∈ [2,16]，rolling offset 随机），让模型学会"从任意位置开始、预测任意长度"。

3. ConfAdapt：按置信度"该快则快、该慢则慢"

推理时的自适应解码策略，是全文最实用的部分：

  • 设一个置信度阈值 τ（比如 90%）；
  • 模型一次生成 k 个 token，只保留置信度 ≥ τ 的；好猜的（模板化、结构化文本）一次吐一大段，难猜的逐个慢吐；
  • 平均加速比 ≈ 平均保留的 chunk 大小。

类比：像老司机开车——直道（高置信）一脚油门过，弯道（低置信）逐段慢行。实测发现学生模型的置信度（低熵）和生成质量高度相关（Figure 6），所以这个简单启发式意外地有效，而且是 pareto 最优的（比固定 k 更好）。

其他发现：

  • 跨域迁移：只在数学数据上训，创意写作、摘要等开放任务也有加速（ConfAdapt 按"领域熵"自动调节，数学/推理任务加速比最高）；
  • SGLang 实测（Figure 5）：跟 EAGLE-3 投机解码在吞吐-延迟 pareto 前沿上打平，且"用延迟换吞吐"的曲线更平滑；高并发下 ConfAdapt 的额外开销会被摊薄；
  • 训练用"hard teacher + 随机 k + 因果 mask、无 NTP 辅助 loss"效果最好（消融结论）。

跟你的研究方向的关联

  • 投机解码的"无辅助模型"替代路线：你 1600 档刚看了两篇投机解码实战（Nivora 70B 降本 38%、Runpod vLLM 指南），这篇是同一问题的另一解——省掉 draft 模型，代价是一次性训练投入 + vLLM/SGLang 的 batching/KV cache 适配。评估 SGLang P/D 解耦时可以对比：decode 池到底是"加 draft 模型"划算，还是"换 MTP 权重"划算。
  • 作者亲口说的定位：一作 Kirchenbauer 对 VB 说，现有加速技术"几乎只关注推理框架和逻辑"，而 MTP "把一部分复杂度烤进模型本身"，跟现有工作是互补的——这意味着 MTP 权重 + P/D 解耦 + 投机解码理论上可以叠加。
  • 落地建议（作者原话）：先用"数数、复读短语"这种玩具 prompt 验证 ConfAdapt 的加速效果，再用自己业务域的数据做一次 MTP 适配——跨域迁移有，但域内适配效果最好。
  • 32B 模型的验证在附录 C.3，说明方法不只适用于小模型。

术语表

  • MTP（Multi-Token Prediction）多 token 预测：一次前向生成多个 token，而不是逐个生成。
  • NTP（Next-Token Prediction）：标准自回归生成，一次一个 token。
  • 自蒸馏 self-distillation：用模型自己（或同源的强模型）当老师，学生学老师的整体行为而非标准答案。
  • On-policy：训练用的数据是学生自己实时生成的（不是预先准备好的静态数据），跟 RL 的 rollout 一个意思。
  • Student forcing：学生用自己生成的序列做训练输入，而不是用标准答案"喂"（teacher forcing 的反面）。
  • ConfAdapt：本文的置信度自适应解码策略，好猜的多吐、难猜的少吐。
  • 加速比 Acceleration factor：平均每次前向生成的 token 数（≈ 平均 chunk 大小）。
  • EAGLE-3：一种流行的投机解码/草稿模型方案，本文在 SGLang 里拿它当 baseline 对比。
  • 熵 Entropy：模型输出分布的"不确定程度"；熵越低=越自信，本文发现低熵跟高质量强相关。
