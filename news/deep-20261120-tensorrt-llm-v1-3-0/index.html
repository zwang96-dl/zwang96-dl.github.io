TensorRT-LLM v1.3.0 正式版：Rubin 预览、KV 缓存 V2、PD 新调度

  • 作者：NVIDIA TensorRT-LLM 团队
  • 原文：GitHub Release v1.3.0，2026-11-20T02:45:00Z 发布（美西 11 月 19 日 18:45）
  • 原文链接：https://github.com/NVIDIA/TensorRT-LLM/releases/tag/v1.3.0
  • 深读：2026-11-19 19点版（1.3 这条线的正式版，不是 rc）

人话解读

1.3.0 是 1.3 这条线的正式版。

1.4.0 还在 rc 阶段，最新是 rc4。

这版一次塞了三件大事。

第一，Rubin 预览支持来了。

Rubin 是英伟达的新一代 GPU。

DeepSeek-V4 和 Kimi K3 能在上面跑了。

第二，KV 缓存换了 V2 管理器。

KV 缓存就是解码时的草稿纸。

还加了压缩和磁盘缓存。

第三，PD 拆分加了新调度。

读题和生成分机器跑，排队更聪明了。

另外还多了一个新方向：VisualGen。

图片和视频生成模型也能用同一套服务跑了。

但这版删东西也很狠。

TensorRT 老后端整个没了。

只剩 PyTorch 这一条后端。

升级前先看迁移指南，别直接升。

核心方法

Rubin 预览支持

  • Rubin 是 SM107 架构的新卡。
  • DeepSeek-V4 和 Kimi K3 已验证能跑。
  • Qwen3.5、MiniMax-M3 也在预览名单里。
  • NVFP4 MoE 加了局域化。
  • 显存流量不出本芯片。
  • 关掉它可以设 DISABLE_LOCALITY_DOMAINS=1。

KV 缓存 V2

  • 管理器按模型选型，大部分模型默认开。
  • 压缩有两招：TriAttention 和 NVFP4 冷页压缩。
  • 冷页就是很久没翻的那页草稿纸。
  • NVFP4 KV 缓存和磁盘缓存都来了。
  • 同一对话的块可以复用。
  • 多模态 KV 块按精确内容哈希。
  • FlexKV 和 LMCache 两个连接器都能接。

PD 拆分（Disaggregated Serving）

  • 新调度叫 gen-first，先排生成再排读题。
  • 对话亲和路由让同一对话落到同一组机器。
  • 混合模型和 beam search 也能拆开跑。
  • Qwen3.8-Flash-Next 新支持拆分部署。
  • 1.2 版的几个拆分挂起 bug 都修了。

投机解码（Speculative Decoding）

  • 新草稿器：DSpark、DFlash、后缀自动机、PARD。
  • EAGLE3 动态树和 Eagle 3.1 草稿模型。
  • 投机解码能跟 LoRA 一起用。
  • 接受率低了会自动关掉动态投机。
  • 拒收采样补上了，单模型路径也能用。

并行与 MoE

  • DWDP：权重分片、数据并行混着用。
  • Helix 上下文并行扩展了。
  • KV 感知的注意力 DP 路由器。
  • NCCL-EP 后端，专家数上限提到 2048。
  • MoE 后端多了 DENSEGEMM、MEGAMOE_DEEPGEMM。
  • 还有 CUTEDSL_FC12，只给 Rubin 用。

量化与稀疏注意力

  • MXFP8 的 W8A8 线性和 MoE 都支持了。
  • NVFP4 纯权重能量化跑在 Hopper 和 Ada 卡上。
  • DSA 的 FP4 和 FP8 解码核来了。
  • GVR Top-K 和 Skip Softmax 注意力。
  • Skip Softmax 就是跳过不重要的注意力分数。

多模态与新方向

  • 多模态编码器缓存和 CUDA 图都加了。
  • 前缀感知调度默认开，共享前缀只算一次。
  • VisualGen 新垂直方向：FLUX、Wan 2.2 等。
  • 图生图、视频生成都能走 trtllm-serve。

关键数据

这版发布说明里几乎没有跑分数字。

只有功能清单和修复清单。

这点先说清楚，别当它有实测。

能抄的数字都在下面：

  • 专家数上限：2048 个。
  • KV 搬运默认超时：60 秒，以前没有超时。
  • TorchCompile 默认流数：从 1 改成 3。
  • Logprobs 上限：100 个，超了直接报错。
  • 随版发了 12 篇技术博客。
  • 部署指南新增：GLM-5、Kimi K3、MiniMax-M3。
  • 还有 Nemotron 3、Qwen3.8-Flash-Next。

升级注意：先看这三条

  • TensorRT 老后端删了，只剩 PyTorch 后端。
  • trtllm-build 等命令都没了。
  • C++ Executor 和老 runtime API 也删了。
  • 两模型投机解码删了，改用单模型实现。
  • 遥测默认开了，不想上报要设开关。
  • 开关是 TRTLLM_NO_USAGE_STATS=1。
  • PD 拆分下 DSpark 的草稿 KV 不搬运。
  • 接受率会掉，聚合部署不受影响。
  • GLM-5.2 的 NVFP4 在 GB200 上可能段错误。
  • max_num_tokens 别超过 4096。
  • Kimi-K3 的 NVFP4 可能加载 tokenizer 失败。
  • 跟自带 transformers 版本有关。

跟研究方向的关联

  • PD 评估可以直接拿这版当 TRT-LLM 基线。
  • gen-first 调度和对话亲和路由是新变量。
  • 评估里要单列：拆分下 DSpark 接受率掉多少。
  • KV 缓存 V2 是默认项，对照组要写清楚。
  • NVFP4 冷页压缩的账要单列一档。
  • 多模态 KV 块精确哈希，跟 ShelfKV 那篇对得上。
  • 读题节点可以试前缀感知调度。
  • 共享前缀只算一次，RAG 流量收益最大。
  • 12 篇技术博客里有两篇值得单读。
  • 一篇讲 Skip Softmax 注意力长上下文。
  • 一篇讲 Helix 并行撑起百万 token 解码。
  • Rubin 预览只是预览，别当生产结论。

术语表

  • Rubin：英伟达新一代 GPU，SM107 架构。
  • KV 缓存 V2：新一代草稿纸管理器，默认开。
  • TriAttention：一种 KV 压缩方法。
  • NVFP4 冷页压缩：不常用的 KV 页压成 4 位。
  • DSpark / DFlash：两种新的投机解码草稿器。
  • EAGLE3：一种草稿模型，猜下一个词。
  • DWDP：权重分片加数据并行的混搭。
  • Helix：上下文并行，把长上下文切开分卡算。
  • VisualGen：TRT-LLM 里新加的图片视频生成方向。
  • gen-first 调度：先排生成请求，再排读题。
  • 对话亲和路由：同一对话固定落到同一组机器。
  • FlexKV / LMCache：外接 KV 缓存的连接器。
