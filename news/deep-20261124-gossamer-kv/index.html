Gossamer：推理模型的 KV 缓存，预算卡死也能跑

  • 原文：Feng Cheng、Cong Guo、Junyao Zhang、Haoxuan Shan、Chiyue Wei、Hong Wang、Hai Li、Yiran Chen，杜克大学、英特尔
  • 文章：Gossamer: A Utility-Driven Architecture for Constant-Budget KV Cache Compression in Reasoning LLMs
  • 提交时间：2026-11-22
  • 原文链接：https://arxiv.org/abs/2611.29497
  • 说明：数字全是作者自报；吞吐来自定制加速器的仿真，不是现成引擎实测

一句话

KV 缓存给个固定预算，超了就按价值选动作。这篇让推理模型在预算卡死时，照样跑得又快又准。

人话解读

推理模型越想越长，KV 缓存跟着越长越大。KV 缓存就是模型记下来的上下文草稿。128K 上下文时，它能占掉 84% 的显存。显存满了，批量就开不大，吞吐跟着掉。

以前的压缩办法分两派，各有短板。本地派只看眼前，固定比例压，不管 token 重要不重要。全局派全盘扫描再决策，准是准了，但每步都要多跑一趟。

全局派还有个毛病：攒够一批 token 才处理一次。反应慢半拍，实时推理里不合身。Gossamer 想两头都要：全局的准，本地的快。

它的办法是给每个 token 算一个效用分。分高的留，分低的压。压的时候三选一：量化、合并、还是扔掉。量化就是降精度存。合并就是跟相似的 token 合成一个。扔掉就是直接逐出。

关键一招叫 Free-Lunch Utilization。解码那步本来卡在访存上。算力大半空着没事干。相似度计算就搭这趟便车。跟注意力算子融在一起跑。不多花时间，不多占带宽。

图 1：Gossamer 总览。左上是全连接层能批量跑，算力吃满。右上是注意力层没法批量，算力空着。右下那个空闲就是免费午餐。下面是三个动作：扔掉、合并、量化。中间按效用分三选一。

核心方法

方法分四步，外加一套硬件。

第一步：新 token 一来，先算它跟旧 token 的相似度。相似度用余弦算。算的过程融进注意力里。注意力本来就要算 Q 乘 K。相似度顺手就出来了。

第二步：相似度加重要性，合成一个效用分。两个信号用一个参数 β 调配比。β 等于 0 只看冗余。β 等于 1 只看重要性。实测 β 等于 0.1 最好。

第三步：缓存超预算时，挑效用最低的 token 下手。三选一，各有代价。量化最轻，但留一个低精度副本。合并最省，但要找个最像的搭子。扔掉最狠，信息直接没了。

第四步：三个动作各有自己的小金库。主缓存只留全精度。量化缓存单独记账。合并直接改主缓存里的值。选哪个动作，要看它会不会挤掉别人的位置。

硬件是一套定制的脉动阵列。128 乘 128 个计算单元。片上缓存 64MB。片外是 HBM2，带宽 512GB 每秒。压缩那套逻辑只占 1.46 平方毫米。功耗 811 毫瓦。占整机面积 0.68%，功耗 0.65%。

图 2：不同 KV 预算下的准确率。绿线是完全不压的上限。橙线是 Gossamer，全程离绿线最近。蓝线是 R-KV。红线是 SnapKV，小预算时掉得最狠。左上 AIME 对预算最敏感。

关键数据

  • 模型是 DeepSeek-R1 蒸馏版 Llama-8B 和 Qwen-14B。
  • 评测是 AIME 2024 和 MATH-500。
  • 解码用 pass@1，温度 0.6，top-p 0.95。
  • 生成上限 8192 个 token，AIME 放到 16384。
  • 端到端吞吐最高 16.7 倍，对不压的基线。
  • 对 Oaken 是 5.5 倍，对 Ecco 是 4.9 倍。
  • 对 R-KV 是 1.8 倍。
  • 预算越紧，优势越大。预算大了，优势收窄。
  • 预算 256 时，50% 全精度版批量比不压大一个数量级。
  • QwQ-32B 上，8192 个 token 时吞吐超 10 倍。
  • 精度上，Gossamer 全程最接近不压的上限。
  • AIME 上差距最明显，MATH 上各家差距小一些。
  • 预算 2048 时，R-KV 的全局扫描占总运行时间 23%。
  • Gossamer 把这步融进注意力，额外开销基本为零。
  • 全精度配比 50% 到 75% 最好。
  • 配比太低，量化失真拖累精度。配比太高，等于没压。
  • 仿真基于 SCALEsim-v2，周期级精确。
  • 芯片用 28 纳米工艺，500MHz 主频综合。
  • 注意：16.7 倍是仿真峰值，不是现成引擎的实测。

跟研究方向的关联

跟 PD 解耦评估直接对口。KV 就是拆分后要传的东西。

第一，传之前先压一压。预算恒定，解码节点的显存就可预测。批量上限能提前算出来。

第二，效用分这个思路能抄。按 token 价值选动作。比固定比例压更贴合推理模型。

第三，免费午餐值得单列。注意力核里有空闲算力。相似度、打分这些活可以塞进去。不用另起一趟。

第四，数字要分段看。16.7 倍只在最紧的预算下。预算一放宽，优势就收窄。抄数字时要带上预算档。

第五，这是定制加速器的仿真。vLLM 和 SGLang 今天还用不上。落到引擎里，还得有人把这套逻辑写成核。

第六，精度曲线可以当对照。AIME 比 MATH 对预算敏感得多。评估里长推理任务要单列一档。

术语表

  • KV 缓存：模型记下来的上下文草稿，解码时不用重算。
  • 推理模型：擅长多步思考的模型，输出很长，缓存涨得快。
  • 余弦相似度：两个向量方向有多像，越像越冗余。
  • 量化：用更少的位数存数字，省显存，精度略降。
  • 合并：把两个相似的 token 合成一个，省一个位置。
  • 逐出：直接扔掉不重要的 token，信息就没了。
  • pass@1：采样多次里第一次就答对的比例。
  • AIME：美国数学邀请赛题，推理模型常用评测。
  • MATH-500：500 道数学题，难度分档的评测集。
  • 脉动阵列：一种硬件结构，数据像流水一样过计算单元。
  • HBM2：高带宽显存，显卡上给计算供数据的那层。
  • R-KV：推理模型 KV 压缩的代表方法，定期全局扫描。
  • SnapKV：按注意力分数留 token 的经典压缩方法。
  • Oaken / Ecco：把 KV 压到 4 位附近的量化框架。
  • SCALEsim-v2：模拟加速器跑多快的周期级仿真器。
  • β：冗余和重要性两个信号的调配比，0.1 最好。
