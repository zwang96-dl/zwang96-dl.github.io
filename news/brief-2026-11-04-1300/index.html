框架更新

vLLM 9 笔

#65198：GLM-5.3 的草稿模型显存直接砍半

GLM-5.3 用户好消息：草稿模型显存直接省一半。 投机解码就是小模型先打草稿、大模型再改。 这笔把草稿 KV cache 格式跟目标对齐。 每个草稿模型省 50% GPU 显存。 跑 EAGLE 这类多草稿的，等于白捡显存。 来源：https://github.com/vllm-project/vllm/pull/65198

#64760：H200 上 GLM-5.3 又快了 6%

GLM-5.3 在 H200 上再提速：端到端涨了 6% 到 7.6%。 FP8 是 8 位浮点权重格式，MoE 的下投射换了新 kernel。 纯性能包，升级就能吃到。 来源：https://github.com/vllm-project/vllm/pull/64760

#59747：NIXL 拒收对不上号的 P/D 握手

你的 PD 评估可能会撞上的坑：NIXL 现在主动拦了。 P/D 解耦是 prefill 和 decode 分开跑的分工流水线。 KV 搬运靠 NIXL，两端块大小对不上就拒掉。 以前是悄悄连上、错了再查，这笔让错配当场现形。 来源：https://github.com/vllm-project/vllm/pull/59747

#64129：DCP 的 top-k 合并更省了

DCP 就是分布式上下文并行，长上下文分片并行算。 稀疏 indexer 做 top-k 合并时只取 key 的有效位。 算得更快，玩 DCP 的升级吃得到。 来源：https://github.com/vllm-project/vllm/pull/64129

#65537：MiniMax-M3 序列并行能跟流水线并行双开

玩 MiniMax-M3 的注意：并行组合又多一种。 序列并行加流水线并行一起开，支持进来了。 大并行度部署可以试试这条路。 来源：https://github.com/vllm-project/vllm/pull/65537

#62057：Beam 1.0 登上 ROCm

AMD 卡用户的新模型支持：Beam 1.0 能跑了。 来源：https://github.com/vllm-project/vllm/pull/62057

其余 3 笔都是小修。

#65689 是多模态 dummy input 不再被误校验。

#65522 修准了 HiSparse 的 FlashInfer all-reduce 后端。

#64782 修了 WSL 核显的 CUDA 显存记账。

SGLang 9 笔

#48440：Kimi-K3 在 AMD 卡上 MoE 更顺

AMD 卡跑 Kimi-K3 的同学：MoE 又快了一截。 small-batch 的排序加 stage-1 量化，现在撑到 1024 pairs。 来源：https://github.com/sgl-project/sglang/pull/48440

#48439：草稿模型的全连接层按行切

dflash 是 SGLang 的投机解码框架。 草稿的 target-hidden 全连接层在 prefill 块里按行分片。 访存更顺，AMD 卡加 spec decode 的升级吃得到。 来源：https://github.com/sgl-project/sglang/pull/48439

#48437：DSA 稀疏 MLA 的 decode 又压了延迟

DSA 是 DeepSeek 稀疏注意力，长上下文省显存那招。 AMD HIP 上 decode 和 verify 换成 Split-K 并行。 延迟再压一压。 来源：https://github.com/sgl-project/sglang/pull/48437

#48001：spec decode 里 KV 写回位置修准

投机解码的上下文 KV 以前可能写错位置。 这笔把 DFLASH 和 DSPARK 的写回修到草稿自己那行。 数据对齐修准，用 spec decode 的注意。 来源：https://github.com/sgl-project/sglang/pull/48001

#48002：非法 KV 布局配置直接拦

碎片化 CP 的 KV 布局混搭统一内存，这笔直接拒掉。 别等跑起来再炸。 来源：https://github.com/sgl-project/sglang/pull/48002

其余 4 笔是重构和文档，略过。

#48005、#48004、#48003 是 mem_cache 和 hicache 的内部整理。

#48432 是 MI355X 的 cookbook 文档。

#21662：Helix 聚合下 KV 块复用开了
