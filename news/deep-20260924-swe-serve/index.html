SWE-Serve：给推理工程 agent 的"生产考试"

原文：SWE-Serve: Benchmarking Agentic Engineering For Production Inference Serving
作者：Jennifer Williams, Dave Farris, Jeff Farris（NVIDIA），Jiantao Jiao（UC Berkeley）
链接：https://arxiv.org/abs/2609.26777

人话解读

让 agent 给推理引擎写代码，容易。 让它写的代码在真实 serving 链路里不出事，难。 这篇给 agent 出了一套"生产考试"：53 道题。 题全是从 SGLang 的真实生产改动里扒出来的。 每道题都要在容器里真刀真枪跑：CPU 或单张 H100。 本地单元测试过了不算，还要过端到端测试。 端到端测试的意思是：把服务进程真起起来。 走公开接口发请求，看模型能不能正常吐 token。 11 个模型测下来，最好成绩 pass@1（一次做对的概率）只有 75%。 最扎心的是这组数字：同一批补丁。 算上端到端测试，通过率 45.9%。 把端到端测试从评分里拿掉，通过率 69.4%。 也就是说，三分之一"本地跑通"的补丁。 放到真实 serving 链路里全挂，一个不少。 这就是作者说的 production correctness gap。 中文叫生产正确性鸿沟。 本地正确不等于生产正确。

核心方法

三步做出 53 道题。

  • 选题：从 2025 年 12 月之后合入 SGLang 的生产改动里挑。

共用了 83 个合入的 PR（代码合并请求）。 37 道题来自单个 PR，16 道题合并了 2 到 6 个相关 PR。

  • 六个工程方向，互不重叠：

模型与后端接入，12 题。 投机解码与高级解码，14 题。 内核、量化与性能，8 题。 缓存与运行时状态，7 题。 分布式执行与调度，4 题。 服务 API 与运行时正确性，8 题。

  • 质检：进库之前过四道关。

no-op 对照：原仓库不改，隐藏测试必须挂。 oracle 对照：参考解必须全过。 agent 对抗性探测：让 agent 找测试的漏洞。 人工裁决：人最后看一遍证据拍板。

测试设计有三层。

  • F2P 测试（fail-to-pass）：改之前挂、改之后必须过。

中位数 7 个，最多 246 个。

  • P2P 测试（pass-to-pass）：回归保护，别修好一个砸坏一片。

中位数 10 个，最多 2034 个。

  • 端到端测试：19 道题有，3 道题还有性能门（慢了也算挂）。

真起服务进程，走公开接口断言行为。

防作弊也有两招。

  • 闭卷执行（closed-book）：agent 不能联网抄答案。
  • 轨迹审计：把 agent 的操作记录留下来备查。

关键数据

  • 题量：53 题，12 道纯 CPU，41 道要 H100。

题目说明中位数 200 词，参考解中位数改 553 行、7 个文件。 最大的一道改了 6077 行、35 个文件。

  • 排行榜：11 个模型 × 31 种配置。

Claude Opus 5 和 GPT-5.6 Sol 并列第一。 pass@1 都是 75%。 用的都是 mini-SWE-agent（与模型无关的通用脚手架）。 换成各家专用脚手架（Codex、Claude Code）反而没涨分。

  • 生产正确性鸿沟：19 道有端到端测试的题。

同一批补丁，去掉端到端测试，通过率 45.9% 涨到 69.4%。 差 23.4 个百分点，11 个最佳配置全都涨。 Gemma 4 MoE 那道题最典型：16 个补丁过了所有非端到端测试。 但服务一起、对着公开接口一打，模型根本 serve 不起来。

  • 哪类题最难：跨多个运行时域的题（请求进、token 出要经过好几个模块）。

通过率比单域题低 21.3 个百分点。 要处理持久状态的题低 20.8 个点。 要处理并发协调的题低 29 个点，只有 6 道题考这个。

  • 花钱和提分不成正比：推理成本（美元，对数轴）画出来。

贵的不一定分高，同分的配置成本能差好几倍。 推理力度（reasoning effort）拉满，成本涨，分不一定涨。 GPT-5.6 家族里，加大力度能提总分。 但生产正确性的鸿沟，力度拉满也填不平。

跟你研究方向的关联

三条直接相关。

  • 你想做 AI 自动调参系统。

目标：SGLang + P/D 解耦 + SLA 内吞吐最优。 这套基准开箱即用，53 道题全是 SGLang 的真实生产任务。 你的调参 agent 能不能干活，先在这上面量一遍。 比自己攒测试集靠谱得多。

  • 端到端测试那 23.4 个百分点的鸿沟，是给你的预警。

调参 agent 在离线 benchmark 上调出的"最优配置"。 不经过真实服务链路验证，数字再好看也可能是假的。 你的系统里必须有一环是起真实服务压测。

  • 六个方向里，这四个跟你最相关：

投机解码 14 题，内核量化 8 题。 缓存状态 7 题，分布式调度 4 题。 正好是你调参系统要覆盖的参数空间。 哪类参数 agent 最搞不定，排行榜已经告诉你了：并发和状态。

术语表

  • production correctness（生产正确性）：

补丁在真实 serving 链路里行为正确。 不只是单元测试过。

  • F2P（fail-to-pass）：没修之前挂、修完必须过的测试。
  • P2P（pass-to-pass）：回归测试，修完之后原来好的还得好。
  • pass@1：agent 第一次尝试就做对的概率。
  • oracle solution（参考解）：出题人写的标准答案。

用来证明题是可解的。

  • no-op control（空操作对照）：代码一行不改。

测试必须挂，证明测试真能抓到问题。

  • closed-book execution（闭卷执行）：评测时不能联网。

防止抄到原 PR 的解法。

  • trajectory audit（轨迹审计）：记下 agent 每一步操作。

事后可查有没有作弊。
