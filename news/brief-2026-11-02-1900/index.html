多模态大模型推理服务简报 · 2026-11-02（19点版）

19点版来了。这轮框架都很忙。PD 解耦又添三笔新料。

框架更新

vLLM #63420：前缀缓存不再乱续租 这笔跟前缀缓存直接相关。前缀缓存就是复用算过的提示词。Mooncake 查前缀时，以前会给所有命中键续租。有些键其实根本不会被读到。满了之后，该留的被挤走。不该留的反倒留下。这笔改成只租真正要读的键。先探查不续租，再按实际读取集合续租。说白了，只给要用的草稿纸续费。 来源：https://github.com/vllm-project/vllm/pull/63420

vLLM #61435：Kimi-K3 有了专属解码 这笔跑在 MI355X 上。这笔是给 Kimi-K3 做专属解码。专属解码就是为一个模型量身定制的快路。它把 MoE 解码层换成常驻内核。常驻内核就是一直待在卡上不用反复启动。TP8 下跑 FP8 KV，DCP1 和 DCP8 都支持。DCP 就是解码上下文并行。性能图在 PR 里，数字是作者自报。 来源：https://github.com/vllm-project/vllm/pull/61435

vLLM #60339：后缀投机解码上了新版运行器 后缀解码就是靠结尾重复片段猜下文。以前它只能跑旧运行器，还依赖 CPU。还强制关掉异步调度。现在它跑上 GPU 新版运行器。异步调度也回来了，接受率跟旧方案打平。Qwen2.5-7B 上吞吐不输旧方案。 来源：https://github.com/vllm-project/vllm/pull/60339

vLLM #61609：稀疏 MLA 的 bf16 路也能切分了 FlashMLA 稀疏版以前 bf16 下不支持 DCP。DCP 就是把解码上下文分到多卡。这笔把它打通了，Hopper 卡上独一份。GLM-5.3-Flash 的 GSM8K 分数基本没变。DCP4 是 0.904，DCP1 是 0.894。 来源：https://github.com/vllm-project/vllm/pull/61609

vLLM #61795：UMBP 单机模式先搭骨架 UMBP 就是 vLLM 的跨引擎 KV 共享机制。这笔只加单机服务器运行时。多个引擎共用一块内存池。KV 字节走 HIP 直传，不走套接字。服务器挂了就直接失败，不无限等。注意，这只是实现，测试在下一个 PR。 来源：https://github.com/vllm-project/vllm/pull/61795

vLLM 其余三笔带过

#65238 是 CI 自动打标签。#65199 是文档列插件。#64651 是 XPU 测试。

来源：https://github.com/vllm-project/vllm/pulls

SGLang #43906：调度器修了分块计数的坑 这笔接上 17点版的调度器重构。分块预填充就是把长提示切段算。以前计数器只加不减，尾段会被误认成中段。PD 预填充下，尾段会被重新排队。流水线并行下，输出交换也可能被跳过。现在每步按自己的记录认身份。这个坑跟你的 PD 评估直接相关。 来源：https://github.com/sgl-project/sglang/pull/43906

SGLang #45785：空闲时也要上报 KV 用量 Dynamo 会按 KV 用量决定接不接请求。引擎空闲后，旧的用量数字还留在那。结果明明有空位，请求却被拒。实测里，第一单跑完，后三单全被拒。修掉后，四单全跑通，空闲用量回到零。这笔虽小，却是 PD 联动的运维坑。 来源：https://github.com/sgl-project/sglang/pull/45785

SGLang #47476：常驻专家数不用手调了 Paged Experts 就是把专家按需换进换出。常驻数以前要靠手试。设大了，启动就内存不足。设小了，显存空转，还多换页。现在系统按卡、模型和量化自动算。例子里，K 从 63 调到 92。解码从 208 涨到 233 token 每秒。 来源：https://github.com/sgl-project/sglang/pull/47476

SGLang #44148：Kimi-K3 的 NVFP4 路打通了 SiTU 是 Kimi-K3 路由专家用的激活函数。以前两处检查只认 silu 和 relu2。结果 K3 用不上 FlashInfer 的 NVFP4 内核。NVFP4 就是 4 比特浮点量化。这笔把 SiTU 放行，参数也传过去了。 来源：https://github.com/sgl-project/sglang/pull/44148

Dynamo #15500：多模态传输出错不再漏资源 发送方准备共享内存或 NIXL 注册时，中途失败会丢清理句柄。NIXL 就是跨节点传 KV 的高速通道。丢了句柄，第一段资源就没人管了。现在准备失败就自己释放，错误原样保留。已传出去的仍按老路子走。 来源：https://github.com/ai-dynamo/dynamo/pull/15500
