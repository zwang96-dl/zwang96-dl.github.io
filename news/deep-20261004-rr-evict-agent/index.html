RR-Evict：Agent 前缀缓存别连根拔，轮流薅尾巴

原文：https://arxiv.org/abs/2609.32278 作者：Zaifeng Pan、Chris Wu、Zhengding Hu、Xinwei Qiang、Zhongkai Yu、Yufei Ding 单位：UC San Diego 日期：2026-09-26（arXiv:2609.32278；10/4 12点版补扫，往期简报未报过）

人话解读

Agent 跑长任务，是一路"想一步、调一次工具"走下来的。 每次调模型，都把之前攒下的全部历史带上。 prefix caching 就是前缀缓存。 把算好的 KV 存下来，下次直接复用，省掉重复 prefill。 这是 agent serving 的标配。

但缓存就那么大。历史越攒越长，并发一高就得腾地方。 腾谁？默认答案是 LRU（最近最少用：谁最久没被碰就先扔谁）。

问题出在一个怪现象上。 它叫 recency synchronization，翻译过来是新近度同步。 一次调用会把整条历史的缓存节点同时"刷新"一遍。 所以一个 agent 的私有历史节点，新近度全都一模一样。 LRU 按新近度杀，一杀就把某个 agent 的全部历史连根拔起。

被拔光的 agent 回来时，历史一点不剩。 得从头重算整个上下文。TTFT（首 token 延迟：发请求到吐出第一个字的时间）直接爆表。 更气人的是：这时候整体缓存命中率可能还挺好看。 等于少数几个倒霉 agent 替所有人扛了长尾。

RR-Evict 的解法就一句话：别连根拔，轮流薅。 按 round-robin（轮询：排队轮流，一家薅一点）的顺序。 每个 idle 的 agent 只薅掉尾巴上一小截。 这样每个 agent 都还留着大部分历史。 回来时只补算一小段，不用从头再来。

核心方法

缓存结构沿用 SGLang 原来的 radix tree。 基数树，按 token 前缀拼起来的树形索引。 正在被请求的节点照旧不动，只改"杀谁"的排序。

  • LRU 的做法：所有能杀的叶子按最后访问时间排一个全局堆，从最老的开始杀。
  • RR-Evict 的做法：按 agent（trajectory）分组，轮流拜访。
  • 轮到哪个 agent，就从它的尾巴薅掉一个 tail chunk（一块）。
  • tail chunk 是后端一次能薅走的量，或者叶子节点里后缀的一部分。
  • 被薅过的叶子如果还剩有效前缀，就当这条 trajectory 的"新叶子"。
  • 继续薅会暴露它的父节点，父节点符合条件也能薅。
  • 不需要预测未来请求啥时候来，也不需要知道工具调用要多久。

还给了个适用区间分析。 RR-Evict 在"中间地带"最灵：活跃请求能装下，但活跃加空闲装不下。 太空了根本不用淘汰，太满了谁都救不了。

关键数据

H100 上跑的 SGLang 实现。 tail chunk 取 1024 token。

  • τ²-bench（对话类 agent 负载）：vs LRU，P99 TTFT 最高降 75.4%。
  • P99 未缓存 prompt token：最高降 65.7%。
  • vs LRU + Completion Signals（完成信号：agent 跑完直接通知后端回收）：TTFT 再降 46.9%，未缓存 token 再降 30.6%。
  • 并发 64 / 80 / 96 三档，全线优于两个基线。
  • SWE-bench coding agent（Qwen3-8B）：1P3D prefill-decode 解耦配置下同样有效。
  • 1P3D 是一个 prefill worker 配三个 decode worker，prefix cache 留在 prefill 侧。

跟研究方向的关联

  • 直接相关：实现和评估都在 SGLang 上，跟你正在评估的 SGLang P/D 解耦是同一套栈。
  • Figure 6 就是 1P3D 解耦配置下的实测：prefix cache 留在 prefill 侧，淘汰策略的好坏直接决定 prefill 侧的 TTFT 长尾。
  • SGLang 默认的淘汰就是 LRU。这篇指出 LRU 在 agent 负载下有个结构性毛病（recency sync），评估 SGLang 时值得盯一下这块。
  • 跟 9/30 的 KVTether 深读是姊妹篇。KVTether 解决"杀错对象"（缓存看不懂谁死了），RR-Evict 解决"杀得太狠"（一杀杀一串）。两篇对照看，prefix cache 淘汰这条线就齐了。
  • 跟今天 12点版简报里 Nebius 播客呼应：厂商在谈 prefix caching 和 KV cache 优化，这篇是学术界给出的具体解法。

术语表

  • prefix caching（前缀缓存）：prompt 前缀算好的 KV 存下来，后续请求直接复用，省掉重复 prefill。
  • LRU：最近最少用。谁最久没被碰到，先扔谁。简单但不懂业务语义。
  • recency synchronization（新近度同步）：一个 agent 的历史节点被一次调用同时刷新，新近度全都一样，导致 LRU 成片误杀。
  • TTFT：time to first token，首 token 延迟。用户感知最强的指标之一。
  • tail chunk：每次从 agent 尾巴上薅下来的一块，本文取 1024 token。
  • round-robin（轮询）：排队轮流，一家一次，公平分配。
  • radix tree（基数树）：SGLang 组织缓存 KV 的树形索引，按 token 前缀拼起来。
  • 1P3D：1 个 prefill worker 配 3 个 decode worker 的解耦部署。
  • τ²-bench：本文用的对话类 agent 评测负载。
