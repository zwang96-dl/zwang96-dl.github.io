一句话

1T 的 Mistral Large 4，怎么在 vLLM 上跑。 配方给了全套打法和实测数字。 P/D 拆分那部分，最值得抄。

人话解读

Mistral Large 4 是 Mistral 的旗舰大模型。 总参数 1T，每次只激活 49B。 它是 MoE，多专家混合那类结构。 每次只挑 4 个专家干活。 还带看图的能力，是多模态模型。 vLLM 刚把它接进来。 配方页就是官方的部署说明书。 哪种硬件、哪种切法、配什么参数，全写了。 最值钱的是 P/D 拆分那几组数。 读题和解码分开跑，到底快多少。 这正是你评估里缺的那档。 1T 模型、开源权重、能自己跑。 配方里的配置表，可以直接抄进评估清单。

核心方法

模型结构先说清楚。 72 层，128 个路由专家。 每次 top-4，再加 1 个共享专家。 注意力是 MLA，配 DSA 稀疏索引。 DSA 只挑前 2048 个 key 算。 跨层共享 KV，草稿纸复用。 视觉编码器是 Pixtral。 内置 DSpark 草稿器。 推测解码不用再外挂草稿模型。 草稿深度固定 3，由 checkpoint 定死。

服务这边走 vLLM V2 runner。 默认开断点续跑的 CUDA 图。 注意力用 FlashMLA 稀疏版。 KV 缓存默认 FP8 latent 格式。 名字叫 fp8_ds_mla。 不用再手动传注意力参数。 上下文标称 1M，实测只验证到 256k。

三个权重版本。 NVFP4 是默认，约 610GB。 FP8 是 AMD 上的默认，约 1.06TB。 MXFP4 是 AMD Quark 版，约 578GB。 两个 checkpoint 都带 DSpark 草稿器。

硬件覆盖四档。 GB300 上 NVFP4 或 FP8。 8 张 B300，NVFP4 或 FP8。 8 张 B200，只测了 NVFP4。 H200 要 16 张，FP8。 AMD 是 8 张 MI350X。

P/D 拆分是配方的重点。 读题节点和解码节点分开。 KV 用 NIXL 在节点间传。 长上下文再拆 DCP 和 PCP。 DCP 是上下文并行，拆 KV 那段。 PCP 是预填并行，拆读题那段。 前缀缓存默认开着。 会话钉在同一组 DP rank 上。

关键数据

先说默认配置。 TP8 加 DSpark，交互最好。 单用户每词 3.13 毫秒。 NVFP4 的数，FP8 是 3.56 毫秒。 接受长度约 2.9。 比不开推测解码快 1.9 到 2.2 倍。

再说吞吐那档。 DP8 加专家并行，再加 DSpark。 8k 输入，每卡每秒 209.8 词。 32 并发时每用户 55 词每秒。 32k 输入，每卡每秒 50.6 词。

长上下文那档最说明问题。 TP8 加 DCP8，KV 容量 28.76M 个 token。 不拆的 TP8 只有 3.60M。 差了 8 倍。 按 KV 算，能并跑约 27 个 1M 上下文请求。

首字时间那档。 TP1 乘 PCP8 乘 DCP8，再加专家并行。 单用户首字 0.16 秒、0.54 秒、1.08 秒。 对应 8k、32k、60k 输入。 比 TP8 快约 3 倍。 但这档只支持纯文本。

拆分跑吞吐那档。 读题 DP4 加专家并行，解码 TP4。 32k 输入，每卡每秒 241 词。 每用户不少于 40 词每秒。 60k 时，每卡每秒 129 词。

拆分跑首字那档。 读题 PCP4 乘 DCP4，解码 TP4。 单用户首字 0.35 秒、0.64 秒、1.21 秒。 对应 8k、32k、60k。

短输入拆分那档。 读题和解码都是 DP4 加专家并行。 8k 输入，每卡每秒 766 词。 这是全场最高的吞吐数。

agent 场景那档。 读题 PCP4 乘 DCP4，解码 TP4 加 DCP4。 不开推测解码。 32 个会话时，首字中位数 0.72 秒。 解码不拆 DCP 的对照组，要 14.95 秒。 差了 20 倍。

合跑和拆跑直接比。 8k 输入，拆跑快 1.8 到 2.2 倍。 32k 和 60k 时，拆跑快 4 到 5 倍。 原因是合跑时，解码要等读题切块。 步子被读题拖住了。

NVFP4 和 FP8 比。 TP8 上，每词快 1.09 到 1.18 倍。 开 DSpark 时，快 1.14 到 1.22 倍。 KV 容量多约 1.5 倍。

调优参数两条。 专家并行时，MoE 后端换 MegaMoE。 32k 时读题每秒请求多 14% 到 17%。 要装 nvshmem4py-cu13。 DCP 那侧，KV 交错粒度设 64。

AMD 那边也给了数。 MXFP4 专家比 FP8 快 22% 到 71%。 并发 1 到 64 都测了。 TP4 加 DSpark，接受长度 3.1。 单用户每词比不开快 2.7 倍。 8 并发快 1.9 倍，32 并发快 1.8 倍。 专用解码配置，每层一个融合核。 单用户每词省 1.5 倍。 再加 DSpark，省 2.9 倍。 MXFP4 专家让模型能塞进 4 张卡。 一台 8 卡机器能跑两个 TP4 副本。 FP8 latent KV 比 BF16 省 1.86 倍容量。

准确率对过参考实现。 2 张 GB300、TP8 上，逐层一致。 256k 长上下文困惑度也一致。 GSM8K 1319 题，5-shot。 FP8 是 0.909，开 DSpark 是 0.918。 在基础服务自身的噪声范围内。 P/D 和合跑各配置，GSM8K-200 零样本。 分数在 0.965 到 0.980 之间。

跟研究方向的关联

这篇跟你的 PD 解耦评估直接对口。

先说拆跑和合跑的分档。 8k 时拆跑快约 2 倍。 32k 以上快 4 到 5 倍。 这说明收益跟着上下文走。 评估里要按输入长度分档报。 别只报一个倍数。

再说首字那档。 agent 场景 32 会话，首字从 14.95 秒压到 0.72 秒。 靠的是读题拆 PCP、解码拆 DCP。 长上下文 agent 评估里，这组配置可以直接抄。 注意对照组是解码不拆 DCP。 拆和不拆的差，比拆和合的差还大。

再说 KV 容量那档。 DCP8 把 KV 容量从 3.60M 拉到 28.76M。 长上下文并发数，跟着 KV 容量走。 评估长上下文时，先报 KV 容量。 再报能并跑几个 1M 请求。

再说 NIXL 传 KV。 P/D 拆分要跨节点传 KV。 配方里用 NIXL 当传输层。 你的评估清单里，传输层要单独一栏。 传多快、占多少带宽，都要测。

再说 DSpark 草稿器。 内置草稿器，深度固定 3。 接受长度约 2.9，TPOT 快约 2 倍。 推测解码评估里，内置和外挂要分开报。 外挂草稿模型要多占显存。

最后是 MI350X 那档。 AMD 上 MXFP4 专家快 22% 到 71%。 你的硬件清单里有 MI350X。 同一模型、同一配方，AMD 也能跑。 评估可以把 MI350X 也放进去。

局限与提醒

数字都是 vLLM 官方自报。 没有第三方复测。 硬件只覆盖 GB300、B300、B200、H200、MI350X。 换硬件，数字会变。 上下文标称 1M，只验证到 256k。 超过 256k 的表现，配方没给。

P/D 拆分的限制有三条。 PCP 只支持纯文本。 DSpark 在 DCP 解码节点上还跑不了。 DSpark 也没跟流水线并行验证过。

AMD 上限制更多。 AMD 上这几样都不支持。 NVFP4 checkpoint、DCP、PCP、NIXL、HiSparse。 TP8 加 DSpark 也没在 AMD 上验证。 MI300 系列也没验证。

GSM8K 的分数在噪声范围内。 0.909 和 0.918 的差，别当真。 支持 PR 刚合入，还没进发布版。 要用专用镜像，别等 nightly。 配方页是 10 月 28 日的。 PR 是 11 月 13 日合入的。 两者时间对不上，配置可能有微调。

术语表

  • Mistral Large 4：Mistral 的 1T 旗舰多模态模型
  • MoE：混合专家，每次只激活少数专家
  • 路由专家：按 token 内容挑出来干活的专家
  • 共享专家：每个 token 都要过的专家
  • MLA：多头潜注意力，KV 压成 latent 向量
  • DSA：稀疏索引，只挑前 2048 个 key
  • 跨层 KV 共享：多层复用同一份 KV
  • Pixtral：Mistral 的视觉编码器
  • DSpark：Mistral 内置的推测解码草稿器
  • NVFP4：4 位浮点量化，带缩放因子
  • MXFP4：AMD 的 4 位浮点量化格式
  • FP8：8 位浮点，更省显存的记法
  • DCP：上下文并行，拆 KV 那段
  • PCP：预填并行，拆读题那段
  • NIXL：英伟达的跨节点 KV 传输库
  • HiSparse：host 上的稀疏 KV 卸载
  • TPOT：每输出一个词的时间
  • 接受长度：推测解码每轮平均留下的词数
  • 专家并行：MoE 专家分到不同卡上
  • MegaMoE：vLLM 的 MoE 专家并行后端
  • latent KV：压成低维向量的 KV 缓存
  • GSM8K：小学数学题评测集
