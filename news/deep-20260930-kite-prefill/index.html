KITE：双塔架构，把 prefill 成本锁死在"小模型"水平

  • 论文：KITE: KV-Invariant Transformer Expansion for Efficient Agentic LLM Scaling
  • 作者：StepFun（阶跃星辰）团队，ZhiHeng Hu 等
  • arXiv：https://arxiv.org/abs/2609.27294（2026-09-23 提交）
  • 一句话：模型越做越大，但 prefill 的算力账单永远按小模型收。

人话解读

  • 平时模型扩规模，prefill 和 decode 一起变贵。
  • KITE 换了个思路：新增参数全部塞进"不碰 KV 缓存"的区域。
  • KV cache 就是推理时的草稿纸，存着 prompt 的键值对。
  • 新增参数不参与造草稿纸，prefill 成本就钉死在小模型水平。
  • 模型变聪明了，prefill 却没变贵。

核心方法

  • 具体实现叫 SST（Step Scale Transformer），双塔结构。
  • 第一座塔叫 Prefiller，负责读 prompt、逐层产出 KV。
  • 第二座塔叫 Decoder，新增的，只读 KV、不产出供未来用的记忆。
  • 两座塔各 18 层，Decoder 每层直接复用对应 Prefiller 层的 KV。
  • 训练分两步：先把 Prefiller 当普通小模型训好。
  • 然后复制权重初始化 Decoder，两座塔一起继续训（upcycling，旧模型复活再利用）。
  • Entry bridge（入门桥）把词嵌入和 Prefiller 末态拼起来喂给 Decoder。
  • 推理时：bulk prefill 只跑 Prefiller；decode 时两座塔都跑。
  • Decoder 的计算全是 token-local（只看当前 token），历史包袱为零。

*图注：SST 双塔架构。左：Stage 1 只训练 Prefiller（普通小模型）。右：扩展时从源权重初始化 Decoder，Stage 2 双塔联合训练。绿色箭头是逐层共享的 KV，橙色是 token-local 的入门桥。Decoder 只读 KV、不生产未来需要的记忆，所以 prefill 成本不随模型变大而涨。*

关键数据

  • 源模型 33.8B 参数，先训 167.98B tokens。
  • 扩展后 67B（66.959B），再联合训 222.55B tokens。
  • 总计 390.54B tokens，跟 47B/63B 经典基线同量级训练量。
  • 67B SST 每 decode token 激活 2.15B body 参数。
  • 训练 loss（EMA-200）：SST 1.5900。
  • 比 47B 经典模型低 0.0106，比 63B 经典模型低 0.0021。
  • 推理成本代理（prefill 占 75%、decode 占 25%）：比 47B 低 6.7%。
  • 同口径下比 63B 经典模型低 31.6%。
  • 下游任务（MMLU、GSM8K、MATH、HumanEval 等 7 项）全部超过两个基线。

*图注：Figure 1 上半是三步训练路线：训小模型 → 加只读 KV 的 Decoder → 联合继续训。下半雷达图以 47B 经典模型为基准（灰色虚线，越靠内越好）：左侧 63B 经典模型推理代价高出 36.5%；右侧 67B SST 推理代价反而低 6.7%，训练 loss 也更低。三个维度（训练成本、推理成本、模型质量）同时占优，这是论文最想证明的点。*

*图注：Table 2 是四组模型配置：Source（33.8B，18 层）、SST（67B，18+18 双塔）、47B/63B 经典基线。注意 SST 的 decode 激活参数 2.155B，比 63B 基线的 2.016B 还高——Decoder 的代价全压在 decode 端。Figure 3 是训练时间线：167.98B tokens 训源模型，换 checkpoint 后 222.55B tokens 双塔联合训。*

动机：生产流量本来就是 input-heavy

  • 论文统计了 OpenRouter 2026-08-22 到 09-20 的真实流量。
  • Claude Fable 5：未缓存 input token 是 output 的 16.29 倍。
  • 未缓存 input 的费用占到总账单的 76.7%。
  • GPT-6 Astra：input 是 output 的 14.64 倍，费用占比 74.6%。
  • 说白了：线上花的钱，四分之三都在 prefill。
  • prefill 便宜一分，账单就薄一分。

跟你的研究方向的关联

  • 你正在 SGLang 上评估 P/D 解耦（prefill/decode 分工流水线）。
  • KITE 是从模型架构侧把 prefill 做便宜，跟你做的系统侧解耦正交互补。
  • 解耦后 prefill 池和 decode 池本来就是不同机器。
  • KITE 的 Prefiller 塔天生适合塞进 prefill 池：小、快、KV 生产者。
  • 跟 9/24 报过的 Disaggregated Quantization 可以对照看。
  • DQ 是"两阶段穿不同的量化鞋"，KITE 是"两阶段长不同的身子"。
  • 两者都认一个理：prefill 和 decode 根本不是同一种计算。
  • OriginsHQ 有篇五系统横评（Splitwise / HMA-Serve / SPAD / DQ / KITE），入门可读：https://originshq.com/blog/llm-prefill-decode-disaggregation-five-systems/

局限与冷水

  • KITE 要重新训练，现有已部署模型吃不到红利。
  • 省的是 prefill，decode 反而变贵了（Decoder 新增参数每步都跑）。
  • 论文的推理成本是解析代理（75:25 加权），不是实测 QPS。
  • 真实 serving 收益要看 prefill 占比，decode-heavy 的 workload 别指望。
  • 作者自己也承认 SST 未必是最优的 KITE 实现，只是"能 work 的第一个"。

术语表

  • prefill：模型第一次读完整 prompt、算出 KV 的阶段，算力密集。
  • decode：逐个吐 token 的阶段，访存密集，一次只算一个 token。
  • KV cache：注意力机制的键值缓存，推理时的"草稿纸"。
  • upcycling：把训好的小模型当起点、扩成大模型继续训，省训练费。
  • MoE：混合专家模型，每次只激活部分"专家"子网络，省算力。
  • token-local：只依赖当前 token 的计算，不用翻历史，decode 友好。
