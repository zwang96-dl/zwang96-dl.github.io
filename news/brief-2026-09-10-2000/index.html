业内新闻

  1. 闲置的 GPU 也能拿来赚钱了

还记得 continuous batching 吗？就是 vLLM 里那个"GPU 别空等"的核心机制。它的发明人叫 Byung-Gon Chun。这次他带着新公司 FriendliAI 回来了。

这次他们发布了 InferenceSense。说白了，就是把机房里闲着的 GPU 拿出来跑推理。按单收钱，再跟机房分成。

技术上也有料：自研 C++ 推理引擎，不套 Python 框架那一套。自称吞吐是标准 vLLM 的 2 到 3 倍。投机解码、量化、KV cache 管理全自带。

多说一句：KV cache 就是推理时的"草稿纸"。投机解码呢，是让小模型先猜、大模型只管点头摇头，猜对了就省时间。

部署在 Kubernetes 上。机房自己的任务一回来，GPU 秒级让位。需求侧已经接上了 OpenRouter 这类聚合器。

对你意味着什么？这条路要是跑通，推理 API 的价格长期看跌。

新技术与论文

  1. 3 倍加速，直接"烤"进权重里

投机解码有个麻烦：得配个"小跟班"草稿模型。多一套系统要养，挺累。

UMD 和 TogetherAI 换了条路。训练时就让模型"一次说好几个词"。这叫多 token 预测（MTP）。GSM8K 上快了 3 倍，精度只掉了不到 3%。

加速能力长在权重里。部署时零额外组件，省心。

核心 trick 挺有意思：换了个"判卷老师"。学生一次吐一整段，老师只打"整段通不通顺"的分。这叫在线自蒸馏。

还有个 ConfAdapt 策略。置信度超 90% 的算有把握，直接出。没把握的逐词慢吐。SGLang 实测里，跟 EAGLE-3 投机解码打了个平手。

作者给了个上手建议：先拿"数数、复读"这类玩具 prompt 验证。再用自己业务的数据适配一次，效果最好。

为什么值得深读？这是投机解码的"无辅助模型"替代路线。跟你研究的 P/D 解耦、decode 加速直接相关。MTP 权重叠上 P/D 解耦，理论上效果还能再上一层。

技术深扒（跟进）

  1. DeepSeek V4.1-Flash 扒完了

0800 档报了发布，今晚把技术细节扒完。这是个"看着胖、用着瘦"的模型。

552B 参数，听着吓人。但推理时只激活 8B（读输入）/16B（生成）。就像 500 人的公司，干活的永远是那十几个人。

最狠的是 KV cache。只有 890 字节/token，上一代的 1/4。怎么做到的？解码器不自己记笔记，直接"复印"编码器的压缩版。这叫 CED 架构（20+20 层）。

原生多模态，MIT 开源。API 已经降价。V4 Pro 从 9 月 14 日起下线，并入它。

对你意味着什么？KV cache 是 serving 成本的第一性原理。同样显存，能塞 4 倍并发。

还有个有意思的对照。CED 让编码器只跑 prefill，解码器只跑 decode。这跟 P/D 解耦是同一套分工哲学，可以当参照系看。
