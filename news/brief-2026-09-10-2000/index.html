人话版：FriendliAI（创始人 Byung-Gon Chun 就是写出 continuous batching 那篇 Orca 论文的人，vLLM 的核心机制就来自他）本周发布 InferenceSense——neocloud 机房里闲置的 GPU 不用再"空转烧电"，直接跑付费推理任务，收益跟机房分成。 细节：自研 C++ 推理引擎（不用 Python 框架那套），自称吞吐是标准 vLLM 的 2-3 倍，自带投机解码（speculative decoding：小模型先猜、大模型验证的加速法）、量化、KV cache 管理；跑在 Kubernetes 上，机房自己的任务一回来就秒级让出 GPU。需求侧接 OpenRouter 等聚合器。对你的意义：如果 neocloud 能把闲置算力变现，推理 API 价格长期有下行压力。 🔗 https://venturebeat.com/infrastructure/the-team-behind-continuous-batching-says-your-idle-gpus-should-be-running

  1. 把 3 倍加速"烤"进权重：不用投机解码的另一条路（论文 2026-02，今日 VentureBeat 深度报道）

人话版：投机解码要配个"小跟班"草稿模型，又多一套系统要养；UMD/TogetherAI 这篇直接训练模型"一次说好几个词"（多 token 预测 MTP），GSM8K 上 3 倍提速、精度只掉不到 3%——加速能力长在权重里，部署时零额外组件。 细节：核心 trick 是"换判卷老师"——学生一次吐一整段词，老师模型只打"整段通不通顺"的分（student-forced 在线自蒸馏），外加 ConfAdapt 策略：置信度超 90% 的大段直出、没把握的逐词慢吐。SGLang 实测里跟 EAGLE-3 投机解码在吞吐-延迟曲线上打平。作者建议先拿"数数、复读"这类玩具 prompt 验证，再用自己业务域数据适配一次效果最好。 为什么值得深读：这是投机解码的"无辅助模型"替代路线，跟你评估的 P/D 解耦、decode 侧加速直接相关——MTP 权重 + P/D 解耦理论上可以叠加；精读笔记已存 → 深度阅读/MTP自蒸馏-3倍加速免投机解码.html 🔗 报道 https://venturebeat.com/orchestration/researchers-baked-3x-inference-speedups-directly-into-llm-weights-without ｜ 论文 https://arxiv.org/abs/2602.06019 ｜ 代码 https://github.com/jwkirchenbauer/mtp-lm

  1. DeepSeek V4.1-Flash 架构扒完了：KV cache 压到 890 字节/token，精读笔记已存。

人话版：0800 档报了发布，今晚把技术细节扒完——这是个"看着胖、用着瘦"的模型：552B 参数但推理时只激活 8B（读输入）/16B（生成）；解码器不自己记 KV 笔记，直接"复印"编码器的压缩版（Causal Encoder-Decoder，20+20 层）；KV cache 降到上一代的 1/4、初代的 1/437；原生多模态、MIT 开源、API 已降价，V4 Pro 9 月 14 日起下线并入它。 对你的意义：KV cache 压缩是 serving 成本的第一性原理——同样显存能塞 4 倍并发；CED 的"编码器只跑 prefill、解码器只跑 decode"跟 P/D 解耦是同一套分工哲学，可当参照系。精读笔记 → 深度阅读/DeepSeek-V4.1-Flash-KV压缩极限.html（含原文两张关键图：agent 基准对比、历代 KV cache 体积对比） 🔗 模型卡 https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash ｜ 中文报道 https://k.sina.cn/article_5953740931_162dee08306703y92q.html?from=tech
