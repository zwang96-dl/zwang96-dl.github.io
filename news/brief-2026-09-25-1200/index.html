新技术与论文

Crossflow：P/D 解耦的墙会"呼吸"了。「值得深读」 Meta 嫌 P/D 解耦的墙太死，干脆让它会"呼吸"了。 P/D 解耦就是 prefill 和 decode 拆到两拨 GPU 上跑。 它的死结：两边忙闲节奏根本对不上。 Meta 实测：输入输出 token 比例，分钟级峰值能到均值 4.7 倍。 agent 流量更狠，一天内这个比例中位数跨度 24.5 倍。 Crossflow 的招：decode 节点发"租约"，闲算力临时借给 prefill。 租约短命可撤销，decode 一忙立刻收回，不耽误正事。 关键洞察：光看 GPU 利用率不够，长短上下文能挤出的算力差 11–34%。 实测在 SGLang 上实现，GB300 跑 GPT-OSS-120B 和 GLM-5.2。 吞吐几何平均 +16.2–17.4%，高负载点最高 +43.4%。 首 token 时间每个点都降，GLM-5.2 最多降 57%。 划重点：这正是你 SGLang P/D 解耦评估缺的那块拼图。 SARA 是静态配卡算公式，它是运行时弹性借算力，一静一动。 深读笔记已生成，3 张原文图配中文图注。 来源：https://arxiv.org/abs/2609.27085

前缀缓存的驱逐策略：花里胡哨不如 LRU。 说白了：prefix caching（重复前缀的"草稿纸"留着复用）的驱逐算法，越 fancy 越没用。 论文扒了两家公司的生产 trace，测了 14 种驱逐算法。 结论：传统缓存的精巧策略，效果跟 LRU（最近最少用）差不多。 原因很结构：prefix 复用的节奏太规律了，"最近用过"就是最强信号。 但也有新坑：会话 footprint 长尾，miss 代价随序列变长。 作者给了 compute-savings ratio 指标和两个离线 oracle。 trace 和 simulator 会开源，做 prefix 缓存的可以直接拿去用。 来源：https://arxiv.org/abs/2609.28870

CoRePrune：多模态模型的视觉 token，该删谁要看"场合"。 说白了：图片 token 占了多模态模型的大头，剪掉能省算力。 但"重要"不等于"能删"，同一个 token 在不同层删、跟谁一起删，效果差很多。 只看重要性分数剪枝，迟早剪错。 CoRePrune 两步走：先按扰动感知逐步剪，再回炉看谁值得救。 全程免训练，5 个多模态模型（标图、高清、视频）上激进剪枝保性能。 划重点：VLM 的 prefill 瘦身就靠这类招，跟你的多模态推理优化直接相关。 来源：https://arxiv.org/abs/2609.26484

EMA：多卡显存也能"互相借钱"。 一台机器里 8 张卡，有的显存爆了、有的闲着，EMA 让它们互相借。 借方用 prefetch 藏起远程访问开销，用起来跟本地没差。 出借方可随时收回，性能不比静态切分差。 实测个人用户吞吐最高 +52%，达到 2 倍显存配置的 96%。 划重点：decode 阶段 KV 吃显存是大头，这种弹性池值得关注。 来源：https://arxiv.org/abs/2609.27040

Rift：卫星上跑 VLM，剪掉 78% 能耗答案反而更准。 卫星上想直接用视觉语言模型答题，但整图平铺推理又慢又费电。 论文发现：很多图片块删了不影响答案，叫"答案不变冗余"。 两步：先按问题剪掉无关图块，再弹性 prefill 压 token 预算。 在 Jetson AGX Orin 上跑 LLaVA-1.5 7B。 能耗降 78%、延迟降 69%，准确率 45% 涨到 73%。 边缘 VLM 的小众但漂亮的工作，顺手一提。 来源：https://arxiv.org/abs/2609.29029
