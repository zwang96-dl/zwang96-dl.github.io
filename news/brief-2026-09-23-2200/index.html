新技术与论文

1. 「值得深读」The KV Cache Working Set：给推理服务算清缓存留多大。 说白了：prefix caching（前缀缓存，复用之前算过的 KV）好不好使。 全看缓存留不留得住历史的 KV 状态。 划重点：这篇定义了"working set"，即达到目标命中率缓存最少要多大。 还给了在线容量规划方法，不用离线调参。 打个比方：跟饭馆备菜一个道理，备多了浪费、备少了现做来不及。 它帮你算出"刚好够"的备菜量。 跟你的方向很相关：你在评估 SGLang 的 P/D 解耦。 容量规划正是部署配卡的直接依据。 agentic 工作负载下，前缀缓存命中率直接决定 prefill 开销。 来源：arXiv:2609.27746 https://arxiv.org/abs/2609.27746

2. Risk-Controlled KV-Cache Eviction：驱逐策略不看平均分，看挂科率。 说白了：以前评 KV 缓存驱逐只看"平均掉多少分"。 但平均分会掩盖个别请求崩盘的事实。 划重点：这篇把驱逐变成部署风险控制问题。 超过容忍阈值的请求占比就是风险。 还给了压缩器无关的认证流程，保证风险达标。 打个比方：考试不看平均分，看"不及格率"。 保证挂科的人数压在合同线以下。 来源：arXiv:2609.27981 https://arxiv.org/abs/2609.27981

3. Tensor Decomposition of KV Caches：KV 缓存这个四维张量哪儿能压。 说白了：KV 缓存是个四维张量，维度是头、token、特征、层组。 这篇把四个轴逐个拆开，看低秩结构在哪。 划重点：token 轴和特征轴低秩好压缩。 头轴和层轴几乎满秩，压不动。 四个经典分解里，Tucker 的压缩误差最小。 打个比方：这份名单里谁能当替补、谁是铁主力，一次测清楚。 来源：arXiv:2609.28029 https://arxiv.org/abs/2609.28029

业内新闻

英特尔：Agent 时代 CPU 需求回暖，KV Shrink 开源了。 说白了：英特尔在技术创新大会上说，智能体任务一多。 CPU 侧的执行量也在跟着涨。 划重点：至强 6+ 有 288 个能效核，单颗最高撑 1000 多个智能体。 KV Cache 智能加速方案"KV Shrink"已经在 GitHub 开源。 KV Shrink 是把部分 KV 缓存从显存卸载到内存甚至远程服务器的方案。 打个比方：显存像办公桌放不下了，KV Shrink 把不常用的文件搬去隔壁仓库。 搬运用的是英特尔自家的数据加速器。 英特尔把未来数据中心分成三类：CPU 集群管智能体编排。 GPU 管模型推理，也就是"Token 工厂"。 存储集群管长对话、文档、合同这类不断变多的数据。 这条是今天早上第一财经的报道（9/23），之前几轮漏了，这轮补上。 来源：第一财经（新浪转载）https://finance.sina.cn/stock/jdts/2026-09-24/detail-inisvytr8393027.d.html
