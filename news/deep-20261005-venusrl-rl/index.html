VenusRL：把"解耦"做到极致的智能体 RL 系统——优先级调度 + KV 常驻

  • 原文：https://arxiv.org/abs/2610.03286v1
  • 作者：北航 + Infrawaves 等（Mingjun Zhang 等）
  • 笔记生成：2026-10-05（10点版简报「值得深读」）

一句话人话

智能体 RL 训练有两个隐形税：慢轨迹拖住全局，沙盒内存大量闲置。

VenusRL 用"全解耦 + 优先级调度"一次收走两个税。 端到端训练最高快 4.24 倍，环境成本最高降 89%。

解决什么问题

Agentic RL 是让 LLM 当智能体、跟工具环境多轮交互再拿反馈训练。 它有两个系统级瓶颈。

瓶颈一：训练吞吐被最慢的轨迹卡住。

只优化单卡利用率，会把各样本组的 rollout 进度打散。 打散了就凑不齐下一轮训练要的 batch。

好比全班交作业，老师非要等最慢的那个，交得快的只能干等。

瓶颈二：工具沙盒按申报内存上限静态超配。

实测单节点上沙盒内存平均只用了 8%，大部分物理内存被闲置。

沙盒还占了生产环境非 GPU 成本的 60% 以上。

推理 serving 里似曾相识：慢请求拖尾 + 显存被僵尸占着，思路可迁移。

核心方法

系统拆成两大件：优先级感知动作调度器 + 环境资源管理器。

第 1 件：Priority-aware Action Scheduler（优先级感知动作调度器）

先解决"谁先跑"的判断问题。

它训了一个轻量预测器。 在每轮边界，预测器估计每条样本还剩多长。 英文叫 remaining generation length。

预测快做完的样本组 = 高优先级：它的完工最可能解锁下一轮训练。

然后高优先级在三个地方插队：

  • GPU slot 执行：低优先级样本只在 GPU 有空位时才跑。
  • 高优先级一到，直接抢占低优先级的 slot。
  • KV Cache 常驻：淘汰时先踢没人用的 KV 页。
  • 正在跑的轨迹引用的前缀页，死保不踢。
  • 第三板斧是跨 worker 请求编排。

runtime 把样本在不同 rollout worker 之间搬家。 搬家的目的是抹平各 worker 的负载。

类比一下：像急诊分诊。

快出院的病人先办手续，床位、护士、检查排期全给他让路。

还有一个配套小件：Trajectory-Aware Radix Cache。 中文叫轨迹感知的基数缓存。

radix 树（按 token 前缀组织、可复用相同前缀 KV 的缓存）结构不变。

给缓存的 token 页多打一个"轨迹级"标签，淘汰时认得出哪页属于正在跑的轨迹。

第 2 件：Environment Resource Manager（环境资源管理器）

解决沙盒"占着茅坑"的问题，分三层下手。

集群层：全局控制器从共享环境池分配沙盒，RL 框架不用管部署细节。

节点层：按内存页粒度放沙盒 + 动态准入控制。

看实际用量放行，不看申报上限，密度拉满但不超配。

复用层：同 prompt 启动的沙盒，状态几乎一模一样。

用 template-keyed page-sharing pool 复用快照页。 中文叫按模板键组织的页面共享池。

隔离靠两招：写保护页表项别名、copy-on-write（写时复制）。 共享页只读，谁要写才复制一份给他。

类比：宿舍从"一人一间按申报住"改成"按实际行李排床位"。

行李都一样的直接拼床，动笔写字时才分开。

关键数据

  • 端到端训练吞吐：vs Slime 最高 3.26 倍。

vs RollFlash 最高 4.24 倍。 vs ThunderAgent 最高 2.67 倍。

  • 严格 on-policy（async_factor=1.0，陈旧度为零）下也有涨。

Qwen3-4B 最高 1.15 倍，Qwen3-32B 最高 1.85 倍。

  • batch 32/64 + 放宽陈旧度：Qwen3-4B 最高 1.71 倍。

Qwen3-32B 最高 4.24 倍。

  • 消融（Qwen3-32B，batch=32）：基线 1.00。

加优先级调度到 1.81，加 KV 常驻到 2.72，再加请求迁移到 2.89。

  • KV 常驻是最大单项贡献，说明"保住正在跑的前缀"这招最值钱。
  • 环境成本：最高降 89%。
  • 收敛性：三套系统 reward 曲线几乎重合。

VenusRL 的长尾丢弃率不高于基线。

跟你的研究方向的关联

"全解耦"思路跟 P/D 解耦同构。 rollout（生成）、环境交互、训练三权分立。 再往下做到 action 粒度调度。

优先级调度的三板斧可以直接抄进 SGLang P/D 评估。 三板斧是：准入、KV 常驻、跨 worker 搬家。

decode 池的 KV 淘汰是现成题目。 prefill/decode 之间的请求迁移也是。

它是 SGLang RadixAttention 的"轨迹感知"版。 它在淘汰时保护 in-flight 请求的前缀。

对 autotuner 来说有个好消息。 length-prediction 是现成的调度特征。

Table 1 的消融是"哪个旋钮最值钱"的实测答案。 KV 常驻大于请求迁移，请求迁移大于纯调度。

注意边界：这是 RL 训练（rollout）场景，不是纯在线 serving。

但调度器和 KV 管理的机制是通的，结论可以搬。

术语表

  • Agentic RL：让 LLM 当智能体，跟工具环境多轮交互、拿反馈训练。
  • Rollout：模型实际跑起来生成轨迹的过程，也就是采样阶段。
  • Trajectory：一条完整的多轮交互轨迹。
  • async_factor：允许样本过期（stale）的程度。
  • 1.0 等于严格 on-policy。
  • on-policy：训练用的样本必须来自当前版本权重的模型。
  • Radix cache：按 token 前缀树组织、可复用相同前缀 KV 的缓存。
  • Copy-on-write：共享页只读，谁要写才复制一份给他，省内存又保隔离。
  • Staleness：样本是几个版本之前的权重生成的，陈旧度。
