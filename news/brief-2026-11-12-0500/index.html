vLLM：8 条，KV 缓存淘汰那条最值得看

先说 #67098。

KV 缓存外存到 CPU 那层，淘汰策略修了。

KV 缓存就是草稿纸。

ARC 是自适应替换缓存。

以前 ARC 策略先扔正在跑的请求的前几块。

可查缓存要从第 0 块连续往后找。

前几块没了，后面的块就查不到了。

白占着地方，却一次也命中不了。

现在改成从尾巴开始扔。

复现里够不着的块从 252 个清到 0。

说白了，CPU 那层草稿纸不再白占地方了。

来源：https://github.com/vllm-project/vllm/pull/67098

再说 #65535。

多模态那条，修了个会崩引擎的 bug。

预先算好的图文向量，以前会走编码器那张加速图。

加速图就是提前排好的计算表。

结果直接把引擎崩了。

现在这类请求改走慢速的老实路。

像素输入照常走加速图，不受影响。

来源：https://github.com/vllm-project/vllm/pull/65535

其余六条一句话带过。

#58619、#67152，都是 KV 外存那条线的修补。

混合模型在解码并行下也能分段外存了。

#66608，多模态：视频帧数只传个数，不再多传。

#66773，Rust 前端：引擎彻底挂了就直接退出。

#66891，工具返回的图片能在渲染器里显示了。

#61872，ROCm 上 MoE 的权重补齐被之前改动弄丢了，现在补回来。

SGLang：13 条，混合模型缓存那条最值得看

先说 #49430。

混合模型的前缀缓存，淘汰规则升级了。

混合模型就是注意力和 Mamba 层混着用的模型。

Mamba 是不用注意力的循环结构。

缓存一个前缀，要同时留住 KV 和循环状态。

可循环状态的池子比 KV 池小得多。

GLM-5.3-Flash 的例子里，状态位只有 419 个。

KV 那边却能装将近 300 万个 token。

以前一次只扔一个状态，KV 还留着。

agent 跑完工具回来，常发现状态没了。

前缀还在，却接不上，只好重算。

现在按 GreedyDual-Size 策略成批淘汰。

GreedyDual-Size 就是按性价比挑着扔的算法。

状态和 KV 一起走，缓存才真正能续上。

跟 agent 的多轮会话直接相关。

来源：https://github.com/sgl-project/sglang/pull/49430

再说 #49669。

PD 解耦那条，修了个越界口子。

PD 就是读题和解码分开跑。

交接时有个长度上限，本来该卡住超长提示词。

可上限取的是整个池子的容量。

离容量只差一两页的提示词也能混进来。

进来后一算账就超了，直接报错。

现在按实际能接的上限卡。

来源：https://github.com/sgl-project/sglang/pull/49669

再说 #48996。

MI355X 上 KV 缓存默认改成 FP8 了。

FP8 是 8 位浮点，省显存。

MI355X 是 AMD 的新卡。

以前默认用 BF16，16 位浮点。

那条稀疏 MLA 快路只认 FP8。

现在不用手动加参数了。

来源：https://github.com/sgl-project/sglang/pull/48996

#48412，流水线并行下，MoE 的专家路由记录能跨阶段接力了。

流水线并行就是把模型切成几段分卡跑。

#48031，昇腾 NPU 上，MLA 和 DeepSeek V4 的缓存传输打通了。

#41501、#49354、#49456、#49808、#49714。

TRT-LLM：3 条，Qwen3.8 那条最值得看

先说 #21346。

Qwen3.8-Flash-Next 的 FP8 模型，热身就崩。

热身就是正式跑之前先试跑一遍。

原因是 FP8 的查表还没反量化就先清零。

PyTorch 没有 FP8 的清零核，直接报错。

现在改成按字节清零，热身能过了。

来源：https://github.com/NVIDIA/TensorRT-LLM/pull/21346

LMDeploy：1 条

#5115，GLM-5.3 Flash 的 KPool 能选 BF16 了。

KPool 就是存键向量的池子。

现在加了个环境变量开关，能切到 BF16 不旋转。

对齐训练那边的索引器用的。

来源：https://github.com/InternLM/lmdeploy/pull/5115

业内新闻

单张 5090 跑 256K 上下文，实测跑通了

Groot-19B-A3B 这个模型，FP8 版 20.9GB。

一台 RTX 5090 上，用 vLLM 0.32.0 跑起来了。

262,144 个 token 的上下文全开。

20 万 token 的提示词也答对了。

账是这么算的：权重占 19.7GB。

剩 6.8GB 给 KV 缓存，能装 30.7 万个 token。

刚好够一整窗，再多 4.5 万个 token 的富余。

说白了，消费级单卡跑超长上下文，内存账能算得过来。

但有个坑：这模型每答必先想一通。

300 字的小作文，思考占了 2000 到 7000 个 token。

上限设紧了，答案还没出来就被截断。

来源：https://dev.to/inferencekey/serving-groot-19b-a3b-at-256k-on-one-rtx-5090-the-memory-budget-and-the-thinking-trap-4b2
