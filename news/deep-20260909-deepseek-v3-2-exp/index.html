DeepSeek-V3.2-Exp：稀疏注意力把长上下文推理成本砍掉 6–7 倍

新闻：DeepSeek-V3.2-Exp 发布（MIT 协议开源）
来源：The Batch（deeplearning.ai，2026-09）
原文：https://info.deeplearning.ai/deepseek-cuts-inference-costs-openai-tightens-ties-with-amd-thinking-machines-simplifies-fine-tuning-robots-improve-spatial-awareness
权重：https://huggingface.co（搜 DeepSeek-V3.2-Exp）

一句话人话版

DeepSeek 开源了新版本。核心是"闪电索引器"做动态稀疏注意力。推理时，每个 token 做 attention，只看 2048 个最高分。不再逐字全看。相当于给模型装了副"只看重点"的速读眼镜。128k 上下文的推理成本大降。从 $2.30 降到 $0.30/百万 token。

关键规格

  • 架构：MoE Transformer。总参数 685B，每 token 激活约 37B。
  • 输入最长 128k tokens，输出最长 8k
  • 协议：MIT（商用友好）
  • API 定价：输入 $0.28。缓存命中 $0.028。输出 $0.42（每百万 token）。

它是怎么做到的：闪电索引器（Lightning Indexer）

三步走：

  1. 学一个"注意力预测器"。拿 21 亿 token 的文本，训练一个加权相似度函数。学的是"稠密注意力机制会重点关注哪些 token"。这个预测器本身很轻，简单操作加 FP8 精度，打分飞快。
  2. 微调适配。在约 1000 亿 token 上微调全部参数。让模型适应"只看被选中的 token"这种稀疏模式。还蒸馏了 5 个 specialist 模型。推理、数学、代码、agentic coding、agentic search。都是 V3.2-Exp。再用 GRPO 把推理加对齐训练合并成单阶段，避免多阶段 RL 的灾难性遗忘。
  3. 推理时动态筛选。对每个新 token，索引器给所有历史 token 打相关性分。只取 top-2048 做 attention 计算。输入越长，省得越多。推理速度随输入长度线性扩展，不再平方级爆炸。

效果数据

场景V3.1-TerminusV3.2-Exp变化
32k 上下文成本~$0.60/百万 token~$0.10降 6×
128k 上下文成本~$2.30/百万 token~$0.30降 ~7.7×
7k+ token 输入处理速度基准—快 2–3×

精度代价（基本可以接受）：

  • Codeforces：2121 Elo（vs 2046，反而涨了）
  • BrowseComp agentic 任务：40.1%（vs 38.5%，涨）
  • AIME 2025 数学：89.3%（vs 88.4%，涨）
  • GPQA-Diamond：79.9%（vs 80.7，微降）；HLE：19.8%（vs 21.7，微降）

结论：效率暴涨，精度基本持平、部分任务还涨了。稀疏注意力这条路，走通了。

跟你研究方向的关联

  • 现成的实验靶。SGLang 已 Day-0 支持 V3.2-Exp。你研究多模态长上下文推理成本时，可以直接拿它做实验。不用自己训稀疏注意力模型。
  • 技术路线的验证。动态稀疏注意力，每个 token 动态选 top-k。静态稀疏，固定 pattern 不变。DeepSeek 用产品级结果证明了动态路线的价值。这跟你简报里看到的 RouteRelay、CEDAR 是同一波技术浪潮。可以对照着读。
  • 国产芯片适配。代码支持华为等国产 AI 芯片。这是多硬件推理生态的又一个信号。
  • 成本参照系。以后评估任何"长上下文优化"技术，都有了参照线。"$0.30/百万 token @128k"就是 baseline。

术语表

  • 稀疏注意力（sparse attention）。不让每个 token 看所有历史 token，只看其中最相关的子集。把 attention 的平方复杂度降下来。
  • MoE（mixture of experts）。混合专家架构。每层有很多"专家"子网络，每个 token 只激活其中几个。
  • GRPO。一种强化学习算法。英文全称 Group Relative Policy Optimization。DeepSeek 系常用的 RL 方法。
  • 灾难性遗忘（catastrophic forgetting）。多阶段训练里，新学的东西把旧能力覆盖掉的问题。
  • FP8。8 位浮点数。精度比 FP16 低，但算得快、省显存，推理常用。
  • Day-0 支持。模型发布当天推理框架就支持。说明框架生态响应快。
