SGLang：7 条，PD 心跳修补是头条

#51790 是 PD 的修补。

PD 就是读题和生成分机器跑。

解码机每 3 秒给读题机发一次心跳。

心跳就是报个平安，确认还活着。

Rust 服务模式下，心跳走了健康检查接口。

这个接口默认会跑一次生成探测。

读题机只读题，不生成。

探测一跑，心跳就超时。

两次超时，解码机就把读题机踢掉。

现在心跳直接回 200，不跑探测了。

你的 PD 评估里记一笔。

读题机被误踢，请求会全失败。

#48208 是投机解码的提速。

投机解码就是小模型先打草稿。

以前每行 top-k 概率各拷一次。

现在同一 k 的请求批量拷。

批量越大，省的主机开销越多。

#51718 和 #51615 都是 Gemma4 的修补。

视觉池化跳过时，有效图块别丢了。

填充部分要排除在外。

其余是缓存初始化和启动修补。

来源：https://github.com/sgl-project/sglang/pull/51790

vLLM：12 条，HY4 检查点注册是头条

#68210 是快速启动的新后端。

权重预热后用 VMM 共享。

VMM 就是 CUDA 的虚拟内存管理。

多进程之间零拷贝传权重。

启动更快，占的内存也更少。

#68479 是多模态的卸载。

视觉塔能挪到 CPU 上跑。

CPU 卸载就是显存不够时借内存。

大图模型在小卡上也能跑了。

#68672 是 Rust 前端的修补。

多模态缓存不再走引擎的 LRU。

LRU 就是最近最少用的淘汰策略。

其余是两条安全修补。

#52605 管视频解码池的显存峰值。

腾讯 Hy4 权重开源了：770B 旗舰能下载了

Hy4 是腾讯的多模态旗舰模型。

770B 总参数，每 token 只激活 49B。

上下文 1M token，图文视频都能读。

三份权重都放出来了。

Hy4 是指令版，Hy4-FP8 是 8 位版。

Hy4 base 是没微调的预训练版。

FP8 版约 770GB，BF16 版约 1.55TB。

许可证换了，不是 Apache 2.0。

现在是腾讯自己的 Hy License。

大模型即服务年入超 5000 万美元。

或者月活超 1 亿，要另外拿许可。

小团队自己部署不受影响。

vLLM 和 SGLang 都有官方镜像。

配方是 8 卡张量并行加 DFly2。

DFly2 是 Hy4 自带的投机解码草稿器。

草稿和主模型共用 KV 缓存。

长上下文生成不额外占显存。

今天上午 8 点到 10 点有 AMA。

腾讯 Hy 团队在 Reddit 上答问。

来源：https://news.sulat.com/2026/11/20/tencent-hy4-open-weights/
