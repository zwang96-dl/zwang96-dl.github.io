vLLM 批量不变 MoE 调优：确定性模式的代价砍了一半

  • 原文：vLLM 团队，GitHub PR #63627（2026-11-11 合入）
  • 原文链接：https://github.com/vllm-project/vllm/pull/63627
  • 作者：yifanFengg，标签 batch-invariance
  • 说明：这篇是工程 PR，不是论文；数字全是作者自报
  • 说明：原 PR 未附图，关键数字见下表

一句话

确定性模式一直有个慢速档。

开它之后，MoE 只能用一套固定配置。

现在按架构查调优表，解码直接快了一倍。

代价是：配置不能按 batch 大小分档。

分档看着更快，但会破坏确定性。

人话解读

先讲确定性模式是什么。

它就是批量不变模式。

开关是 VLLM_BATCH_INVARIANT=1。

开它之后，同样输入不管 batch 多大。

输出逐位相同，一个字都不差。

这对评估很重要。

你要比两次跑分，先得保证输出不变。

不然分不清是模型变了，还是 batch 变了。

以前这模式有个短板。

MoE 内核只用一套固定配置。

配置就是分块大小那几个数。

64x64x32，加 GROUP_SIZE_M 8，加 SPLIT_K 1。

不管什么模型，什么 batch，全用这一套。

固定配置求稳，但不求快。

这篇就是给它配了一张调优表。

按架构查表，一种模型形状配一套参数。

形状就是专家那几块权重的尺寸。

表是作者在 GB300 上扫出来的。

扫的模型有三个 FP8 的。

Qwen3-235B、DeepSeek-V3.1、GLM-5.3。

还有一个 BF16 的，Qwen3-30B。

不在表里的形状，还是用老固定配置。

核心方法

1. 一张小表：一种形状一套配置

改动集中在两个文件。

batch_invariant_configs.py 里加了一张表。

键是架构族、精度、块形状、专家数。

值就是那套调优好的配置。

fused_moe.py 里改了默认配置的查找。

开了确定性模式，就先查表。

查到就用表里的，查不到就用老固定配置。

表很小，只覆盖调过的几个形状。

没有改非确定性那条路。

2. 扫表的方法：扫一遍，挑最快的

每个形状都扫一遍候选配置。

分块 M 取 16、32、64、128。

分块 N 取 64、128、256。

num_warps 取 4 或 8。

num_stages 取 2、3、4。

分块 K 取 32、64、128。

GROUP_SIZE_M 固定 8，SPLIT_K 固定 1。

在 batch 大小 1 到 4096 之间跑。

用 CUDA Graph 计时，每个点取 20 次中位数。

先筛掉输出不对的。

候选输出跟固定配置差超过 3% 的不要。

剩下的里挑总时间最短的。

3. 关键发现：分档换配置会破坏确定性

第一版表是按 batch 大小分档的。

batch 小用一套，batch 大换一套。

像密集矩阵那张表一样。

内核级检查看着没问题。

8 行探测数据，随机 batch 从 1 到 16384。

每档 5 个上下文，FP8 块量化。

跨档边界，每行结果逐位相同。

但模型级针尖测试挂了。

针尖测试就是拿固定输出验确定性。

分档加固定 K=128，5 次全挂。

分档加 K=32，5 次挂 1 次。

固定分块加 K=128，通过。

一种形状一套配置，通过。

结论很直接。

在 Blackwell 上，Triton 融合 MoE 的逐行结果。

跟分块配置有关，哪怕 K 方向的归约固定。

真实激活值下，分档就是不安全。

扫出来的数据也说明分档确实更快。

Qwen3-235B 那个形状，batch 32 时。

固定配置 381 微秒，单套调优 211 微秒。

分档只要 132 微秒。

但快不能要，确定性丢了就没意义。

4. 验证：精度和确定性都没丢

gsm8k 上跑了一遍。

Qwen3-235B，5-shot，确定性模式。

原来 0.8802，新表 0.8772。

误差棒都是 0.009 左右，基本没变。

确定性测试套件 6/6 通过。

DeepSeek-V3.1 那组是 2/3 通过。

但主分支也是 2/3，挂的是同一个 case。

那是旧问题，不是这篇引入的。

跟研究方向的关联

这篇直接撞上你的确定性评估。

三招能直接进评估清单。

第一招：确定性模式的代价要单列。

以前开批量不变，MoE 只能用固定配置。

现在有调优表，DeepSeek 解码翻倍。

评估里要分两档报。

固定配置那档，和调优表那档。

别把旧数字当成现在的代价。

第二招：分档调优是个坑。

按 batch 大小分档，看着能再快四成。

但针尖测试 5 次全挂。

内核级检查说没问题，模型级照样挂。

评估清单里要加一问。

调优表是不是一种形状一套配置。

分档的方案，确定性测试必须重跑。

第三招：差距还在，别报过头。

不开确定性模式，同样 4 张卡。

Qwen3-235B 是 7351，新表是 3587。

DeepSeek-V3.1 是 3807，新表是 2480。

确定性模式还是慢一半左右。

报收益时，两档数字都要给。

只给涨幅，会让人以为追平了。

还有一个方向值得跟。

这张表只调了 GB300 上的几个形状。

H100、MI350X 上还没有。

你的评估卡是 H100 和 MI350X。

这张表在你那边的收益，要实测才知道。

术语表

  • 批量不变：同样输入不管 batch 多大，输出逐位相同
  • 确定性模式：批量不变模式的开关，VLLM_BATCH_INVARIANT=1
  • MoE：专家混合模型，每层有多个专家，只激活几个
  • 融合 MoE 内核：把 MoE 的计算并成一个内核跑
  • 分块配置：BLOCK 大小、num_warps、num_stages 这几个数
  • GROUP_SIZE_M：分组大小，MoE 里按组算的一个参数
  • SPLIT_K：K 方向切几份并行归约
  • 针尖测试：拿固定输出验确定性，batch 一变就验
  • 逐位相同：每个数字的每一位都一样，不是约等于
  • CUDA Graph：把一串操作录下来反复放
  • FP8：8 位浮点数，省显存
  • BF16：16 位浮点数
  • TP=4：张量并行，模型切 4 张卡
  • gsm8k：小学数学题测试集，常用精度基准
  • GB300：英伟达 Blackwell 架构的服务器 GPU
  • SM 10.3：GB300 的算力架构版本
  • 读题：prefill，把输入一次性算完
  • 解码：decode，一个词一个词往外吐

注意事项

  • 数字全是作者自报，没有第三方复现
  • 表只调了 GB300 上的 4 个形状
  • Qwen3-30B 那组只涨 5.8%，MoE 占比小
  • 分档方案内核级检查通过，模型级照样挂

  • 对照组用的是 FlashInfer 路径，不是 Triton
  • 读题那组是 4096 词进 1 词出，解码很短
