框架更新

vLLM #46370：MoE 部署加了断臂求生 容错框架以前只会 retry，默认所有 DP rank 都活着。 DP 是数据并行，把请求分摊到多卡跑。 EP 是专家并行，把 MoE 专家分摊到多卡跑。 现在某张卡彻底挂了，可以下发 scale-down 指令。 死的 rank 直接摘掉，专家重新排布，服务不整站停摆。 生产部署 MoE 的人，这个开关值得记住。 来源：https://github.com/vllm-project/vllm/pull/46370

vLLM #63886：DSpark 采样不再重复算 DSpark 是 DeepSeek 自家的投机解码方案。 以前每个 rank 把全 batch 的草稿 logits 都算一遍。 算完只保留自己负责的那几份，剩下的全扔掉。 现在每个 rank 只跑自己那份请求的打草稿循环。 换句话说：以前每人抄全班作业再扔别人的。 现在只做自己那份，省的全是白算的算力。 来源：https://github.com/vllm-project/vllm/pull/63886

vLLM #63205：推测解码可以插自己的插件了 Model Runner V2 现在支持自定义 speculator。 speculator 是推测解码里负责打草稿的小模块。 以前想换打草稿的算法，得改 vLLM 核心代码。 现在注册一个配置类，写上名字就能选上。 想自己折腾推测解码算法的人，这扇门开了。 来源：https://github.com/vllm-project/vllm/pull/63205

TRT-LLM #19646：专家排班多了逐层动态档 EPLB 是专家并行负载均衡，给 MoE 专家排班的。 以前只有 offline 和 online 两种模式。 现在加了第三种：per-layer dynamic，逐层动态调。 用一行配置就能开启。 你在评估 EPLB，这个新档可以放进对比清单。 来源：https://github.com/NVIDIA/TensorRT-LLM/pull/19646

TRT-LLM #21042：第一时间接入 Muse Spark Muse Spark 是 Meta 新开的开放模型。 TRT-LLM 把解码器、视觉塔、音频编码器一次接全。 多模态输入处理和 checkpoint 加载也都备好了。 新模型支持信号：生态跟进速度很快。 来源：https://github.com/NVIDIA/TensorRT-LLM/pull/21042

TRT-LLM #21104：适配 V4.1 的工具调用 V4.1 的 checkpoint 自带 encoder。 它用命名空间来定义工具。 TRT-LLM 现在按 checkpoint 自带的格式展开工具名。 不再硬套自己的扁平化规则。 来源：https://github.com/NVIDIA/TensorRT-LLM/pull/21104

SGLang 五笔：两个生产排障值得看

#47319 修了多节点 DP 下的负载查询接口。

以前每个节点都返回 503，路由以为全网都没负载。 路由和自动扩缩容全看错了表，现在修了。

#46937 修了 Anthropic 兼容接口的缓存污染。

cache_salt 在校验时被默默丢掉，不同请求串了缓存。 现在 salt 原样透传，隔离回来了。 其余三笔：#47106 是 logprob 输出的性能小修。

#47113 修 metrics 竞态，#46277 是视频生成解码六小修。

来源：https://github.com/sgl-project/sglang/pull/47319 来源：https://github.com/sgl-project/sglang/pull/46937

FlashInfer 两笔性能核

#8023：SM107 上 MXFP8 的 SwiGLU 融合 kernel 优化。

SwiGLU 是大模型里常用的激活函数结构。 小单量走专用小灶，不用开大锅。

#8018：B200 上小矩阵乘新增 4 个路由窗口。

属于 B200 kernel 持续打磨系列。 来源：https://github.com/flashinfer-ai/flashinfer/pull/8023

llama.cpp #31341：OpenCL 初步支持 IQ1 IQ1 是 1.x bit 的超低比特量化。 手机、核显、NPU 这类弱算力设备跑大模型更省了。 来源：https://github.com/ggml-org/llama.cpp/pull/31341
