访谈与深度

补漏：LinkedIn 实战复盘《单 H200 上把 vLLM 优化到基线 3.69 倍》，拿 KV cache 当第一性原理（约 9/14 发布）

  • 一句话：有人在一块 H200 上跑 vLLM 做 agent 长上下文，把效率分刷到基线的 3.69 倍。
  • 这活儿不是 prefill 瓶颈，也不是 decode 瓶颈，是 KV cache 容量瓶颈。
  • KV cache（推理时的"草稿纸"，存着算好的注意力状态）。
  • 负载长这样：prompt 平均 11 万 token，最长近 100 万，输出却很短。
  • agent 每轮都把差不多的上下文重发一遍，86–89% 的 prompt 能命中前缀缓存。
  • 前缀缓存（prefix cache，之前算过的 prompt 片段直接复用）。
  • 所以真正的问题变成：谁占了 KV cache，谁就赢了。
  • 划重点 1：投机预填充（speculative prefill）立了大功。
  • 拿 0.5B 小模型给长 prompt 打分，只留 20% 关键内容进引擎。
  • prompt 从 11 万 token 剪到 4.2 万，单这一招涨了 23.32 分。
  • 关键细节：剪完的文本按内容 hash 冻结。多轮里同一条消息字节级一致，才能命中前缀缓存。
  • 划重点 2：投机解码（speculative decoding）单独用反而是负收益。
  • 投机解码（先让小模型打草稿、再让大模型批改的加速法）。
  • draft 模型权重占了显存，KV cache 容量掉了 28.7%。
  • 前缀命中率从 82.8% 跌到 43.3%，首 token 延迟直接崩。
  • 先剪枝再上投机解码，同一招反而值 +23.76 分。
  • 划重点 3：FP8 内核有个"静默丢精度"的坑。
  • vLLM 的 FlashAttention-3 分支有个"两级累积"开关。
  • 关掉它在这套配置上快 2.5 倍，但 26 万上下文下会静默丢掉 90% 的注意力结果。
  • GPQA 这种短题基准根本测不出来，得用对抗输入才抓得到。
  • 他们的折中：定期把累积值刷到全局内存。误差从 -90.6% 降到 -3.4%，只花 11.6% 的速度。
  • 一句话原则：长上下文+高前缀复用场景下，别看优化省了多少算力，看它挤占了多少 KV cache。
  • 跟你直接相关：你正在评估 SGLang 的 P/D 解耦。P/D 解耦（prefill 和 decode 拆到不同 GPU 跑）的核心代价就是 KV 搬运，这篇跟你的评估是同一套语言。
