投机解码实战：给 70B 模型配个"小跟班"，推理成本降 38%

原文：Speculative Decoding: Cutting LLM Inference Costs by 40% with Early Token Prediction（Nivora Technology 博客，2026-09-10）
⚠️ 阅读前说明：这是家 IT 咨询公司的博客。所有数据都是"自报"的（一个月 A/B 测试）。文末带着销售话术（"让我们帮你落地"）。数字和方法可以借鉴。但别当成同行评审过的结论。

人话解读

大模型生成文字是"一个字一个字往外蹦"。每蹦一个字都要把 70B 参数全跑一遍。贵就贵在这儿。投机解码的思路是这样的。雇一个便宜的"小跟班"（2B 的小模型）。先一口气猜出后面几个字。然后让 70B 大模型一次性验算。猜对了就直接采用。相当于大模型一次前向"批改"了好几个 token 的作业。猜错了才回头重算。

为什么这招灵？因为语言里"废话"的比例很高。"今天天气很…"后面跟"好"的概率极大。小模型足够猜中。原文的比喻是统计冗余（statistical redundancy）。确定性强的 prompt 里，下一个 token 的概率分布非常尖。小模型用很少的算力就能抓住。

核心方法

部署架构（原文 ASCII 图，原样转录）：

`` ┌─────────────────────┐ ┌─────────────────────┐ │ Draft model (2B) │──▶│ Token buffer (k) │ ← 小模型先猜 k 个 token，攒进缓冲 └─────────────────────┘ └─────────────────────┘ │ │ ▼ ▼ ┌─────────────────────┐ ┌─────────────────────┐ │ Verifier (70B) │ │ Acceptance logic │ ← 大模型一次验证 + 接受/拒绝判定 └─────────────────────┘ └─────────────────────┘ │ │ └──────▶ Output stream ◀────┘ ``

关键工程细节（可直接抄）：

  • 置信度阈值（confidence threshold）。draft 猜的 token。只有大模型给出的概率超过阈值才采纳。经验值：高质量/严谨领域设 0.95。创意写作可放宽到 0.80。
  • Batch 对齐。draft 的 batch 大小。对齐 verifier 的最大 token 窗口。通常 128。避免流水线气泡。
  • Fallback 路径。verifier 拒绝某个 draft token 时。从该位置重新计算并同步 buffer。猜错的代价是一次重算，不是全盘重来。
  • 防"草稿过期"。draft 模型要定期重训。用和 verifier 相同的数据分布。否则接受率会明显下滑（model drift）。

代价与坑（原文自己列的，值得记）：

  1. 显存翻倍：两个模型常驻。<80GB 显存的卡可能要做模型并行切分。
  2. 高并发下可能反效果：draft 会挤占并发序列的显存和调度。高并发时开投机解码反而可能丢吞吐。Runpod 的实战指南给了熔断思路。SPECULATIVE_DISABLE_BY_BATCH_SIZE。batch 一大就自动关掉。
  3. 扩缩容复杂度：draft-verifier 之间有个同步点。流量尖峰时可能成为瓶颈。

跟你的研究方向的关联

  • 投机解码 × P/D 解耦是天然搭档。draft 和 verify 都发生在 decode 侧。评估 SGLang P/D 解耦时。decode 池可以单独开投机解码。SGLang 支持 EAGLE 系列。vLLM 用环境变量开。SPECULATIVE_MODEL。NUM_SPECULATIVE_TOKENS。prefill 池不受影响。这正是"解耦"的好处：优化可以按阶段独立上。
  • 接受率是核心观测指标。上线后第一件事。看 acceptance rate 监控大盘。阈值 0.95/0.80 的经验值可作起点。但一定要按自己的业务 prompt 分布重调。
  • 先做"免草稿"验证：Runpod 指南建议先用 n-gram 猜测快速验证。不用训练 draft 模型。看业务流量适不适合投机解码。接受率可观再训专用 draft 模型。低成本试错路径。

术语表

  • 投机解码 speculative decoding。小模型先猜。大模型一次验证的加速技术。猜对的部分省掉大模型的前向计算。
  • Draft model 草稿模型：轻量小模型（本文 2B）。负责快速预测接下来 k 个 token。
  • Verifier 验证器：目标大模型（本文 70B）。一次性验证 draft 的 k 个 token。接受或纠正。
  • Acceptance rate 接受率。draft 猜的 token。被 verifier 采纳的比例。越高加速比越大。
  • Confidence threshold 置信度阈值。采纳 draft token 的概率门槛。越高越保守（质量稳、加速少）。
  • Model drift 模型漂移。draft 与 verifier 数据分布脱节。导致接受率下降。需定期重训 draft。
