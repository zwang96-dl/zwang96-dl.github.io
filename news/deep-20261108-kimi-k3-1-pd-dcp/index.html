Kimi K3.1 的 PD 解耦：DCP 下终于能跑了

原文：SGLang #48741《[Feat] kimi-k3.1: PD disaggregation under decode context parallelism》，另参考 SGLang 官方博客《Kimi K3.1 Pro: Day-0 Inference and RL Support with SGLang and Miles》
原文链接：https://github.com/sgl-project/sglang/pull/48741
合入：2026-11-08，15点版深读

一句话人话版

Kimi K3.1 想把读题和吐字分开跑。 之前一开 DCP 就报错。 这回把口子打开了。 新架构的 PD 从来不是免费送的。

先说问题：稀疏注意力多了一份行李

Kimi K3.1 的 24 层全历史注意力换成了 DSA。 DSA 就是带索引器的稀疏注意力。 每层有个小索引器给历史 token 打分。 注意力只读分数最高的 2048 个。 长上下文的注意力算力省下来了。 但多了一份索引缓存要搬。 这份缓存叫 index-K。 它是每个 token 的键和缩放系数。 DCP 一开，KV 缓存按 token 分片。 token p 存在 p 除以 8 余数的卡上。 index-K 也得跟着自己的 token 走。 之前 PD 只会搬 MLA 的 KV。 index-K 没人搬，DCP 下 PD 直接拒绝启动。 说白了：新注意力多了一份行李。 搬运工没认这份行李，车就不发。

*图1：Kimi K3.1 的架构。69 层 KDA 是线性注意力，状态固定大小。24 层 DSA 是稀疏注意力。索引器每层挑出分数最高的 2048 个历史 token 再算注意力。*

*图2：DCP 下的 DSA。KV 缓存和索引缓存都按 token 分片。每张卡先挑本地最好的 2048 个。再用一次 NVLink 组播交换前 384 名。合并结果跟单卡挑出来的完全一样。*

核心方法：index-K 跟着 KV 行走

PR #48741 的做法分四步。 一是 prefill 发 KV 的时候。 把每个 token 的 index-K 键和缩放系数一起发。 发到 decode 那边归属卡的页布局里。 二是页面级的状态发送跳过 index-K。 因为重排那一步已经把它搬过去了。 不重复搬。 三是同 DCP 的 prefill。 decode 那边按页给 index-K 分页。 四是草稿 KV 跟着目标走。 DFLASH 的草稿池也按 DCP 分片。 注册的时候就声明自己是分片的。 重排就按目标的行映射发草稿。 不按原始的宽行发。 同时之前加的限制解开了。 PD 在 Mooncake 上不再拒绝 DCP。 注意：传输后端只认 Mooncake。 别的后端在 DCP 下两边都不认。

#49105 顺手补了另一块。

HiCache 加 DFLASH 也能在 DCP 下跑了。 HiCache 是 SGLang 的主机内存 KV 缓存。 之前 DCP 一开，这俩组合就起不来。

关键数据

以下数字来自 SGLang 官方博客。 测试环境是 GB300 NVL72。 三档部署按并发分。 1 到 4 会话：聚合跑，TP8 或 TP16。 24 到 56 会话：1P2D，24 张卡。 160 到 300 会话：2P1D 或 3P1D，32 或 40 张卡。 每卡吞吐从 1563 涨到 33688 token/s。 每人速度从 449.0 降到 69.8 token/s。 DFlash2 接受长度 3.764。 这是 24 到 56 会话那档。 160 到 300 会话那档是 3.508。 MI350X 单节点 8 卡就能跑。 两节点走 Mooncake 跑 1P1D。 解耦的每卡吞吐最高。 聚合的每人速度最快。

*图3：AgentX 在 GB300 NVL72 上的实测。横轴是每人速度，纵轴是每卡吞吐。每个点是一种部署。解耦部署的每卡吞吐最高，聚合部署的每人速度最快。*

跟你的研究方向的关联

你的 PD 评估要测的就是这类组合。 新注意力一换，PD 的搬运清单就得重对。 这篇给了现成的检查项。 index-K 这类"第二份缓存"有没有跟着走。 草稿 KV 的行映射跟不跟目标。 传输后端在分片下认不认。 MI350X 两节点 1P1D 是你的卡能直接抄的配置。 注意边界：数字是官方自报。 AgentX 的跑分口径，不是你的流量。 DCP 下 PD 刚合入主线。 Kimi 的正式支持还在 dev 分支镜像里。 生产用之前先在小规模上跑精度门。

术语表

  • PD 解耦（prefill/decode disaggregation）：读题和吐字分到两拨卡上，各干各的。
  • DCP（decode context parallelism）：decode 的上下文并行，KV 缓存按 token 分片。
  • DSA（DeepSeek Sparse Attention）：带索引器的稀疏注意力，只读分数最高的 token。
  • index-K：DSA 索引器的键缓存，每个 token 一份。
  • KDA（Kimi Delta Attention）：Kimi 的线性注意力层，状态固定大小。
  • HiCache：SGLang 的主机内存 KV 缓存。
  • DFLASH：Kimi 的投机解码草稿器。
  • Mooncake：PD 传输后端，KV 缓存跨节点搬运。
  • MegaMoE：SGLang 的大专家并行。
