vLLM：13 条，跨引擎共享是头条

#67539 是 DeepSeek V4.1 的新功能。

Engram 表可以跨引擎共享了。

Engram 是 V4.1 记长期记忆的表。

以前每个引擎各存一份。

现在拆成行，分散存在各卡上。

走 NVLink 或 RDMA 去取。

RDMA 就是跨机器的高速直连。

不用专门的宿主进程，也不用额外依赖。

#61620 是量化的新功能。

NVFP4 的权重能在线转成 MXFP4。

MXFP4 是更新的 4 位浮点格式。

不用重新导模型，直接加载就能用。

#64289 是 MoE 的提速。

SM90 的 MXFP4 MegaMoE 走了 FlashInfer。

MegaMoE 是个很快的专家并行核。

#68844 加了 HY4 的配方。

HY4 是腾讯 770B 的大模型。

配方就是官方给的部署做法。

#68041 是 RL 训练的改动。

权重更新后默认直接重载。

不用再重启服务。

其余是修补和 CI。

#68270 修了 Qwen3-VL 的视频位置。

#62589、#60153 是 AMD 卡的提速。

#68176 是快速启动支持 INT8 权重。

来源：https://github.com/vllm-project/vllm/pull/67539

SGLang：9 条，CPU 量化是头条

#51459 是 CPU 上的量化。

每 token 的 FP8 量化上了 AVX10.2。

AVX10.2 是新一代 CPU 的向量指令。

纯 CPU 跑推理也能用 8 位了。

#51363 是采样的提速。

注意力并行时，top-p 归一化不用走慢路。

top-p 就是只留概率够高的词。

#51691 是文档。

Hy4 的 cookbook 加进来了。

#50140 是 profiler 的小功能。

前向步骤能打上 NVTX 标记。

NVTX 是英伟达的性能分析标记。

#48227 是模型加载的保护。

多线程加载时，在途字节数有了上限。

其余是测试、修补和 NPU 重构。

来源：https://github.com/sgl-project/sglang/pull/51459

TRT-LLM：5 条，V4.1 解码提速是头条

#22465 是 DeepSeek V4.1 的提速。

CSA2 注意力在解码时预取候选块。

CSA2 是稀疏注意力的一种。

候选块提前放进 L2 缓存。

L2 就是 GPU 上 fast 的二级缓存。

解码时不用现去内存里翻。

这是 19 点版那套 V4.1 提速包的延续。

其余是修补和重构。

#19949 修了 BF16 的 MoE 权重。

#22340 修了 MXFP4 的描述符对齐。

来源：https://github.com/NVIDIA/TensorRT-LLM/pull/22465

FlashInfer：7 条，GDN 读题核是头条

#9704 是 GDN 的新核。

Cake CP 读题后端可以选了。

GDN 是一种带门控的递推层。

CP 就是把长上下文切开分卡算。

小批量加长序列，最快 4.25 倍。

批量一大就反而不如老核。

所以还加了 auto 模式自动挑。

#8497 是 MoE 的提速。

MXFP4 乘 MXFP8 的矩阵乘更快了。

#9463 是注意力的扩展。

Blackwell 的分页自动模式支持 FP16。

Blackwell 是英伟达 B200 那代架构。

其余是构建和修补。

来源：https://github.com/flashinfer-ai/flashinfer/pull/9704

Dynamo、Mooncake：各 1 条小修补

Dynamo #17558 是观测修补。

P/D 拆分仪表盘上，主机名显示对了。

Mooncake #5538 是构建修补。

NPU 的轮子包关掉了随机堆基址。

来源：GitHub pulls

新技术与论文

arXiv：11 月 20 日那批进来了，6 篇相关

FrontierReplay：混合模型的前缀缓存不用切读题了

混合模型的前缀缓存一直很难做。

递推层的状态不能随便截断。

想在中间存检查点，就得切断读题。

这篇不切了，读题一口气跑完。

事后只重放递推层，补出检查点。

每 token 比重算便宜 6–37 倍。

好吞吐比 vLLM 高 1.11–4.26 倍。

首字中位数降 16–89%。

近似方法长上下文掉 13–17% 准确率。

它一分不掉。

细节见文末深读。

来源：https://arxiv.org/abs/2611.26020

Aggron：智能体等排队时，顺手把 KV 压了

智能体会话越跑越长，KV 越攒越多。

以前等 KV 攒到阈值，才一次性摘要。

摘要还跟正常请求抢算力。

Aggron 每回合都摘要，只压一部分。

它挑请求排队卡住的空档干活。

用的是排队堵出来的闲置算力。

高负载下，P99 延迟降 27–31%。

P99 就是最慢那 1% 的请求。

吞吐涨 1.34–1.40 倍。

来源：https://arxiv.org/abs/2611.26435

AscMLA：FP4 解码，长上下文 MLA 更省了

MLA 是 DeepSeek 那种省显存的注意力。

长上下文解码，老要反复读 KV。

FP4 能把 KV 压得更小。

但 K 和 V 的缩放要求不一样。

以前得先反量化，或者各存一份。

这篇用不对称缩放，一份 FP4 直接算。

缓存比 FP8 少 38.2%。

比 TRT-LLM 的 FP8 核快 1.35 倍。

比 CAKE 的 NVFP4 核快 1.26 倍。

来源：https://arxiv.org/abs/2611.26106

BlockJack：KV 缓存的页表也能被劫持

这是第一篇 KV 地址翻译攻击。

页表就是逻辑块到物理块的对照表。

攻击者改一个页表项。

读 KV 就读到别人租户的块上。

受害者的上下文会漏进攻击者的回答。

医疗场景里，41.1% 的回答被带偏。

变得不那么紧急，但看起来还合理。

好消息是 vLLM 已经确认了漏洞。

补丁也提了，作者验证过。

多租户部署的，要去看一眼补丁。

来源：https://arxiv.org/abs/2611.25945

G-MTP：草稿头一次猜多个词，服务端快 3.1 倍

投机解码的草稿头，一次只猜一个词。

这篇换成多 token 预测。

一个共享草稿头，一次猜好几个。

还加了三处优化。

目标模型的激活直接注进去。

KV 交叉注意力零拷贝，省了读题。

词表投影按簇算，省了全词表开销。

Gemma 4 上，服务端最快 3.1 倍。

手机 GPU 上也有 2.2 倍。

来源：https://arxiv.org/abs/2611.25813

Validation-driven：智能体负载评测法

企业把智能体从闭源 API 搬到自家部署。

上线前的验证流程，工具却很随意。

这篇给了一套端到端的评测管线。

录好的 trace 重放，95 分位只差 1.18 倍。

现场重跑能差到 4.98 倍。

少量录好的会话，就能稳定复现负载。

来源：https://arxiv.org/abs/2611.25905

FrontierReplay：混合模型的前缀缓存，读题不用切了

这篇值得精读，三个原因。

第一，它盯的是混合模型。

Qwen3.5、Kimi-K3 都是这个结构。

你的评估里迟早要过这一关。

第二，办法很干净。

读题不切，事后只重放递推层。

1–3 毫秒就能补一个检查点。

第三，数字够硬。

好吞吐最高 4.26 倍，准确率一分不掉。

但要注意：只在 1 张 A800 上测过。

用的 vLLM 0.30.0，版本有点老。
