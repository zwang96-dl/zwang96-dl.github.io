TorchTPU：vLLM 和 SGLang 原生上 TPU 精读

原文链接：https://developers.googleblog.com/announcing-new-vllm-and-sglang-inference-engines-on-tpu/ 发布时间：2026-10-20（PyTorch Conference 2026 当天，Google 开发者博客） 代码仓库：https://github.com/vllm-project/vllm-torchtpu 代码仓库：https://github.com/sgl-project/sglang-torchtpu 代码仓库：https://github.com/google-pytorch/torch_tpu

人话解读

  • vLLM 和 SGLang 以前也能上 TPU。
  • 但要先过一层 JAX 翻译。
  • JAX 是 Google 自家的计算框架。
  • 现在不用翻译了。
  • Google 新出了 TorchTPU。
  • 它让 TPU 直接听懂 PyTorch。
  • 两个引擎各出了一套原生版。
  • vLLM 版跟 Inferact 合作做。
  • Inferact 是 vLLM 创始人的公司。
  • SGLang 版跟 RadixArk 合作做。
  • RadixArk 是 SGLang 创始人的公司。
  • 不是外人移植，是原班人马。
  • SGLang 版已经在 Meta 上线跑了。
  • 这是 Meta 的人亲口确认的。
  • 划重点：PD 解耦是正式功能。
  • PD 就是读题和答题分开跑。
  • 像流水线分工，各干一段。
  • 多模态模型也在一等公民名单。
  • 图片和视频输入都支持。
  • 你的三台机器都不是 TPU。
  • 所以这篇不是让你去部署。
  • 价值在看它怎么解 PD 的老问题。
  • 尤其是草稿纸怎么跨机搬。
  • 草稿纸就是 KV 缓存。
  • 搬运方案跟你评估的路线同题。

核心方法

  • TorchTPU 把 TPU 变成原生设备。
  • 张量就是普通 PyTorch 张量。
  • 不用套一层包装类型。
  • 可以急切模式直接跑着调。
  • 也可以走 torch.compile 编译。
  • 编译底层还是走 XLA。
  • 每台设备跑自己的进程。
  • 引擎的调度器原样保留。
  • KV 缓存管理器也原样保留。
  • 只在底下换上 TPU 实现。
  • 这叫平台插件式设计。
  • 上层框架和底层各走各的节奏。
  • 自定义内核用 Pallas 写。
  • Pallas 是 TPU 的内核语言。
  • 内核直接当算子塞进计算图。
  • 搬草稿纸靠 TPU Sync。
  • 它是开源的 C++ 传输库。
  • 它直接读张量背后的显存。
  • 中间不用在主机上再倒一手。
  • 传输跑在自己的线程上。
  • Python 这边不用等它。
  • 搬运和计算可以同时进行。
  • vLLM 版走自家连接器接口。
  • 就是 KV connector 那套口。
  • SGLang 版拿它当两件工具。
  • 一是解耦时的传输后端。
  • 二是 HiCache 的读写后端。
  • HiCache 是 SGLang 的分层缓存。
  • 草稿纸放不下就往下沉。
  • 先沉到主机内存当第二层。
  • 再沉到托管 Lustre 存储。
  • Lustre 是并行文件系统。
  • 老 JAX 版不会被砍掉。
  • 官方说两个都继续维护。

关键数据

  • 以下数字均为官方自报。
  • 成本数来自公开榜单提交。
  • 榜单是 SemiAnalysis 的 InferenceX。
  • Qwen 3.5 跑在 Ironwood 上。
  • Ironwood 是第七代 TPU。
  • 每百万词元最低成本 2.01 美分。
  • 官方称这是全场最低。
  • 智能体专用榜叫 AgentX。
  • Ironwood 在多数前沿点领先。
  • 这句也是官方口径。
  • Kimi K3 有一个巨型内核。
  • 它有 2.8 万亿参数。
  • 整个答题步塞进一个内核跑。
  • 单用户每秒出 700 多个词元。
  • 这是 Inferact 做的 Pallas 内核。
  • SGLang 版已在 Meta 生产跑。
  • 引擎已给预览客户规模化跑。
  • 贡献者能申请免费 TPU 算力。
  • 这是 vLLM 发起的算力池。

跟你的研究方向

  • 你在评估 SGLang 的 PD 解耦。
  • 这篇给了另一套搬运实现。
  • 值得对着 Mooncake 逐项比。
  • 比什么？比三件事。
  • 一是零中转，直读显存。
  • 二是独立线程，不堵主流程。
  • 三是传输和计算重叠。
  • 这三点正是解耦的命门。
  • 草稿纸搬慢了，解耦就白拆。
  • SGLang 版拿它喂 HiCache。
  • 等于官方认证了一条分层路线。
  • 跟你看的 LMCache 是同一层。
  • 多模态这块也值得记一笔。
  • 视觉语言模型明确在支持名单。
  • 编码和解耦可以拼着看。
  • 成本数字先别当采购依据。
  • 是 Google 自家栈调优后提交的。
  • 等独立复测出来再说。
  • 对你的三台机器没有直接件。
  • H100 和两台 AMD 都用不上。
  • 但 autotuner 可以借一个视角。
  • 传输线程独立是个可调维度。
  • 搬运和计算的重叠比例也是。

术语表

  • TorchTPU：让 PyTorch 原生跑 TPU 的后端。
  • Pallas：TPU 上的自定义内核语言。
  • TPU Sync：开源的 KV 缓存传输库。
  • HiCache：SGLang 的分层 KV 缓存。
  • KV connector：vLLM 的外部缓存接口。
  • Ironwood：Google 第七代 TPU。
  • InferenceX：SemiAnalysis 的公开推理榜。
  • AgentX：榜单里的智能体负载赛道。
  • Managed Lustre：Google 托管的并行存储。
  • megakernel：把整步计算塞进一个内核。
