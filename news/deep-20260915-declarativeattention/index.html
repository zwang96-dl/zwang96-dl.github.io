Declarative Attention：让模型自己"申报"要看哪里，KV 读取砍掉三到五成

原文：Language Models Can Control Their Own Attention（arXiv:2609.02737）
作者：Namgyu Ho 等，KAIST AI + Google DeepMind（2026-09-03 发布）
解读：AI Weekly 快讯 · DAIR.AI 课程页

一句话人话

长上下文推理里，模型每生成一个 token 都要把全部 KV 缓存读一遍。这篇论文反其道而行：让模型在思考过程里自己"申报"下一步要看哪段，引擎只读被点名的部分。实测被读到的 token 少了一半，精度几乎没掉。

核心方法

  • 长文本先切成约 2048 token 一段的"魔法片段"（magic chunks）。
  • 片段以"假装的工具调用记录"形式呈现给模型。
  • 这样模型能用它熟悉的"工具调用边界"来定位片段。
  • 模型在思考链里插三种标签，声明下一步的注意力范围。
  • <global>：全看，用于开头扫全文、定位关键段。
  • <focus magic_chunks="K">：只看第 K 段，用于精读细节。
  • <local>：只看自己刚写的内容，用于收尾算答案。
  • 推理引擎里跑一个 DA 状态机，实时监听输出流。
  • 一看到标签切换，就更新下一步允许看的 KV 位置。
  • 生成一张"片段级注意力掩码"，剩下的 KV 直接跳过不读。
  • 掩码按 vLLM 的 KV 块对齐（16–32 token 一块）。
  • 块内多读几个 token，开销可忽略。
  • FlashAttention 核函数不用改，直接吃这个掩码。
  • 作者已把这套机制集成进 vLLM（PyPI 有 declarative-attention 包）。

关键数据

  • 15 个长上下文任务，零样本、开箱即用，不用训练。
  • Gemma-4-31B：被读到的 token 从 13.43M 降到 6.45M，少 52.0%。
  • 精度 87.01% → 85.74%，只掉 1.27 个百分点。
  • Qwen-3.6-27B：被读到的 token 从 22.54M 降到 15.52M，少 31.1%。
  • 精度 85.31% → 82.56%，掉 2.75 个百分点。
  • 解码墙钟时间：Gemma 是原来的 0.71 倍，Qwen 是 0.77 倍。
  • 消融实验证明省的是"掩码"不是"步数"。
  • DA 的步数比原来多 15–35%（标签本身要占 token）。
  • 但每步只读一半 KV，总账还是大赚。
  • 去掉掩码只留分段格式（DA-no-mask），精度跟 DA 一样。
  • 说明分段本身不伤精度，省的全靠掩码跳读。
  • 模型越大效果越好：31B 上精度基本打平，4B 小模型会翻车。
  • 小模型的 focus 标签解析成功率只有 58%，31B 是 99%。
  • 上下文越长越划算：64K–256K 上下文单次响应最多省 21M token。
  • 屋顶线分析：1M 上下文下，单步注意力的理论耗时约是 FFN 矩阵乘法的 145 倍。
  • 所以"多花几步、每步少读"这笔账，在大批量长上下文部署里是划算的。

跟你研究方向的关联

  • 这是"模型驱动"的 KV 读取优化，跟你研究的 KV 缓存优化是同一条路。
  • 传统稀疏注意力靠外部打分选 token，每步还是 O(N) 扫描。
  • DA 把选择权交给模型，引擎只做 O(1) 的标签解析。
  • P/D 解耦里，decode 侧的 KV 搬运是大头成本。
  • "按需声明再读"的思路，可以借鉴到解耦架构的 KV 调度上。
  • 它只动 global 注意力层， sliding window 和 GDN 这类层碰不得。
  • 跟你评估的 SGLang/vLLM 都兼容（vLLM 已有集成，掩码块对齐是通用做法）。
  • 小模型翻车提醒你：这招吃模型能力，弱模型别硬上。

术语表

  • KV 缓存：模型把每个 token 的 key 和 value 存下来，后面生成时不用重算。长上下文里它是显存大户。
  • 魔法片段（magic chunks）：论文里对上下文分段的叫法，约 2048 token 一段，提醒模型"这是检索单位、不是语义章节"。
  • DA 状态机：跟推理引擎并肩跑的小模块，监听输出流里的标签，实时更新注意力掩码。
  • 块对齐掩码：掩码按 KV 缓存块的边界取整，多读几个 token，换来核函数不用改。
  • 屋顶线模型（roofline）：估算硬件性能上限的经典方法，分"算力受限"和"带宽受限"两种天花板。
  • MBU/MFU：带宽利用率/算力利用率，屋顶线分析里的实际达成比例。
  • FFN：前馈网络，Transformer 里注意力之外的另一大计算块。
  • global 注意力层：能看到全部上下文的注意力层，DA 只优化这种层。
  • 消融实验：去掉某个部件再测，看增益到底是谁贡献的。

局限和小心

  • 精度还是掉了 1–3 个百分点，对精度敏感的任务要掂量。
  • 小模型（4B 级）focus 标签解析成功率只有 58%，基本不可用。
  • 多出来的解码步数在小批量、低并发下可能把省的钱吃回去。
  • 论文没跟 sliding window、landmark attention 这类稀疏基线对比。
  • 中文媒体解读里的"已集成进 vLLM"指作者的原型实现，不是 vLLM 官方合入。
