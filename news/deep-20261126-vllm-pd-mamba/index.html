vLLM 的 P/D 检查点对齐：生成机不再重算整段历史

  • 原文：vLLM 团队，GitHub PR #67064
  • 原文链接：https://github.com/vllm-project/vllm/pull/67064
  • 合入时间：2026-11-26
  • 适用范围：Mamba 混合模型
  • 数字来自作者自报

人话解读

这条修的是一个缓存对齐问题。

P/D 就是读题和生成分开跑。

读题机先处理输入。

生成机再接着出字。

多轮对话里有个坑。

下一轮追问可能直达生成机。

它绕过了读题机。

生成机手里要有可复用存档。

没有存档就要重算历史。

旧跑法里存档留在读题机。

生成机只拿到末尾状态。

末尾状态不在缓存格子上。

缓存格子就是能复用的存档点。

所以生成机一个词也命中不了。

新跑法让读题机停在存档点。

生成机自己补算最后小尾巴。

补完后存档就在生成机了。

下一轮追问就能直接命中。

核心方法

  • 只管 Mamba 对齐模式。
  • Mamba 是带记忆状态的层。
  • 对齐模式就是按块存状态。
  • 读题机停在检查点 C。
  • C 是本地读题会存的点。
  • 生成机只加载 C 个词。
  • 后面的尾巴由生成机补算。
  • 尾巴长度小于一个缓存块。
  • 补算后会把 C 写进缓存。
  • 下一轮就能在 C 处命中。
  • 推和拉两种传输都适用。
  • 传输协议不用改。
  • 两边不用事先约好 C。
  • 对不齐只损失缓存命中。
  • 对不齐不会算错结果。
  • 状态太靠后就本地重算。
  • 读题机也有代价。
  • 它本地复用会低一个块。

  • 这组测的是 Qwen3.5-122B。
  • 用的是 2 卡张量并行。
  • 张量并行就是切开模型分工算。
  • 模型估算也给了。
  • 每台生成机每秒 1 个请求。
  • 七成请求直达生成机。
  • 补算约占 0.7% 到 1.0%。
  • 影响主要在尾部词间隔。
  • 块变小后代价可忽略。

跟你的研究方向的关联

你正在评估 P/D 解耦。

这条正好补一块账。

缓存命中不能只看总命中率。

要按机器分开算。

读题机命中不等于生成机命中。

直达生成机的轮次要单列。

短追问也要单列。

长历史追问也要单列。

读题机停在哪也要算账。

停在存档点会多一次补算。

补算会抬高 P/D 轮首字。

但它能救直达轮首字。

这笔交换要分轮次看。

缓存块大小也要进清单。

块越大，尾巴越长。

块越小，补算越便宜。

路由器也要一起看。

它要知道哪台有存档。

不知道就会路由错机器。

局限与提醒

  • 只对 Mamba 对齐模式生效。
  • 普通注意力模型不受影响。
  • 数字是作者自报。
  • 评论区实验只跑一轮。
  • 原文说端到端还要跟进。
  • 慢网络下结论会变。
  • 另一种传存档方案传得更多。
  • 慢网络时它反而更慢。
  • 路由器侧还有配套改动。
  • 配套改动还没合入。

术语表

  • P/D：读题和生成分开跑。
  • 读题机：处理输入的机器。
  • 生成机：接着出字的机器。
  • Mamba：带记忆状态的层。
  • 检查点：能复用的存档点。
  • 前缀缓存：复用开头算过的内容。
  • 首字：第一个词出来的时间。
  • 词间隔：相邻词之间的时间。
