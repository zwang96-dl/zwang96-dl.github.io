给推理优化装一把"校准过的尺子"：量化/早退/投机解码到底伤了多少质量

  • 作者：Jerry Kaplan（斯坦福大学），2026-09-11 初稿
  • 原文链接：https://arxiv.org/abs/2609.18005
  • 代码与 prompt 全部开源：https://github.com/jerrykaplan/Calibrated-Instrument
  • 阅读方式：PDF 全文已读；2 张原文关键图已下载配中文图注

一句话人话版

大家都在说"快 X 倍"，但"质量掉了多少"从来没人认真量过。这篇论文干了一件事。给 LLM judge（用大模型当裁判）这把尺子做一次正规校准。然后用这把尺子，在同一批题上挨个量。量的对象：4-bit 量化、3-bit 量化、投机解码、早退（early exit，算到一半提前交卷）。结论很扎心。4-bit 基本无伤。3-bit 中文伤得比英文深一倍。早退在数学题上直接崩盘。而这些，困惑度（perplexity，模型对答案的"熟练度"）全都看不出来。token 一致率（两种方案逐词相同比例）也看不出来。

核心方法：这把尺子怎么校准的

类比一下：你买个体重秤，空秤必须显示 0，放个 1kg 砝码必须显示 1kg。作者就是给"模型当裁判"这台仪器做了同样的事。

  1. 双基准配对设计。每道题，原模型先自己答两遍。每种优化方案的分数 = 自己的裁判分 − 原模型两遍的平均分。这样基准的抽样噪声砍了一半。
  2. 可交换性零点。原模型两遍答案地位完全一样。裁判给它们的分差，理论上必须是 0。实测差 −0.05，置信区间 [−0.18, +0.08]。这就是"空秤归零"。
  3. 实现零点。严格投机解码当第三个零点。它是小模型打草稿、大模型验算。标准接受规则下数学上无损。读数不是 0，就说明是你代码写错了。他们自己就靠这一招抓出过 2 个 bug。
  4. 阳性对照。放两个已知会掉分的早退方案进去。尺子得能读出已知损失，方向和大小都得对。这就是"1kg 砝码"。
  5. 等价界。事先拍板：7 分制里 ±0.3 分算"没区别"。220 道题，整体置信区间 ±0.11，每领域 ±0.3。
  6. 硬答案校验。数学题和代码题有标准答案。直接跑代码、解析"最终答案"行。跟裁判打分互相印证。

顺带一个冷知识。贪心解码（temperature=0）下，同一模型在两台机器上跑。几百个 token 后输出就分叉了。纯粹是浮点加法顺序不同。所以"逐词比对"从根上就不靠谱。

关键数据

实验对象是两个 7–8B 模型。Qwen2.5-7B-Instruct 是主角。Llama-3.1-8B-Instruct 负责复现。220 道题，5 个领域。英文散文、Python 代码、算术应用题、中文散文、硬核可验证题。硬核题 = 27 道数学 + 13 道编程。

  • NF4 4-bit ≈ 全精度。Qwen +0.01 分 [-0.10, +0.12]。Llama −0.10 [-0.24, +0.04]。五个领域全在等价界内。中文也一样（−0.16）。结论：4-bit 放心用。
  • HQQ 3-bit 开始掉分，而且看领域下菜碟。Qwen 整体 −0.70。算术题 −0.09（几乎无伤）。英文散文 −0.46。代码 −0.84。中文 −0.91。硬核数学 −1.11。同一道菜，数学题的伤是算术题的 10 倍。
  • 同一把刀，砍不同模型深浅不一。HQQ 3-bit 在 Llama 上整体 −1.84。Qwen 上只有 −0.70。前者是后者的 2.6 倍。Llama 代码领域 −3.11，23% 的回答陷入复读。
  • 早退（第 15 层提前交卷）在数学题上崩盘。整体 −1.07（带缓存修复）。硬核数学 −2.54。27 道数学对 19 道 → 只剩 6 道。13 道编程全灭 0 道。散文领域只掉 0.69：写作文能糊弄，算数糊弄不了。
  • 放宽的投机解码（λ=0.2，几乎照单全收）竟然无伤。跟全精度等价。严格版更是完美零点。
  • 裁判打分跟硬答案对得上。校验说答对的，裁判给 6.07 分。答错的，给 2.45 分。没有一道校验判错的拿到 6 分以上。
  • 噪声主要来自模型自己，不是裁判。同一段文字让裁判评两次，波动 0.26。模型换一遍答案重抽，波动 0.94。裁判只占配对比较方差的 8%–12%。想更准？加题数，别换裁判。
  • 常用代理指标全都不行。一段循环复读的废话，困惑度 1.151，比正常答案的 1.239 还"好"。因为复读太好预测了。token 一致率把"错个标点"和"错个数字"当一回事。期望接受率（EAR，大小模型分歧程度）在散文里分歧最大、伤害却最小，完全排反了。
  • 模型越"自信"，错得越要命。数字和标点的生成置信度几乎一样（0.999 vs 0.989）。但换掉一个数字，23.3% 的位置会改变裁判结论。换掉一个标点，只有 3.3%。靠置信度做接受规则，等于闭眼开车。

原文关键图

图 1 人话解读：横轴是 7 种方案。每组 6 个点 = 5 个领域 + 整体。落在灰带里 = 跟全精度没区别。看黑色整体点：前四个在灰带里趴着，后三个掉出去了。再看紫色点（硬核数学）：3-bit 掉到 −1.1。早退直接掉到 −2.5 和 −3.3。同一优化，领域不同，伤害差出一个数量级。

图 2 人话解读：同样的题、同样的裁判，换 Llama 跑。NF4 4-bit 照样在灰带里。HQQ 3-bit 的黑色整体点掉到 −1.84。橙色代码点（−3.11）一骑绝尘。同一把 3-bit 的刀，砍 Qwen 掉 0.7，砍 Llama 掉 1.8。量化方案的"质量账单"，模型不同不能直接抄。

跟你研究方向的关联

  • 量化评估直接抄这套流程。你正在评估 AWQ/GPTQ/FP8。这篇的结论是 4-bit（NF4）可以放心用，3-bit 得按领域单独验收。它的双基准 + 零点 + 等价界设计，就是一套现成的"量化验收 SOP"。
  • 你的 vLLM 吞吐 benchmark 建议加一列"质量账单"。只报 QPS 不报质量，等于只报油耗不报动力。按这篇的教训：困惑度、token 一致率都别用。用 LLM 裁判 + 双基准，220 道题就能做到 ±0.11 精度。
  • 中文场景要单独测。3-bit 在中文上掉 0.91，英文散文只掉 0.46。你的负载里如果有中文流量，英文 benchmark 的结论不能直接搬。
  • SGLang P/D 解耦评估的对照。放宽的投机解码（λ=0.2）在这套尺子下跟全精度等价。说明"有损加速"不一定真有损，得拿校准过的尺子量了才知道。反过来，早退这种"看着还行"的方案，在数学题上是真崩。
  • 确定性那篇笔记的呼应。这篇亲手验证了：贪心解码在两台机器上都会分叉。所以 benchmark 里"逐词 diff"式的回归测试，本质上是在测浮点噪声。质量回归要用分布级比较。

术语表

  • LLM as a judge：用大模型当裁判。给 prompt + 回答打分。便宜但得先校准。
  • 校准（calibration）：证明尺子在零点读零、已知重量读对。计量学的基本功。
  • 零点（null）：理论上分差必须为 0 的对照组。读数不为 0 就是实验设计有 bug。
  • 等价界：事先定好的"算没区别"的分差上限。这里是 ±0.3。
  • TOST：双单侧检验。证明"差值落在等价界内"的标准统计方法。
  • 投机解码：小模型先打草稿，大模型一次性验算。严格规则下数学无损。
  • 早退（early exit）：算到中间层就提前输出。省算力，但后面层的信息全丢了。
  • EAR（期望接受率）：大小模型 next-token 分布的分歧程度。投机解码优化的目标，但跟质量伤害排不齐。
  • 困惑度（perplexity）：模型对一段文本的"熟练度"。越低越"顺"，但顺≠好。
  • NF4 / HQQ：两种权重量化格式。NF4 是 4-bit。HQQ 是 3-bit 免校准。
  • 置信度（certainty）：模型对自己选的词有多确定。确定≠重要，这是全文最扎心的一课。
