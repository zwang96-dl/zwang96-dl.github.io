给投机解码的"实习生"换一套考核标准：直接看全局要跑几轮

  • 作者：Yunxiao Zhao、Changxiao Cai（密歇根大学），2026-10-07 初稿
  • 原文链接：https://arxiv.org/abs/2610.10411v1
  • 代码开源：https://github.com/y-x-zhao/AngelSpec-EDR
  • 阅读方式：PDF 全文已读；2 张原文关键表已裁剪配中文图注

一句话人话版

以前训练草稿模型，考的是"每块草稿写得像不像"。 这篇说：考核标准错了。 真正该考的是"整个任务要跑几轮验算"。 新目标叫 EDR（期望解码轮数）。 两个主流草稿模型换上它，9 个测试全赢。

核心方法：三个关键招

先说背景。投机解码 = 小模型打草稿、大模型验算。 并行草稿一次出一整块，更快。 但训练时有个坑：某一轮从哪开始，取决于上一轮接受了几个。 旧目标只看块内，不管这个跨轮耦合。

  1. 把解码过程建成马尔可夫奖励过程。状态是（第 n 轮，块内位置 t）。接受 = 留在本轮，代价 0。拒绝 = 开新轮，代价 1。期望总轮数就有了精确公式（命题 1）。
  2. EDR 目标：直接最小化期望轮数。局部拒绝代价按"状态占用率"加权。不像旧目标需要手调超参数。EDR 一个都不需要。
  3. TD 形式梯度 + 离线评估器。TD 形式支持无偏随机优化。用目标模型的 rollout 就能算梯度。离线评估器更妙：不用真跑投机解码。同一批目标输出上，直接比较两个草稿模型谁轮数少。评估方差直接砍掉。

还有一个扎心的定理（定理 3）。 每个块都做到局部最优，全局反而可能更差。 因为当前轮写得好，可能让下一轮从更难的位置开始。 这就是旧目标的病根。

关键数据

实验对象：两个 SOTA 并行草稿模型 DSpark 和 DFly。 目标模型：Qwen3-4B（配 DSpark）和 Qwen3-8B（配 DFly）。 块大小 B = 7。训练集 Open-PerfectBlend。只微调一轮。 评测 9 个基准：数学（GSM8K、MATH、AIME25）、代码（MBPP、HumanEval、LiveCodeBench）、聊天（MT-Bench、Alpaca、Arena-Hard）。 指标 MAL（平均接受长度，越高越好）。

  • EDR 对 E2E（最强旧目标）9 战全胜或打平。两个草稿模型都是。
  • DSpark + EDR 最大的涨幅在聊天类。Arena-Hard 从 3.67 涨到 3.70。LiveCodeBench 从 3.75 涨到 3.78。HumanEval 从 5.58 涨到 5.59。
  • DFly + EDR 同样 9 个全赢。Arena-Hard 从 3.21 涨到 3.25。LiveCodeBench 从 3.61 涨到 3.65。GSM8K 从 6.34 涨到 6.35。
  • 涨幅不大，但稳定跨架构、跨模型规模。两个不同草稿架构、两个目标模型规模，全都赢。这说明方向对了。
  • 只训一轮、单卡 H100/H200 就够。batch 96。成本很低，收益是白捡的。

跟你研究方向的关联

你正在评估 SGLang 的 P/D 解耦。 这篇是另一个维度的加速：投机解码。 两者是乘法关系，不冲突。 P/D 解耦省的是 prefill 和 decode 的排队。 EDR 省的是 decode 阶段的验算轮数。 如果你的 serving 栈里有草稿模型，训练目标可以直接换成 EDR。 成本只是一轮微调，论文连代码都开源了。

术语表

  • 投机解码（speculative decoding）：小模型先打草稿，大模型一次验算一整块。草稿对了就白赚速度。
  • 并行/半自回归草稿（parallel/semi-AR drafter）：一次前向出一整块草稿，不用逐词生成。DSpark 和 DFly 是代表。
  • EDR（Expected Decoding Rounds，期望解码轮数）：整个任务要跑几轮"草稿+验算"。这篇的优化目标。
  • MAL（mean accepted length，平均接受长度）：每轮平均接受几个 token。越高越好。
  • 锚点（anchor）：开始写一块草稿的位置。
  • TD（temporal difference，时序差分）：一种算梯度的方法，把长期回报拆成"眼前代价 + 未来价值差"。
