Remote KV：远程草稿纸比 GPU 重算还慢

原文：When the KV Cache Is Slower Than the GPU 作者：Muhammad Ibrahim（Multiverse Computing） 提交：2026-10-15 链接：https://arxiv.org/abs/2610.21500v1

人话解读

  • 远程 KV 本来是来帮忙的。
  • KV 缓存就是模型的草稿纸。
  • 草稿纸存到大家共用的一层。
  • 新请求来了就不用重算。
  • 这篇发现帮忙能帮倒忙。
  • 在 B300 这种快卡上更明显。
  • 取草稿比现场重算还慢。
  • 慢的不是网络本身。
  • 慢在仓库只有一个窗口。
  • 所有人挤一个窗口取货。
  • 队伍越排越长，尾巴就爆了。
  • 说白了，仓库要先扩窗口。
  • 不然缓存命中反而是惩罚。

图注：图 1 是原文的最终设计。 左边是路由器，中间是读题节点。 读题节点里有 8 张卡并行。 每张卡配一个独立仓库实例。 右边是续写节点，走专线收 KV。 关键改动是仓库从一个变八个。

核心方法

  • 第一步，先给命中算一笔账。
  • 重算耗时等于题长除以速度。
  • 取货耗时等于固定开销加搬运。
  • 固定开销文中记作 T0。
  • 搬运耗时看字节数和带宽。
  • 两笔账一比，盈亏线就出来。
  • 盈亏带宽等于每词字节乘速度。
  • 这篇里盈亏线约 2.53 GB/s。
  • 低于这条线，命中必亏。
  • 单仓库实测最高约 1.71 GB/s。
  • 所以当时每次命中都在亏。
  • 第二步，把仓库按卡分片。
  • 每个分块只归一张卡管。
  • 存、查、取都只找那张卡。
  • 第三步，仓库按卡拆实例。
  • 8 张卡就配 8 个实例。
  • 实例之间不用互相协调。
  • 第四步，取货改成异步。
  • 引擎不用停下来干等取货。
  • 第五步，修三个客户端毛病。
  • 毛病会让引擎卡住好几秒。
  • 改动都已提交给 LMCache。
  • LMCache 是 KV 复用工具。

图注：图 2 是原文的成本模型图。 横轴是取货带宽，纵轴是延迟。 虚线是纯重算的耗时水平。 竖虚线标出盈亏线 2.53。 红点是单仓库，落在亏本区。 绿点是八仓库，带宽明显更高。 带宽再高也会撞上固定开销。

关键数据

  • 实验模型是 GLM-5.3。
  • 它是 FP8 的 MoE 模型。
  • MoE 就是一堆专家轮流干活。
  • 硬件是 8 张 B300 的节点。
  • 读题速度约每秒 5.22 万词。
  • 每词 KV 约 48.4 KB。
  • 16K 题重算只要约 0.31 秒。
  • 单仓库取货却要约 0.88 秒。
  • 开远程层后尾巴先爆了。
  • 16K 题 p99 从 3.96 秒起。
  • 一路涨到 17.3 秒。
  • 命中多的回放里更夸张。
  • p99 最高到 83.32 秒。
  • 那时 GPU 利用率只有 7%。
  • 拆成 8 个实例后变了。
  • 取货带宽涨了约 6.3 倍。
  • 最高到约 10.76 GB/s。
  • 同批请求 p99 降到 0.67 秒。
  • 命中比例约 98.5%。
  • 读题吞吐也涨了约 14%。
  • 再加一个内核修复后涨 34%。
  • 固定开销 T0 约 0.33 秒。
  • 所以短题命中很难赢重算。
  • 门槛大约在 1.7 万词。
  • 以上数字都是作者自报。
  • 每种条件只跑了一轮。
  • 本期没有独立复核。

跟你研究方向的关联

  • 这篇正中 P/D 解耦的搬运账。
  • 解耦后 KV 要跨节点搬。
  • 远程复用还要多搬一次。
  • 盈亏线公式可以直接抄。
  • 它只用两个量就能估算。
  • 每词字节数乘读题速度。
  • 这就是 autotuner 的现成项。
  • 命中该不该用远程层。
  • 短题该不该直接重算。
  • 仓库该拆几个实例。
  • 这三个都是现成决策变量。
  • 它还提醒了一个大坑。
  • 同步取货会把队列拖失稳。
  • 你测 SGLang 解耦时要盯。
  • 盯 p99，不要只看中位数。
  • 中位数没变，尾巴能爆四倍。

局限和要注意的

  • 实验只测了一个模型。
  • 只测了一种卡，B300。
  • 你的 H100 和 MI350 要重算。
  • 盈亏线会跟着硬件变。
  • 每种条件只跑了一轮。
  • 尾巴数字的波动要小心。
  • 中位数上命中仍没赢重算。
  • 赢的是尾巴和省下的算力。
  • 别把结论读成命中必赚。
  • 五节点解耦部署文中说过线。
  • 细节在原文第 6 节里。

术语表

  • KV 缓存：模型存下的注意力草稿。
  • 远程层：多引擎共用的 KV 仓库。
  • LMCache：开源的 KV 复用工具。
  • Valkey：存 KV 分块的仓库软件。
  • PCP：按题长切分的读题并行。
  • MLA：把 KV 压成一份潜向量。
  • p99：最慢那 1% 的门槛值。
  • 盈亏带宽：命中不亏的最低带宽。
