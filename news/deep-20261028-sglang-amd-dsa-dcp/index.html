SGLang 在 AMD 上给 DSA 打开 DCP：KV 容量涨到 3 倍多

原文：SGLang PR #44322 链接：https://github.com/sgl-project/sglang/pull/44322 合并时间：2026-10-28 09:45 UTC

人话解读

  • DSA 是一种稀疏注意力。
  • 它只看最重要的那部分上下文。
  • DCP 是解码上下文并行。
  • 说白了就是几张卡分摊草稿纸。
  • KV 就是算好的草稿纸。
  • 以前 AMD 这条路开不了 DCP。
  • 这次把缺的三块补齐了。
  • 草稿纸总量涨到 3 倍多。
  • 中等并发下吞吐翻倍还多。
  • 但并发太高时反而拖后腿。
  • 这条跟你的 MI350 同线。
  • 你评 DCP 时能直接借它的工况。

核心方法

  • 稀疏 MLA 内核开始返回 LSE。
  • LSE 是各卡结果的合并依据。
  • 没有它，各卡算完没法拼。
  • FP8 的 KV 写入改对了行号。
  • DCP 下每卡只写自己那份行。
  • 草稿模型的分片规则跟着改。
  • 草稿就是 MTP 先猜的词元。
  • 以前草稿在 DCP 下会访存崩。
  • 预填充的索引行也拆开算。
  • 以前每卡重复算同一批索引。
  • 现在各卡分工，再汇总结果。
  • Q 在卡间传输改用 FP8。
  • 传输量直接砍一半。
  • 结果跟以前逐位不变。

关键数据

  • 测试卡是 MI355X。
  • 模型是 GLM-5.2 的 MXFP4 版。
  • 配置是 TP4 加 EP4。
  • KV 用 FP8 存，DCP 开 4。
  • KV 容量从 283 万涨到 881 万。
  • 单位是词元数，约 3.1 倍。
  • 密钥找回测试三个长度全过。
  • 长度是 8K、34K、96K。
  • GSM8K 四百题分数不变。
  • 开和不开都是 0.953。
  • 草稿接受长度还涨了。
  • 从 3.11 涨到 3.47。
  • 并发 24 时吞吐涨 2.2 倍。
  • 每卡从 10872 到 23416 tok/s。
  • 并发 40 时吞吐涨 4.8 倍。
  • 每卡从 5144 到 24740 tok/s。
  • 但并发 16 时没有收益。
  • 吞吐是基线的 0.99 倍。
  • 交互速度只剩 0.78 倍。
  • 并发 48 时有个大坑。
  • 吞吐还涨，但交互只剩 0.41 倍。
  • 原因是缓存池满了。
  • DCP 现在拒绝配 HiCache。
  • HiCache 是主机内存那层缓存。
  • 被淘汰的前缀只能重算。
  • 以上数字都是 PR 作者口径。
  • 跑分是智能体回放一小时测的。

图注：这是 PR 原图的性能汇总。 横轴是并发数，纵轴是吞吐和交互。 能看到中段并发涨得最猛。 也能看到并发 48 交互塌下去。 这正是容量和重算在打架。

跟你的研究方向的关联

  • 你正在评估 PD 解耦。
  • DCP 是 decode 侧的扩容招。
  • 两招经常要一起上。
  • 这条给了完整的对照工况。
  • 同模型、同卡、同题集对照。
  • 划重点是它报了负收益段。
  • 并发 16 和 48 都不如预期。
  • 厂商口径里肯报负收益很少。
  • 你压测时照着这四档并发扫。
  • 16、24、40、48 各测一档。
  • 重点盯池满后的交互延迟。
  • 还有一条已知问题要记。
  • DCP 加 HiCache 还没打通。
  • 后续 PR 编号是 45205。
  • 等它合并，48 档可能翻盘。

术语表

  • DSA：稀疏注意力，只看关键上下文。
  • DCP：解码上下文并行，多卡分摊 KV。
  • KV：算好的草稿纸，避免重复计算。
  • MLA：一种压缩 KV 的注意力结构。
  • LSE：合并各卡部分结果的依据值。
  • MTP：一次多猜几个词元的草稿法。
  • HiCache：把 KV 存到主机内存的层。
  • TP/EP：张量并行和专家并行。
