KV-Repurpose：前缀缓存认不出"同一段话换了个位置"

原文：https://arxiv.org/abs/2610.13060（arXiv:2610.13060v1，2026-10-09）

代码开源（Apache-2.0）：https://github.com/taiga333/eval-kv-repurpose

作者：Taiga Ikeda、Daisuke Miyashita、Jun Deguchi，铠侠（Kioxia，日本存储公司）。

一句话人话版

同一份文档，换个系统提示或对话历史，前缀缓存就认不出来，只能重算。 这篇论文把 KV cache 按"段"拆开存，请求来了按段拼回去。 RAG 场景下命中率直接翻 19 倍。

痛点：前缀缓存像按门牌号认人

前缀缓存（prefix caching）只复用"开头一模一样"的 KV。 开头差一个字，后面整段都得重算。 RAG 里 retrieved 的文档经常出现在不同的 system prompt、对话历史、时间戳后面。 内容高度重叠，但开头不一样，缓存全浪费。 打个比方：你认识邻居只靠门牌号，他搬个家你就不认识了。

核心方法：KV 按段拆开，按段复用

  • 请求进来，先按文档切成段（segment）。
  • 每段的 KV 单独存，带内容指纹，不带位置前缀。
  • 新请求里出现同一段，直接把存好的 KV 拼回去。
  • 位置对齐（positional realignment）只做最基础的 key 重排。
  • 作者自己说这是"naive"实现，目标是做个可复现的 baseline。
  • 整个系统是 vLLM v0.20.0 的扩展，不到 900 行 Python。

类比：以前是按整本书的页码复印，现在是按章节复印。 章节内容一样，放在哪本书里都能用。

关键数据

实验配置：GPT-OSS-120B（OpenAI 的开源模型），vLLM，单卡 H200。 KV 存 NVMe SSD。对照组是 LMCache 做前缀缓存。

质量（LongBench，单文档问答/摘要）：

  • QASPER 单文档问答：重算 0.42，复用 0.42，打平。
  • GovReport 摘要：重算 0.26，复用 0.26，打平。
  • 单文档场景质量基本不掉。

质量（多文档跨文档推理）：

  • HotpotQA：重算 0.71，复用 0.60，掉了。
  • 2WikiMultihopQA：重算 0.80，复用 0.50，掉得明显。
  • MuSiQue：重算 0.61，复用 0.40，掉得明显。
  • 结论：跨文档拼 KV 目前不行，几个文档混一起它就晕。

命中率（Zipfian RAG 负载，2500 请求，8K–128K token 文档）：

  • 30GB 缓存：KV-Repurpose 63.9%，前缀缓存只有 3.3%（20% 请求共享固定前缀的配置）。
  • 前缀缓存加到 1TB：命中率也只有 17.9%。
  • 容量效率差了两个数量级。

延迟：30GB 缓存、Poisson 到达下，p50/p95 TTFT（首字延迟）随请求率上升都显著更低。

诚实说局限

  • 这是 testbed，不是 SOTA 方法。作者明确说不 claim 首创。
  • 位置不匹配没有精细处理。CacheBlend、EPIC 那类"位置无关缓存"（PIC）做了对齐，它没做。
  • 跨文档推理质量掉得厉害，只适合单文档 RAG。
  • naive 拼回去为什么质量不掉太多，论文没有深究机理。

跟你研究方向的关联

  • SGLang 的 RadixAttention（前缀树复用）还是认"开头一样"。
  • KV-Repurpose 是同一道题的升级版：开头不一样也复用。
  • 两者互补，不是替代。PIC 对齐 + 段级复用可以叠。
  • 你评估 SGLang P/D 解耦时，KV 复用直接决定 prefill 负载。
  • RAG serving 里"同一文档+不同 system prompt"是常态，命中率 3.3%→63.9% 这种量级值得进 autotuner 的代价模型。
  • 代码不到 900 行，vLLM 插件形式，复现成本低。

术语表

  • 前缀缓存（prefix caching）：KV cache 只复用开头完全相同的请求。大白话：按门牌号认人。
  • KV cache（草稿纸）：模型算过的 key/value 存下来，后面直接用，不用重算。
  • TTFT（time to first token）：首字延迟。用户发问到看到第一个字的时间。
  • Zipfian 分布：热点长尾分布。少数文档被反复问，大多数很少被问。
  • Segment-wise reuse：按段复用。KV 按文档段拆开存，不按整请求存。
  • 位置对齐（positional realignment）：缓存的 KV 位置编号和新请求对不上时，重新编号。
  • PIC（位置无关缓存）：即使位置变了，缓存照样能用的一类方法。
