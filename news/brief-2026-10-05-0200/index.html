新技术与论文

  • 这轮有 4 篇 10/2 的新论文，之前周末模式漏报了，补上。
  • KV 缓存又出新压法：SlimKV 一次压两个维度。
  • KV cache 是推理时的"草稿纸"，长上下文先爆的是显存。
  • 老路线两条：删 token 会丢信息，压特征维度要重建才慢。
  • SlimKV 两手抓：分块插"信标 token"写小结，只存小结的 KV。
  • 小结从训练起就是低秩形态，存量直接砍一刀。
  • 最妙的一招：信标去掉位置编码几乎不掉分。
  • 解码直接在潜空间算 attention，重建这步省了。
  • 数据：16 倍/32 倍压缩仍超基线，4 倍/8 倍保住原模型 96% 以上。
  • 128K 长度下 attention 快 7.34 倍，端到端解码快 3.38 倍。
  • 跟你的 P/D 解耦评估直接相关：decode 卡的显存规划就看 KV 预算。
  • 精读笔记已生成，含原文两张关键图。
  • 来源：arXiv 2610.02953
  • 投机解码不用草稿模型了：BitNest 把草稿"绣"进权重里。
  • 投机解码就是小模型先打草稿、大模型改，旧方案要多备一个模型。
  • BitNest 把低精度草稿嵌进高精度权重的比特表示，一套权重两种精度。
  • 专为显存紧张的设备省内存，端侧友好。
  • 来源：arXiv 2610.02800
  • 调度器也能被"插队"：一篇给 P/D 调度敲警钟的攻击论文。
  • 现在的调度器靠预测输出长度排优先级，短任务先上。
  • 这篇证明：对抗后缀能操纵长度预测，让请求插队降延迟。
  • 你在调 P/D 解耦的调度策略，安全维度值得知道。
  • 来源：arXiv 2610.03430
  • 端侧多 agent 推理：decode 阶段把内存总线堵死了。
  • 统一内存架构就是 CPU 和 GPU 共用一块内存。
  • 多 agent 在上面一跑，decode 期内存瓶颈引发总线争用。
  • 还发现多 agent 下投机解码的草稿难度方差极大。
  • 偏端侧，跟你数据中心 serving 主线关系不大，一句话带过。
  • 来源：arXiv 2610.03394
