HeteroReason：推理模型的"打草稿"搬上 FPGA，GPU 专心改作业

原文：HeteroReason: Heterogeneous FPGA-GPU Acceleration for Disaggregated Speculative Reasoning（arXiv:2609.28717，2026-09-23，帝国理工 + 清华 + 布里斯托，MICRO 2026 接收）
一句话版本：大推理模型的投机推理，三步走拆到两种硬件上。
小草稿扔给 FPGA，GPU 只管打分和修正。

人话解读

先说背景：LRM（大推理模型），就是 o1、DeepSeek-R1 那类。

先长思考再回答，思维链（CoT）又臭又长。

推理慢的核心矛盾：自回归一个 token 一个 token 吐，链越长越慢。

投机推理（speculative reasoning）是解法之一。

小模型先写一个推理步骤，大模型再验。

跟投机解码的区别：不要求 token 逐字相同。

推理步骤看的是"意思对不对"，语义对了就行。

所以它比 token 级投机更能容忍近似，加速空间更大。

这套流程有三个模型：draft（小草稿，约 1B）。

PRM（过程奖励模型，打分裁判，7B），target（大模型，7B，负责修正）。

流程：小模型写一步，PRM 打分，分数低就请大模型重写。

论文指出了三个痛点，一个比一个扎心。

第一，纯前向推理没有"后悔药"。

第 3 步写砸了，后面全跟着歪，错得越走越远。

第二，三个模型脾气完全不同，硬塞在 GPU 上浪费。

草稿是串行自回归，吃显存带宽。

PRM 是并行打分，吃算力。

GPU 跑小草稿就像用大卡车送外卖，油耗感人。

第三，三步串行等：写完才打分，打完分才修正。

HeteroReason 的答案：算法和硬件一起改。

算法上加"回溯"：这步写砸了，退回去换条路。

硬件上拆开：草稿扔给 FPGA，PRM 和大模型留给 GPU。

调度上"超前一步"：PRM 还在验第 i 步，草稿已经写第 i+1 步了。

对你意味着什么：这是 P/D 解耦思路在异构硬件上的延伸。

你现在拆的是 prefill 和 decode，用的都是 GPU。

这篇告诉你：拆的维度可以更多，连硬件种类都可以换。

核心方法

三板斧：算法一斧，硬件一斧，调度一斧。

第一斧：回溯增强的工作流。

PRM 打分低的步骤，不直接丢掉重写。

系统回退到之前的状态，换一条推理轨迹再试。

类比：做数学题做到一半发现思路错了。

以前的做法是硬着头皮往下写，这篇是擦掉重来。

第二斧：FPGA 加 GPU 异构。

草稿模型（0.5B 到 1B）放到 AMD U280 或 V80 FPGA 上。

FPGA 是可编程硬件，功耗低，擅长流式小任务。

PRM 和 target 模型留在 RTX 3090 GPU 上，吃大算力。

FPGA 内部还做了 prefill/decode 解耦。

FPGA 这边用影子同步。 GPU 改历史状态时，它在后台悄悄跟上。

FPGA 在后台悄悄同步自己的 KV，不挡前台计算。

第三斧：超前一步的投机和修正调度。

原来的流程是串行的：写、验、改，一步完了下一步。

现在改成流水线：PRM 验第 i 步的同时。

草稿已经在写第 i+1 步，target 也在预修正第 i+1 步。

类比：餐厅里前台还在点菜，后厨已经开始备下一桌的料了。

还加了两个工程优化：target 异步预取，KV 动态管理。

设备之间传的是 token，不是 KV cache。

通信开销只有端到端延迟的 0.0123%，基本可以忽略。

关键数据

配置先摆出来，论文测了两组。

配置 1：0.5B 草稿，7B PRM，7B target。

配置 2：0.5B 草稿，7B PRM，1.5B target。

数据集有四个：MATH500、GSM8K。 还有高考英语 2023、OlympiadBench。

先看回溯带来的精度，平均准确率。

配置 1：基线 58.8%，加回溯 60.8%，涨 2.0 个点。

配置 2：基线 45.3%，加回溯 50.3%，涨 5.0 个点。

全套优化上完，配置 2 还保住 4.2 个点的涨幅。

划重点：小 target 吃红利更大。

1.5B 的小模型涨 4.2，7B 的大模型只涨 1.7。

能力弱的更容易写错，更需要"后悔药"，很符合直觉。

再看延迟分解，四个数据集上。

draft 占 34.6% 到 55.4%。 target 占 22.4% 到 47.5%。

PRM 只占 16.1% 到 22.2%。

小模型反而是大头，因为它每步都被无条件调用。

这就是把它搬上 FPGA 的理由：高频小活，GPU 跑着贵。

硬件加速结果，相对弱基线（只加回溯的纯 GPU）。

U280：延迟快 1.01 到 1.12 倍。 goodput 涨 1.01 到 1.12 倍。

V80：延迟快 1.26 到 1.42 倍。 goodput 涨 1.25 到 1.42 倍。

V80 那套基本追上了强基线（纯 GPU 加全套调度优化）。

能效：弱基线 1.25 到 1.57 倍，正文口径约 1.3 倍。

超前一步调度单独拎出来看。

配置 1 贡献 1.25 到 1.33 倍加速。 配置 2 贡献 1.35 到 1.40 倍。

是延迟收益里的大头。

废 token 的能耗开销：0.48% 到 0.719%。

超前写的东西偶尔会被 PRM 判废，浪费的电不到 1%，忽略不计。

高达 80% 的投机步骤会被接受，所以废的本来就少。

诚实地说个 caveat：光加回溯不上异构硬件，速度反而变慢。

纯 GPU 上回溯版只有基线的 0.73 到 0.93 倍。

是 FPGA 加流水线把账算回来的，算法红利要配硬件才能兑现。

跟你研究方向的关联

你在 SGLang 上评估 P/D 解耦。 HeteroReason 是"解耦再往前走一步"。

P/D 解耦拆的是阶段，这篇连硬件种类一起拆了。

思路可以借：memory-bound 的小活，不一定非要用 GPU。

你的 MI350X 跑这种小 batch 串行活。 能效比未必好看。

以后做自动调参系统，配卡维度可以从"几张 GPU"。

扩展成"什么硬件各放几张"，FPGA 或推理卡做 draft 池。

step-ahead 的"超前执行"跟 mooncake 是同类思想。 都是传输和计算重叠。

都是"别等上一步彻底完，提前把下一步备好"。

你的 SGLang P/D 评估里，KV 传输和计算重叠可以直接抄这个哲学。

对多模态推理还有一层启发：步骤级粒度。

VLM 的 encoder、prefill、decode 也是不同脾气。

encoder 吃算力，decode 吃带宽，完全可以按阶段分硬件。

这篇的 step-wise 摊薄通信（传 token 不传 KV）。

在多模态场景下就是"传特征不传 KV"，值得记一笔。

一个提醒：V80 的数据是投影值，不是实测。

U280 实测跑在 200MHz，投到 300MHz 才有 V80 的数。

引用 1.42 倍加速时记得加这个定语。

术语表

  • LRM（大推理模型）：先长思考再回答的模型，如 o1、DeepSeek-R1。
  • speculative reasoning：小模型先写推理步骤。

大模型负责验或改。

  • PRM（过程奖励模型）：给每个推理步骤打分的裁判，分数低就重写。
  • backtracking（回溯）：这步写砸了，退回去换条推理轨迹。
  • speculative decoding：token 级投机，要求逐字一致。

投机推理只要求语义对。

  • prefill/decode disaggregation：

prefill 和 decode 拆开放到不同硬件。 放到不同硬件或实例上。

  • shadow synchronization：后台悄悄同步状态。

不挡前台计算。

  • step-ahead speculation：验证还没完，草稿先写下一步。
  • goodput：单位时间产出的有效 token 数。
  • weak/strong baseline：弱基线是纯 GPU 加回溯。

强基线再加全套调度优化。

  • CoT（思维链）：模型一步一步的推理过程，越长延迟越高。
