vLLM v0.34.0：草稿纸变大、老执行器退役

原文链接：https://github.com/vllm-project/vllm/releases/tag/v0.34.0 发布时间：2026-11-16 15:22 PST（本轮窗口内发布） 版本规模：1061 个提交，412 位贡献者（120 位新人）

人话解读

  • vLLM 发了新大版本。
  • 这版不是只加新模型。
  • serving 的三处都动了。
  • 草稿纸、执行器、运维。
  • 草稿纸就是 KV 缓存。
  • 它记着算过的中间结果。
  • 对你最值钱的是草稿纸。
  • 还有 V1 退役和断点续跑。
  • 下面按你的硬件拆开讲。
  • 不是你的卡的，我会标明。

核心更新

草稿纸默认变大：按真实空闲显存来划

  • 以前按估算先划一块地。
  • 现在热身完了再看。
  • 看真实空闲显存有多少。
  • 再决定草稿纸划多大。
  • 名字叫可扩展 KV 缓存。
  • 现在默认就开着。
  • MiniMax-M3 在 H200 上。
  • 缓存从 433k 个 token 涨到 672k。
  • 高并发下吞吐更高，首字更快。
  • 代价也有，要先知道。
  • 部分模型单 token 延迟涨 6–18%。
  • 并发 128 的 H200 上测到的。
  • 不想用就加参数关掉。
  • 两个开关都行。
  • --gpu-memory-utilization 0.9。
  • 或者 --no-enable-extensible-kv-cache。

老执行器退役：只剩 Model Runner V2

  • Model Runner V1 删了。
  • V2 是现在唯一的 GPU 执行器。
  • 执行器就是真正跑模型的工人。
  • VLLM_USE_V2_MODEL_RUNNER=0 现在报错。
  • 启动就失败，别再设了。
  • 双批重叠也搬到了 V2 上。
  • 双批重叠就是两批活重叠跑。
  • prefill 和 decode 各干各的。
  • 连投机解码和 DCP 也能叠。
  • DCP 是把超长上下文切开分卡算。

投机解码：后缀解码上了 V2

  • 投机解码就是先让实习生打草稿。
  • 再让专家一次性改完。
  • 后缀解码现在跑在 V2 上。
  • 草稿器直接放 GPU 上。
  • 不用再装 Arctic Inference 了。
  • 还加了自定义投机方法。
  • 声明式配置加插件接口。
  • 想自己写草稿器能插进来。
  • V2 的草稿模型也有 CUDA 图了。
  • 自适应验证能跟 XPress 配合。
  • 草稿的 KV 跟目标模型同精度。
  • FP8 目标就配 FP8 草稿缓存。

提速：谁快了多少

  • Step5 在 4 张 GB200 上。
  • decode 快了 1.95 倍。
  • GLM-5.3-Flash 吞吐涨 1.6 倍。
  • 对照组是 DEP4。
  • GLM-5.3 长 prompt 首字更快。
  • 32K 到 128K 快 1.24–1.40 倍。
  • 靠的是分片稀疏 MLA prefill。
  • Kimi-K3 的 decode 注意力也快了。
  • GB300 上快 1.34–1.59 倍。
  • 要手动开，不默认。
  • Qwen3.5 的 decode 也快了一点。
  • 延迟降 3.0–8.8%。
  • MI355X 上 DSpark 解码更顺。
  • 低并发互动性涨 35–57%。

P/D 拆开跑：这版的新东西

  • P/D 就是 prefill 和 decode 分开跑。
  • 像流水线分工，各干各的。
  • MiniMax-M3.1-Flash 支持混搭并行度。
  • prefill 和 decode 的 TP 可以不一样。
  • prefill 收压缩 KV 的次数少了。
  • 每步从 38 次收到 4 次。
  • 解码的 replay 图共用模型图池。
  • prefill 图显存每卡省了不少。
  • GB200 上从 15.52 降到 9.88 GiB。
  • DCP 接上了 FlashMLA 稀疏路径。
  • BF16 的 KV 也能走 DCP 了。
  • 分片稀疏 MLA prefill 默认开。
  • 就是上面 GLM-5.3 变快的那条。

运维：断点续跑，不用重启

  • 检查点恢复来了。
  • 服务能像游戏存档一样断点续跑。
  • 接口是 /checkpoint/prepare。
  • 还有 status 和 restore。
  • 两个前端都能用。
  • DP+EP 容错缩容也来了。
  • 有卡挂了不用重启。
  • 专家自动重分到活着的卡上。
  • NUMA 绑定默认开了。
  • 尽量让进程贴着自己的内存跑。
  • 缓存感知的准入排序可以选开。
  • Rust 前端加了无状态 Responses 接口。
  • 还支持一次返回多个结果。

AMD：只剩 ROCm 10.0

  • ROCm 7.2 的镜像没了。
  • 发布镜像和 wheel 只有 10.0。
  • MoRI 的 EPv2 能用了。
  • 参数是 --all2all-backend mori。
  • Kimi-K3 在 MI355X 上有专用 decode。
  • 要手动开。
  • RDNA3 和 RDNA4 默认走 TRITON_ATTN。

新模型：一次加了 10 个

  • Mistral Large 4 是大头。
  • 总参数 1T，激活 52B。
  • FP8 和 NVFP4 都能跑。
  • Blackwell、Hopper、MI350 都行。
  • MiniMax-M3.1-Flash 也来了。
  • 还有能听会说的 Nemotron-3.5-Transcribe。
  • 30B 参数，4B 激活的语音模型。
  • 能跑音频聊天和转录接口。
  • 其余还有 Ripple-65B、ZAYA1。
  • 和 Baidu 的 Unlimited-OCR-2。
  • Liquid 的 LFM3 三件套也在内。

升级前先看：三条会弄坏现有配置

  • 默认 block size 从 16 改成 64。
  • block 就是草稿纸的一页大小。
  • 想留旧行为就传 --block-size 16。
  • ROCm 的分页注意力还是 16。
  • ROCm 7.2 的包不再发布。
  • 要用 ROCm 10.0 的 wheel 和镜像。
  • huggingface_hub 要求 2.0.0 以上。
  • tokenizers 和 timm 也要升。
  • QuTLASS 和 fp_quant 删了。
  • fp_quant 的 checkpoint 打不开了。
  • Marlin W4A8 也删了。
  • 改走 humming 量化。

术语表

  • KV 缓存：模型的草稿纸，记着算过的中间结果。
  • 可扩展 KV 缓存：按真实空闲显存来划草稿纸。
  • Model Runner：真正跑模型的执行器。
  • 双批重叠：prefill 和 decode 两批活重叠跑。
  • 投机解码：实习生先打草稿，专家再改。
  • 后缀解码：一种投机解码，草稿从后缀往前猜。
  • DCP：把超长上下文切开分给多张卡。
  • block size：草稿纸一页能装多少个 token。
  • 检查点恢复：服务存档，挂了能断点续跑。
  • NUMA 绑定：进程贴着自己的内存跑，少跨节点。
  • ROCm：AMD 显卡的计算平台，对标 CUDA。
  • NVFP4：4 位浮点量化，省显存的压缩格式。
  • TP：张量并行，一层模型切开分卡算。
  • EP：专家并行，MoE 的专家分卡放。
  • DP：数据并行，请求分流到多组卡上。
