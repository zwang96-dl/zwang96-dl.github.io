CONDUIT：视觉语言模型的统一 KV Cache 复用框架

论文：CONDUIT: A Unified Residual-Stream Restoration Framework for KV Cache Reuse in Vision-Language Models
作者：Pengan Chen, Kaisheng Zheng, Liang Hong 等（2026-09-05，arXiv:2609.05821，已被 EMNLP 2026 Findings 接收）
原文：http://arxiv.org/abs/2609.05821v1

一句话人话版

多模态推理里最常见的浪费，是"同一张图被不同问题反复问"。前缀稍稍一变，传统的前缀缓存就整个作废。CONDUIT 只刷新 10% 的视觉 token。效果达到完整重算的 97%–99.5%。首字延迟快了近 3 倍。

它解决什么问题

先看个典型场景。用户上传一张图，然后轮番问："图里有几个人？""左边那辆车什么颜色？""把文字抄出来"。图是同一张，问题（query）每次都变。

理想很美好：图的 KV cache 只算一次，后面反复用。KV cache 就是"草稿纸"，存着算好的注意力状态。但现实很骨感：

  • 精确前缀复用（exact-prefix reuse）。前缀必须一字不差。问题一变，前缀就变，缓存直接作废。整张图得重算，视觉 token 又多又贵。
  • 选择性重算（selective recomputation）。只刷新一小部分视觉 token。但"刷新哪几个"要是选错，质量就崩。之前的方法用 raw attention（原始注意力分数）来选，有两个坑。

1. 注意力分数高的 token，不一定真影响输出。value 向量本身可能很小，相当于"嗓门大但没内容"。 2. 多图场景下，预算会浪费在跟当前问题无关的图片上。

核心方法：CONDUIT

打个比方：像给旧讲义做"选择性修订"。不是整本重印，而是先打分，找出"这次考试真会考、旧版还写错了"的几页。只重印那几页。

技术上分三步。先说个好消息：训练无关，不改模型结构和权重。推理时只多做一次打分前向。

  1. Norm-weighted attention 打分。不用 raw attention。改用"注意力分数 × value 向量的模"排序。直觉很简单。一个 token 得"被关注得多"，还得"自己有料"，才值得刷新。这样就避开了"嗓门大没内容"的坑。
  2. Query-conditioned。打分用的 query 就是当前问题的 query。选出来的是"对这个问题重要"的 token，不是泛泛重要的那种。
  3. 图像级相关性放大。英文名是 Image-level relevance amplification。多图场景下，先判断哪张图跟问题相关。预算向相关的图倾斜，别浪费在无关图上。然后做一次全局统一选择。单图和多图，用同一套框架搞定。这套框架叫残差流恢复（residual-stream restoration）。

最优雅的地方：单图时图像级系数就是 1。整个方法自动退化成"图内 token 选择"。一套规则，两种场景全包。

原文关键图

图 1 人话解读。左上先讲问题。请求 A 和请求 B 用的图完全一样，只是问题变了：从"哪张图风格和参考图一样？"变成了"这些画的原作是什么？"。exact-prefix 的 KV 缓存复用就此失效，因为前缀对不上。右上是 CONDUIT 的解法：给每个 visual token 打"吞吐分"。紫色是注意力，红色是实际写入量。再按"哪张图跟问题更相关"，在图之间分配刷新预算。下面两排色块是实际效果。浅色是直接复用的 visual KV。深色是只重算的那一小撮 token。一张图讲清"旧方法为什么失效、新方法怎么修"。

关键实验数据

  • 3 个 VLM backbone × 5 个数据集，取平均。10% 刷新预算，达到完整重算效果的 97.0%–99.5%。同预算的方法里，它平均最强。
  • MMLongBench-Doc 延迟子集。只用 13.5% 的 full-prefill FLOPs。TTFT（首字延迟）加速 2.99×。
  • 代价：推理时多一次打分前向。一次前向换来 86.5% 的计算节省，这买卖很划算。

图 3 人话解读。横轴是"重算预算 r"。0 是纯复用，0.10 是重算 10% 的 visual token。纵轴是 5 个数据集的平均分。深红横线是全量重算的天花板，灰色虚线是纯复用的地板。紫色星线 CONDUIT 在三个 backbone 上都爬得最快。r=0.10 时几乎摸到天花板。只花 10% 的钱，买到 97–99.5% 的效果。其他方法（CacheBlend、KVShare 等）在同样预算下明显更低。

表 3 人话解读。实测 serving 延迟。看最后一行 CONDUIT。分数 43.26，几乎追平 full prefill 的 43.59。TFLOPs 从 90.36 降到 12.24，省了 86%。TTFT 从 0.519s 降到 0.174s，加速 2.99×。对比"纯 Cache reuse"那行。10.69× 加速看着唬人，但分数掉到 41.41。省过头了。CONDUIT 正好卡在"又快又准"的甜点上。

跟你研究方向的关联

  • 高度相关。你的研究方向：多模态 encoder/prefill/decode 资源分离。这篇解决的是 prefill 侧的核心问题。视觉前缀的 KV cache 到底怎么复用？CONDUIT 把它从"系统工程技巧"，变成了"可定量打分的算法问题"。
  • 思路可迁移。打分时别只看 raw attention。norm-weighted attention 更诚实。这个洞察可以用在任何 KV cache 淘汰/压缩策略里。比如 H2O、StreamingLLM 那类方法的打分函数。
  • 工程启示。10% 预算换 97%+ 效果，说明视觉 token 高度冗余。做多模态 serving 时，视觉部分的 cache 策略值得单独设计。别照搬文本那一套。

术语表

  • KV cache。推理时的"草稿纸"。存着已算好的 key/value 状态。新 token 不用重算历史。
  • prefix caching / 前缀复用。相同开头的请求直接复用已算好的 KV cache，跳过 prefill。
  • TTFT（time to first token）。首字延迟，从发请求到看到第一个字的时间。
  • residual stream（残差流）。Transformer 里层与层之间累加传递的主信息通道。"恢复残差流"≈把旧缓存里"过时"的部分，修正到接近重算的值。
  • value norm。value 向量的模长，衡量这个 token 自身携带的信息量大小。
  • FLOPs。浮点运算次数，这里用来衡量 prefill 阶段的计算量。
