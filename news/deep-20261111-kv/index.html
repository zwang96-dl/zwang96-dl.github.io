模型升级了，旧草稿纸还能用吗？

  • 原文：Zhikun Tao、Fangyong Jin、Junping Zhao（Rank Computing），arXiv:2611.14051，2026-11-10 提交，共 30 页
  • 原文链接：https://arxiv.org/abs/2611.14051
  • 深读来源：23点版简报，11 月 10 日那批新论文

一句话

模型升级后，旧缓存不用全扔。

长前缀问答里，首字延迟能快 2 到 5 倍。

但精确找针的任务，前缀越长越容易翻车。

复用之前，先看任务，再看前缀长度。

人话解读

模型越更越快，小版本三个月就发一个。

DeepSeek-V4-Flash 四月发预览版。

七月就出了 Flash-0731。

架构没变，尺寸没变，只是后训练又打磨了一轮。

但线上的缓存是按旧权重算的。

新模型一上线，旧缓存按理就作废了。

系统提示词、RAG 捡回来的文档、常用指令，这些上下文天天都在复用。

全重算一遍，首字延迟就上去了。

这篇问了一个很实在的问题。

新模型直接吃旧缓存，到底行不行？

答案不是行或者不行，是分情况。

聊天续写这种自然文本，复用很稳。

单字找针这种精确检索，前缀一长就跑偏。

作者还给了个新尺子，叫 FCD。

FCD 就是量新旧缓存下，下一个词的分布差多远。

分布差得多，行为就跑偏得多。

这篇最值钱的结论是两个标准要分开看。

任务分保住了，不等于行为没跑偏。

首字答对了，不等于后半句和停不停都对。

核心方法

  • 直接复用，不做任何映射。
  • 新模型拿旧模型的前缀 KV 缓存，接着往下算。
  • 不重算，不转格式，原样吃进去。
  • 对照组有三个。
  • Target 是新模型用自己的缓存。
  • Source 是旧模型用自己的缓存。
  • KV Reuse 是新模型用旧模型的缓存。
  • 还拉了个 Ridge Mapper 做对比。
  • Ridge Mapper 是 Heo 等人 2026 年的办法。
  • 用闭式岭回归把旧缓存映射一下再喂给新模型。
  • 测了四个升级组合。
  • GLM-5.2 到 GLM-5.3，750B 参数。
  • DeepSeek-V4.1-Flash 到 Flash-1017，552B 参数。
  • DeepSeek-V4-Flash 到 Flash-0731，284B 参数。
  • Qwen3-30B-A3B 到 Instruct-2507，30.5B 参数。
  • 检索任务用 NIAH，也就是大海捞针。
  • 前缀里塞很多键值对，每对只有一个词。
  • 问一个键，让模型还回对应的值。
  • 前缀从 512 词扫到 32K 词。
  • 每个长度 192 个问题，来自 8 段历史。
  • V4.1-Flash 那组一路延到 512K 词。
  • 问答任务用四个长上下文基准。
  • HotpotQA、2WikiMQA、MultiFieldQA-en、BABILong。
  • 一共 585 个例子。
  • 首字时间 TTFT 包含缓存加载和恢复。
  • 不含源模型重算和模型启动。
  • 新指标 FCD 用 Jensen-Shannon 散度算。
  • 散度就是两个分布差多远。
  • FCD 从 0 到 100，越大跑偏越多。
  • 测了找针第一个答案位置和自然文本续写。

关键数据

  • GLM 那组复用最稳。
  • 32K 前缀时复用 90.62%，新模型自己只有 86.46%。
  • 复用反而比新模型自己还准。
  • V4.1-Flash 那组全程贴着新模型。
  • 每个长度差距都在 1.04 个百分点以内。
  • 32K 时两者都是 97.92%。
  • 延到 512K 时复用 61.46%，新模型 66.15%。
  • 旧模型自己 57.81%，复用还比它强。
  • V4-Flash 那组复用帮了倒忙又帮了忙。
  • 32K 时新模型自己只有 25.52%。
  • 复用提到 31.25%，但旧模型自己有 55.73%。
  • 总分涨了，里面却有 13 个对的答案被翻错。
  • 同时又修好了 24 个错的。
  • Qwen 那组最惨。
  • 32K 时新模型自己 55.21%，复用掉到 13.02%。
  • 有害翻转率 78.30%，十个对的答案翻错近八个。
  • 有害翻转率就是新模型答对的题，复用后答错的比例。
  • GLM 只有 4.22%，V4.1-Flash 只有 0.53%。
  • V4-Flash 是 26.53%。
  • 首字延迟中位数，三个长前缀任务都快了。
  • HotpotQA 快 5.08 倍。
  • 2WikiMQA 快 2.10 倍。
  • MultiFieldQA-en 快 2.51 倍。
  • BABILong 只有 0.86 倍，反而慢了。
  • BABILong 的前缀中位数只有 1.7K 词。
  • 省下的重算还不够抵缓存加载的开销。
  • 分数上，两个任务基本保住。
  • BABILong 准确率 59.0 对 58.7。
  • MultiFieldQA-en 的 F1 是 45.9 对 46.2。
  • 两个多跳问答任务掉了分。
  • HotpotQA 的 F1 从 69.3 掉到 66.3。
  • 2WikiMQA 从 61.7 掉到 54.7。
  • FCD 的分化最说明问题。
  • 找针任务里，FCD 从 512 词的 2.87 涨到 32K 的 30.62。
  • 自然文本续写里，FCD 一直在 3.04 到 3.64 之间。
  • 同一个缓存，续写稳如泰山，找针越长越飘。
  • Ridge Mapper 没有稳赢。
  • 32K 时它 40.10%，比直接复用的 31.25% 高。
  • 2K 时它反而从 96.35% 掉到 92.19%。
  • 256K 和 512K 时它只有 52.60% 和 40.10%。
  • 直接复用是 72.40% 和 61.46%。
  • 前缀越长，直接复用赢得越多。

跟你的研究方向的关联

  • 前缀缓存的命是跨版本复用。
  • 模型一升级，缓存池要不要全清，这篇给了实测边界。
  • 你的 PD 解耦评估里可以加一组升级复用测试。
  • 聊天续写类负载可以放心复用，RAG 找针类要小心。
  • 前缀长度是分水岭，32K 附近是翻车高发区。
  • FCD 这个尺子可以直接进你的确定性评估清单。
  • 它量的不是分数，是行为跑偏多少。
  • 首字答对不等于行为没变，这篇拿数据钉死了这一点。
  • 跟 BridgeKV 那条线是一体两面。
  • BridgeKV 是大模型读题、小模型接着写，靠缓存翻译。
  • 这篇是同一架构的新旧版本之间，直接复用。
  • 两篇一起看，缓存跨模型复用的账本就全了。
  • Ridge Mapper 的教训也值得记一笔。
  • 映射在短前缀有用，长前缀不如直接复用。
  • 你的评估里别默认映射总比直通强。
  • 注意实验边界：离线评测，不是线上服务。
  • 数字都是作者自报，只测了四个升级组合。
  • Qwen 那组翻车最狠，说明小模型升级更要小心。
  • 还有一个细节：缓存里不光有事实，还有指令。
  • Flash 的缓存喂给 Base 模型，Base 也能按 Flash 的指令答题。
  • 缓存复用会连带着把旧模型的行为习惯也带过去。

术语表

  • KV cache（草稿纸）：读题时算好的键值，吐词时接着用。
  • Prefix caching（前缀缓存）：复用之前算好的 KV，少算重复的提示词。
  • NIAH（大海捞针）：长上下文里找一个值的检索测试。
  • TTFT（首字时间）：从发请求到吐出第一个词的时间。
  • FCD（功能缓存散度）：新旧缓存下，下一个词分布差多远。
  • Jensen-Shannon divergence（JS 散度）：量两个概率分布差多远的办法。
  • Harmful flip rate（有害翻转率）：新模型答对的题，复用后答错的比例。
  • Ridge Mapper（岭映射）：用岭回归把旧缓存映射成新模型格式的办法。
  • Post-training（后训练）：预训练之后再打磨模型的训练。
  • MLA（多头隐注意力）：DeepSeek 用的压缩注意力，缓存存的是隐向量。
  • RoPE（旋转位置编码）：给词标位置的一种编码办法。
  • HotpotQA、2WikiMQA：多跳问答基准，要跨几段文本找答案。
  • MultiFieldQA-en：多领域长文档问答基准。
  • BABILong：长上下文推理基准，前缀比较短。
  • FineWeb-Edu：高质量英文网页文本数据集，这里用来测续写。
  • Bootstrap interval（自助置信区间）：反复抽样算出来的可信范围。
