vLLM：KV 卸载装不下时，别整单扔掉

#66719 修的是 KV 卸载。

KV 卸载就是把 KV 缓存挪到 CPU 内存。

CPU 那层装不下时，以前整单直接拒掉。

每步都重试，每步都失败，还记一次分配失败。

现在能装几块就先存几块。

按 token 位置从前往后存，存不下的下步再试。

验证用的是 Qwen3-0.6B，7663 token 的提示词。

来源：https://github.com/vllm-project/vllm/pull/66719

vLLM：多模态输入又补了两种格式

#69052 和 #69099 都是输入格式的小修补。

#69052 让 InternVL 这些模型吃上 Tensor 视频。

Tensor 就是 PyTorch 的张量格式。

以前只认 NumPy，传张量就报错。

现在开头先转成 NumPy，后面流程不变。

#69099 修的是 Muse Spark Open 的预处理。

NumPy 图片和 PIL 帧视频以前会报属性错误。

现在图片先转 PIL，视频帧先转 RGB 再堆叠。

来源：https://github.com/vllm-project/vllm/pull/69052

来源：https://github.com/vllm-project/vllm/pull/69099

TRT-LLM：DSA 建索引改用 NumPy，快了 3 倍

#22644 改的是 DSA 的索引搭建。

原来用 Torch 表达式建这张映射表。

现在改用 NumPy，在原来的 int32 缓冲区里建。

单次调用从约 21.6 微秒降到约 6.7 微秒。

请求顺序、固定缓冲和异步拷贝都不变。

来源：https://github.com/NVIDIA/TensorRT-LLM/pull/22644

llama.cpp：Vulkan 终于接了不连续的 SCALE

#32735 修的是 Vulkan 后端。

Inkling 2 Mini 在 Radeon R9700 上跑得很慢。

只有 20 token 每秒。

GPU 利用率才 47%，其中 5% 花在拷贝上。

原因是 SCALE 算子遇到不连续输入就被拒。

不连续就是数据在显存里不是挨着放的。

每层两个 SCALE 都被踢回 CPU 跑。

整张图被切成 194 段，来回倒腾。

现在 SCALE 跟 log 算子一样走索引寻址。

Vulkan 也接了，跟 CUDA 和 Metal 看齐。

来源：https://github.com/ggml-org/llama.cpp/pull/32735

来源：https://github.com/ggml-org/llama.cpp/releases/tag/b12628
