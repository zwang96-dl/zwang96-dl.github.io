Purlin：把集合通信拆成三层，换硬件不再伤筋动骨

原文：Purlin: Separating Orchestration from the Datapath of Collectives
作者：Stanford + NVIDIA（Osayamen Jonathan Aimuyo 等）
arXiv:2609.36954，2026-09-29

一句话人话

分布式推理里卡和卡之间传数据，用的那套通信库跟不上新硬件。 Purlin 把通信拆成三层：描述要干什么、编排何时何地搬、底层具体怎么搬。 换新卡、新机制时只换底层，上面的编排逻辑不用重写。

核心方法

  • 三层结构：Layouts/Policies（语义层，说要干什么）、SNAC（编排层）、Atom（数据通路层）。
  • SNAC 是 Stage、Notify、And Consume 的缩写，是全系统共用的编排协议。
  • 它从集合的语义描述里自动推导出协调方案，不用人手写通信调度。
  • Atom 只管两件事：copy（搬数据）和 reduce（归约求和）。
  • Atom 按 GPU 代际单独实现，换卡只换这一层。
  • Codesign policies 是调参旋钮，管流水线深度这类执行细节。
  • 动机很实在：Hopper 出了 TMA 机制四年后，通信库才跟上支持。
  • 老卡还大量在服役，新旧硬件都要兼顾，耦合式实现做不到。

关键数据

  • 微基准：7 种集合通信，延迟最高快 5.14 倍，带宽最高涨 4.5 倍。
  • 对比 NCCL：AllGather/AllReduce 延迟几何平均快 1.65–4.36 倍。
  • 带宽：A100 上 1.14–1.42 倍，H200 上 1.05–1.25 倍，B200 上 1.35–1.53 倍。
  • 接入 SGLang 后：离线 serving 吞吐和交互性平均 1.13 倍，最高 1.37 倍。
  • 在线推理交互性平均 1.26 倍，超载时最高 2.85 倍。
  • 低并发下提升最明显：通信占端到端延迟的比例越高，收益越大。
  • 测试卡：8×A100、8×H200、8×B200。
  • 测试模型：Qwen3.5-122B-A10B、DeepSeek-V4-Flash、DeepSeek-V4-Pro。

跟你研究方向的关联

  • P/D 解耦评估里，prefill 和 decode 之间传 KV，走的就是集合通信。
  • 论文原文明确点名：prefill 是吞吐导向，decode 是延迟敏感，通信得分开优化。
  • 你在 MI350 上测 vLLM 的 P/D 解耦，瓶颈分析里通信开销是绕不开的一环。
  • Atom 按硬件代际单独实现：新卡出来，只换这一层就行。
  • SNAC 的思路跟你的自动调参系统很像。
  • 语义层稳定不动，调参只动 codesign 那一层。

术语表

  • 集合通信（collective communication）：多卡之间按固定模式交换数据的操作总称。
  • 编排（orchestration）：决定数据在何时、从哪张卡搬到哪张卡。
  • 数据通路（datapath）：具体怎么搬字节的底层实现。
  • TMA（Tensor Memory Accelerator）：Hopper 引入的硬件级数据搬运机制。
  • 归约（reduce）：把多张卡上的数据按某种运算合并，如求和。
