Callo：失效的 KV 别扔，拿来打草稿

原文：Jianjun Ou、Matthew Lentz，杜克大学，arXiv:2611.18459v1，2026-11-13 提交。

原文链接：Callo（arXiv:2611.18459）

一句话人话版

智能体改了上下文，缓存就失效了。

以前只能干等重算，Callo 不等了。

它拿失效的 KV 先打草稿。

等正确的算出来，再验算一遍交卷。

输出一字不差，请求还快了一成多。

这篇讲了什么问题

智能体跑的是长会话。

一次会话几十个请求，上下文越攒越长。

真实数据：Claude Code 会话里。

每请求上下文中位数约 6.2 万 token。

每会话中位数 38 个请求。

智能体还会经常改上下文。

删旧内容、去错、做摘要，都算改。

一改，前缀缓存就失效了。

前缀缓存就是按开头复用算过的 KV。

改动后面的 token，位置全变了。

哪怕 token 本身没变，KV 也对不上了。

后面那段全得重算，这叫缓存失效。

失效那段越长，等得越久。

主实验里，Llama-3.3-70B 上 79% 的请求都撞上失效。

中位数每次要重算 3.1k 个 token。

P/D 拆开跑也救不了这个请求本身。

P/D 就是 prefill 和 decode 分开跑。

拆开只能保护别的请求不受拖累。

这个请求还是得等自己的重算完成。

核心方法：三招

  • 第一招：失效 KV 拿来打草稿
  • 失效的 KV 跟正确的只差一处改动。
  • 大部分上下文根本没变。
  • 实测：下一个词跟正确 KV 算出的一样。
  • 98.3% 的位置都对得上。
  • 分布差距也很小，80% 的位置在 0.01 以内。
  • 拿它打草稿，质量接近直接用正确的 KV。
  • 32 个词整窗通过率 65%。
  • 正确的 KV 也只有 80%。
  • n-gram 那种抄提示词的办法只有 12%。
  • 所以草稿必须用目标模型加失效 KV 一起打。
  • 只用模型不用 KV，同样只有 10%。
  • 第二招：正确的 KV 按层流，一边到一边用
  • prefill 节点每算完一层，就把这层 KV 推过去。
  • 不用等整段算完再传。
  • decode 节点边收边打草稿，不用锁。
  • 混着用也不会变差。
  • 一半层变正确后，通过率就追上正确 KV 了。
  • 按位置一小块一小块给，反而没这个效果。
  • 所以必须按层给，一层一层变正确。
  • 为了不改 vLLM，每 8k token 一块按层推。
  • 88% 的重算一单块就装下了。
  • 基本还是纯按层的顺序。
  • 第三招：只在 decode 有空时投机，不行就让路
  • 打草稿用的是 decode 节点的空闲算力。
  • 正常请求永远优先，草稿随时让位。
  • 准入要同时满足三个条件。
  • 至少 256 个可复用的失效 token。
  • 准备工作的量乘上批里请求数不能超预算。
  • 预算默认 4096，超了就不接这个投机。
  • 打着打着会算一个累计通过概率。
  • 模型自己越犹豫，通过概率越低。
  • 低于 0.3 就停，不再浪费算力。
  • 判据来自 logit 差距，离线标定好的。
  • logit 差距就是第一名和第二名得分差。
  • 差距不到 0.5 的位置，只占 2.4%。
  • 却占了 60% 的首次验错。
  • 模型犹豫的地方，草稿最容易错。
  • 所以一犹豫就停，是划算的。

关键数据

  • 主实验：2 张 H200 NVL，vLLM 0.29，NIXL 传 KV。
  • 模型三组：Llama-3.3-70B FP8、Gemma-4-31B。
  • 还有 Mistral-Small-3.2-24B。
  • 负载三档：轻载 12%、中度 52%、满载 100%。
  • 主配置中度负载：全请求快 1.14 倍。
  • 失效请求快 1.19 倍。
  • 满载时全请求快 1.27 倍。
  • 三组模型全请求：中度负载 1.05 到 1.19 倍。
  • 失效请求的等待平均省 0.8 秒。
  • 失效代价的 47% 被折掉了。
  • 留 10 条旧记录：失效从 79% 降到 58%。
  • 但单次重算更长，收益反升到 1.19 倍。
  • 拆分贡献：纯传 KV 的流式占大头。
  • 投机本身再降 8% 到 10% 的延迟。
  • 显存代价：decode 节点留 0.75GB 缓冲。
  • KV 池子只小 1.5%。
  • 96 卡集群仿真：P:D 配比 1:2 到 3:1。
  • 失效请求加速 1.027 到 1.13 倍。
  • 配比越偏 prefill，收益越小。

跟研究方向的关联

  • P/D 评估要加一个场景：智能体改上下文。
  • 只看追加式会话，会低估失效的代价。
  • 失效那段的重算时间，要单独列出来。
  • 传输和投机要分开报收益。
  • 这篇里传 KV 的流式占大头。
  • 投机只占 8% 到 10%。
  • 评估里别把两笔账混成一笔。
  • 失效 KV 的质量可以先离线量。
  • 下一词一致率 98.3%，是个现成的门槛。
  • 低于这个数，投机可能不划算。
  • 准入和让路策略可以直接抄。
  • 256 个可复用 token 起步。
  • 累计通过概率低于 0.3 就停。
  • 正常请求永远优先。

局限与提醒

  • 实测只有 2 张卡，1 个 prefill 配 1 个 decode。
  • 大集群的数全是仿真，不是真跑的。
  • 用的 vLLM 0.29，版本有点老。
  • 评测只用了 SWE-agent 的会话。
  • 温度 0，贪心解码，采样没测。
  • 每组配置跑没跑多次，论文没写。
  • 数字均为作者自报，没有独立复现。
  • 失效比例跟智能体的编辑习惯强相关。
  • 换个智能体，79% 这个数会变。

术语表

  • P/D 解耦：prefill 和 decode 分开跑，各用各的卡。
  • prefill：读提示词、算 KV 的那一步。
  • decode：一个词一个词往外吐的那一步。
  • KV 缓存：算过的提示词草稿纸，存着 K 和 V。
  • 缓存失效：改了上下文，旧的 KV 对不上号了。
  • 失效 KV：对不上号但还留着的那份旧 KV。
  • 推测解码：先打草稿，再让目标模型验算。
  • NIXL：英伟达的 KV 搬运库，走 NVLink 或网卡。
  • logit 差距：模型最看好的两个词得分差，越小越犹豫。
  • SWE-agent：一个让模型修代码库的智能体框架。
  • SWE-bench：真实代码库修 bug 的评测集。
