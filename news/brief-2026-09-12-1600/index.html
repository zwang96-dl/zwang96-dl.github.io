新技术与论文

1. Composable CXL：给 KV 缓存修了个"跨节点共享网盘"（值得深读）

跨节点复用 KV 缓存，最怕的是搬数据太慢。这篇论文的思路很野：把可组合的 CXL 内存（一种能跨机器共享的高速内存）做成 K8s 可调度的资源。vLLM 和 llm-d 接上后，KV 缓存就能直接存在这块共享内存里。

两节点、Qwen2.5-7B-Instruct 的实测：跨节点前缀复用，首 token 延迟（TTFT）降了 5.5–36.6 倍。更狠的是，跨节点复用跟同节点复用只差 1–4%。说白了，数据搬去隔壁机器，几乎感觉不到慢。

值得深读理由：你上午刚看了 AWS 的前缀感知路由（路由层帮复用）和 vLLM 的分级 KV 仓库（缓存搬去下层）。这篇是从内存硬件层面解决同一个问题——跨节点共享 KV cache，正好补上拼图。注意作者自己说了，这只是可行性研究，不是正式性能评测。

🔗 https://arxiv.org/abs/2609.10790（9/11 发布）

2. FlexComp：一个压缩模型，想压多少倍都行（值得深读）

软上下文压缩是把长文本压成几个"记忆 token"。以前的毛病：压缩比训练时就焊死了，换个比例得重新训一个。

FlexComp 一次训练，就能部署时按输入动态选压缩比。说白了，压缩比从"出厂设置"变成了"现场旋钮"。

关键数据：级联路由平均压缩最高 266 倍，精度几乎不掉。单遍压缩做到 158–236 倍。在 serving 规模的 batch 下，上下文 KV cache 砍掉一半，decode 吞吐提升 47%。

值得深读理由：长上下文 serving 的显存救星候选，跟你关心的 KV cache 优化是同一个赛道。"一个模型适配任意压缩比"这个训练技巧本身也值得偷师。

🔗 https://arxiv.org/abs/2609.11192（9/11 发布）

3. EMMI：手机端的多模态"瘦身快递"

多模态模型放手机上太重。EMMI 的做法：边缘设备先做多模态编码和融合压缩，只传一份固定大小的隐表示（可以理解为"信息摘要"）给服务器做推理。

通信量缩小 32 倍。带宽受限的场景下，端到端延迟最高降 3.4 倍。精准度基本不掉。

跟多模态 encoder 和推理拆开部署的思路呼应。做端侧多模态 serving 的人值得看一眼这个压缩传输方案。

🔗 https://arxiv.org/abs/2609.11058（9/11 发布）

4. ExaServe：把 vLLM 铺到 256 个节点

一键部署到超算 ALCF Aurora。扩展到 3072 个 vLLM 副本，每秒 2.71 万请求。

最有价值的不是规模，是踩坑：顺手定位了 Ray Serve（vLLM 常用的调度控制层）控制平面的 O(N²) 瓶颈。想把 vLLM 推到极大规模的人，可以直接看它怎么爬的坑。

🔗 https://arxiv.org/abs/2609.10812（9/11 发布）

5. REVA：RAG 的 prefill 开销"吃剩饭"

RAG serving 里，每个 query 都要压缩一次上下文，prefill 开销大。REVA 把历史 query-文档-模型的交互挖成可复用的"证据视图"，后面的 query 直接吃剩饭，不用每次单独压缩。

质量升 1–5.8 分，压缩开销降 5.3–15.6 倍，只多不到 40ms 延迟。跟 prefix caching 是一个家族的新思路。

🔗 https://arxiv.org/abs/2609.11209（9/11 发布）

6. PATTON：把 KV cache 的"仓库管理"搬到 PIM 上

PIM 是存算一体芯片（内存里直接算，不用把数据搬来搬去）。这篇把生产级 serving 的 KV cache 生命周期管理搬到商用 PIM 上。

attention 平均加速 1.95 倍，能效提升 4.83 倍，而且不用改 PIM 硬件。路线比较小众，看个热闹就行。

🔗 https://arxiv.org/abs/2609.11392（9/11 发布）

业内新闻

7. 安全速报：SGLang 新 RCE 漏洞 CVE-2026-86793

你在评估 SGLang，这条必须看。9/11 披露的远程代码执行漏洞。

SafeUnpickler（SGLang 用来防反序列化攻击的"白名单检查器"）被绕过了。白名单把 builtins 放得太宽，黑名单又漏了 __import__ 和 getattr，攻击者组合一下就能执行任意代码。

入口是 /update_weights_from_tensor 端点。没配 API key 时可以匿名访问。披露时官方还没补丁。

对策就两句：别把 SGLang 暴露到公网，管理端点赶紧配上 API key。

🔗 https://cvj.ai/briefing/crypto-news/ai-stack-under-siege-four-critical-cves-in-18-days-expose-inference-server-flaws/（9/11）

8. The Batch 9/11：GPT-6 Astra"花小钱办大事"

OpenAI 新模型登顶榜单的同时，token 用量和成本是"零头级"。还原生支持隐式和显式 prompt caching（提示词缓存，第二次问相同开头就不用重算）。

对做 serving 的人意味着：同等质量下推理账单能大降。代码扫描这类大 prompt 工作流，prefill 成本有优化空间。

🔗 https://www.deeplearning.ai/the-batch/tag/sep-11-2026
