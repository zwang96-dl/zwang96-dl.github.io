业内新闻

1. SGLang 爆高危漏洞，今天刚披露，还没补丁

你正在评估 SGLang，这条必须看。

漏洞编号 CVE-2026-86793。不用登录，就能远程执行任意代码。相当于大门没锁，陌生人直接进厨房开火。

问题出在 SafeUnpickler 上。它是管反序列化的安检门。安检名单写得太宽，黑名单又漏了两个关键函数。攻击者拿 __import__ 加 getattr 打组合拳。绕过检查后，直接调系统命令。

/update_weights_from_tensor 接口中招了。默认没配 API key 的话，谁来都接待。

时间线有点扎心。7 月 2 日研究员就上报了，官方也认了。但到今天公开，补丁还没影。

自查三件事。第一，SGLang 别直接暴露在公网。第二，配上 API key。第三，盯紧官方补丁。

顺带一提，SGLang 今年 4 月也曝过 9.8 分的漏洞。这已经是 18 天里第四个 AI 基础设施高危漏洞。推理服务正在变成攻击者的主战场。

🔗 报道 https://cvj.ai/briefing/crypto-news/ai-stack-under-siege-four-critical-cves-in-18-days-expose-inference-server-flaws/

2. 俄罗斯 Sber 发了个 432B 推理模型，KV cache 省了 4 倍

Sber 是俄罗斯最大的银行，也在搞大模型。今天发了 GigaChat 3.5 Reasoning。

432B 参数的 MoE（混合专家模型），每次只激活 28B。看着胖，用着瘦。

省显存的招数值得看。注意力机制混用了两种技术。MLA 是 DeepSeek 那套压缩注意力。GatedDeltaNet 是线性注意力。KV cache 直接砍到 1/4，上下文干到 262K。

全程用 FP8（8 位浮点精度）训练。MIT 协议开源，已经上 Hugging Face。

对你意味着什么？混合注意力这条路，能降 KV cache。跟你深读过的 DeepSeek V4.1-Flash 思路相通。KV cache 优化这块，又多一个参照系。

🔗 报道 https://www.alextech.ai/en/news/sber-releases-gigachat-35-reasoning-with-432-billion-parameters/
