新技术与论文

SlimWise：prefill 用完整模型，decode 用"瘦身版"

这篇跟你正在评估的 SGLang P/D 解耦正对口。

MoE（一群专家分工的混合模型）decode 时要反复搬专家权重。

搬着搬着，带宽先顶不住了。

SlimWise 让 prefill 用全量专家，保住质量。

decode 换剪掉一半专家的版本，专心提速。

KV 缓存（模型的"草稿纸"）直接交接，一个字节都不用转，免训练。

数据：Qwen3.6-35B-A3B 上测的。

decode 吞吐最高 1.81 倍。

精度基本不掉。

vLLM 实现，P/D 解耦和同机部署都支持。

论文：https://arxiv.org/abs/2609.34117

深读笔记已生成，见文末链接。

WavePP：流水线 prefill 的"满载调度"

流水线并行（把模型按层切段分给各卡）跑 prefill 有个毛病。

各段缓存各管各的，互不通气。

局部缓存命中了，全流水线不一定能复用，管线经常吃不饱。

WavePP 建在 TensorRT-LLM 上。

它异步找"全段可复用"的前缀。

请求准入和流水线执行重叠跑，管线不再空转。

数据：并发 128、高缓存复用下，prefill 吞吐涨 2.91 倍。

另一组模型上是 2.02 倍。

40 组设置里，37 组赢过基线。

基线包括 TRT-LLM、SGLang、vLLM 三家。

论文：https://arxiv.org/abs/2609.35263

PEARL：给 agentic RL 的 P/D 配比装"自动挡"

训 agent 时，开销大头是 rollout。

rollout 就是模型跟环境多轮交互采样。

colocate 还是解耦？P/D 配比多少？

最优答案随 workload 变，静态设死就亏。

PEARL 按实时画像动态选 P/D 模式和配比。

还能临时借用训练卡的闲 GPU。

数据：吞吐是固定资源方案的 2.17–2.79 倍。

论文：https://arxiv.org/abs/2609.35158

KV-streams：KV 缓存不倒掉，往前"流"

agent 轨迹太长塞不进显存，常用手段是压缩上下文。

但压缩一次就要把整条轨迹重新 prefill 一遍，训练被拖慢。

KV-streams 把 KV 缓存往前流式传输，不用每次倒掉重算。

数据：三种压缩策略，训练墙钟提速 2.6–5 倍。

论文：https://arxiv.org/abs/2609.35750

KVCMAS：多智能体共用一份"草稿纸"的修正术

多个 agent 共用一个模型，各自带着专属前缀。

这些前缀会污染共享上下文的 KV 缓存。

结果是每个 agent 都要重复 prefill，算力和显存双浪费。

KVCMAS 用紧凑的低秩状态表示缓存偏差。

偏差沿着 agent 链在线修正，不用重算。

数据：TTFT（首 token 延迟）快 2 倍。

峰值显存降 3.7 倍。

论文：https://arxiv.org/abs/2609.34060

DAS：循环模型的"浅层打草稿、深层改稿"

Looped Transformer，循环复用同一组权重。

它 decode 很贵。

每个 token 都要跑很多遍循环。

DAS 发现 query/key 比 value 更早"长大"。

浅层的 Q/K 已经接近最终表示。

于是草稿在浅层算，value 直接借用成熟的深层表示，不用重算。

数据：四组模型上吞吐快 4–6.96 倍。

论文：https://arxiv.org/abs/2609.34538

Redline：给扩散模型 serving 的加速配置买"保险"

Block-diffusion 模型，分块并行解码的扩散语言模型。

它的加速配置，以前靠平均分定。

说白了就是拍脑袋。

平均分不告诉你：加速配置在多少 prompt 上会输给慢配置。

Redline 是个有限样本流程，先拿校准 prompt 实测。

把"翻车概率"压进预算，再选最快的过线配置。

数据：风险预算 10% 时，LLaDA2 数学任务提速明显。

每 forward 多提交三分之一 token。

方法同样适用于投机解码和量化，代码已开源。

论文：https://arxiv.org/abs/2609.33887
