Uno：用扩散一次吐多个 token，3 倍加速还不掉精度

原文：Unlocking Lossless Speedups in LLMs via Discrete Diffusion（arXiv:2609.04010v1；Subham Sekhar Sahoo 等，Institute of Foundation Models / UIUC / Cornell Tech / Harvard / Cerebras Systems；2026-09-03 提交）
代码与权重：https://s-sahoo.com/uno

人话解读

大模型慢，慢在"一个字一个字往外蹦"。想快起来，目前两条主流路都有代价。投机解码（speculative decoding，先让小模型打草稿、大模型改）要多养一个 draft 模型。纯扩散 LLM（diffusion LLM，一次吐一堆的并行生成模型）快是快，质量会打折。

这篇论文干了件漂亮事：鱼和熊掌都要。它把模型参数拆成两套。AR 权重（自回归权重，管"说得对不对"）还是标准训练，质量原封不动。另加一套轻量扩散权重（管"一次吐几个"），一次蒸馏就学会并行吐词。推理时扩散权重负责"猛写草稿"，AR 权重负责"严格验稿"。验稿用的是拒绝采样（rejection sampling，不合格就扔），所以最终输出跟原模型逐字生成完全一致。这就是"无损加速"。

打个比方：投机解码是"雇个实习生打草稿"。Uno 是"专家自己练出了左右互搏"：左手哗哗写，右手逐字审。实习生不用雇了，稿子质量还跟专家亲笔一样。

核心方法

1. 参数解耦：两套权重，各管各的

  • θAR（AR 权重）：标准 next-token 训练。决定输出质量。
  • θΔ（扩散权重）：轻量适配器。用 gated LoRA 实现（带开关的 LoRA，只在噪声位置生效）。
  • 训练顺序：先把 AR 训好。然后冻结 AR，只训扩散权重。
  • 扩散权重学的是什么？学会"从 AR 分布里一次并行抽多个 token"。

类比：AR 权重是"主厨的菜谱"。扩散权重是"帮厨的刀工"。菜谱不动，帮厨只练切菜。

2. Diffusion Distillation：一次 drop-in 训练，几乎零负担

  • 灰格子训 AR，蓝格子训扩散（见图 1 上半）。
  • 两条 loss 一起上：蒸馏 loss（学 AR 分布）+ TV loss（让扩散分布贴近 AR，接受率更高）。
  • 训练可以在 SFT（监督微调）之后、RL（强化学习）之前插入。也适合直接拿开源模型（如 Qwen3-8B）做"无痛改造"。

3. Ψ-Spec 采样器：无损的并行采样

这是全文最妙的一笔。分两步走：

  • 第一步，扩散打草稿：一次前向，并行生成一整块 B 个 token。
  • 第二步，AR 验稿：用 AR 分布做拒绝采样。只保留"最长合法前缀"。后面不合法的扔掉。
  • 因为验稿标准就是 AR 自己，所以输出分布数学上等于纯 AR 生成。无损是证明出来的，不是测出来的。
  • 两种采样器：Linear（单条候选，冲系统总吞吐）/Tree（树形多候选，冲单用户延迟）。
  • 还有个附赠技能：inference-time scaling（推理时加算力提质量）。denoising 步数可以超过草稿 token 数。多花算力不涨上下文长度。论文留作未来工作。

类比：Linear 是"生产线只开一条，快而稳"。Tree 是"同时开好几条线赌一把，赌中了延迟最低"。

4. 工程细节：跟投机解码比，省了一套 KV cache

  • EAGLE-3、DFLash 这类投机解码：draft 和 verify 各维护一套 KV cache（KV cache，解码时的"草稿纸"）。
  • Uno：一套 cache 全家共用。峰值显存更低，大 batch 更友好。
  • 两种采样器都已接入 Nano-vLLM（轻量 vLLM 实现）。说明跟 vLLM 生态兼容。

关键数据

  • 最高 3 倍加速：相对基座 AR 模型。各 batch size 下都成立。包括设备能塞下的最大 batch。
  • 最大 batch 下系统吞吐 >5700 tokens/s：UnoQwen（Qwen3-8B 改造版）。相对基座 AR 是 1.6×。单请求（batch=1）是 2.5×。
  • 全 batch 压过投机解码：Uno 的吞吐曲线在 EAGLE-3、DFLash 之上。Pareto 占优（见图 4）。
  • 8B 打 26B：8B Uno 在 agent 工具调用、代码、长上下文上。全面超过 26B 的 DiffusionGemma 和闭源 Mercury 2。
  • 系统吞吐 5255 vs 1197：8B Uno 对 Mercury 2。约 4.6 倍。硬件还更慢。
  • 具体分数：τ2 Banking 90.1（Mercury 2 是 71）。SWE-bench Verified 68.4（DiffusionGemma 18.7）。AA-LCR 长上下文 68.0（Mercury 2 是 36）。
  • RL 训练也受益：扩散权重加速 RL rollout（RL 的"试错采样"）。数学/代码 expert 端到端训练快 40%。RL 改了 AR 权重后，加速比基本还在（TPF 只降 6%）。
  • TPF（Tokens-Per-Forward-pass，单次前向平均出几个 token）：核心效率指标。越高越好。

跟你的研究方向的关联

  • 投机解码的"去 draft"替代路线。你在 MI350 上用 vLLM 跑 llama3.2-3B 测出 660 QPS。瓶颈在 CPU 调度/分词/HTTP。Uno 这条路不碰那些，它摊薄的是"每步搬权重"的开销。大 batch 下还有 1.6×。评估 SGLang P/D 解耦时可以一起看：decode 池到底是"加 draft 模型"划算，还是"换扩散权重"划算。
  • 跟昨天那篇 MTP 自蒸馏是亲戚。MTP 自蒸馏笔记也是"把加速烤进权重"。区别是：MTP 是有损加速（精度掉几个点）。Uno 是无损（AR 验稿背书）。两篇放一起读，能看清"有损 vs 无损"两条路线的取舍。
  • KV cache 视角。EAGLE-3/DFlash 要维护 draft+verify 两套 cache。Uno 一套共用。你关注 KV cache 优化，这个"共享 cache"的设计值得记一笔：显存峰值低，等于同样硬件能塞更大 batch。
  • P/D 解耦的互补性。Uno 加速的是 decode 侧的"每步出词数"。跟 prefill/decode 解耦不冲突。理论上可以叠加：P/D 解耦管资源调度，Uno 管单步效率。
  • 落地提醒。论文的 UnoQwen 基于 Qwen3-8B。Linear sampler 配 B=4 时系统吞吐最优。batch=1 拼延迟用 Tree sampler。真要试，先看 https://s-sahoo.com/uno 的开源代码和 Nano-vLLM 接入。

术语表

  • AR（Autoregressive，自回归）：一次生成一个 token。每个词都看前文。
  • NTP（Next-Token Prediction）：标准训练目标。预测下一个词。
  • d-LLM（Diffusion LLM）：扩散大模型。并行生成，快但通常掉质量。
  • Diffusion Distillation（扩散蒸馏）：让扩散权重学会模仿 AR 分布的训练阶段。
  • Ψ-Spec：本文的采样器家族。扩散打草稿 + AR 验稿。
  • TPF（Tokens-Per-Forward-pass）：单次前向平均生成的 token 数。核心效率指标。
  • Rejection sampling（拒绝采样）：按目标分布"验货"。不合格的草稿扔掉重抽。
  • Lossless（无损）：加速后输出分布与原模型完全一致。精度零损失。
  • Gated LoRA：带开关的 LoRA 适配器。只在指定位置生效。
  • Linear / Tree sampler：单候选采样器 / 树形多候选采样器。前者冲吞吐，后者冲延迟。
  • Inference-time scaling：推理时多花算力换更好结果。不增加上下文长度。
  • Pareto 占优：两个维度上同时不输对手。至少一维严格更好。
  • Nano-vLLM：社区写的轻量 vLLM 实现。教学和实验常用。
