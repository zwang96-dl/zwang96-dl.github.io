BeaconKV：给长推理的 KV 缓存装"信标"，只压不重要的

原文：BeaconKV: Key-Value Cache Compression Guided by Beacon Queries for Efficient Large Reasoning Model Inference
arXiv:2609.04971v1，2026-09-04 提交；ICML 2026（第 43 届，首尔）。
作者：Janghyeon Kim、Minsoo Kim、Kyuhong Shim、Jungwook Choi（汉阳大学、成均馆大学）。

人话解读

  • 长思考模型想得越多，草稿纸（KV cache）越占显存。
  • Qwen3-4B 生成 32K token、batch 16 时，草稿纸超过 77GB。
  • 一张 80GB 的卡，差点被草稿纸 alone 塞爆。
  • 旧的压缩方法有个毛病：只看最近几步猜谁重要。
  • 但这篇发现，模型思考时有些 token 会"回头看"。
  • 它们会翻出早期定的解题计划，保持全局不跑偏。
  • 这些"回头看"的 token 叫 TRT（Thought Revisiting Tokens）。
  • 旧方法猜不到它们，于是把后面要用的 KV 提前扔了。
  • 更妙的是：回头看的查询们会扎堆，聚成少数几类。
  • 那就不用存全部历史，只存每类的"代表"就行。
  • 这些代表就是"信标查询"（beacon queries）。
  • 像灯塔一样，照出未来会被重访的 KV。

核心方法

  • 把查询分成两类：local（只看邻居）和 global（看远处，对应 TRT）。
  • 观察发现：global 查询在向量空间里聚成少数几个簇。
  • BeaconKV 维护两套观察查询：最近的 16 个 + 信标查询。
  • 信标查询是每个簇的代表，用来预测未来谁会被重访。
  • 挑代表用 Continual FPS（最远点采样，在线算法）。
  • 它专挑几何上最分散的查询，存得少、覆盖全。
  • 打分方式：信标查询和最近查询一起算注意力权重。
  • 聚合用 max（取最大），不压稀疏但高价值的信号。
  • 定期淘汰：缓存满了就按打分 Top-K 保留。
  • 全程不用训练，即插即用。

关键数据

  • 显存：77.0GB → 13.3GB，压了 5.8 倍（Qwen3-4B，32K 生成，A100 80GB，2K 预算）。
  • 吞吐：82.3 → 356.4 tokens/s，提了 4.3 倍以上。
  • 解码延迟：5573.4 秒 → 1287.3 秒。
  • 精度：基本追平全量 KV，4 模型 × 4 基准（AIME24、MATH-500、GPQA-Diamond、LiveCodeBench）。
  • 最大领先：Qwen3-14B 的 AIME24，1024 预算下比旧方法高 31.7 个百分点。
  • 同预算对打 RPC：2K 预算/batch 192，LiveCodeBench 高 6.3 个点。
  • 预算压到 1K/batch 320，领先扩大到 12.3 个点。
  • 消融：最近 16 + 信标 16 是最佳配比（AIME24 上 64.6% 精度）。
  • max 聚合稳赢 mean 聚合：256 预算下 23.3 对 18.8。

跟你研究方向的关联

  • 你在评估 SGLang 的 PD 解耦，KV 要在 prefill/decode 节点间搬。
  • KV 越小，搬运越便宜，解耦的收益越大。
  • 你在 MI350 上跑 vLLM 吞吐 benchmark，显存是硬瓶颈。
  • 5.8 倍压缩直接放大 batch size，吞吐数字会好看很多。
  • "回访预测"的思路，可以借到多模态长上下文上。
  • 多模态的 encoder 输出同样是"早期定计划"的那类 KV。

术语表

  • KV cache：草稿纸。存每个已生成 token 的 key/value，解码时复用，省得重算。
  • LRM（Large Reasoning Model）：长思考推理模型。靠超长思维链解题，比如 DeepSeek-R1。
  • TRT（Thought Revisiting Tokens）："回头看"的 token。会重新关注早期上下文的解码步。
  • local/global queries：本地/全局查询。只看邻居的 vs 看远处的。
  • beacon queries：信标查询。每类全局查询的代表，用来预测未来重访。
  • FPS（Farthest Point Sampling）：最远点采样。专挑互相离得最远的点做代表。
  • pre-RoPE query：加旋转位置编码之前的查询向量。用来算几何相似度，避开位置干扰。
  • Top-K selection：只保留打分最高的 K 个 KV，其余淘汰。
  • max aggregation：跨 head、跨查询取最大值聚合，保住稀疏但高价值的信号。
  • TTFT：首 token 延迟。用户敲回车到看到第一个字的时间。
  • pass@1：一次采样就答对的比例。推理基准常用指标。
