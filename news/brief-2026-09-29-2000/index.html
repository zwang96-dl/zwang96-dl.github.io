新技术与论文

  • 中科院计算所发了篇 SPLASH：注意力并行也能「运行时换挡」了。
  • 现在的引擎启动时定死一种并行方式。
  • 请求少用 TP：张量并行，权重切开分到各卡。
  • 长 prompt 用 CP：上下文并行，按位置切分。
  • 请求多用 DP-attention：数据并行注意力，每卡独立干一批。
  • Agent 负载一直在变：开头几千个短请求，结尾只剩几条长推理链。
  • 定死的布局总有一段跑亏，像穿一双鞋跑全程马拉松。
  • SPLASH 让引擎在服务中切换布局，不用排空重启。
  • 切换开销不到单步的 0.51%，几乎无感。
  • 它还提出了新布局 DOP：权重切分、KV 单主人，零冗余。
  • B200 上跑 GLM-5.3，每卡腾出 12.69 GiB 给 KV。
  • 吞吐快 1.3–1.73 倍。
  • SGLang 实现已经开源。
  • 「值得深读」：跟你做的 P/D 解耦评估同维度，静态部署追不上动态负载。
  • 这篇的调度思路可以直接参考：成本模型选布局，设阈值防来回抖。
  • 论文：https://arxiv.org/abs/2609.37626
  • 动态跳层一直「省了算力、亏了调度」，vSkipper 把这账算平了。
  • 跳层就是让每个 token 只跑一部分层，算力能省。
  • 但旧方案配不上连续批处理，省的算力全被调度亏掉。
  • FlexiDepth 跳了 8 层，解码反而慢 14–21%。
  • vSkipper 做了一层虚拟化：跳层变成插件。
  • 连续批处理、paged KV、CUDA 图全保留。
  • 想用跳层加速，先得过 serving 引擎这一关。
  • 论文：https://arxiv.org/abs/2609.37062
  • Agent 服务的 KV 存哪是个新问题：历史长，还穿插工具调用。
  • 新论文把稀疏 KV 存到 SSD 上，比放 CPU 内存便宜。
  • 难点是选哪些 KV 要读：选择依赖推理中间值。
  • SSD 读取卡在关键路径上。
  • 长上下文 agent 服务的存储分层思路，值得看一眼。
  • 论文：https://arxiv.org/abs/2609.36938
  • 这批论文里 KV 压缩扎堆。
  • WUSH-KV 做低比特量化，KV-Kaizen 学压缩配置。
  • ARC-KV 做重建式压缩。
  • AVSG 加速 KV offload 的稀疏读取。
  • 说明长上下文的瓶颈全压在 KV 显存上，各种路数都在卷。
  • 论文：https://arxiv.org/abs/2609.38121
  • 论文：https://arxiv.org/abs/2609.37988
  • 论文：https://arxiv.org/abs/2609.36835
  • 论文：https://arxiv.org/abs/2609.37538
  • SEED 是自投机解码的新玩法：自己写草稿、自己改。
  • 早退法草稿便宜但质量差，多 token 预测质量好但每步都要全量前向。
  • SEED 复用深层表示，草稿又好又便宜，像让实习生先看专家笔记再打草稿。
  • 论文：https://arxiv.org/abs/2609.36590
