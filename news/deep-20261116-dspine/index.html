DSpine：草稿并排猜，相邻层互相递话，投机解码接受长度涨 28%

  • 原文：Haohui Zhang、Keyu Chen 等，腾讯优图实验室，arXiv:2609.36173（2026-09-28 提交，v2 为 2026-10-10）
  • 原文链接：https://arxiv.org/abs/2609.36173
  • 工程落地：vLLM PR #67094（2026-11-16 合入），Qwen3.8-27B 已接上
  • 工程链接：https://github.com/vllm-project/vllm/pull/67094
  • 项目页：https://dspine-project.github.io
  • 说明：数字全是作者自报，每组配置只跑一次

一句话

并行草稿的问题是各猜各的。

拼在一起经常对不上号。

大模型验到一半就卡住。

DSpine 让每个位置把猜测递给下一个。

递话从第一层就开始。

接受长度一下涨了 28%。

人话解读

先讲投机解码是什么。

它就是先让小模型打草稿。

大模型再一次验完，省时间。

草稿越准，省得越多。

以前的并行草稿一次猜一整块。

块里每个位置同时开猜。

问题是它们互相不知道对方猜了啥。

每个词单独看都挺合理。

拼成一串可能驴唇不对马嘴。

大模型按顺序验，第一个错的就截断。

后面的猜得再好也全作废。

以前的修补都在事后打补丁。

DFlash2 用卷积把邻居状态混一混。

Domino、DSpark 在骨干算完后再调分布。

这些都没把前任的猜测真正送进计算。

DSpine 换了个思路。

它在每一层都让前任把预测递给后任。

后任一边算一边收到前任的消息。

因果链随着网络深度一层层展开。

所有位置还是并行更新，不用排队等。

核心方法

方法分四块，缺一块都不完整。

第一块是统一迁移空间。

它用目标模型的输出词向量建表。

先归一化，再做 PCA 白化。

白化就是去掉所有词共有的成分。

剩下的方向才能区分不同的词。

预测特征和已定 token 都进同一张表。

这样一条通道能传两种东西。

骨干里传的是预测，解码时传的是定好的词。

第二块是相邻因果注入。

每层算完，前任把预测特征递给后任。

门控决定后任吸收多少。

门由双方特征一起算出来。

浅层的前任预测还不太稳。

门控会自己把不可靠的消息压小。

注入从第一层就开始。

消息在下一层继续往下传。

前任的前任也能间接影响后任。

第三块是块因果注意力。

位置 t 只能看目标上下文和块内 0 到 t。

注意力方向和注入方向一致。

训练时注入的信息不会倒流回前面。

草稿还是一次前向，成本没变。

第四块是转移缓存。

解码时每个位置的分数依赖前任选了啥。

直接算要一个个位置串行走。

转移缓存先把所有相邻候选对的分数并行算好。

候选数 K 取 16，一共 K 的平方对。

选的时候直接查表，不用再算矩阵。

最后再加逐层监督。

每层都用余弦损失对齐词向量表。

逼浅层早点形成能用的预测特征。

训练用 5 层骨干，块大小 16。

ShareGPT 数据，训 6 个 epoch。

四个基线都在同一份数据上重训过。

关键数据

先看接受长度，温度 0，Qwen3-8B。

七个任务平均，DFlash 是 3.77。

DSpine 涨到 4.82，高了 27.8%。

比最强的基线 DFlash2 高 10.0%。

采样温度 1 时，比最强基线高 12.8%。

Qwen3-4B 上，领先幅度是 5.4% 和 10.1%。

七个任务是数学、代码、聊天三类。

数学是 GSM8K 和 MATH-500。

代码是 HumanEval、MBPP、LiveCodeBench。

聊天是 MT-Bench 和 Arena-Hard。

再看 SGLang 上的真实吞吐。

Qwen3-8B 比 DFlash2 平均高 11.1%。

比自回归解码最高快 4.0 倍。

Qwen3-4B 比 DFlash2 平均高 6.5%。

比 DFlash 平均高 23.3%。

并发 2 到 32，每个任务都领先。

成本拆解也值得看。

验证占每轮时间的 72% 到 76%。

注入只加 0.15 毫秒，分摊到五层。

每生成一个词，DSpine 是 1.32 毫秒。

DFlash2 是 1.48 毫秒，快了 10.9%。

vLLM 这边的落地数也出来了。

Qwen3.8-27B 配 DSpine 草稿。

单张 H100，并发 8，每步 15 个草稿词。

贪心草稿时，GSM8K 每步接受 6.93 个词。

MATH-500 是 6.38 个，HumanEval 是 5.71 个。

MBPP 是 5.91 个，MT-Bench 是 4.69 个。

概率草稿时，每项低 0.4 到 0.5 个词。

跟研究方向的关联

这篇跟投机解码评估直接对口。

DSpine 是 DFlash、DFlash2 之后的新草稿器。

评估清单里应该给它单列一档。

接受长度 τ 和每轮时间拆解都能直接复用。

注入成本只有 0.15 毫秒，说明条件做进骨干里不贵。

以后评估新草稿器，先问注入成本占几成。

P/D 解耦这边也有个待确认的点。

论文和 PR 都只在单机上测过。

P/D 拆开跑时，草稿模型放哪一侧还没验证。

读题节点和解码节点各放一个草稿器。

还是只在解码侧放，值得先想清楚再测。

还有一点跟 H100 评估相关。

vLLM 的数是在 Qwen3.8-27B 上测的。

论文的数是在 Qwen3-4B 和 8B 上测的。

两个设置里的思考模式还不一样。

论文关了思考，PR 开了思考。

两边的接受长度不能直接放一起比。

注意事项

数字全是作者自报，每组只跑一次。

论文只测了 Qwen3-4B 和 8B 两个模型。

27B 的数只在 vLLM 的 PR 里出现。

K 取 16 时，转移缓存要算 256 对分数。

K 再放大，预算成本按平方涨。

吞吐只在 SGLang 上测过。

硬件细节在附录里，没在正文展开。

术语表

  • 投机解码：小模型先打草稿，大模型一次验完的加速办法
  • 接受长度：每轮大模型平均接受几个草稿词
  • 草稿模型：专门用来打草稿的小模型
  • 并行草稿：一次前向同时猜一整块词
  • DFlash：腾讯的并行草稿方法，DSpine 的前身
  • DFlash2：DFlash 的升级版，用卷积混邻居状态
  • 统一迁移空间：预测和定好的词共用的一张词向量表
  • 门控注入：用门决定吸收多少前任消息的机制
  • 转移缓存：提前算好所有相邻候选对分数的表
  • 块因果注意力：块内只能看前面位置的注意力
  • 逐层监督：每层都对齐词向量表的训练约束
  • 残差流：每层输出累加的主通道
  • PCA 白化：去掉共有成分、让方向更能区分词的处理
