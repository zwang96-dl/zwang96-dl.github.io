TideCache：混合架构的缓存调度，智能体轮次最多涨 2 倍

  • 原文：TideCache: Efficient Hybrid LLM Serving with Transparent Cache Management and Layer-Wise Streaming
  • 作者：Jinbin Luo、Shang Yang、Song Han、Qinghao Hu，麻省理工学院；Xiaozhe Yao，苏黎世联邦理工学院；Zhijian Liu，加州大学圣迭戈分校
  • 提交：2026-11-19，arXiv:2611.26619
  • 原文链接：https://arxiv.org/abs/2611.26619
  • 说明：数字全是作者自报。
  • 只在 GB300 和 GH200 超级芯片上测过。
  • 只测了 7 组模型和平台配置。

一句话

混合模型的缓存分两类，需求天天变。

死板分区总有一边不够用。

这篇让分池跟着需求动，还把取数藏进算力空隙里。

智能体轮次最多涨到 2.04 倍。

人话解读

现在的开源大模型，很多是混合结构。

Kimi K3、GLM-5.3、Qwen3.8 都是这路数。

模型里隔几层才有一个全局注意力层。

其余是滑窗或循环层，状态大小固定。

全局注意力层的 KV 缓存跟着上下文长。

循环层的状态多大都固定。

两边的缓存需求不一样，还天天变。

聊天多时全局 KV 吃紧。

智能体多时循环状态吃紧。

固定分区就像把衣柜隔死。

一边塞爆了，另一边还空着。

SGLang 和 vLLM 都有动态分池。

但换分区要搬数据、改地址。

注意力后端和前缀缓存都得跟着改。

这篇换了个思路。

虚拟地址一次定死，永远不动。

只换地址底下挂的物理页。

搬家不用改门牌号。

这是第一个办法，叫透明缓存池。

第二个办法更巧。

解码时 CPU 和 GPU 之间的链路基本是空的。

GB300 上这条链路能跑 211 GB/s。

一个 57 毫秒的解码步，能搬约 12 GB。

混合模型算循环层时，根本不用全局 KV。

这段时间正好把下一层要的前缀取回来。

上一层的用完就扔。

一层一层流着取，不用全放显存里。

像流水线一样，边算边取。

第三个是请求调度器。

它看一眼队首的请求。

能常驻就常驻，不行就走流式。

三个件拼起来，就是 TideCache。

核心方法

  • 透明缓存池：每个缓存组件一个子池。
  • 子池占一段固定虚拟地址。
  • 底下挂多少物理页，可以随时变。
  • 物理页 2 MiB 一张，用 CUDA 虚拟内存接口管。
  • 每 8 个前向步为一个周期，最多同时搬一次。
  • 先定接收方、数量和捐献方。
  • 再把捐献方的行从分配器里停掉。
  • 等所有前向步跑完，才真正换页。
  • 换页只动物理映射，不动虚拟地址。
  • 注意力后端、页表、CUDA 图都不用改。
  • 分池策略是失败驱动。
  • 队首请求进不来，才给卡住的组件扩容。
  • 扩容先找空闲页，再找别的池子的闲置容量。
  • 最后才清掉放了 τ 秒没人碰的冷前缀。
  • 热前缀不碰，免得回头重算。
  • 缓存流式器：全局 KV 分常驻区和流式区。
  • 流式区是所有全局注意力层共用的槽位。
  • 每层跑之前，才把这层的前缀拷进槽位。
  • 双缓冲重叠：一个槽位在读，另一个在算。
  • 只给调度器挑中的一部分请求走流式。
  • 全走流式会把链路撑爆。
  • GPT-OSS-120B 的例子里，整批 8K 上下文。
  • 全量搬要 21.9 毫秒，超过 19.7 毫秒的解码步。
  • 所以只挑一部分请求流式，其余常驻。
  • 请求调度器：看队首请求和队列状态。
  • 能常驻就常驻，显存不够就走流式。
  • 两边都不行，就报是哪个组件卡住了。
  • 触发缓存池扩容或缩容。

关键数据

  • 7 组配置，GB300 和 GH200 上都测了。
  • 模型有 GLM-5.3-Flash、Qwen3.8-27B。
  • 还有 GPT-OSS-120B、Kimi K3。
  • Ring-2.6-1T、Qwen3.8-2.4T 也在内。
  • 对照是 SGLang 加 HiCache，调到最好分区。
  • 智能体轮次最多涨到 2.04 倍。
  • 在 GH200 上，GPT-OSS-120B 这组。
  • GB300 上最多 1.44 倍。
  • 整体每词延迟降 20% 到 59%。
  • 智能体首字时间最多快 3.05 倍。
  • 透明缓存池单独看也不差。
  • 不用按流量调分区，也能拿到最好分区的 96.3% 到 113.6%。
  • 跟 SGLang 的统一内存池比，Kimi K3 上还高 0 到 3.7%。
  • 分区敏感度实验里，Kimi K3 最好的固定分区跑 67 轮。
  • TideCache 跑 94 轮，高 40%。
  • 每词延迟还低 29.5%。
  • 负载突变实验里，Qwen3.8-27B 在 GH200 上。
  • 300 秒到 600 秒来了个突发。
  • TideCache 完成 183 轮，HiCache 只有 115 轮。
  • 多 59%，智能体首字从 25.70 秒降到 5.68 秒。
  • 降了 78%，整体每词延迟从 63.4 毫秒降到 39.3 毫秒。
  • 突发时有界状态池从 5.6 GiB 长到 17.6 GiB。
  • 突发过去又缩回约 6.0 GiB。
  • HiCache 的排队峰值 74 个请求。
  • TideCache 只有 15 个。
  • 代价很小：同等批量下解码步最多慢 6.3%。
  • 有效全局 KV 容量从 148K 涨到 260K 个 token。
  • 能撑住的最大批量从 16 涨到 29。
  • 峰值解码吞吐从 1.19K 涨到 1.47K 词每秒。
  • 涨 24%。
  • 短板也要记下来。
  • 只在超级芯片上测过，NVLink-C2C 是前提。
  • 普通 PCIe 卡上链路窄得多，流式收益要打折。
  • 数字全是作者自报，只跑了 7 组配置。

关键图表

图 1：两个机会。上半截是容量共享。固定分区下，一个请求因为全局 KV 不够被挡住。TideCache 把闲置的容量挪过来，请求就放行了。下半截是带宽利用。解码时 CPU 到 GPU 的链路基本是空的。TideCache 趁算循环层的空隙，把下一层要的前缀流式取回来。

图 2：混合模型的结构。左边是模型堆叠。隔几层一个全局注意力层，其余是有界状态层。右边是两种层的计算模式。全局注意力要看全部历史。滑窗、GDN、KDA 只看窗口或固定大小的状态。两种状态都存在显存里，抢同一块地方。

图 3：TideCache 的总览。左边数据面。显存里虚拟布局固定，物理页在底下换。内存里放着待取的前缀。右边控制面。请求调度器决定走常驻还是流式。缓存流式器用双缓冲，把前缀一层一层取回来。聊天、智能体、文档、标注四种流量都走同一套。

图 4：7 组配置的端到端结果。左三列是 GH200，右四列是 GB300。浅灰是 SGLang，深灰是 SGLang 加 HiCache，红色是 TideCache。上中下分别是每词延迟、智能体轮次、首字时间的加速比。柱子越高越好。红色柱子全面高于 1.0 那条虚线。GH200 上 GPT-OSS-120B 的智能体轮次到 2.04 倍。

跟研究方向的关联

  • 混合模型是现在的主流，Kimi K3 和 GLM-5.3 都是。
  • KV 缓存账要按组件分开算。
  • 全局 KV 和有界状态各记一笔。
  • 固定分区调得再好，也追不上会动的分池。
  • 评估里分区比例要当变量报。
  • 只报最好分区会把差距藏起来。
  • 流式取数是 PD 解耦之外的另一条藏延迟路子。
  • 解码节点的空闲带宽也能算进账里。
  • 透明换页不改虚拟地址，是个通用套路。
  • 前缀缓存和 CUDA 图都不用动。
  • 智能体流量下，首字时间比吞吐更敏感。
  • 这篇首字最多快 3 倍，值得抄进评估指标。
  • 跟 21 点版的 NVMe KV 实测对照看。
  • 一个往硬盘扩容量，一个在显存里腾地方。
  • 两篇拼起来，分层缓存的账就全了。
  • 跟 DisSparse 和 IndexerStage 也能对照。
  • 那两篇省的是读 KV 的带宽。
  • 这篇省的是放 KV 的地方。
  • 超级芯片是前提，普通卡上要重测。
  • PCIe 链路窄，流式收益先打个问号。

术语表

  • 混合架构：全局注意力层和循环层混搭的模型。
  • 全局注意力层：每个词都能看到全部历史的层。
  • 有界状态层：滑窗或循环层，状态大小固定。
  • 全局 KV：全局注意力层的 KV 缓存，跟着上下文长。
  • 透明缓存池：虚拟地址不动，只换物理页的分池办法。
  • 缓存流式器：解码空隙里逐层取前缀的组件。
  • 请求调度器：决定请求走常驻还是流式的组件。
  • 子池：一个缓存组件占的固定虚拟地址段。
  • 周期：每 8 个前向步，缓存池最多搬一次家。
  • 冷前缀：放了 τ 秒没人碰的前缀，可清。
  • 双缓冲：一个槽位在读，另一个在算。
  • HiCache：SGLang 的分层缓存，前缀放内存里。
  • 统一内存池：SGLang 的动态分池方案。
  • 首字时间：从发请求到第一个词出来的耗时。
  • 每词延迟：每输出一个词的平均耗时。
  • NVLink-C2C：超级芯片上 CPU 和 GPU 之间的高速链路。
