RaReCache：小模型 prefill，大模型只重算关键 token

  • 原文：https://arxiv.org/abs/2610.11358
  • 作者：USC、UCI、Intel Labs（Sreetama Sarkar 等）
  • 日期：2026-10-08（arXiv 10/8 批次）

一句话人话

级联 serving（先小模型、后大模型）有个老大难。 中途换大模型，KV cache（推理时的草稿纸）不能通用。 大模型得把提示词从头重算一遍，贵得很。 RaReCache 让小模型先做 prefill。 大模型只重算信息最密的 30% token。 剩下的 cache 用线性映射（一次矩阵乘法）翻译过来直接用。 效果：Qwen3 0.6B→14B 上测的。 prefill 快 3 倍，单卡吞吐 1.8 倍。

核心方法

  1. 线性映射：把小模型的 KV 翻译成大模型的 KV。
  2. 同一家族的模型共用分词器，提示词 token 数对得上。
  3. 每个目标层挑 K 个最相关的源层，拼成输入。
  4. 用岭回归（带正则的最小二乘）解映射矩阵 W。
  5. 离线一次拟合，不用梯度下降，成本很低。
  6. key 先去旋转再映射，位置信息不掺和进来。
  1. Rank disagreement 打分：找出映射不可信的 token。
  2. 核心观察：映射的失败集中在少数信息密集的 token 上。
  3. 注意力分数试过：都盯着模板 token，问题 token 一个没挑中。
  4. l2 误差也试过：误差大不等于下游掉点，照样不准。
  5. 新打分法：对比全秩映射和降秩映射的预测差。
  6. 校准数据没见过的方向，两个映射分歧大。
  7. 分歧大的 token，就是该重算的信息密集 token。
  1. 选择性重算：只重算打分最高的 ρT 个位置。
  2. ρ 是重算预算，0.3 是甜点。
  3. 各层共用同一批重算位置，实现简单。
  4. 打分只用源模型和映射算，不用碰大模型。

关键数据

  • Qwen3 0.6B→14B（23 倍参数差），重算 30%。
  • GSM8K 精度 71.6%→90.2%，恢复 14B 原生精度的 94.8%。
  • MMLU-Redux、ARC 两套上同样。
  • LongBench-E 恢复 95% 以上。
  • Llama3 8B→70B（8.8 倍），重算 40%，保留 96.5%。
  • prefill 加速最高 3.04 倍，ρ 取 0.2–0.3 最划算。
  • 单卡吞吐是纯大模型 prefill 的 1.8 倍。
  • 高负载下 TTFT（首 token 时间）大降。
  • 中位数降 5 倍，p99 降 6.4 倍。
  • 同样 30% 预算，比 CacheBlend 高约 10 个点。
  • 反向（大→小）也有效。
  • 14B 的 cache 带飞 1.7B。
  • MMLU-Redux 涨 14.4 个点。

跟你的研究方向的关联

  • 你正在评估 SGLang 的 P/D 解耦。
  • prefill 和 decode 分开跑。
  • RaReCache 是同一家族的思路：prefill 和"重算"分开跑。
  • 级联 serving 里小模型先 prefill。
  • 大模型只做关键 token 的重算。
  • P/D 解耦要传 KV cache，跨模型复用是下一步的自然延伸。
  • 它的 rank disagreement 打分法可以借来用。
  • 挑 P/D 传输里值得重算的 token。
  • Dual-QK（本轮另一篇）做的是同 cache 内压缩，两篇可以叠加看。

术语表

  • KV cache：推理时的草稿纸。
  • 存每层每个 token 的 key 和 value。
  • prefill：提示词理解阶段，一次性算完所有提示词 token。
  • decode：生成阶段，一个 token 一个 token 往外吐。
  • TTFT：首 token 时间，用户感知的延迟。
  • 级联 serving：简单问题小模型答，难问题升级给大模型。
  • 岭回归：带 L2 正则的最小二乘，防过拟合。
  • rank disagreement：本文的打分法。
  • 映射在陌生方向上分歧大的 token 优先重算。
