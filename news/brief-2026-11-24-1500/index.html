vLLM：语音转写模型能跑了

#69683 让 OmniASR 走 Transformers 后端。

OmniASR 是个 300M 的语音转写模型。

说话转文字，就是它干的活。

以前要手动指定后端才能加载。

现在默认就能跑。

#68820 修了 HiSparse 的缓存排序。

HiSparse 是稀疏注意力的缓存管家。

请求跑完后，显存里的干净页会留下来。

以前这些副本比旧前缀活得久。

结果新请求来了，旧前缀的索引块没了。

副本再快也没用，等于白留。

现在先复用副本，索引块不会被提前挤掉。

#62004 给 Gated DeltaNet 的解码提速。

Gated DeltaNet 是一种循环结构模型。

跟 Mamba 一类，不用传统注意力。

ReplaySSM 会把状态空间模型的输入缓存下来。

解码时少算一遍，速度就上来了。

这是 ReplaySSM 的第二块拼图。

第一块 Mamba2 早就合入了。

#69564 砍掉了 LM Format Enforcer 后端。

这是个结构化输出的老后端。

用的人少了，直接移除。

#64163 让集成显卡走更快的 MoE 路径。

多 token 的批量推理也能用排序融合版。

#53377 是 MNNVL 集合通信的修补。

来源：https://github.com/vllm-project/vllm/pull/69683、https://github.com/vllm-project/vllm/pull/68820、https://github.com/vllm-project/vllm/pull/62004、https://github.com/vllm-project/vllm/pull/69564、https://github.com/vllm-project/vllm/pull/64163 和 https://github.com/vllm-project/vllm/pull/53377

SGLang：KV 缓存能跨机柜走 NVLink 了

#51416 给 Mooncake Store 加了新池子。

Mooncake 是 SGLang 的 KV 缓存跨机传输层。

KV 缓存就是解码时的草稿纸。

新池子用 EGM 撑腰。

EGM 是跨机柜共享内存的技术。

一台机器的 GPU 能直接读写另一机柜的内存。

HiCache 的三级缓存页可以放过去。

对 P/D 解耦部署很友好。

prefill 和 decode 分开跑时，缓存不用绕远路。

#47578 把 KV 分片的分配器改成批量操作。

一页一页拿改成一批一批拿。

分配和释放都省了来回。

#47576 是上下文并行的元数据上传优化。

一次固定内存拷贝就搞定。

#51631 是 AMD 的表更新。

给 gfx1250 的 TP2 和 TP4 配了新表。

来源：https://github.com/sgl-project/sglang/pull/51416、https://github.com/sgl-project/sglang/pull/47578、https://github.com/sgl-project/sglang/pull/47576 和 https://github.com/sgl-project/sglang/pull/51631

TRT-LLM：FLUX 图像生成少等了

#22657 给 VisualGen 的 FLUX 瘦身。

FLUX 是个文生图模型。

以前每步都要跟 CPU 同步一次。

像每跑一步就停下来打个报告。

现在这步同步砍掉了。

不变的文本和位置编码也缓存下来复用。

#22848 修了并行 JIT 探测的张量释放。

#22794 是 MXFP8 的调优日志。

#22399 是测试重构。

来源：https://github.com/NVIDIA/TensorRT-LLM/pull/22657、https://github.com/NVIDIA/TensorRT-LLM/pull/22848、https://github.com/NVIDIA/TensorRT-LLM/pull/22794 和 https://github.com/NVIDIA/TensorRT-LLM/pull/22399

Dynamo：滚动升级不断供了

#18586 修了滚动升级时的 503。

滚动升级就是新老版本交替上线。

以前新 decode 起不来时，老 prefill 先被缩到零。

请求进来直接 503。

现在老 prefill 会留着站岗。

直到新一代 worker 真能接活才撤。

做 P/D 解耦部署的人最吃这颗定心丸。

#18061 让 GLM 的 JSON 流式输出更早开始。

#18166 是快照恢复的环境变量刷新。

vLLM-GR 0.30.0：给推荐模型用的 vLLM

vLLM 家出了个新框架。

专门跑生成式推荐模型。

推荐模型就是猜你接下来想点什么。

它一次请求要返回一堆候选物品。

用束搜索一次探索多条候选路径。

束搜索就像同时追好几条线索。

vLLM-GR 把这套搜索直接做到引擎里。

提示词的 KV 缓存还能跨束共享。

官方报的 P99 延迟比 SGLang Beam 低不少。

H20 上束宽 256、批量 8 时是 369 毫秒。

SGLang Beam 同档是 1280 毫秒。

数字是官方自报，没独立复现。

支持 NVIDIA 卡和昇腾 NPU。

来源：https://github.com/vllm-project/vllm-gr/releases/tag/v0.30.0
