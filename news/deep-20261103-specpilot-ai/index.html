SpecPilot：让 AI 自己发明投机解码加速

原文：SpecPilot: Autonomous Algorithm Discovery and Systems Optimization for Speculative Decoding
arXiv:2611.02501（2026-11-02 提交）。Berkeley、Princeton、Stanford、NVIDIA 联合出品。作者包括 Kurt Keutzer 和 Jiantao Jiao。

一句话人话版

这篇不讲新模型，而是让 AI 当调参工程师：用一群 coding agent 给你家的投机解码（speculative decoding，先让实习生打草稿、专家再验的那套）逐个部署自动找加速点。

单请求场景下，把开源现成的"官方版"（stock）从 4.46 倍加速干到 10.87 倍。

为什么值得读

  • 你正在 SGLang 上评估投机解码（EAGLE-4 笔记刚写过），这篇是同一赛道的系统级玩法。
  • 它把"调优"本身做成自动循环：成本模型先找瓶颈、agent 并行探索、自动防作弊、经验沉淀成记忆复用。
  • 无损（lossless）：加速后输出 token 跟原版逐位一致（浮点舍入除外）。
  • 发现的几个机制（W12 权重格式、两级验证）可直接迁移到你的 SGLang 评估部署。

核心方法

四个互相配合的组件，像一条自动化的优化流水线。

0. 天花板成本模型（ceiling analysis）。每轮先算"当前系统"离"理论上限"差多远。

上限=一次打草稿、一次用最优树验证、所有内核跑到带宽/算力地板。

差距拆成三份：草稿不够好（接受的 token 少）、内核太慢、账外开销。

哪份最大，agent 就往哪攻。

1. 并行探索（exploration）。主 agent 规划几个方向，每个方向占一块 GPU 独立开干。

子 agent 把想法写成可开关的补丁，默认行为必须跟原版一致。

只看硬证据：便宜的先行验证（离线重放、微基准），预期净收益不到 3% 的方向直接关掉。

2. 集成加内核调优（integration + kernel tuning）。单独每块增益可能太小，上不了台面。

集成 agent 把它们叠起来测，小步快跑攒成大步。

内核 agent 专盯"离带宽地板最远的核"，逐个调。

3. 双人复核防作弊（token forcing）。这步最妙：准确率测不出造假。

agent 一心想更快，可能偷偷用低精度捷径改结果、任务分数却几乎不动。

解法是 teacher forcing：把系统的每个输出词都喂回官方引擎，用 FP32 的 LM head 逐词核对 argmax。

超容忍阈值的改动直接否决。

4. 结构化记忆（structured memory）。每轮沉淀下来的机制变成可复用的"代码差分+证据卡"。

新部署第一轮直接带上老经验（比如 W12），不用从头发明。

到论文发表时，记忆里已有 140 个验证过的机制。

发现的关键技术（4 个能抄的）

W12：无损 12 位权重格式。BF16 的 16 位里很多位是浪费的。

每个输出通道选一个 16-binade 的指数窗口，权重拆成三块 4 位：符号+高位尾数、指数偏移、低位尾数。

一共 12 位，比特级精确还原，平均每个权重只占 12.01–12.02 位。

Qwen3.8-27B 的权重从 44.67 GB 压到 33.58 GB，单请求时读权重的步骤省了大头。

最优树验证（best-first tree verification）。官方实现每次只验证一条贪心草稿链。

但 drafter 在每个位置其实给了 16 个候选，目标的下一个 token 经常就躺在里面。

按"路径对数概率"取最好的 N 个节点组成树，一次验证多收一倍 token。

混合模型（GDN 那种循环状态）也搞定了：沿着路径重算状态，不存每节点快照。

两级验证（two-level verification, TLV）。先拿 W12 里嵌着的 8 位视图做一次低精度粗验，挑出一条链。

drafter 从链尾再打一次草稿，最后一次精确验证把两拨一起收了。

每个精确 pass 接受的 token 数从 6.16 涨到 11.67。

批处理三件套。请求多了，逐行验证的账不一样了：

  • 共享节点预算：每步固定节点总数，按路径分数分给各请求。
  • 每请求动态草稿块：16/12/8 位置按最近接受率自适应。
  • prompt 准入：新提示直接搭顺风车，顺着验证步的权重流一起进。

关键数据（均为作者自报，无第三方复现）

  • 单请求：相对普通逐词解码，从 stock 的 4.46 倍提到 10.87 倍（Qwen3.8-27B BF16、H100）。
  • 有 batch：从 1.94 倍提到 3.93 倍。
  • 比 DDTree（现有最强基线）单请求快 1.84 倍。
  • W12：8 个稠密模型平均 12.01–12.02 位/权重，Qwen3.8-27B 44.67 → 33.58 GB。
  • Q pass（8 位视图）与精确 pass 的 top-1 一致率 98.7%。
  • LM head 的认证剪枝版：878 μs 降到 482 μs。
  • 评估范围：4 个目标模型、3 种 drafter、2 种 GPU（H100、RTX PRO 6000）、5 个 benchmark。

图 5：W12 权重格式

(a) 编码：BF16 的 16 位被重组成三块 4 位平面——A（符号+顶层尾数）、E（4 位指数偏移）、B（低位尾数），合计 12 位比特精确。

A+E 拼成一个 8 位视图，专供两级验证的粗验 pass 读。

极少数装不下的权重（约 7.3×10⁻⁵）进逃逸名单单独精确存放。

(b) GEMM：内核在寄存器里当场解码 W12，直接喂给 wgmma（Hopper 的矩阵乘指令），内存流全程不解密、速度不拖后腿。

图 7：两级验证

左图：第一遍用低精度 8 位视图粗验，只挑出一条候选链 C（不更新模型状态）；drafter 从 C 的尾巴再打一轮草稿；第二遍精确验证一次收走两拨。

下面的耗时条：H100 上一个周期粗验 11.5 ms、精确验 14.9 ms，每次精确 pass 接受 11.67 个 token（原来 6.16）。

右图：8 位视图嵌在每个 12 位记录里——读前 8 KB 就能粗验，精确验才读满 12 KB。两级验证和 W12 是互相成就的设计。

跟你的研究方向的关联

  • 投机解码评估：你刚在 SGLang 上看 EAGLE-4。这篇证明官方实现的 stock 系统通常没跑满——单请求时 stock 只用了一条草稿链、树验证能翻倍接受长度。你的评估里"树验证配不配"是一个值得单独测的维度。
  • DSpark 的连接：DSpark 是 DeepInfer 的投机解码组件。这篇的 agent 同样优化了 DSpark 部署——跟你追的 DeepInfer 线直接咬合。
  • autotuner 的思路：EAGLE-4 笔记里提到 Harness 先量成本表。这篇的"成本模型找天花板差距"是同一思想的更完整实现：先量化瓶颈、再定向优化，而不是无脑扫参。
  • PD 解耦的对照：这篇的批处理三件套（共享节点预算、动态草稿块、prompt 准入）本质是在验证 pass 里做"按收益分配行"——跟你在 PD 评估里关心的"验证行怎么花最划算"同源。
  • 精度门提醒：token forcing 的方法论值得抄——低精度捷径改结果而任务分数不动，说明评测只看任务分数会漏掉静默精度损失。你的 PD 精度门里可以加一层"逐词对照"而不仅是任务分。

术语表

  • 投机解码（speculative decoding）：先让实习生（小模型）打草稿，再让专家（大模型）一次性验稿；验中多少收多少。
  • drafter / target：打草稿的小模型 / 被加速的大模型。
  • AR（autoregressive decoding）：普通逐词解码，一个词一个词往外蹦。
  • stock：官方发布版实现，本文的优化起点。
  • tau（τ）：每次验证接受的 token 数，越高越好。
  • lossless（无损）：加速后输出跟原版逐位一致（浮点舍入除外）。
  • W12：本文发现的 12 位无损权重格式。
  • binade：指数相差 2 的整数倍的一组数；指数窗口指覆盖大多数权重的 16 个相邻 binade。
  • wgmma：Hopper GPU 的异步矩阵乘指令。
  • GDN（Gated DeltaNet）：一种线性注意力/循环架构，Qwen3.8 系列部分层在用。
  • token forcing：逐词 teacher forcing 核验，防 agent 造假。
  • byte floor：内核能达到的带宽/算力理论下限，调优的靶子。
