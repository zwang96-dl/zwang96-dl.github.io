DynaCore：P/D 解耦的硬件版——阵列形状跟着 batch 走

原文：A Shape-Adaptive Architecture with Disaggregated Quantization for Efficient LLM Serving（arXiv:2610.07443v1，Duke 大学 Cong Guo 等，2026-10-05）

一句话人话

P/D 解耦大家都在软件层做：prefill 和 decode 扔到不同卡上跑。 这篇说光分开还不够，芯片本身也要"变形"。 decode 的小矩阵乘法在固定大阵列上天天摸鱼，利用率低得可怜。 它设计了一款会随 batch 形状变形的加速器，两个阶段各穿各的量化鞋。

核心方法

  • 背景：prefill 是大矩阵乘法（GEMM），算力密集；decode 是小矩阵向量乘（GEMV），访存密集。
  • 脉动阵列（systolic array，乘加单元排成网格、数据像脉搏一样流动的芯片结构）天生为大 GEMM 设计。
  • 跑 decode 的窄 GEMV 时，大部分计算单元闲置，decode 成了端到端瓶颈。
  • 连续批处理让 batch 大小忽大忽小，GEMM 形状动态变化，固定阵列更难适配。
  • 招数一：形状自适应。把最小高效单元（MEU，一次能高效执行的最小计算块）沿三个维度重塑。
  • 空间上非对称调宽高：给权重通道加宽，输入路径保持不动。
  • 时间上用 Split-K：把累加拆开映射到阵列上，用阵列自带的互连传递部分和。
  • 招数二：解耦量化。prefill 用双边量化 W8A8，decode 用权重量化 W4A16。
  • 内积混合精度数据通路：输出位宽不随精度变化，两种格式拼在同一条通路上算。
  • 招数三：运行时调度。按当前 batch 查表选最合适的 MEU 形状，编译时穷举、运行时查表。

关键数据

  • 单设备：比固定脉动阵列快 23.07 倍，比 Planaria 快 7.57 倍，比 SARA 快 2.48 倍。
  • decode 阶段单拎出来：比 Planaria 快 23.03 倍，比 SARA 快 3.48 倍。
  • 能效：比五个基线分别高 4.96 倍、13.76 倍、7.39 倍、5.71 倍、2.86 倍。
  • batch 越小优势越大：batch=1 时比固定阵列快 85.2 倍；batch=256 时每请求 60.7ms 全场最低。
  • 系统级（8 卡 P/D 解耦，真实 trace）：首字延迟比 Planaria 快 2.97 倍，比 FIGLUT 快 3.50 倍。
  • 每 token 延迟比 Planaria 快 8.02 倍，比 FIGLUT 快 36.55 倍。
  • 精度：Llama3.1-8B 六个下游任务，平均只掉 0.07%，基本无损。
  • 对照：纯 W4A16 的 GPTQ 要掉 2.81%，这套解耦量化保精度能力强得多。

术语表

  • P/D 解耦：prefill 和 decode 拆到不同设备上跑，互不干扰。
  • prefill：一次性读入整个 prompt 的阶段，算力密集。
  • decode：逐个吐 token 的阶段，访存密集。
  • 脉动阵列：乘加单元排成网格、数据逐拍流动的芯片结构，为大矩阵乘法而生。
  • MEU：最小高效单元，阵列一次能高效执行的最小计算块。
  • Split-K：把累加维度拆开并行，再把部分和加起来。
  • W8A8：权重和激活都量化到 8 位；W4A16：权重 4 位、激活 16 位。
  • TTFT：首字延迟，从请求到第一个 token 出来的时间。
  • TPOT：每 token 延迟，decode 阶段平均每个 token 的时间。
  • FIGLUT / Planaria / SARA：三篇做量化或可重构加速器的前人工作，本文的对比基线。
