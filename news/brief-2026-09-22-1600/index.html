新技术与论文

SPLASH：KV 缓存一半搬进新型闪存，长上下文 decode 快 3.5–11.4 倍「值得深读」 显存不够用是长上下文 serving 的头号瓶颈，这篇换了个思路：不压缩，换地方存。 SPLASH 是稀疏注意力 + 高带宽闪存的协同设计。KV cache 横跨两层放：热数据放 HBM，冷数据放 HBF。 HBM 是 GPU 上的高速显存。HBF 是高带宽闪存，容量 TB 级、读速接近显存。 稀疏注意力按闪存"按页读取"的特性重新设计，读的时候只抓需要的页。 实测每卡 decode 吞吐涨 3.5–11.4 倍，精度损失不到 4%。 划重点：这是除压缩之外的第二条路——存不下就换更大的"仓库"，跟你 P/D 解耦评估里的显存账直接相关。 https://arxiv.org/abs/2609.23816

ValueDiff：新模型上，老的 KV 缓存"踢人"策略失灵了「值得深读」 Qwen3 这类新模型用了 QK 归一化，注意力 sink 变弱了。 QK 归一化是让注意力分数更稳定的手法。sink 是几个常年被高看的 token。 老的驱逐策略都指望 sink 来保命，sink 一弱就抓瞎。 ValueDiff 是按 value 向量"长相"决定踢谁的驱逐法：看每个 token 的 value 向量离"平均脸"有多远，越特别的越留着。 RULER 上 2k 预算保住 88–99% 精度，7 个新架构模型里 6 个拿第一。 划重点：你现在评估的模型大多是这类新架构，老方法的假设已经变了，这是新假设下的第一套打法。 https://arxiv.org/abs/2609.23314

PREM：长视频问答不用再把几百帧全塞进 prompt 长视频最费的是视觉 token，一股脑塞进 prompt 又贵又慢。 PREM 是前缀引导的循环记忆，分两步走：先让一个循环 writer 把视频流"看"成 256KB 的联想记忆，看完就存起来。 问问题时不加新 token，只给 prompt 前缀加一层记忆引导的"调制"，一次写入、反复问。 只调 0.24% 参数，16 帧预算下平均精度涨 3.06%。 跟你的多模态推理线相关：encoder/prefill 侧的降本新姿势。 https://arxiv.org/abs/2609.23601

一篇机理小品：KV 缓存里到底写了啥 这篇不做优化，纯好奇：forward 时 KV cache 里"操作"那段到底留了什么。 因果实验证明：Llama-3.1-8B 第 12–15 层藏着操作的"路由记录"，能读出它读了哪个值。 偏机理，serving 直接用不上，感兴趣再点。 https://arxiv.org/abs/2609.24635
