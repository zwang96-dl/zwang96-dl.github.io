Spexis：投机解码不当加速器，当"第三条并行轴"用——多卡推理最高快 34%

原文：Spexis: Speculative Lookahead Scheduling for LLM Inference（arXiv:2609.34370，2026-09-28；作者 Hyungyu Jung 等，首尔大学/汉阳大学；基于 vLLM v0.8.4 + Ray 实现；代码已开源：https://github.com/mlsys-seo/spexis）

一句话人话

投机解码（speculative decoding，先让小模型打草稿、大模型只负责改）以前只是个"加速 token 生成"的小技巧。

Spexis 把它升格成跟流水线并行、张量并行平起平坐的第三条并行轴。

换句话说：以前它是给发动机加的涡轮增压，这篇把它变成了第三个轮子。

核心问题：多卡并行的两头堵

模型太大塞不进一张卡，就得用多卡。

流水线并行（PP，把模型按层切段分给各卡）的问题：micro-batch（小批量）的 KV 缓存各自占坑，显存被切碎，batch 做不大，GPU 空转。

张量并行（TP，把每层权重切分给各卡）的问题：每层算完都要 all-reduce 同步，通信开销随卡数涨。

简单加卡不一定更快，有时反而更慢。

核心方法：三件套

1. 投机并行（SP）：用"打草稿"填满流水线的空泡

自投机模型（self-speculative model）：不另训小模型，直接拿目标模型的前几层当草稿模型。

比如两段流水线：GPU1 的前几层生成草稿 token，GPU2 的后几层负责验证。

关键操作：草稿一出来，GPU1 立刻开始对这些草稿做"投机执行"，同时 GPU2 在验证它们。

两边并行，流水线的空泡（bubble）被填上了。

最妙的一点：投机执行跟正常执行共享同一份 KV 缓存（KV cache，模型的"草稿纸"），不额外占显存。

类比：实习生打草稿和专家改稿用同一张桌子，不用再摆一张。

对比 PP 的 micro-batch：每个 micro-batch 各占一份 KV，显存碎成渣。

2. 成本模型：PP/TP/SP 怎么组合，算一下再定

论文给三套并行各建了个吞吐估计公式。

用有效 batch 大小统一口径：PP 的有效 batch 是 B/N（N 是流水线段数），SP 的是期望被接受的 token 数。

实测验证：估计值跟真实吞吐贴得很近（图 4 右）。

有了准的估计，就能自动选出最优组合，而不是人肉试。

3. 前瞻调度：两个预测，专治"白算"和"踢人"

选择性投机：草稿 token 按置信度（confidence，模型自己觉得能中的把握）排序，垫底的 α 比例（0.15–0.3）直接扔掉不投机。

道理很直白：没信心的草稿基本中不了，算了也是白算。

剩余长度感知：训了个 3 层小 MLP，预测每个请求还剩多长（分档：4/8/16/32/64 token）。

用它估算未来 64 步的 KV 显存占用。

如果现在放新请求进来会导致正在跑的被驱逐（eviction，显存不够踢掉重算），就让新请求先排队。

类比：餐厅先算好桌子几时空出来，再决定放不放新客人进门，免得把正在吃饭的赶走。

关键数据

  • 跨节点（2 节点 × RTX PRO 6000，千兆网）：Qwen3-32B 在 LMSYS-Chat 上，每秒多接 34% 的请求。
  • 解码吞吐：batch 64–100（Llama-3.3-70B）或 128–256（Qwen3-32B）时，比纯 PP 高 54%。
  • 单机 8 卡（A40，PCIe）：比 PP+TP 最优组合还快 8–16%。
  • 云 GPU（Runpod，8 卡固定 batch 64）：8 组里 5 组赢过纯 TP；PCIe 互联的 4 组全赢（1.02–1.21 倍）；A100 SXM 上 Llama-70B 快 1.27 倍。
  • 拆解贡献：SP 本体 +10–15%；选择性投机再 +3（Llama）/+12（Qwen）个百分点；长度感知再 +3 个百分点。
  • 草稿接受率：第一个草稿 token 约 78%（前半模型当草稿时 0.60–0.79）。
  • 训练成本：draft 用的 adapter 在 ShareGPT 上训 5 个 epoch，Llama-70B 用了一张 H200 约 12 小时。

跟你的研究方向的关联

  • 投机解码：这是你方向清单里的一项。这篇给了新视角：投机不只是加速单卡 token 生成，还能当多卡并行的第三轴。做多模态推理时，decode 阶段同样可以套这套思路。
  • AI 自动调参系统：论文的成本模型正是"按负载选最优并行组合"的雏形——跟你想做的 autotuner（SLA 内 throughput 最优）是同一类问题，公式可以直接参考。
  • vLLM 生态：实现基于 vLLM v0.8.4，代码已开源（github.com/mlsys-seo/spexis），想复现或借鉴门槛不高。
  • 提醒一句：投机接受率跟任务强相关。Qwen 上选择性投机多赚了 12 个点，Llama 只赚 3 个点——换到多模态任务上，接受率曲线可能完全不同，照搬前先测。

术语表

  • 投机解码（speculative decoding）：小模型先打草稿、大模型批量验证的加速法，草稿中了就省算力。
  • 流水线并行（PP）：模型按层切段，每段放一张卡，像流水线一样接力。
  • 张量并行（TP）：每层的权重矩阵切分到多卡并行算，算完要同步。
  • 空泡（bubble）：流水线里某张卡在等上游结果、干瞪眼的时间。
  • micro-batch：为了填空泡，把一个 batch 再切成小份轮流进流水线。
  • 接受率（acceptance rate）：草稿 token 被大模型验证通过的比例。
  • 驱逐（eviction）：显存不够时把正在跑的请求踢掉，KV 丢了要重算。
  • 置信度（confidence）：模型对自己输出的把握程度，本文用来筛草稿。
