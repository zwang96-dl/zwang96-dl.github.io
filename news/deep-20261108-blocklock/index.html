BlockLock：温度设 0 还飘？只保一个请求，确定性便宜一半

原文：Xiuyuan Qi 等《BlockLock: Reproducible LLM Inference with Fixed Batch Geometry》
原文链接：https://arxiv.org/abs/2611.06977
提交：2026-11-04，arXiv:2611.06977v1，14点版深读

一句话人话版

同一个 prompt，今天跟 A 拼一批、明天跟 B 拼一批。 结果能不一样，温度设 0 也救不了。 这篇不重写 kernel，只把你想保的那个请求钉死。 确定性就回来了，代价还很小。

先说问题：batch 里的邻居会改你的答案

浮点加法不满足结合律，求和顺序一变，结果就变。 batch 大小一变，算子内部的切分就变。 同一个请求，邻居一换，logits 就飘。 飘得不多，但足够翻转两个接近的 token。 真实工作负载里也有这事：188 个函数调用问题里。 有 2 个问题会因为 batch 形状变化改掉生成的调用。 对评测和 agent 来说，这等于结果不可复现。

*图1：同一个 prompt，邻居一换答案就变。x 是目标请求，f1、f2、f3 是同批的其他请求。batch 1 里 x 跟 f1、f2 拼，batch 2 里跟 f3 拼。答案从 A 变成了 B。只有邻居变了。*

核心方法：两种模式，钉死形状

老解法有两条路，都贵。 一条是全套 batch-invariant kernel，所有算子都锁死。 另一条是顺序隔离，prefill 一个一个跑。 BlockLock 换了个思路：只保住想保的那个请求。 不动别人，普通框架就能跑。

*图3：三种执行形状对比。(a) 普通 padded batching：所有行补到最长，x 的填充偏移跟着邻居变。(b) Rows：每行按固定块宽切块，x 的块永远不变。(c) Pack：拼成一个长块，x 锚在末尾，长度变化由隔离段吸收，prefill 完抽出 x 的 KV 单独 decode。*

1. BlockLock-Rows：切成固定宽度的行

batch 切成固定宽度的行，每行宽度 W 是块大小的倍数。 每个请求占整数个块，目标请求的块永远不变。 邻居再怎么换，x 的块还是那几块。 prefill 一次调用，decode 照常批量跑。 不用显式 mask，这是它比 Pack 便宜的地方。

2. BlockLock-Pack：锚在末尾，前面塞隔离段

把所有请求拼成一个长块，目标请求锚在末尾。 前面塞一段隔离 dummy 段，长度变化全由它吸收。 prefill 完把目标的 KV 一层一层抽出来。 然后只解目标一个请求，不跟别人拼 decode。 适合低并发、单请求审计这种场景。 想保多个请求，要给每个各拼一个 Pack。

3. 保证成立的三个条件

两套模式给的是同一个承诺：部署配置定死的前提下。 目标请求的输出逐位不变，邻居随便换。 承诺成立要三个条件同时满足。 一是规范形状：部署时定死的一套形状参数。 二是重复稳定的算术：同一形状重复算，结果稳定。 三是忠实的缓存交接：KV 交接不能丢、不能串。

关键数据

  • 5 款稠密模型：Qwen3-8B/14B、Llama-3.1-8B、Gemma-3-4B/12B。
  • 3 张卡：A6000、A100、H100，8 个数据集。
  • 100% 序列一致、Top-20 logit 逐位一致。
  • 每个数据集 4 个目标，各重复 10 次。
  • Rows 相对 vLLM batch-invariant：延迟降 53.5% 到 55%。
  • 吞吐涨 115.2% 到 122.2%。
  • Rows 自身代价：几何均值延迟只多 5.4% 到 6.9%。
  • prefill 吞吐在 batch 到 16 之前基本不掉。
  • Pack 的总耗时看着更低，别被骗了。
  • 它只解目标一个请求，别人不算在内。

*图5：七种做法的 prefill 加 decode 总耗时。Qwen3-8B 和 14B，batch 是 4。vLLM batch-invariant（BI）最慢，是标准做法的 2 倍多。Rows 和 Pack 跟标准做法几乎一样快。深色是 prefill，浅色是 decode。Pack 带星号：只解目标一个请求。*

跟你的研究方向的关联

你在评估 PD 解耦，精度门是硬指标。 这篇给你加了一条可操作的检查。 固定目标请求，换邻居，逐位比对输出。 batch 形状本身就是精度变量，要写进测试矩阵。 比 Thinking Machines 的全套 kernel 便宜得多。 不用换 kernel 就能先测起来。 注意保证的边界：只在同一部署配置下成立。 换卡、换并行度要重验。 只测了稠密模型，MoE 没测。 投机解码也没覆盖，Kimi K3 这类带新注意力的更不在 scope。

术语表

  • batch invariance（批不变性）：batch 大小变化时，单个请求的结果不变。
  • bitwise 一致：逐位相同，不只是 token 相同。
  • Top-20 logit：每步概率最高的 20 个候选 token 及其原始分数。
  • padded batching：把 batch 里所有行补到一样长。
  • CoRun-style baseline：顺序隔离的基线，prefill 逐个跑。
  • canonical geometry（规范形状）：部署时定死的一套形状参数。
  • repeat-stable arithmetic：同一形状重复算，结果稳定。
  • faithful cache handoff：KV 交接忠实，不丢、不串。
