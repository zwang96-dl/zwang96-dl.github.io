SPLASH：注意力并行布局的「运行时换挡」

  • 原文：SPLASH: Switching Parallel Layouts of Attention with Seamless Handoff for LLM Serving
  • 作者：中科院计算所（Chuan Liu 等 9 人），2026-09-29
  • 原文链接：https://arxiv.org/abs/2609.37626
  • 开源实现：https://github.com/ict-agent/SPLASH-sglang（基于 SGLang）

人话解读

没有一种注意力并行布局在所有负载下都最快。 请求少的时候，张量并行（TP）最快。 请求多的时候，数据并行注意力（DP-attention）最快。 prompt 很长的时候，上下文并行（CP）最快。 以前的引擎启动时定死一种布局，中途换不了。 Agent 和强化学习采样（RL rollout）的负载一直在变：开头上千个短请求，结尾只剩几条超长推理链。 SPLASH 让引擎在请求运行中切换布局，不用排空重启。 切换代价藏在推理计算背后，几乎感觉不到。

核心方法

  • 关键观察：MLA 把 KV 头砍没了，「权重切哪」和「KV 缓存归谁」变成两个独立选择。
  • 现有三种布局各留了一份冗余拷贝：TP 每卡存一份全量 KV，DP-attention 和 CP 每卡存一份全量权重。
  • 新布局 DOP（解耦所有权并行）：权重像 TP 一样切分，KV 像 DP-attention 一样每请求固定主人。
  • DOP 零冗余：每块权重、每段 KV 在集群里只存一份。
  • 四种布局两两切换共 12 个有向切换，只用三种原语：丢弃、全收集、全交换。
  • 切换时逐层搬运：第 i 层搬新状态时，第 i-1 层照常计算，搬运时间藏在计算后面。
  • 切换感知调度器：永远跑当前负载下最快的布局，新布局领先超过阈值才换。
  • DOP 变体 DOP-P：缓存部分全量权重，拿一点内存换更少的通信。

关键数据

  • B200 上跑 GLM-5.3，端到端吞吐比固定布局快 1.3–1.73 倍。
  • DOP 比 DP-attention 多 27–60% 的 KV 容量。
  • GLM-5.3 FP8 在 B200 上，DOP 每卡腾出 12.69 GiB 给 KV。
  • 单层切换通信：权重 0.29–0.30 ms，KV 3.47–3.81 ms（batch 16、单请求 256K token）。
  • 完整切换端到端多花 0.02–11.76 ms，排空重启要 667.31 ms。
  • DeepSeek-V3.2 在 H200、GLM-5.3-Flash 在国产 DCU 上，规律完全一样。

跟你研究方向的关联

你正在 SGLang 上评估 P/D 解耦，SPLASH 是同维度的思路。 P/D 解耦是把 prefill 和 decode 分到不同机器上跑。 SPLASH 是把「注意力怎么并行」也变成可调参数，跟着负载实时换。 两者都冲着一个目标：负载在变，静态部署跟不上。 这篇的调度器可以直接参考：成本模型选布局，设切换阈值防来回抖。 DOP 布局特别适合 KV 吃紧的长上下文解码，正好是 decode 卡的瓶颈。 作者直接给出了 SGLang 实现，评估时值得对照着看。

术语表

  • TP（张量并行）：把权重矩阵切开，每卡算一部分，像流水线分工。
  • DP-attention（数据并行注意力）：每卡独立处理一批请求，权重每卡一份全量。
  • CP（上下文并行）：把长 prompt 按位置切给不同卡，像分段读书。
  • DOP（解耦所有权并行）：SPLASH 新布局，权重切分加 KV 单主人，零冗余。
  • MLA（多头潜在注意力）：DeepSeek 系用的注意力，KV 压成一个共享潜向量。
  • RL rollout（强化学习采样）：一次撒出上千个生成请求，多数很快结束、少数长尾拖住整批。
