vLLM 原班人马：在 TPU 上焊了个 Megakernel，Kimi K3 比 GB200 快 57%

原文：700 TPS on Kimi K3: A Case for TPU Megakernels（Inferact Engineering，2026-09-23）
开源仓库：inferact/tpu-megakernels
作者：George Novack、Xuting Liu、Jeff Ma、Woosuk Kwon。划重点：Woosuk Kwon 是 vLLM 的核心作者之一。这家公司就是 vLLM 原班人马出来做的推理优化服务。

人话解读：这事是什么

  • Inferact 在 Google TPU v7 上，给 Kimi K3 手写了一个"超级大内核"。
  • 16 块 TPU v7 跑出 709 tokens/s。同样 16 块 GB200 用 vLLM 只能跑 452。
  • 快了 57%，精度还没掉。GPQA-Diamond 94.4%，GSM8K 97.2%。
  • 对做推理服务的人意味着什么？decode 的瓶颈从来不是算力，是搬运权重的速度。
  • 谁把"搬运"调度得更聪明，谁就更快。硬件换代之外，软件调度还有大把油水。
  • 这篇文章等于一份"上限参考"。它告诉你：把搬运做到极致，能快到什么程度。

类比时间：megakernel 就像取消了流水线的交接班。原来每层都要交班一次：搬权重、算、存结果。现在一个人从头干到尾，中间不停。

核心方法

为什么要 megakernel

  • 普通推理是几百个小 kernel 排队跑。每个 kernel 都是三段式：搬权重、计算、存结果。
  • 只有"搬权重"那段吃 HBM 带宽。计算和存结果时，带宽就闲着了。
  • 这叫带宽气泡：搬运的空档期。类比水管时断时续，有水没水看运气。
  • 小 kernel 各自为战，气泡加起来很可观。CUDA Graphs 能省启动开销，但 kernel 的边界还在。
  • CUDA Graphs 是打包 kernel 启动的技术：把一串启动命令一次下发，省掉次次喊话。
  • megakernel 直接把边界拆了。92 层 MoE 的前向，塞进一个 Pallas 程序里跑完。
  • MoE 是混合专家模型：每次只激活一部分专家，省算力。
  • 权重搬运不再属于某个 kernel。它可以在任何空档提前发出，只要片上存得下。

三个关键手法（Pallas）

Pallas 是 TPU 的内核语言。写 TPU kernel 就用它，地位类似 CUDA。

  1. 无网格启动

- TPU 本来就是单线程执行模型。megakernel 索性只启动一个程序，不搞网格。 - 一个程序从头跑到尾，调度完全自己说了算。类比：不搞轮班制，一个人包干。

  1. 作用域化的 VMEM 分配

- VMEM 是 TPU 片上高速内存。每 TensorCore 有 64 MiB，软件自己管理放什么。 - TensorCore 是 TPU 里的计算核心。一块 TPU v7 芯片里有 2 个。 - run_scoped 让每段"迷你 kernel"声明自己要多少 VMEM，用完即还。 - 不用手算字节地址，寿命管理交给作用域。类比：工具箱分格，用完归位。

  1. 异步 DMA

- DMA 是不经过计算单元的搬运：数据从 HBM 直达片上内存。 - 搬运可以异步发出。.start() 开始搬，.wait() 等搬完，搬运和计算精确重叠。 - 在单个 kernel 里，XLA 没法乱重排你的搬运顺序。XLA 是 Google 的自动编译器。 - 类比：提前叫货，货到再开工。叫货时机你说了算。

Kimi K3 的具体实现

  • 92 层 MoE 前向全部塞进一个 Pallas 程序。层循环就写在 kernel 里面。
  • 每一层的权重，都在更早的阶段发出搬运。理想情况：用到之前已经躺在 VMEM 里。
  • 跨层预取的例子：第 N 层还在算 MoE，第 N+1 层的 attention 权重已经在路上了。
  • 并行策略：16 块芯片共 32 个 TensorCore。attention 头拆到全部 32 个 rank。
  • routed experts 用 TP4×EP8：4 路张量并行乘 8 路专家并行。routed experts 是被路由选中的专家。
  • TP 把权重切分到多卡，EP 把专家分到多卡。两个维度一起拆。
  • 残差流还加了序列并行。batch 从 1 涨到 8 时，向量运算成了新瓶颈。
  • 瓶颈一变，索性把残差流也拆开分给多卡算。
  • MoE 的 latent-to-hidden 投影，机器内分片、跨机器复制。用多读一次权重，换更便宜的集合通信。
  • 芯片拓扑是 2×2×4。TPU 的芯片怎么连、选什么拓扑，本身也是个调参维度。
  • 意外收获：编译只要 90 秒。XLA 全自动融合要 30 分钟以上。
  • 人肉排好顺序只付一次代价。XLA 每次编译都要重新发现一遍。

DSpark 投机解码

  • batch 8 跑通后，megakernel 还能当投机解码的 verifier。verifier 就是验证器。
  • 投机解码像实习生打草稿、专家改：小模型先写几个 token，大模型一次验完。
  • 每步验证 1 个 anchor 加 7 个候选续写。anchor 是主干 token。
  • 每步约 8.5 毫秒。draft 模型每步能中 3 到 6 个 token。
  • 单用户拿到 700+ tokens/s。改得快就赚，验得慢就亏。

跟研究方向的关联

  • 你在评估 SGLang 的 P/D 解耦。这篇文章做的是 decode 步内部的"时间维重叠"。
  • P/D 解耦是"空间维分离"：prefill 和 decode 分到不同的卡。两者正交，可以叠加。
  • 直接参考价值：decode 的本质瓶颈是搬权重的内存墙。这篇文章是"搬运做到极致"的天花板样本。
  • SGLang 的 P/D 解耦把 decode 摘出来单独优化。这篇文章告诉你 decode 优化的上限在哪。
  • 你在 MI350 上跑 vLLM。思路可以借：megakernel 的核心是消除 kernel 边界、让预取跨越层边界。
  • GPU 上没有 VMEM，但有 CUDA Graphs 和 PDL。程序化依赖启动能让 kernel 提前备料。
  • 这部分红利 GPU 也吃得到，只是没有 TPU 那么彻底。
  • 你想做 serving 自动调参系统。这篇文章是最好的"调参空间"案例。
  • batch 从 1 涨到 8，瓶颈就从搬运变成向量运算。并行策略得跟着换。
  • 连芯片拓扑（2×2×4）都是调参维度。人肉试不完，正好是自动调参要啃的。
  • 另外注意可比性：对照组是 vLLM 官方 recipe 在 GB200 上的成绩。TPU 侧是手写 megakernel。
  • 两边优化投入不对等。57% 是"上限参考"，不是"TPU 天生快 57%"。
  • 编译 90 秒 vs 30 分钟，对调参迭代是质变。调参系统一天能多试几十轮。

术语表

  • megakernel：超级大内核。把整个前向塞进一个 kernel，取消 kernel 之间的交接。
  • Pallas：TPU 的内核语言。写 TPU kernel 就用它，地位类似 CUDA。
  • VMEM：TPU 片上高速内存。每 TensorCore 64 MiB，软件自己管理。
  • P/D 解耦：把 prefill 和 decode 拆到不同设备上跑。分工流水线。
  • MoE：混合专家模型。每次只激活一部分专家，省算力。
  • TP/EP：张量并行/专家并行。TP 按权重切分，EP 按专家切分。
  • 投机解码：小模型先打草稿，大模型批量验证。实习生打草稿、专家改。
  • acceptance length：每步被接受的 token 数。草稿一次性能过几个。
  • XLA：Google 的自动编译器。自动做算子融合和调度。
  • DMA：不经过计算单元的搬运。数据从 HBM 直达片上内存。
  • ICI：TPU 芯片之间的互连。类似 NVLink。
  • MLA：多头潜在注意力。DeepSeek 系的省显存注意力。
  • KDA：Kimi Delta Attention。Kimi K3 用的注意力变体。
