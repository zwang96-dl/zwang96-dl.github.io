多模态大模型推理服务简报 · 2026-10-29（6点版）

6点版来了，夜里这轮的关键词是静默算错。 SGLang 的 PD 这次修的是 prefill 侧的结论共识。 vLLM 那边，sleep 加 Mooncake 组合有个 0/8 的静默坑。 本期不标深读。

框架更新

正式版全平 vLLM 还是 0.32.0 版。 SGLang 还是 0.5.22 版。 LMDeploy 还是 0.18.0 版。 FlashInfer 还是 0.7.2.post1。 TensorRT-LLM 预发还是 v1.4.0rc2。 SGLang 的 v0.5.23 tag 还没打。 llama.cpp 只有每日快照，不算正式版。 窗口内实质更新一共 13 条。

SGLang 给 PD 的 prefill 侧补了结论共识 4点版报的是 decode 侧，这次是 prefill 侧的孪生修复。 背景：PD 解耦就是 prefill 和 decode 分开跑。 再加 PP（流水线并行），模型按层切成几段。 坑在这：请求传到一半被客户端取消。 0 号段觉得传成了，后面的段觉得没成。 各段按自己的判断去释放前缀缓存。 结果各段的前缀缓存开始分叉。 后续请求在各段匹配出不同前缀，实测直接崩溃。 行数凑巧对上时不崩，静默地用错 hidden states 算 KV。 hidden states 就是每层算出来的中间结果。 修法：所有段先达成一致，再一起释放。 好比几个工段先对口径，再统一拆包装。 对你：PD+PP 组合又一个静默坑，评估清单可添一条。 来源：https://github.com/sgl-project/sglang/pull/47045

vLLM 修了 sleep 加 Mooncake 的静默算错 先说组合：sleep 是让 GPU 休眠省显存。 Mooncake 是 KV 缓存的搬运和存储组件。 之前这俩一起用，启动直接被拒绝。 修完能启动了，但作者实测发现了个静默坑。 wake 后 store 还在读写旧的物理页。 A 自己和 B 读到的 KV 全错，8 次里 0 次对。 关键是没有任何错误日志。 修法：sleep 前先注销 buffer，wake 后重新注册。 失败就全量回滚，保证不带病上线。 好比仓库换班前先把旧货架牌摘掉。 对你：PD 解耦搬运链路如果用 Mooncake，这笔必看。 数字是作者实测，没独立复测。 来源：https://github.com/vllm-project/vllm/pull/59934

vLLM 修了 KV offload 的 CPU 缓存淘汰顺序 KV offload 就是把 KV 缓存溢出到 CPU 内存。 eager 模式下，一直走 GPU 前缀命中的前缀很吃香。 它的 CPU 拷贝 LRU 位置却从不动。 结果这些热前缀反而最先被 CPU 缓存淘汰。 修法：admission 时把对应 CPU 拷贝挪到 MRU 端。 MRU 就是最近最常用那一端。 作者口径：Kimi-K3 的 agentic 负载跑 PD 解耦。 2 节点 8 张 MI355X，TP8 加 DCP8。 KV 用的是 FP8 格式。 每卡总吞吐涨 8.7%，首词元延迟从 8.58 秒降到 5.27 秒。 重算的 prefill token 少 15.9%。 数字是作者口径，没独立复测。 来源：https://github.com/vllm-project/vllm/pull/62444

vLLM 给 Qwen3.8-Flash-Next 补了 SM100 的 skinny GEMM skinny GEMM 就是又瘦又长的矩阵乘法。 瘦长矩阵乘法 cuBLAS 跑不爽，定制核更顺。 这次是 B200 上 TP=1 的 BF16 线性层。 作者口径：每个 projection 比 cuBLAS 快。 快 1.35 到 2.24 倍，是冷 L2 下的数字。 decode 每步约省 0.6 毫秒，无端到端数字。 Qwen3.8 系列在 B200 上跑值得更新。 来源：https://github.com/vllm-project/vllm/pull/64482

SGLang 修了 MiniMax-M3.1-Flash 投机解码的崩溃 DSpark 是 SGLang 的投机解码实现。 投机解码就是先让小模型打草稿，大模型再改。 坑在 attn-DP 下第一个 decode 步。 draft 做集合通信时，卡的切分方式对不上。 直接报 Mismatched shape 崩溃。 修法：把那步的 commit_hidden 包进 draft 上下文。 作者口径：4 张 GB300 上 GSM8K 从崩溃到 96.36。 同一天 vLLM 也在修这模型的适配，双框架都在跟进。 来源：https://github.com/sgl-project/sglang/pull/46851

vLLM 修了多模态的一个 400 拒绝 bug 多模态请求里混了 image 和 embedding 两种输入。 embedding 的占位 ID 超出了词表范围。 结果请求直接被 400 拒绝。 SmolVLM-256M、Gemma 4 这些小模型都复现了。 修法：预处理阶段先把占位 ID 消费掉。 不用改 runner，改动很小。 来源：https://github.com/vllm-project/vllm/pull/64367

其余一句话带过 vLLM 的 175GB KV 池改 torch.empty，启动省掉全量清零。 作者声明这只是微基准优化，不能外推成 serving 加速。 AMD 那边复用已编译的 launcher，host 开销降 88%。 SGLang 修了 reasoning token 统计越界的 bug。 SGLang 还修了 GDN 空状态路由的小 bug。 vLLM 的 RADIO 视觉编码器对齐了新版权重。 llama.cpp 加载模型时复用中转 buffer，省掉反复分配。 vLLM Rust 版 bench 传 0 并发不再永远卡死。 来源：https://github.com/vllm-project/vllm/pull/64345

DeepInfer 星标还在涨 星标到了 24152 个。 4点版时是 24129 个。 两小时涨了 23 个。 代码还是一行没动。 来源：https://github.com/deepseek-ai/DeepInfer

业内新闻

NVIDIA 开源了个语音转写模型 名字叫 Nemotron 3.5 Transcribe。 30B 的 MoE（混合专家模型），每次只激活约 4B。 支持 40 种语言的语音转文字。 权重给了 BF16、FP8、NVFP4 三种精度。 还有 GGUF 版，方便本地跑。 商用许可 OpenMDW-1.1。 vLLM 0.32.0 和 SGLang-Omni 0.2.0 直接能跑。 跟你相关：做多模态 serving 又多一个现成组件。 来源：https://www.marktechpost.com/2026/10/28/nvidia-nemotron-3-5-transcribe-open-speech-llm/

投机解码来了个新 drafter：FlashMap drafter 就是投机解码里负责打草稿的小模型。 FlashMap 用连续流映射代替离散扩散。 一次前向能起草 16 个 token。 作者口径：Qwen3-8B 上 6.14 倍无损加速。 给了 vLLM 和 SGLang 的插件。 权重 Apache-2.0，代码 MIT。 来源：https://www.marktechpost.com/2026/10/28/flashmap-flow-map-speculative-decoding/

LG Uplus 的手机端 token 优化论文进了 NeurIPS 两篇论文入选 NeurIPS 2026 的端侧智能 workshop。 公司口径：处理速度约 4.5 倍，电池消耗降 77%。 跟你关系不大，手机端小模型的事。 来源：https://en.sedaily.com/technology/2026/10/29/lg-uplus-token-optimization-papers-accepted-at-neurips-2026

模型圈八卦：DeepSeek 和月之暗面被曝蒸馏 GPT-6 两家被曝用 OpenAI 的 GPT-6 蒸馏训新模型。 受益的是 Kimi K3.1 Pro 和 DeepSeek 新版。 这条是模型背景，不是 infra 本体。 来源：https://northlandnewsradio.com/2026/10/28/deepseek-moonshot-used-openais-gpt-6-astra-to-train-latest-models-the-information-reports/
