DolphinRouting：PD 解耦下，每个请求该走哪条路

原文：DolphinRouting: Cluster-Level Binary Routing for Disaggregated LLM Inference Serving 作者：南京大学 Yishuo Yuan、Shaoyu Yang、Chunrong Fang arXiv:2610.40292v1，2026-10-29 提交，2026-10-31 00点版深读 原文链接：https://arxiv.org/abs/2610.40292

一句话人话

PD 解耦把读题和吐字分到两拨机器，但每个请求走哪条路最划算，一直是拍脑袋定的。这篇用历史数据离线学出一张"查表"，请求一来就查表决定本地读题还是远程读题，实测首字延迟和吐字延迟都降了。

为什么值得读

  • 你正在评估 SGLang 的 PD 解耦，这篇回答的正是"请求级路径选择"这个子问题
  • 跟之前深读的 AMPD 是姐妹篇：AMPD 是每轮在线算，DolphinRouting 是离线学好、在线只查表
  • 对照组直接打的 NVIDIA Dynamo，等价于把你评估清单里的 Dynamo 规则换成学出来的表

核心方法

问题定义很实在：PD 解耦下，一个请求要么在 decode 机器本地读题（聚合路径），要么去 prefill 机器读题再把草稿纸搬回来（解耦路径）。选哪条，要看三笔账：读题成本、缓存复用、吐字压力。

四个特征刻画一个请求：

  • 原始 prompt 长度：没扣缓存前的总长度
  • P 侧有效长度：扣掉 prefill 机器上已缓存前缀后的长度
  • D 侧有效长度：扣掉 decode 机器上已缓存前缀后的长度
  • 预估输出长度：用 CPU 上的 XGBoost 分类器猜短中长三档

划重点：P 侧和 D 侧的有效长度不一样，因为两拨机器的缓存命中情况不同。只用原始长度会误判，这是这篇的关键洞察。

离线学、在线查：

  • 离线：用历史请求按四个特征聚类（k-means 或 GMM），每个簇学一个二元动作：走聚合还是走解耦
  • 学习方法是逐簇扫描初始化、再用 epsilon-greedy 搜索微调，奖励是端到端 SLO 达成率
  • 在线：请求一来，提特征、定簇、查表，平均决策延迟忽略不计
  • 策略优化全在离线做，线上请求路径不加任何打分开销

跟 Dynamo 规则的区别：Dynamo 用固定规则（有效输入长度、prefill 负载等阈值）。DolphinRouting 把这些揉进聚类和搜索里，用实测 SLO 反馈学出边界。

关键数据

  • 真机 PD 解耦集群上，混合负载下 P90 首字延迟降 5.7–7.9%，P90 吐字间隔降 2.6–10.1%（相对 Dynamo）
  • 真实数据上，首字延迟降 5.7–6.5%，吐字间隔降 2.6–5.5%
  • 动机实验（TaiChi 仿真）：TTFT/TPOT 目标 5 秒/250 毫秒时，聚合达标率 97%、解耦只有 42%；目标放宽到 16 秒/60 毫秒时，聚合 7%、解耦 98%
  • 换句话说，SLO 松紧直接决定哪条路赢，这就是为什么要按请求选路
  • 簇数 K 从 8 加到 16，收益继续涨但收敛轮数也涨（Figure 5）
  • 输出长度预测器 Clairvoyant 单次 0.029 毫秒，比推理延迟小几个数量级

以上均为作者自报，真机集群配置未给完整硬件清单，数字别直接搬。

关键图表

图注：横轴是首字延迟（TTFT）目标、纵轴是吐字间隔（TPOT）目标。左上是"合流赢"区：TTFT 要得紧、TPOT 放得松时，一条龙全包更划算。右下是"解耦赢"区：TTFT 放得松、TPOT 要得紧时，分工流水线更划算。中间的问号就是这篇要解决的问题：给定一对 SLO 目标，每个请求到底该走哪边。

图注：左边是新到的请求，中间是在线阶段——提特征（有效输入长度、预估输出长度）、分簇、查决策表，得到 0（本地读题）或 1（远程读题）。右边是执行：0 走 decode 机器一条龙，1 走 prefill 机器读题再 KV 搬运到 decode 机器。下面是离线阶段：用历史 SLO 反馈做逐簇扫描初始化和 epsilon-greedy 搜索，更新决策表。在线只查表、不学习，所以几乎零开销。

跟你的研究方向怎么挂钩

  • 你评估 SGLang PD 解耦时，请求走本地还是远程 prefill 是必测项。这篇给了现成的四特征和查表思路
  • 簇数 K、特征权重都是 autotuner 现成的旋钮，可以直接借
  • 输出长度预测只用 CPU 跑 XGBoost，0.029 毫秒不占 GPU，工程上可抄
  • 注意它只解决"选路"，P/D 配比、KV 搬运引擎这些还是后端的事，跟 SGLang 的 Mooncake/NIXL 是上下叠加

术语表

  • PD 解耦：prefill/decode 解耦，读题和吐字分到不同机器，像分工流水线
  • TTFT：time-to-first-token，首字延迟，用户敲回车到看到第一个字的时间
  • TPOT：time-per-output-token，吐字间隔，每个字之间隔多久
  • SLO：服务等级目标，比如"99% 请求首字延迟小于 5 秒"
  • KV cache：草稿纸，读题时算好的中间结果，吐字时复用
  • k-means：聚类算法，把相似的请求分到一组
  • epsilon-greedy：一种搜索策略，大部分时间走当前最优、偶尔随机试试
  • Dynamo：NVIDIA 的 PD 解耦 serving 框架，这篇的对照组

局限与提醒

  • 只在作者自家的真机集群测过，硬件配置没交代全
  • 输出长度是猜的，猜错会带偏分簇
  • 真实数据上的收益（2.6–5.5%）比混合负载小，说明对负载形状敏感
  • 跟 AMPD 比少了在线自适应，负载漂移后表要重学
