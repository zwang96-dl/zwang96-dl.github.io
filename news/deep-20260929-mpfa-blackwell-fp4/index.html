MpFA：Blackwell 上免训练的 FP4 注意力核，QK 压到 4bit、PV 留 8bit 才最快

  • 原文：https://arxiv.org/abs/2609.33135
  • 作者：Chencheng Deng、Jianbin Fang、Dezun Dong
  • 单位：国防科技大学
  • 提交：2026-09-27，13 页
  • 一句话：Blackwell 的 FP4 算力很猛，但注意力全上 FP4 反而变慢。
  • 它找到甜点：QK 用 4bit、PV 用 8bit，端到端快 2.81 倍

人话版：这篇在解决什么

  • 长上下文推理现在卡在注意力上。
  • 128K 上下文时，注意力占 prefill 72.5% 的 GPU 时间。
  • decode 更夸张：91.4%。
  • FP4 Tensor Core（矩阵乘加速单元）：Blackwell 的新算力。
  • 它的理论算力是 BF16 的 4 倍。
  • 直觉是：注意力全换成 FP4，直接起飞。
  • 现实打脸：全 FP4 实测只有 0.87 倍，比 BF16 还慢。
  • 原因不在矩阵乘，在三处"杂活"。
  • softmax 后的在线量化、数据搬运、softmax 路径堵车。
  • MpFA 干了件"看菜下料"的事。
  • QK^T 用 NVFP4（4bit 浮点格式），吃算力红利。
  • PV 用 FP8（8bit 浮点），省折腾。
  • 再加一个"找平"补偿：精度损失找回 62.5%，多花 2% 开销。
  • 全程免训练，拿来即用。

核心方法：四件套

1. 先诊断：理论 4 倍，实测 0.87 倍，差的钱花在哪了

  • 论文实测了四种精度组合（64K prefill）。
  • NVFP4+NVFP4 理论 4.0 倍，实测 0.87 倍。
  • NVFP4+BF16 实测 1.11 倍。
  • NVFP4+FP8 实测 1.38 倍，唯一真香的。
  • 差的钱花在三处杂活上。
  • 第一：概率矩阵 P 是 softmax 刚算出来的。
  • 要再做一次在线量化，才能喂给 FP4。
  • 量化这活儿落在已经很忙的 softmax 路径上，等于单车道再加一辆车。
  • 第二：FP4 矩阵乘的操作数，必须待在片上高速缓存里。
  • P 刚在 tensor memory 里算出来，得搬一趟。
  • tensor memory 是 Blackwell 新的片上存储。
  • 第三：FP4 的 scale factor 也要占 tensor memory。
  • scale factor 就是量化缩放系数。
  • 而 512 列的"停车位"早被 score 和输出占满了，没地方停。
  • FP8 的 PV 全避开这三笔账。
  • FP8 矩阵乘能直接从 tensor memory 读 P。
  • 不用二次量化，不用搬运，不用抢位置。
  • 结论：选精度不能只看峰值算力，得看数据通路。

2. rank-one 平滑补偿：削峰填谷，多花 2%

  • Q 和 K 的激活值有个毛病：某些通道上常年偏大，像山脊一样。
  • 4bit 量化最怕这种"尖峰"，误差大。
  • 老办法：减均值削峰，再把差值加回去。
  • 但"加回去"这步如果走 softmax 路径，又添堵。
  • MpFA 的招：把补偿做成一个额外的 BF16 Tensor Core 矩阵乘。
  • Tensor Core 在那一刻正好闲着，等于让闲人干杂活，不添堵。
  • 数学上：先中心化 Q、K（减均值），再量化；补偿项是均值与 K 的外积。
  • 外积是个低秩项，所以叫 rank-one（一秩）。
  • 实现分两步：kernel 外用一个 GEMV（矩阵向量乘）算好补偿向量。
  • kernel 里顺手做一次 BF16 MMA（矩阵乘加），把补偿写进 score。
  • 效果：5 个 benchmark 上找回 62.5% 的精度损失。
  • 开销只有约 2.0%。

3. 细粒度流水线：5 种 warp 分工，7 条通道

  • 一个 CTA（线程块）里 5 种 warp（32 线程一组）各干各的。
  • 分工是：搬运、矩阵乘、softmax、校正、收尾。
  • query 双缓冲：两份轮着用，一份算的时候另一份搬。
  • softmax 和矩阵乘重叠：这一块做归一化，另一块做乘法。
  • 7 条执行通道在连续的 KV 块上推进，像流水线工人传零件。

4. tensor memory 复用：512 列定额里挤出空位

  • 每个 CTA 只有 512 列 tensor memory。
  • 两个 score 累加器加两个输出累加器，正好吃满。
  • NVFP4 的 scale factor 没地方放。
  • 解法：借用"对面 stage"的空闲列。
  • 时间差打得好：stage 0 做矩阵乘的同时。
  • stage 1 的 score 区刚被消费完。
  • 空档期借来放 scale factor。
  • P 矩阵更省：直接复用 score 区上半部分，零新增分配。
  • scale factor 的搬运也做成异步流水线，不进关键路径。

5. prefill/decode 分开调

  • prefill：上面这套全开。
  • decode：KV 分块策略固定，列切分另调。
  • 长上下文 decode 本来就是并行度瓶颈，不硬拼精度。

关键数据

  • 硬件：单张 NVIDIA B200。
  • B200 纸面：BF16 2.25 PFLOPS，FP4 9 PFLOPS。
  • 模型：Llama-3.1-8B，GQA（分组注意力）32:8。
  • 还有 Qwen3-14B，GQA 40:8。
  • prefill kernel 吞吐：16K–128K。
  • 跑到 1672–1817 TFLOPS。
  • 相对 BF16 FA4：几何平均 1.31 倍。
  • 相对 FP8 FlashInfer：快 1.17 倍。
  • 端到端输出吞吐：并发 1，1024 个输出 token。
  • 两模型几何平均 2.81 倍。
  • 精度：rank-one 补偿找回 62.5% 损失，开销约 2%。
  • 分任务看：HellaSwag 恢复 83%，MMLU 恢复 73–82%。
  • GSM8K 恢复 77%（Llama）/ 50%（Qwen）。
  • RULER-QA 只恢复 24–49%，长上下文问答掉得最多。
  • 4bit 注意力加长上下文，仍是硬骨头。
  • 短序列别用：4K 只有 0.74 倍，比 BF16 还慢。
  • 8K 回到 1.09 倍，8K 以上才划算。
  • TTFT：量化加写 KV 缓存融进一趟，最高 1.16 倍。
  • SGLang 集成：做成 attention 后端。
  • 支持连续批、paged KV、CUDA Graph 捕获。

术语表

  • NVFP4：NVIDIA 的 4bit 浮点格式，16 个数共享一个缩放系数。
  • FP8：8bit 浮点，Hopper 和 Blackwell 都支持。
  • Tensor Core：GPU 上专门做矩阵乘的加速单元。
  • tensor memory：Blackwell 新增的片上存储。
  • 专门给 Tensor Core 和 softmax 传数用。
  • MMA：矩阵乘加指令，一次算一小块矩阵乘。
  • warp：GPU 上 32 个线程编为一组，一起干活。
  • CTA：一个线程块，一组 warp 的集合。
  • TMA：异步搬运引擎，管显存到片上缓存的搬运。
  • scale factor：量化缩放系数，低比特数的"刻度尺"。
  • online softmax：分块做归一化，不用等全部数据到齐。
  • roofline：理论性能上界分析，看离天花板多远。
  • GQA：分组查询注意力，省 KV 缓存的注意力变体。
  • TTFT：首 token 延迟，用户敲回车到第一个字出来的时间。
