MoSE：让集群网络跟着 P/D 解耦的流量改道

原文：MoSE: Mode-Switching Expander for Mixed LLM Training and Inference
arXiv:2609.39138v1，2026-09-30 发布
作者：Fan Yang（南方科技大学）等
原文链接

人话解读

你评估 SGLang 的 P/D 解耦时，账都算到了 GPU 和 KV 搬运上。但这篇提醒你漏了一层：网络。

P/D 解耦把 prefill 和 decode 拆成两个 GPU 池，中间就会有一条"KV 高速公路"：prefill 算完的 KV 缓存要源源不断运给 decode。训练的流量却是另一幅样子：all-to-all、全规约这种全局均匀的集体通信。

同一集群两种流量混跑，网络拓扑顾此失彼。按训练优化的拓扑，KV 搬运要绕 2 到 3 跳，瓶颈卡死。按推理优化的拓扑，训练流量又跑不动。

MoSE 的办法是：网络别固定，让它跟着负载"改道"。推理忙时把链路朝 prefill-decode 直连倾斜，训练忙时恢复成均匀的扩张器拓扑。端口一个不加，路由也不用改。

*图注：三个圆环是同一套光网络在不同负载下的链路排布。蓝=训练机架，浅绿=prefill 机架，深绿=decode 机架，灰线=光链路，红线=KV 搬运流量。(a) 训练和推理共用一套拓扑。(b) 推理需求上来，KV 搬运要绕 2 到 3 跳，多跳路径挤爆。(c) 光电路交换重配后，prefill 和 decode 之间装上直连链路，KV 一跳直达。说明：拓扑不是固定的，负载一变就重排链路。*

核心方法

  • 问题建模成边分配：拓扑是图，节点是机架组（每组一个机架的 GPU）。每个节点固定度数 d=4，边总数是死的。问题就是这点边怎么分。
  • 两种模板来回切：推理重负载时，用 P-D 偏置模板。每个 prefill/decode 节点留 d-1 条边专连对方。
  • 剩 1 条保全局连通。训练重负载时，切回均匀随机正则扩张器。
  • 靠光电路交换实现：OCS（光电路交换）粗粒度重配光路，不用加端口。每个节点 4 个 OCS 口，1024 个组就是 4096 个端口。只改"光口跟谁配对"，不改速率和路由。
  • 算法就两行逻辑：推理模式下先按二部图把 P-D 直连边装满。
  • 再随机补满剩余度数保连通。训练模式下直接生成均匀随机正则图。
  • 评估是 flow-level 仿真：1024 个组，20 个随机种子。推理重负载=410 prefill 组+410 decode 组+204 训练组。
  • KV 流量占 70%。训练重负载反过来，训练流量占 70%。

关键数据

  • 推理重负载下 KV 通信代价：相对 Static-Training。
  • 平均降 90.8%，P95 降 91.9%。Static-Training 就是"永远按训练配拓扑"的基线。
  • 训练重负载下训练通信代价：相对 Static-Inference。
  • 平均降 22.7%，P95 降 27.6%。Static-Inference 是"永远按推理配拓扑"的反面基线。
  • 瓶颈链路负载：推理重负载下 MoSE 最忙链路 529.35。
  • Static-Training 是 1041.95，直接砍半。
  • 跟 Static-Inference 持平，推理侧没亏
  • 直连比例：DirectKV 从 0.004 涨到 1.000。意思是 KV 搬运几乎全走一跳直连，不再绕路。
  • KV 平均跳数：从 5.66 跳降到 1.00 跳。跳数少了，延迟和拥塞自然下来。
  • 训练侧不翻车：训练重负载下 MoSE 的 MaxLoad 1157.75。
  • 跟 Static-Training 持平。Static-Inference 会飙到 1885.60。
  • 说明纯推理拓扑跑训练是灾难。

跟你的研究方向的关联

  • 你评估 SGLang P/D 解耦的直接对照：你的评估账里。
  • KV 搬运成本按"同节点 NVLink、跨节点 RDMA"算。这篇说跨节点时拓扑形状本身就是变量。部署 P/D 解耦的集群如果还按训练配网络，KV 搬运会被迫多跳，实测收益会打折。
  • 部署 checklist 加一项：P/D 解耦上线前。
  • 先看 prefill 池和 decode 池之间的直连带宽。如果直连不足，要么重排机架，要么像这篇一样用 OCS 重配。
  • 跟 FPT/LMCache 笔记同路：FPT 笔记讲了 NIXL 搬运。
  • 和 KV 感知路由。MoSE 是同一条链的下一层：路由决定走哪条路，MoSE 决定路怎么修。
  • 单卡评估用不上，但扩到多节点必看：你在 MI350 单卡上做评估。
  • 这篇结论暂时不直接影响。但以后 P/D 解耦扩到多节点，这篇就是部署拓扑的设计依据。
  • 跟 PD 解耦功耗笔记呼应：那篇给 prefill/decode 配不同功耗档。这篇给它们配不同网络。思路一致：解耦之后，每种资源都要按阶段单独优化。

术语表

  • P-D 解耦：prefill/decode disaggregation
  • 把"读提示词"和"逐字生成"拆到不同 GPU 池 池上跑。prefill 算完把 KV 缓存运给 decode 池。
  • 扩张器图（expander graph）：边很少但连通性很好的稀疏图。训练集群常用，all-to-all 流量不容易堵。
  • OCS（光电路交换）：用光开关重配物理链路的设备。改的是"谁连谁"，不改带宽，重配是粗粒度的。
  • 度数（degree）：每个节点连出去的链路数。本文固定 d=4，边总数是死的，只能重新分配。
  • P-D Cut：横跨 prefill 集合和 decode 集合的边数。越大说明两池之间直连越多。
  • DirectKV：KV 搬运流量中一跳直达的比例。1.000 就是全部直达。
  • MaxLoad / P95Load：最忙链路的负载 / 95 分位链路负载。衡量网络瓶颈的指标。
  • 负载感知通信代价：load-aware communication cost
  • 流量沿路径累积的拥塞。比单看最忙链路更能反映整体拥堵。
  • all-to-all / 全规约：训练里常见的集体通信模式。每个 GPU 都要跟所有 GPU 交换数据，需要均匀拓扑。
  • flow-level 仿真：不模拟包级细节，只算流的路径和负载。快，但看不到排队和重传。
