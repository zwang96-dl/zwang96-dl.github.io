CPU 才是瓶颈？一篇新文章算了笔账

Medium 今天有篇文章讲 Blink。

Blink 是 4 月的一篇论文。

思路是把 CPU 踢出推理链路。

请求走智能网卡，调度交给常驻 GPU 的核。

文章给了一组实测数字。

H100 跑 Llama-3 8B，vLLM 能到 7475 token 每秒。

在空闲核上跑个压缩任务。

吞吐直接掉到 1961 token 每秒。

首 token 的 P99 延迟从 150 毫秒涨到 21 秒。

同一块卡，同一个模型。

只差一个抢 CPU 的邻居。

来源：https://medium.com/@roanmonteiro/your-30k-gpu-is-waiting-on-a-shared-xeon-1b151389b8e0

论文：https://arxiv.org/abs/2604.07609

温度设 0 还会飘？新文章给了代价表

AppScale 今天发了篇总结。

讲温度 0 下输出仍会变。

真凶是批大小改了核的算术。

SGLang 的确定性模式要慢 25% 到 45%。

Thinking Machines 的原型从 26 秒涨到 42 秒。

vLLM 只要开 VLLM_BATCH_INVARIANT=1。

代价官方没给数字。

这篇跟你之前读过的 Thinking Machines 深读是同一条线。

来源：https://appscale.blog/en/blog/llm-nondeterminism-temperature-zero-batch-invariance-2026
