SGLang 把统一 KV 缓存推倒重搭：22 条 PR 一次落地

原文：SGLang PR 栈 #46970–#46991，代表条 #46984 链接：https://github.com/sgl-project/sglang/pull/46984 合并时间：2026-10-28 11:49–12:04 UTC

人话解读

  • SGLang 有个统一 KV 缓存池。
  • KV 就是算好的草稿纸。
  • 不同模型用的草稿纸不一样。
  • 有的全量存，有的只存窗口。
  • 有的还要存循环状态。
  • 以前每种组合一套代码。
  • 组合越多，代码越乱。
  • 这次 22 条 PR 一起落地。
  • 15 分钟内整栈合并完。
  • 换成一个路由器管所有池。
  • 性能没声称变快。
  • 价值在地基变干净。
  • 你评 PD 绕不开这个池。
  • HiCache 和 PD 传输都走它。

核心方法

  • 先把布局规格单独拆出来。
  • 布局就是草稿纸怎么摆。
  • 再按每层的声明建池。
  • 所有子池共用一个分配器。
  • 分配器就是发草稿纸的人。
  • 容量定价和准入集中管。
  • 谁能进池、占多少有统一账。
  • 地址翻译改用 ID 空间描述。
  • 每一层访问走子池视图。
  • 视图就是各层自己的窗口。
  • 循环状态的归属也集中了。
  • 缓存传输改由存储计划生成。
  • 传输就是 PD 搬草稿纸那步。
  • 最后用 RoutedKVCache 收口。
  • 它按子池把请求路由过去。
  • 组合专属的门面类全删了。
  • 前缀树改由存储槽来建。
  • 草稿绑定到路由后的视图。

术语表

  • KV：算好的草稿纸，避免重算。
  • 子池：按存储类型分的小池子。
  • 分配器：管草稿纸发放回收的组件。
  • 准入：请求能不能进池的判断。
  • RoutedKVCache：按子池路由的缓存。
  • HiCache：把 KV 存到主机内存的层。
  • PD：prefill 和 decode 分开跑。
  • 滑窗：只保留最近一段上下文。
  • MLA：一种压缩 KV 的注意力结构。
  • 变基：把改动挪到最新主线代码上。
