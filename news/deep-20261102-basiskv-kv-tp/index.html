BasisKV：长上下文 KV 瘦身，顺手治好多卡通信

原文：arXiv:2611.02583（2026-11-02 提交，v1）
https://arxiv.org/abs/2611.02583
作者：杜克大学 Lixun Zhang 等（通讯作者 Zishan Shao）
代码：https://github.com/alexz949/BasisKV

一句话人话

长上下文推理里，KV 缓存是不断变厚的草稿纸。 以前的压缩只管草稿纸变薄，不管多卡之间传它贵不贵。 BasisKV 发现：把 Value 压缩好，多卡通信顺手就便宜了。 一份压缩，同时治好缓存和通信两个毛病。

核心方法

  • 问题起点：低秩 KV 压缩以前只在单卡上玩。
  • 低秩压缩就是把高维向量压成矮胖的小向量。
  • 多卡并行（TP）时，注意力要分到各卡算完再通信。
  • 以前没人认真治通信这笔账。
  • 观察一：多卡通信是低秩压缩落地时的大头成本。
  • 观察二：Value 压缩可以挂在输出投影上。
  • 同一份低秩 Value 表示，既压 Value 缓存宽度，又压多卡通信。
  • 联合优化：各卡的低秩因子一起拟合完整的注意力输出。
  • 不是各卡自己玩自己的。
  • 用校准数据算协方差，交替最小二乘求解。
  • 校准数据是 C4 的 256 条 2048 token。
  • 还考虑了卡与卡之间的交叉项误差。
  • Value 复用做 Key 路由：压缩后的 Value 还能猜 Key 长什么样。
  • 用降秩回归从 Value 预测 Key，映射用 SVD 算。
  • 预测够用的信息留给路由，猜不出的部分存成 Key 专用残差。
  • 原版 Key 只在选中的页上取出来算精确分数。
  • 路由对齐的 Value 基：把路由需要的信息旋到 Value 的前几个坐标。
  • 旋转操作离线折进编码器，推理时只读这几维。
  • 全上下文路由只读一小块，省内存带宽。
  • 页级 Fisher 拟合：残差修正只给页打分，不用来还原 Key。
  • 页大小 4，默认 B16R16：16 维 Value 派生基加 16 维残差。

关键数据（均为作者自报，无第三方复现）

  • 多卡推理：8 张 L40S，4K 提示词，128 输出。
  • Llama-3.1-8B-Instruct，batch 256，端到端快 1.42 倍。
  • Qwen3-32B 同配置，快 1.31 倍。
  • 压缩越狠（V64），收益越大，batch 越大越划算。
  • 长上下文路由：RULER-128K 上跟全 Key 基本打平。
  • 在稀疏方法里排最强一档。
  • 模型测了 Llama-3.1、Qwen3、Qwen3.5。
  • 稀疏解码：128K 上下文，单卡 L40S。
  • 注意力块本身快 1.63 倍，整模型解码快 1.25 倍。
  • 精确的 Key 和 Value 全在 GPU 上，不用搬去 CPU。

跟你研究方向的关联

  • 你正在评估 SGLang 的 P/D 解耦，核心成本就是 KV 在卡之间搬。
  • BasisKV 压的正是要搬的那份 KV。
  • 思路可以直接套：搬运前先压缩，通信和缓存两笔账一起算。
  • Mooncake、NIXL 那套传输层，传小了自然快。
  • 19 点版 vLLM #63420 修的是 Mooncake 查前缀时的续租。
  • 这篇是源头瘦身，方向互补。
  • 校准只用 C4 通用文本，是后训练方法。
  • 意味着不用重训模型，现有模型直接套。
  • 注意短板：实测卡是 L40S，不是你手里的 H100 和 MI350X。
  • 数字是作者自报，精度掉多少要看 RULER 和 LongBench 表 2。

术语表

  • 低秩压缩：把高维向量压成矮胖的小向量，精度损失尽量小。
  • 张量并行（TP）：把模型横切分到多张卡上一起算。
  • AllGather：每张卡把自己的结果广播给所有卡。
  • 校准：用一小批数据量出压缩参数。
  • KV cache：解码时的草稿纸，存 Key 和 Value。
  • 路由：决定注意力该看哪些 token 页。
  • 残差：主预测猜不出的那部分误差。
  • TTFT：首字延迟，提示词进去到第一个词出来的时间。
