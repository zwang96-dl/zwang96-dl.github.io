Dynamo v1.7.0 正式版：跨池子路由和实时重调

一句话

Dynamo 是管多引擎推理集群的编排层。

这版把调度从一个池子做到多个池子。

还给排队、重调和故障迁移都加了新机制。

人话解读

先说 Dynamo 是什么。

它坐在 vLLM、SGLang 和 TRT-LLM 上面。

像个总调度，管路由、管缓存、管扩缩容。

一个 Dynamo 部署里有好几个池子。

每个池子是一组跑同一模型的引擎。

以前一个前端只管自己那个池子。

池子之间互不通气。

一个池子排队，另一个池子空着也没办法。

这版加了 Global Router。

多个池子挂到同一个前端下面。

前端看各池子的负载分流。

同一个会话还粘在同一个池子上。

好比以前每个食堂窗口各排各的队。

现在一个总入口按人流量分窗口。

熟客还固定去常去的窗口。

Planner 也升级了。

它以前管扩缩容和 GPU 预算。

这版加了批量排产和池子优先级。

还加了一个实验性的实时重调循环。

它会回放真实 trace，试不同的配置。

找到更优的就换上。

这就像调度员先拿历史录像排练。

排练出最优方案再上岗。

Router 的排队也变聪明了。

以前按先到先得。

这版按截止时间排队。

快过期的请求先走。

过期了还没轮到，直接拒掉。

KV 抓取也加了提示。

只从同组里的机器上取。

跨组取数慢，还占带宽。

Sidecar 是另一条主线。

它让 Dynamo 贴在原装引擎旁边跑。

引擎不用改启动命令。

这版 Sidecar 能顶多节点引擎了。

引擎挂了，正在跑的请求能迁到别的 worker。

Sidecar 自己重启，再重新注册。

多模态也补了一块。

SGLang 的 worker 现在能接图、视频和音频。

TRT-LLM 的 Sidecar 也一样。

前端还加了两个接口。

语音转文字走 /v1/audio/transcriptions。

批量推理走 /v1/files 和 /v1/batches。

核心方法

  • Global Router：发现服务登记池子和路由。
  • 前端按负载选池子，会话亲和粘住。
  • 每个池子的请求、错误、首字节都进 /metrics。
  • K8s 上用 DynamoPoolRelay 部署中继。
  • Planner：批量排产算安全副本数。
  • 池子之间换 GPU 预算，按优先级决定谁让谁拿。
  • 预算、SLA 和阈值改配置不用重启。
  • 实验性重调循环回放 trace 找更优配置。
  • Router：按截止时间排队，过期直接拒。
  • kv.fetch 提示只找同传输岛里的源。
  • 选 worker 和选 KV 源合成一个决定。
  • dynamo-sticky-min-load 把会话钉在最闲的 worker 上。
  • Sidecar：多节点引擎配 leader 和 worker 模板。
  • 引擎死后前端迁移在途请求。
  • Sidecar 自动重启并重新注册。
  • 前端：语音转文字走专用 vLLM worker。
  • 批量接口走 /v1/files 和 /v1/batches。
  • V2 工具调用和推理解析成六个模型家族的默认。
  • 多模态：图片编辑走 /v1/images/edits。
  • Cosmos3 Nano 的文生图、文生视频、图生视频是实验工作流。
  • SGLang worker 接图像、视频、音频输入。

升级注意

  • 跨 minor 升级会被拦住。
  • 从 v1.5.x 不能直接跳到 v1.7.x。
  • 要一级一级升，或者显式放行。
  • Grove 必须升到 v0.2.0-beta1。
  • Python 3.10 不再支持，至少要 3.11。
  • KVBM 整个删了，改走 dynamo.vllm.pd_connector。
  • /health 默认只回状态，不再列实例。
  • 要实例列表得加 ?instances=true。
  • Sidecar 到引擎的 gRPC 连接默认从 8 条涨到 32 条。
  • 并发高了，旧默认值会卡 token 速率。

跟研究方向的关联

  • 你正在评估 SGLang 的 PD 解耦。
  • Dynamo 是 PD 解耦上面那层调度。
  • 跨池子路由能抄进评估清单。
  • 读题池子和解码池子可以分开看负载。
  • kv.fetch 提示就是传 KV 的那一层。
  • 同传输岛里取，跨岛取，代价分开报。
  • 实时重调循环跟自动调参方向撞上。
  • 它回放 trace 找配置，跟你想要的调参系统同路。
  • 截止时间排队能抄进 SLO 那档。
  • 首字达标和过期拒绝一起报。
  • Sidecar 的故障迁移是生产必答题。
  • 引擎挂了请求不丢，这条要进验收清单。
  • 但这版发布说明几乎没有跑分数字。
  • 想抄数字得等官方博客或自己测。

术语表

  • Dynamo：NVIDIA 的分布式推理编排平台。
  • Global Router：跨多个推理池子路由的前端。
  • Planner：管扩缩容和 GPU 预算的组件。
  • Sidecar：贴在原装引擎旁边跑的 Dynamo 进程。
  • 传输岛：同一组高速互连的机器。
  • Velo：Dynamo 的可选响应传输面。
  • Grove：Dynamo 用的 K8s 资源编排器。
  • LPX：Dynamo 里的一种引擎部署形态。
