vLLM：6 条，P/D 代理那条最值得看

先说 #67150。

P/D 代理修了流式返回。

P/D 就是读题和解码分开跑。

以前流式请求的返回类型不对。

现在按 text/event-stream 正确返回。

说白了，PD 部署里流式输出不断线了。

跟你评估的 PD 解耦直接相关。

来源：https://github.com/vllm-project/vllm/pull/67150

再说 #67080。

KV 连接器那条跟 Mooncake 有关。

Mooncake 是跨机器传 KV 缓存的系统。

以前存之前没查过就先存。

现在查不到就跳过，不白存。

缓存外存那条路更干净了。

来源：https://github.com/vllm-project/vllm/pull/67080

再说 #65993。

Rust 前端那条。

Rust 前端就是用 Rust 写的前端。

引擎外渲染器现在同时支持多模态和 LoRA。

LoRA 是低成本微调的办法。

多模态加微调那条路打通了。

来源：https://github.com/vllm-project/vllm/pull/65993

其余三条一句话带过。

#63727，ROCm 上 Muse Spark 的 FP8 融合 MoE 配了新参数。

FP8 是 8 位浮点，省显存。

#62603，SM90 上块 FP8 的 MegaMoE 走 FlashInfer 的 MoE-EP。

SM90 就是 Hopper 那代卡。

#66777，修补：SageMaker 的报错按请求类型正确返回。

SGLang：5 条，推测解码过 PD 那条最值得看

先说 #49665。

推测解码的草稿 KV 也能过 PD 传了。

dflash 是 SGLang 的推测解码方案。

推测解码就是先让小模型打草稿再让大模型改。

以前草稿的 KV 只留在本机。

现在读题那台机器能把草稿 KV 传给解码那台。

K3.1 同机部署上，目标 KV 多了 15%。

说白了，PD 拆开后，推测解码的加速不丢了。

跟你评估的 PD 解耦直接相关。

来源：https://github.com/sgl-project/sglang/pull/49665

再说 #50018。

GLM-5.3-Flash 的默认内存分法改了。

以前状态池占了九成内存。

KV 池太小，多轮会话每轮都被清掉。

前缀缓存命中率跌到 0.056。

现在状态池只占四分之一。

剩下的都给 KV 池。

多轮 agent 会话的缓存终于留得住了。

来源：https://github.com/sgl-project/sglang/pull/50018

其余三条一句话带过。

#48947，小批量读题也能跑层归一化并行。

#47267，dflash 的候选 top-k 改到目标模型的头分片上算。

#50055 只是 CI 杂活：NPU 的精度测试升级了。

TRT-LLM：7 条，长多轮提示词那条最值得看

先说 #21308。

长多轮对话每轮的提示词处理变便宜了。

提示词就是每次发给模型的输入。

多轮 agent 会话里，历史越攒越长。

每轮重复处理历史的开销下来了。

跟 agent 场景的长会话直接相关。

来源：https://github.com/NVIDIA/TensorRT-LLM/pull/21308

其余六条一句话带过。

#21791，DeepGEMM 和 CuTe 的预热核每台机器只建一次。

#21612，NIXL 传完状态就放掉句柄，不再攥着 GIL。

GIL 是 Python 的全局锁。

#21863，GQA 分段解码的工作区按 FlashInfer 的统计量重新算了。

GQA 是分组查询注意力。

#22174、#22103、#19212 都是修补和测试。

llama.cpp：5 条，预填充加速那条最值得看

先说 #26048。

CUDA 上 NVFP4 的预填充快了。

NVFP4 是 4 位浮点格式。

权重缩放那步融进了矩阵乘法的收尾里。

预填充就是读题那一步。

来源：https://github.com/ggml-org/llama.cpp/pull/26048

其余四条一句话带过。

#32128，ARM 的 NEON 上用了 4x4 的矩阵乘法小块。

NEON 是 ARM 的向量指令集。

#32100，后端只预取前面已经算过的输入。

#31897，门控 DeltaNet 走 SpacemiT 的 RVV 核。

RVV 是 RISC-V 的向量扩展。

#29357，Vulkan 上英特尔的 FA 核支持预填充。

FA 就是 FlashAttention。

华为 MACaQ：量化新工具开源了

MACaQ 是华为云出的后训练量化框架。

122B 的模型 64 分钟就能压到 W4A4。

W4A4 是 4 位权重加 4 位激活。

只用 32.5GB 显存。

支持 vLLM 和 llama.cpp。

Qwen3.8-27B 上，读题快 2.33 倍，解码快 2.58 倍。

提醒一句，这是官方自报的数字。

还没看到第三方复现。

来源：https://aiweekly.co/alerts/huawei-open-sources-macaq-quantizes-122b-model-in-64-minutes

仓库：https://github.com/huawei-csl/MACaQ
