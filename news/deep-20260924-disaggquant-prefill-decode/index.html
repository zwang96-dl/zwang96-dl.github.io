DisaggQuant：prefill 和 decode 的量化，各穿各的鞋

原文：Disaggregated Quantization: Specializing LLM Prefill and Decode（arXiv:2609.26333，2026-09-22，NVIDIA + ISTA，Dan Alistarh 组）
一句话版本：量化别再"一把尺子量全身"。
prefill 要算得快，decode 要搬得快，两边各配各的量化格式。

人话解读

以前做模型量化，思路是"一套格式跑全程"。 同一个 4-bit 方案，从 prefill 一直用到 decode 结束。 这篇说：这俩阶段根本不是一回事，凭什么穿同一双鞋。

prefill 是处理 prompt 的阶段，一次性吞掉几千个 token。 它是算力密集型，大矩阵乘（GEMM）说了算。 decode 是逐个吐 token 的阶段，一次只算一个。 它是访存密集型，瓶颈在把权重从显存搬进计算单元（GEMV）。

打个比方：prefill 是短跑选手，要的是爆发力。 decode 是搬运工，要的是每次少搬点。 给短跑选手穿登山靴，给搬运工穿钉鞋，都别扭。

论文的答案就四个字：分开量化。 prefill 用 NVFP4 这种硬件原生低精度格式，算得飞快。 decode 用 LUT3 这种 2-3 bit 权重编码，权重小、搬运快。 各取所长，精度还保得住。

对你意味着什么：你正在 SGLang 上评估 P/D 解耦。 解耦之后 prefill 池和 decode 池本来就是不同机器。 这篇等于告诉你：两边连量化格式都可以不一样。 这是"解耦"思想在量化维度的延伸，跟你评估的方向同路。

核心方法

整套方法分三档，一档比一档"解耦"得彻底。

第一档：不解耦。 一套权重、一种格式，从头跑到尾。 这就是今天大家默认的做法。

第二档：格式解耦。 权重还是同一套，但两个阶段走不同的计算路。 prefill 走 NVFP4：权重和激活都量化，算得快。 decode 走 NVFP4A16：只量化权重，激活保持 16-bit。 NVFP4A16 是 NVFP4 的"高精度表亲"。 精度更高，prefill 慢一点。 只在 decode 关掉激活量化，精度涨了，成本几乎没变。 类比：同一辆车，市区开经济模式，高速开运动模式。

第三档：完全解耦。 prefill 和 decode 各训各的权重，各用各的格式。 prefill 权重是 NVFP4 compute-native：天生为算力而生。 decode 权重是 weight-only 低比特：天生为搬运而生。 训练方法叫 QADD（带解耦的量化感知蒸馏）。 它借用 SFT 的 label mask 来分流。 这个掩码平时只对回答算 loss。 prompt 走 prefill 路，回答走 decode 路。 loss 只看回答。 但梯度会经由 prompt 的 KV 传回 prefill 权重。 一次前向加一次反向，两套权重同时训好。

还有个工程补丁，叫 ODP。 全称是 offloaded disaggregated prefill。 完全解耦要多存一份 prefill 权重，单卡放不下。 ODP 把它放 SSD 里，按块流式加载。 prompt 越长，加载开销摊得越薄。

关键数据

先看"两阶段对量化敏感度真的不一样"这个前提。 Qwen3 和 Gemma3 全家族实测。 decode-heavy 的推理任务上，只量化 decode 的精度损失。 是只量化 prefill 的 2 到 4 倍。 Gemma3-1B 上甚至到 7 倍。 prefill-heavy 的长 prompt 任务上，顺序反过来。 只量化 prefill 的损失是只量化 decode 的 1.1 到 4.1 倍。 结论：哪个阶段吃力，哪个阶段就经不起量化。 分开对待是合理的。

格式解耦的效果。 decode-heavy 任务上，精度接近 NVFP4A16。 但 prefill 速度和存储开销跟纯 NVFP4 一样。 等于白捡了精度，没多花钱。

完全解耦的效果。 2-bit 这种极限压缩下，提升最大。 尤其在 prefill-heavy 任务上，相对格式解耦再往上拉一截。

最抓眼球的一组数。 拿现成的 Qwen3.8-27B GGUF 解码器。 GGUF 是 llama.cpp 的模型格式。 只新训一个 NVFP4 prefiller，decode 那份权重完全不动。 1-bit 权重（IQ1_S）在 MMLU-Pro 上涨 32.5 分。 在 MMMU-Pro（多模态推理基准）上则涨 35.3 分。 1-bit 的精度直接翻倍还多。

ODP 的实测。 llama.cpp 真机，DGX Spark。 8K prompt 下首 token 延迟（TTFT）快 1.78 倍。 4K 上下文以上就开始赢过纯 weight-only 基线。 SSD 读权重的延迟，被长 prompt 摊平了。

规模验证。 vLLM 上验证了解耦 serving 的精度。 shared-weight 的格式解耦做到 2.8T 参数模型。 不是小模型玩具，是真能上生产线的量级。

跟你研究方向的关联

你在 SGLang 上评估 P/D 解耦，核心问题是"拆开之后怎么配最划算"。 这篇给了量化维度的答案：拆开之后，两边的量化也可以不一样。 prefill 池配 NVFP4 算力型，decode 池配低比特搬运型。

SARA 那篇笔记解决的是"两边各配几张卡"。 KV Working Set 那篇解决的是"KV 池留多大"。 这篇解决的是"两边各用什么量化"。 三篇拼在一起，P/D 解耦的部署三问（算力、显存、精度）就齐了。

一个提醒：NVFP4 是 NVIDIA 的格式。 你的 H100 可以用（Marlin 兜底），MI350X 上没有原生支持。 但"分阶段选格式"的思路是通用的。 AMD 侧可以用 quark 或 MXFP4 走同样的路子。

术语表

  • prefill：处理 prompt 的阶段，一次吞掉全部输入。算力密集型。
  • decode：逐 token 生成的阶段，一次吐一个。访存密集型。
  • disaggregation（解耦）：把原来绑在一起的东西拆开，各自优化。
  • NVFP4：NVIDIA 的 4-bit 浮点格式，权重激活都量化。Blackwell 原生加速，算得快。
  • NVFP4A16：NVFP4 的 weight-only 变体。只量化权重，精度更高，prefill 慢一些。
  • LUT3 / LUT2：3-bit / 2-bit 查找表权重编码。权重极小，decode 搬运快。
  • GEMM：矩阵乘。prefill 的主力算子，吃算力。
  • GEMV：矩阵向量乘。decode 的主力算子，吃显存带宽。
  • QADD：带解耦的量化感知蒸馏。一次训练同时训出两套量化权重。
  • ODP：把 prefill 权重放 SSD 流式加载，单卡也玩得起完全解耦。
  • GGUF：llama.cpp 用的模型文件格式。
  • TTFT：time to first token，首 token 延迟。用户感知最强的指标。
  • MMLU-Pro：文本推理基准。MMMU-Pro：多模态推理基准。
  • distillation（蒸馏）：用强模型当老师，教量化模型保住精度。
