DuoPD：把 decode 搬进显存里算，PD 解耦不再拆卡

原文：A Hybrid GPU and Processing-Near-Memory Architecture with Shared DRAM for Efficient Prefill-Decode Disaggregation ｜ arXiv:2610.26131 ｜ 首尔国立大学 ｜ 2026-10-19 提交，10-20 新批次入库

人话解读

  • PD 解耦现在有个老毛病。
  • PD 解耦就是把两阶段拆开跑。
  • prefill 和 decode 分到不同卡上。
  • 拆开之后，两边都在浪费资源。
  • prefill 那组卡，算力拉满了。
  • 但它的显存带宽大量闲置。
  • decode 那组卡正好反过来。
  • 它拼命读显存，算力却闲置。
  • 说白了，一半家当总在睡大觉。
  • 以前有人试过切分 GPU 来救。
  • 把一张卡的算力单元分成两摊。
  • 但 decode 读显存也要占算力单元。
  • 切给 decode 多了，prefill 就饿了。
  • 这篇换了个思路：不拆卡，拆活。
  • GPU 全部算力只干 prefill 一件事。
  • decode 整个搬进显存芯片里算。
  • 显存旁边加一颗小计算单元。
  • 它贴着数据算，不用搬来搬去。
  • 两摊活在同一套硬件上同时跑。
  • 互相干扰还压得很低。
  • 作者模拟结果：吞吐最高 2.23 倍。
  • 先划重点：这是模拟，不是实测。
  • 芯片还没流片，别当现货看。

核心方法

PNM：显存旁边的计算单元

  • PNM 是近存计算单元。
  • 全称 Processing-Near-Memory。
  • 大白话：把小算力塞到显存旁边。
  • 它装在 HBM 的逻辑层上。
  • HBM 就是 GPU 用的高速显存。
  • PNM 每层配 16 条 SIMD 通道。
  • SIMD 就是一条指令算一排数据。
  • 1 GHz 下峰值约 32 TFLOPS。
  • TFLOPS 是每秒万亿次浮点运算。
  • 这个算力只干 decode 足够了。
  • 因为 decode 缺的是带宽不是算力。
  • 向量单元负责 softmax 等杂活。
  • softmax 是注意力里的归一化步骤。
  • 还支持 FlashDecoding 式切分。
  • FlashDecoding 是分块算注意力的办法。

共享显存：两人用同一本草稿纸

  • GPU 和 PNM 共用同一套 HBM。
  • 模型权重只存一份，两边都能读。
  • 权重推理时只读，不用同步修改。
  • KV cache 是推理的草稿纸。
  • KV cache 由各自独占，不抢着写。
  • prefill 写完，交接一次给 decode。
  • 交接之后 PNM 直接接着往下算。
  • 省掉了跨卡搬 KV 的老账单。
  • 传统解耦要走 NVLink 搬草稿纸。
  • NVLink 是卡之间的高速互联线。

三个关键设计

  • 一是 TSV 级带宽共享机制。
  • TSV 是显存堆叠里的垂直连线。
  • GPU 和 PNM 分时共用这条通道。
  • 二是绕开内存控制器直传数据。
  • 数据从显存直达 PNM 的缓冲区。
  • 少绕一圈，延迟和能耗都降了。
  • 三是分层的数据映射方案。
  • GPU 层用张量并行切权重。
  • PNM 层用序列并行切 KV。
  • 序列并行就是按上下文长度切草稿纸。
  • 这样绕开了注意力头不够分的坑。

仲裁策略：先喂 prefill

  • 两边同时抢显存通道，要有人排队。
  • 作者试了三种排队策略。
  • 分别是 prefill 优先和 decode 优先。
  • 还有一种是混合排队。
  • 结论是 prefill 优先整体最好。
  • 因为 TTFT 对排队最敏感。
  • TTFT 是等第一个字的延迟。
  • decode 被堵一下，影响会被摊薄。
  • 它要生成很多字，堵一次不致命。

*图注：左图是传统 PD 解耦。prefill 一组卡带宽闲置，decode 一组卡算力闲置。右图是 DuoPD。GPU 只管 prefill，PNM 在显存里管 decode，两边共用同一份显存带宽。说明：浪费的根源是"拆卡"，DuoPD 改成"同卡分工"。*

关键数据

  • 以下数字全部来自作者模拟。
  • 用的是周期级模拟器加 DRAMSim3。
  • DRAMSim3 是显存行为模拟工具。

评测设置

  • 基线一：传统 PD 解耦两种配比。
  • prefill 和 decode 按 1:1 分卡。
  • 另一种按 3:1 分卡。
  • 基线二：chunked prefill 混跑。
  • chunked prefill 是分块穿插着跑。
  • 全部系统都按 8 张 GPU 算账。
  • 单卡按 GB300 级别参数设定。
  • 每卡 8 堆 HBM4 显存。
  • 每堆带宽 2 TB/s，容量 48 GB。
  • 测了三个服务器级大模型。
  • GPT3-175B、LLaMA2-70B 各一个。
  • 还有 Qwen3-235B-A22B。
  • 它是 MoE，也就是混合专家模型。
  • 输入长度测了 8K 到 32K。
  • 输出长度测了 32 到 512。

吞吐结果

  • GPT3-175B 平均提升 1.46 到 2.23 倍。
  • LLaMA2-70B 平均提升 1.29 到 1.61 倍。
  • Qwen3 平均提升 1.45 到 1.78 倍。
  • 对 1:1 解耦最高高 1.76 倍。
  • 对 3:1 解耦最高高 2.23 倍。
  • 长输出场景最高能到 3.92 倍。
  • 那是对 3:1 解耦和混跑比的。

*图注：蓝柱是 DuoPD，黑灰柱是两种 PD 解耦配比，绿柱是 chunked prefill 混跑。横轴按模型、批大小、输入输出长度分组。说明：几乎每组蓝柱都最高，优势在 GPT3-175B 和长输出时最大。*

延迟结果

  • TPOT 最多降 77.66%。
  • TPOT 是每吐一个字的间隔。
  • 那是对 3:1 解耦比的数字。
  • 对 1:1 解耦最多降 42.61%。
  • 高 QPS 下延迟曲线稳得多。
  • QPS 是每秒进来的请求数。
  • TTFT 涨到 3 倍的临界点上。
  • DuoPD 能扛的 QPS 更高。
  • 对 1:1 解耦最高高 2.13 倍。
  • 对混跑最高高 3.12 倍。
  • PNM 峰值温度模拟约 76 度。
  • 在可接受范围内，没有热爆。

*图注：五列分别是 TPOT 的 p50、p90、p99，以及 TTFT 和端到端延迟。三行对应三个模型。蓝线是 DuoPD，基本贴着底部走。橙线是混跑，高负载下最先冲顶。说明：DuoPD 的优势不只是平均快，是高负载下不崩。*

跟你的研究方向的关联

  • 你正在评估 SGLang 的 PD 解耦。
  • 这篇正好打在解耦的浪费点上。
  • 它量化了一件你关心的事。
  • 解耦的成本不只是搬 KV 那笔账。
  • 还有两组卡各闲一半的结构浪费。
  • 你做 autotuner 时可以借这个视角。
  • 配比搜索之外，再看利用率错位。
  • prefill 侧带宽闲置率值得单独记。
  • decode 侧算力闲置率也值得记。
  • 这篇也是硬件路线的风向标。
  • 近存计算开始正面进 serving 战场。
  • H100 和 MI350X 都没有这种 PNM。
  • 所以短期落不了地，先当思路存着。
  • 等 HBM 新一代方案时再回头看。

术语表

  • PD 解耦：prefill 和 decode 分开跑。
  • prefill：读完输入、算好草稿纸的阶段。
  • decode：一个一个往外吐字的阶段。
  • PNM：塞在显存旁边的近存计算单元。
  • HBM：GPU 用的高速堆叠显存。
  • KV cache：存注意力中间结果的草稿纸。
  • TTFT：从提问到吐第一个字的延迟。
  • TPOT：吐每个字的平均间隔。
  • TSV：显存堆叠层之间的垂直连线。
  • 周期级模拟：按时钟周期仿真硬件行为。
