HAWK：读题用 GPU，吐字交给 NPU

  • 原文：HAWK: Heterogeneity-Aware KV Cache Transfer for Efficient GPU-NPU Phase-Disaggregated LLM Inference
  • 作者：Junhyeok Park、Jungeun Yoon 等
  • 单位：佐治亚理工、韩国 ETRI 研究所
  • 来源：arXiv:2610.29873（2026-10-21 提交）
  • 链接：https://arxiv.org/abs/2610.29873

人话解读

  • PD 解耦你已经很熟了。
  • PD 解耦就是读题和吐字分工。
  • 读题叫 prefill，吐字叫 decode。
  • 以前分工都是同种芯片之间分。
  • 这篇把分工跨到了芯片种类上。
  • 读题交给 GPU，吐字交给 NPU。
  • NPU 是专为 AI 造的加速芯片。
  • 为什么这么分，看算账就懂。
  • 读题是并行大计算，GPU 最擅长。
  • 吐字是一次挤一个词出来。
  • 它拼的是显存带宽，不是算力。
  • GPU 干吐字，算力大半在闲置。
  • NPU 吐字速度只慢 GPU 一成多。
  • 但每度电和每块钱都划算得多。
  • 像流水线上重活给壮汉。
  • 轻活交给便宜又省电的帮手。
  • 难点只有一个：草稿纸怎么搬。
  • 草稿纸就是 KV 缓存。
  • 它要从 GPU 搬到 NPU 上。
  • 两家芯片的通信方式不一样。
  • 草稿纸的摆放格式也不一样。
  • 笨办法是先经主机内存中转。
  • 中转一趟，慢了约 4 到 9 倍。
  • 这篇的 HAWK 就是来拆这个坎的。

图注：这是作者实测的分工账本。 左列是 A100 这张 GPU。 右列是 Tenstorrent 的 NPU。 读题速度 GPU 快了 2.52 倍。 吐字速度差距只剩 1.16 倍。 吐字功耗效率 NPU 高 1.39 倍。 吐字成本效率 NPU 高 5.88 倍。 所以读题归 GPU、吐字归 NPU。

核心方法

  • 第一步是修一条直达的搬运路。
  • 路叫 RDMA（远程直接读内存）。
  • 说白了就是设备之间直通快递。
  • 数据不经主机 CPU 倒手。
  • GPU 和 NPU 接到同一套 RDMA 上。
  • 第二步是搬运时顺手换格式。
  • GPU 侧先做一步布局变换。
  • 把草稿纸摆成 NPU 要的样子。
  • 第三步在 NPU 侧提前备好格子。
  • 格子按目标布局分配好。
  • 还分散到各个显存通道上。
  • 数据到了就能直接用。
  • 不用落地后再重新整理一遍。
  • 像快递直接按货架位打包。
  • 到仓拆箱就能上架卖。
  • 实现底子都是现成开源件。
  • 框架用 vLLM 0.10.0 版。
  • 搬运引擎用 Mooncake。
  • Mooncake 是解耦圈的常用搬运工。
  • NPU 侧靠插件接进 vLLM。
  • 论文还记了一个翻车细节。
  • 缓冲区图省事连成一整块时。
  • NPU 显存碎片化直接爆内存。
  • 所以格子必须按布局分散放。

图注：横轴是单次搬运的数据量。 纵轴是延迟，1.00 是同构中转线。 深灰 GN-Host 是异构加中转。 它慢了 3.79 到 8.91 倍。 最右深色 GN-HAWK 是这篇的方案。 它跟同构直达线 GG-Direct 贴齐。 两者差距不到 1%。

关键数据

  • 以下数字都是作者自报。
  • 模型是 Llama 3.1 70B。
  • 每个实例用 4 张设备并行。
  • 搬运延迟先看结论。
  • HAWK 跟 GPU 直达 GPU 打平。
  • 差距不到 1%。
  • 中转老办法慢 3.79 到 8.91 倍。
  • 数据量越大，差距越收窄。
  • 但中转线始终明显更慢。
  • 再看在线服务的首字延迟。
  • 首字延迟就是用户等第一个词。
  • 达标率九成时比可达请求率。
  • HAWK 只比全 GPU 线低一点。
  • 聊天负载低 2.90%。
  • 摘要负载低 5.90%。
  • 整套系统最后的总账是这样。
  • 同样达标线下跟全 GPU 比。
  • 整体性能差距最多 7.88%。
  • 功耗效率最高涨到 1.26 倍。
  • 成本效率最高涨到 1.72 倍。
  • 注意这是系统级总账。
  • 比单芯片账本保守得多。
  • 摘要负载有个小尾巴。
  • NPU 吐字稍慢会攒出排队。
  • 高请求率时首字延迟被拉开。
  • 作者说优化软件栈能补上。

图注：左图是聊天负载，右图是摘要。 横轴是请求到达率，越高越挤。 纵轴是九成请求的等待上限。 黑线 GN-HAWK 是这篇的异构线。 它跟橙色同构直达线几乎重合。 绿线是异构中转线，早早冲顶。 红虚线是各自的达标线。

跟你的研究有什么关系

  • 你评估的 SGLang 解耦是同构版。
  • 这篇把问题推进了一步。
  • 解耦的真瓶颈在搬运层。
  • 不在读题或吐字本身。
  • 布局对齐要塞进搬运里做。
  • 落地再整理，账就还回去了。
  • 这跟你看 Mooncake 时能对上。
  • 它用的正是同一个搬运引擎。
  • 你的自动调参可以多一个维度。
  • 以前旋钮是几台读题几台吐字。
  • 现在可以多想一层设备种类。
  • 吐字池未必非得用同款贵卡。
  • 但先把丑话说在前面。
  • 它测的是 A100 加 Tenstorrent。
  • 不是你的 H100 和 MI350X。
  • vLLM 版本也停在 0.10.0。
  • 只测了一个 70B 模型。
  • 代码说计划开源，还没放出。
  • 所以这篇适合抄思路。
  • 搬运层设计可以直接借鉴。
  • 数字别直接搬进你的评估。
  • 换成你的卡和负载再测一遍。

术语表

  • PD 解耦：读题和吐字拆开分工跑。
  • KV 缓存：存好的上下文，本文叫草稿纸。
  • NPU：专为 AI 造的加速芯片。
  • RDMA：设备间直读对方内存的快递。
  • 张量布局：数据在显存里的摆放格式。
  • Mooncake：解耦常用的 KV 搬运引擎。
  • SLO：服务达标线，如延迟上限。
  • TTFT：首字延迟，等第一个词的时间。
  • TPOT：每吐一个词的平均耗时。
