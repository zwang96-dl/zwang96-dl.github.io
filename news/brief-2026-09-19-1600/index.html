业内新闻

AWS 给推理网关装上了"GPU 感知" AWS 昨天推出了 HyperPod 推理网关。 一句话：给 K8s 上的推理请求配了个聪明交警。 它不看 CPU、内存这种老指标。 它看的是 GPU 实时状态。 KV cache（草稿纸）还剩多少、队列堵没堵、插件住在哪台机器上。 然后把每个请求发到最合适的机器上。 这是混合 GPU 机型跑出来的。 Llama-3.1-8B 上，首字延迟 P95 降 97%。 Qwen3-32B 更狠：P95 降 98%，吞吐还涨一半。 突发流量下，Llama-3.1-70B 的 P99 降 98%。 它是 Kubernetes 原生的，走官方 Gateway API。 主流推理引擎都能接，不绑死 AWS。 现在上的是单集群版，跨集群的全球路由还在路上。 https://aws.amazon.com/blogs/machine-learning/introducing-amazon-sagemaker-hyperpod-inference-gateway/

AWS 还盘点了今年 13 个推理新功能 官方博客昨天发了篇年中总结。 三条跟你研究方向最贴。 一是托管式分层 KV cache 加智能路由。 L1 放在每台机器的 CPU 内存里，本地复用最快。 L2 用 Redis 跨节点共享：这台算好的前缀，那台也能用。 三种路由：按前缀分、按缓存命中率分、普通轮询。 长上下文和多轮对话场景，延迟最多降 40%。 二是前缀感知路由。 把开头相同的请求固定发到同一台机器。 KV cache 复用率从 25% 跳到 82%。 Llama 3.1 70B 长上下文实测。 P90 首字延迟降了 33–37%。 路由本身只加 1.3–1.9 毫秒。 三是 P/D 解耦（读题和写答案分开干）。 prefill 和 decode 分到不同的 GPU 池。 KV cache 在 GPU 之间直传，不经过 CPU。 混合流量下，首字延迟和 token 间隔都更稳。 https://aws.amazon.com/blogs/machine-learning/amazon-sagemaker-inference-2026-year-to-date-launches-in-review/
