SuffixReplay：让线性状态"忘掉远古历史"——hybrid 模型的前缀缓存，不用再存 checkpoint

原文：Just Let Linear States Forget the Distant Past: Prefix Caching via Suffix Replay for Hybrid LLMs（arXiv:2609.33477，2026-09-27；作者 Yirui Liu 等，TeleAI 中国电信人工智能研究院；实现基于 SGLang v0.5.18，单卡 H100 80GB 实测）

一句话人话

hybrid 模型（全注意力层和线性注意力层混搭，长上下文更省算力）有个死结。

它的线性层把整层压缩成一个"循环状态"。

循环状态就是 recurrent state，一个固定大小的向量。

它逐 token 更新，只进不退。

这个状态只进不退。

打个比方：熬到第 100 分钟的汤，你倒推不出第 30 分钟的味道。

所以前缀缓存没法在任意位置命中。

现有方案只能每隔固定 token 存一个完整 checkpoint。

复用只能对齐这些离散点。

SuffixReplay 的想法很妙：线性注意力本来就会"遗忘"远古输入。

那就别存 checkpoint 了。

只存每层最近一小段输入，叫 anchor（锚点）。

命中前缀时，从锚点出发只重放一小段后缀，重建出近似状态。

核心问题：hybrid 模型的前缀缓存为什么难

长上下文 agent 和多轮对话里，前缀缓存是省 prefill 算力的主力。

但 hybrid 架构越来越主流。

Qwen3.5、MiniMax M3 都是这路数。

全注意力层的 KV 缓存是按 token 存的，像书签，想从哪页续读都行。

线性层的循环状态却没法倒推。

它不像 KV 那样按 token 独立存放。

现有做法是每隔 8192 个 token 存一个完整快照。

Marconi、Sparse Prefix 都是这路数。

问题有三：复用只能命中这些离散位置；存快照本身很贵；粒度越细越贵。

这就逼出了论文的三个设计要求：质量不能掉、存储要省、不能拖慢 serving。

核心方法：四件套

1. 关键洞察：遗忘是 feature，不是 bug

现代线性注意力都有"遗忘机制"。

靠 recurrent decay（循环衰减）和 gating（门控）实现。

远古输入的影响会被指数衰减掉。

所以"第 j 个位置的状态"其实主要由最近的输入决定。

类比：你记得昨天晚饭吃了啥。

但上个月某天的午饭早忘了。

做决策只用记得近期的就够了。

2. anchor 稀疏化：只存"重建材料"

不存完整状态，只存每层输入 hidden state 里的一小段。

稀疏分两层做。

层方向：每 4 层一组，只在组入口存。

token 方向：每页只存最后 k 个 anchor 行。

k 取 16、32 或 64，论文实测 k=32 是甜点。

3. 有界重放：命中时只算一小段

前缀在位置 j 命中时，不从头重放整个前缀。

只拿 j 之前的 k 个 anchor，重放一小段后缀，算出近似状态 S'_j。

因为衰减机制保证了远古贡献可忽略，近似误差是可控的。

4. 系统设计：anchor 边车 + 流水线重放

anchor 单独放在一个 sidecar（边车）里管理，跟 KV 页解耦。

KV 该驱逐驱逐，anchor 按自己的策略走，互不干扰。

重放的搬运和计算跟 serving 主流水线重叠，不挡路。

关键数据

  • 评测用了三个模型。
  • OLMo-Hybrid-7B、Qwen3.5-4B、Qwen3.6-27B-FP8。
  • 质量：LongBench + RULER 平均保留 91.4–100%。
  • 这是相对 full-prefill（完整重算）的质量。
  • 测了 k=16/32/64 三档（表 3）。
  • 存储：每个 token 的额外存储大幅下降。
  • 只有 SGLang 默认 checkpoint 方案的 0.36–0.51 倍。
  • 这是 Qwen 两款模型的数据（表 1）。
  • OLMo 那款是 0.80 倍。
  • TTFT：分支工作负载下中位 TTFT 降 15–70%。
  • 分支工作负载就是一个共享前缀分叉出多个续写。
  • 这是 agent 的典型场景（图 10）。
  • 吞吐：工作集超过 HBM 显存时大幅领先。
  • 达到 SGLang 的 2.3–4.3 倍（图 8）。
  • 高命中延续流量：跟 SGLang 打平，不拖后腿（表 4）。
  • 实现：基于 SGLang v0.5.18。
  • 评测全在单卡 H100 80GB 上跑。

跟你的研究方向的关联

  • 前缀缓存：直接相关。你评估 SGLang 时，hybrid 模型的前缀缓存是个暗坑。这篇是第一个做到"任意 page 边界都能复用"的方案。
  • hybrid serving：这类 hybrid 架构只会越来越多。
  • 比如 Qwen3.5/3.6、MiniMax M3。这篇补上了缓存复用这块拼图。
  • KV 优化思路可迁移：anchor 的哲学是"存重建材料，不存完整状态"。这跟 KV cache 压缩是同源思想。
  • P/D 解耦的提醒：hybrid 模型的 P/D 解耦有个额外麻烦。
  • KV 传输时线性状态同样要处理。mooncake 那类传输层现在传的是完整状态，这篇的重放思想也许能省传输量。
  • 提醒一句：91.4% 是最低档（k=16 配某些 RULER 任务）。anchor 密度和质量的 trade-off 要按自己负载调。
  • 再提醒一句：评测全是单卡 H100。多卡张量并行下 anchor 怎么同步，论文没覆盖，别直接照搬。

术语表

  • hybrid LLM（混合模型）：两种注意力层交错堆叠的模型。
  • 全注意力层加线性注意力层，长上下文更省算力。
  • 线性注意力（linear attention）：不用 O(n²) 注意力矩阵。
  • 用固定大小的循环状态逐 token 更新。
  • 循环状态（recurrent state）：线性层维护的向量 S。
  • 每个 token 更新一次，只进不退。
  • 前缀缓存（prefix caching）：复用之前算过的 prompt 前缀。
  • 跳过重复 prefill，省算力。
  • checkpoint（快照）：定期存一个完整线性状态。
  • 只能对齐命中，存起来贵。
  • anchor（锚点）：存下来的"重建材料"。
  • 即每层输入 hidden state 的一小段。
  • 后缀重放（suffix replay）：从锚点出发重建近似状态。
  • 只重放前缀末尾一小段。
  • 循环衰减（recurrent decay）：让远古输入影响指数衰减。
  • 这是"遗忘"的数学基础。
  • TTFT：首 token 延迟，第一个字蹦出来要等多久。
  • RULER / LongBench：长上下文能力的标准评测集。
