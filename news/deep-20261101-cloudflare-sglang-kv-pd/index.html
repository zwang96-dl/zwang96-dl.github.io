一句话人话

PD 解耦有个隐形坑。PD 解耦就是把推理拆成两道工序：读题和吐字分两拨 GPU 干。

请求中途被干掉时，decode 这边把 KV 槽位标成"空了"。KV 就是草稿纸，存着之前算好的键值。

但 prefill 那边已经发射出去的 RDMA 写还在路上。RDMA 是网卡直写内存，发射了撤不回来。

槽位转手给了新请求。老写入后脚落地。新请求读到的就是别人的草稿纸。

全程静默，不报错。

打个比方：酒店退房，前台说房间空了，保洁还没进门。下一个客人直接入住。前一个客人的行李还在往里送。

核心方法

不变量（一句话版本）

槽位只有在"没有任何远程写还能碰到它"时，才算真正空了。

分配器的"空闲位"只管本地账。它不管网卡队列里在飞的写。

为什么会坏（四步）

  • 请求 A 被干掉。原因可能是用户断连、准入拒绝、传输故障。至少一个已发射的写还没落地。
  • decode 释放 A 的槽位。分配器标空。
  • 分配器把槽位分给请求 B。
  • A 的迟到写落在 B 的 KV 里。B 读着别人的 K/V 往下解码，全程无错。

关键点：RDMA 一旦发射就撤不回来。网卡队列和分配器不共享状态。

"空闲"有两个隐藏条件：本地位空闲，加上在飞的写清零。

修复三件套

  • 通知 prefill（SGLang #27372）。decode 给所有 prefill rank 发 ABORT。prefill 扔掉软件队列里还没发的 chunk。尾巴被砍到只剩一个在飞的 chunk。
  • 按住槽位不释放（#35049，NIXL 移植 #35360）。abort 时 decode 把槽位按住。请求池行和元数据缓冲也一起按住。每个 prefill rank 数着自己在飞的活。清零才回 ABORT_ACK。decode 等齐所有 ACK，或等超时。PR 里默认超时 30 秒。
  • 按能力开、再默认开（#37454、#41023）。只有会回 ACK 的后端才有效果。所以先 opt-in。v0.5.21 起默认开。

公式

保持时间必须大于三项之和。abort 传播时间，加上剩余 chunk，加上在飞的那一笔调用。

即 T_hold > t_abort_propagation + t_remaining_chunks + t_in_flight_call。

作者的设计口诀值得抄：任何降级都要拉长保持时间。

运维清单（原文附了可直接用的脚本）

  • 每次改配置都对一遍：prefill KV 池的 token 容量。拿它去对配置的 context 长度。池小于窗口就拦下发布。
  • 跑 PD 解耦用 SGLang v0.5.21 及以上。MORI 后端要 v0.5.22。
  • 保持超时建议 60–120 秒。对应环境变量 SGLANG_DISAGGREGATION_DEFERRED_DECODE_KV_RELEASE_TIMEOUT。
  • 看 v0.5.22 的新指标。sglang:decode_deferred_kv_release_total{outcome}。drained 占比 95% 以上算健康。timeout 太多说明 ACK 路径有问题。

关键数据

  • 155 条泄露回复。全部是超过 681,280 token 的长 prompt。时间 2026-08-27 到 09-09。
  • 配置坑：context window 标 1,048,576。prefill KV 池只有 681,280。只覆盖 65%。请求能进窗口、进不了池，走到报错路径。
  • 影响版本：默认 PD 配置从 v0.4.x 到 v0.5.21。这段版本都有这个 race。MORI 到 v0.5.22。修复没回灌到老分支。单机部署不受影响，因为没有跨引擎传输路径。
  • 稳态开销：SGLang 团队在 2×H100 上测了 21 轮。1P1D、1024 请求、并发 256。开和关吞吐差在 ±2% 以内，噪声级。保持只发生在 abort 路径。
  • 实测复现：2×H200 上，受害者数到 80 还是对的。之后输出变成捐献者的 prompt 原文。污染是静默的：传输报成功，各组件都不记错。
  • 示意模型结论（作者自搭，非实测）。abort 不通知 prefill 时，中途 abort 几乎必污染。通知后 10ms 复用仍有 43% 污染率。只有按住槽位才归零。60 秒保持把每万次 abort 的污染从约 500 压到 113。120 秒压到 6。

术语表

  • PD 解耦（prefill/decode disaggregation）。
  • 就是把"读题算草稿"和"逐字吐答案"拆到两拨 GPU 上跑。草稿纸（KV cache）靠网络从 prefill 传到 decode。
  • KV 槽位：decode 侧给每个请求预留的 KV 存储位置。
  • RDMA：网卡直写内存的技术，CPU 不参与。发射出去的写撤不回来。
  • Deferred KV release（延迟释放）：abort 时不立刻释放槽位。按住一段时间，等在飞的写落地。
  • ABORT_ACK：prefill 回给 decode 的确认。表示"我这边在飞的写清零了"。
  • Mooncake / NIXL / MORI：三种 KV 传输后端。Mooncake 是月之暗面开源的。NIXL 是 NVIDIA 的传输库。
  • Use-after-free：内存释放后又被使用。这里是分布式版本：槽位"释放"了，远程写还在用。
  • KV checksum：传输校验和。开启后能发现传错，但发现不等于防住。
