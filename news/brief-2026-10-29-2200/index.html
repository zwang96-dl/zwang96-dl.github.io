多模态大模型推理服务简报 · 2026-10-29（22点版）

头条

SGLang 修了 PD 重启时"草稿纸缩水"的 bug PD 重启是 decode 请求被抢占、prefill 重算前缀的情形。 旧代码重启前会把最后一个输出 id 先弹出去。 弹出去的那段时间，客户端看到的完成 token 数会变小。 重发时 logprob 还会再推一遍给客户端。 这版改成保留最后一个输出 id。 prefill 采样出的 token 照例丢弃。decode 侧采样不受影响。 KV 大小不变，commit 时不重复推 logprob。 对你评估 PD 有用：这是 decode 侧状态机的坑。 来源：https://github.com/sgl-project/sglang/pull/47366

TRT-LLM：Kimi K3 的 DSpark 解码修好了 今晚的 nightly dev 版装不上 Kimi K3。 两个地方断了：checkpoint 加载缺字段。DSpark 首步参数也对不上。 都是新改动打破了旧契约，紧急修复。 跑 Kimi-K3 的人，得等这个修复。 来源：https://github.com/NVIDIA/TensorRT-LLM/pull/21261

TRT-LLM：多模态 KV 事件带上 UUID 了 V2 KV 事件协议里，多模态 token 的 UUID 会丢。 路由观察者认不出这是哪个请求的事件。 这版把 UUID 透传到底，多模态缓存可观测性补齐。 来源：https://github.com/NVIDIA/TensorRT-LLM/pull/19529

TRT-LLM：OpenEngine 的 gRPC 支持音频输入了 多模态入口又加一个：音频。 来源：https://github.com/NVIDIA/TensorRT-LLM/pull/20655

TRT-LLM：serve 默认 frontend 改成 8 个 这是个 BREAKING 变更。 单 frontend 时会自动回退。 来源：https://github.com/NVIDIA/TensorRT-LLM/pull/19379

新技术与论文

注：arXiv 本窗口零入库，下面两篇是 10/30 00:00 批次的补拾。

Raincheck：多轮多模态里，视觉预处理可以"先欠着" 多轮对话里，前面的图片问题一直在上下文里占位置。 每轮都把图片全量 prefill，首 token 等太久。 Raincheck 把多模态 prefill 推迟。先留 30% 的 token 顶上。 没算完的用 decode 时的空闲算力慢慢补上。 SGLang 实现，首轮 TTFT 最高降 24.1%。 decode 速度几乎不掉，TPOT 只涨不到 0.5%。 跟你的多模态资源分离方向直接对口。 原文：https://arxiv.org/abs/2610.39562

PDScope：MoE 在本地 CPU-GPU 节点上的跷跷板 显存不够，大部分 expert 只能躺在 CPU 内存里。 prefill 是算力瓶颈，想多往 GPU 里塞。 decode 是 PCIe 搬运瓶颈，想少塞点。 一个策略伺候不了两边，这是跷跷板。 这篇想打破它，跟 PD 解耦是同一条账。 原文：https://arxiv.org/abs/2610.39216
