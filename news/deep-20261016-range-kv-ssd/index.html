Range：从 SSD 捞草稿纸，别按件收费

原文：Range: Decoupling KV-Cache Reuse Granularity from Storage Work 作者：Dingsen Shi 等（北得州大学与 SageShield） 提交：2026-10-15 链接：https://arxiv.org/abs/2610.21241v1

人话解读

  • KV 放不下，就会溢到 SSD。
  • KV 缓存就是模型的草稿纸。
  • SSD 就像楼下的仓库。
  • 用时要先把草稿捞回显存。
  • 大家一直以为 SSD 太慢。
  • 这篇说，慢的不是 SSD。
  • 慢的是按件收费的流程。
  • 同一份草稿，字节没变。
  • 切成的件数越多就越慢。
  • 每件都要查、登记、搬运。
  • 件数翻 32 倍，耗时涨四成。
  • 说白了是快递按件计费。
  • 拆成小包，运费就爆炸。
  • Range 把计费改成按重量。
  • 件数再多，耗时也不涨。

图注：图 1 是原文的主结果图。 横轴是同一份草稿的切件数。 纵轴是用户等首字的耗时。 蓝点是 Range，全程贴着绿点。 绿点是草稿已在显存的对照。 橙点是原装路径，越切越慢。 灰点是全部重算，最慢那档。

核心方法

  • 原则只有一条，很好记。
  • 所有开销只跟字节数走。
  • 永远不跟逻辑件数走。
  • 第一步，发明一张区间票。
  • 票就是一张取货凭证。
  • 一张票代表一整段草稿。
  • 不再给每小件单独建档。
  • 查一次，只选出 6 条记录。
  • 原装路径要选 6144 条。
  • 第二步，磁盘按条带存。
  • 条带就是固定大小的包。
  • 草稿装进 1 GiB 的大包。
  • 恢复永远只读 192 次。
  • 切多细，都不影响读法。
  • 第三步，设中转银行。
  • 银行就是 GPU 旁的中转台。
  • 一共 8 台，每台 32 MiB。
  • 哪层先到，哪层先开算。
  • 不用等全部到齐才开工。
  • 它是 LMCache 的存储后端。
  • LMCache 是 KV 复用工具。
  • 接进 vLLM 只改了 4 行。
  • 底层读盘通道保持原样。

图注：图 2 是原文 Figure 3。 左边是调度器，先查目录。 查完发一张区间票出去。 中间按条带从 SSD 读盘。 右边是干活的 worker。 它领票后把数据送进银行。 再散放到对应的 KV 槽位。 某层齐了就发就绪信号。 注意力马上能用上那层。 下方是回存新草稿的流程。

关键数据

  • 实验在一张 H100 上跑。
  • 模型是 Llama-3.1-8B。
  • 软件是 vLLM 加 LMCache。
  • 版本分别是 0.25.1 和 0.5.2。
  • 两块 NVMe 盘组了阵列。
  • 测试题总长约 6.5 万词。
  • 其中约 4.9 万词有缓存。
  • 要恢复的草稿共 6 GiB。
  • 切件数从 192 涨到 6144。
  • Range 的首字耗时几乎不动。
  • 中位数一直在 1.79 秒上下。
  • 全程波动只有 15 毫秒。
  • 只比显存直用慢约 60 毫秒。
  • 原装路径则一路往上爬。
  • 从 2.12 秒涨到 3.01 秒。
  • 逐层加载时它要 2.66 秒。
  • Range 逐层也只要 1.79 秒。
  • 全部重算要约 4.8 秒。
  • 所以恢复仍然很划算。
  • 以上数字都是作者自报。
  • 每档只测了三轮重复。
  • 本期没有独立复核。

图注：图 3 是原文 Table 2。 它数的是每条路径的动作数。 原装切到 6144 件时最惨。 查记录、读盘、搬运全是 6144。 回存提交也涨到 2016 次。 Range 在两种切法下都一样。 只选 6 条物理记录。 读盘和搬运都固定 192 次。 回存提交也固定在 64 次。 动作数不随件数涨是关键。

跟你研究方向的关联

  • 这篇接上昨天的 RemoteKV。
  • RemoteKV 讲远程仓库的账。
  • 这篇讲本地 SSD 的账。
  • 两篇都说瓶颈不在介质。
  • 瓶颈在按件办事的流程。
  • 你的 autotuner 要记这笔。
  • KV 分级不能只估带宽。
  • 还要估每件的固定开销。
  • 切分粒度本身就是旋钮。
  • 粒度越细，复用越灵活。
  • 但恢复的账单也越贵。
  • Range 给了脱钩的办法。
  • 逻辑上细切，物理上整装。
  • 你测 P/D 解耦时也能借。
  • KV 跨机搬运也是按件的。
  • 件数乘固定开销要单列。
  • 别只盯网线带宽一个数。

局限和要注意的

  • 实验一次只服务一个请求。
  • 并发服务还没做，是未来工作。
  • 多卡只实现了，没有实测。
  • 模型只测了 8B 这一个。
  • 盘只有两块 NVMe 阵列。
  • 换你的 H100 和 MI350 要重测。
  • AMD 侧的读盘通道也不同。
  • 结论方向可信，数字别照搬。

术语表

  • KV 缓存：模型存下的注意力草稿。
  • TTFT：用户等到首字的耗时。
  • 逻辑对象：一件可复用的草稿块。
  • 区间票：一整段草稿的取货凭证。
  • 字节条带：固定大小的磁盘存包。
  • 传输银行：GPU 旁的数据中转台。
  • 逐层加载：按网络层逐层恢复 KV。
  • cuFile：GPU 直读磁盘的通道。
