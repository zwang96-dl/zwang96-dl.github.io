ACSeL：硬件不够，调参来凑 ⭐值得深读

serving 的旋钮太多了。 模型大小、batch、量化配方。 一股脑全试，试不完。 这篇换了个思路。 先拿便宜的办法估质量。 再拿便宜的办法估延迟。 两个估算器带着搜。 搜出预算里最好的配置。 质量估算器叫 RMQD。 它量的是候选模型跟参考模型。 下一个词的分布差多远。 跟真实分数的相关性很强。 MMLU 上 -0.85。 算一次只要 6.84 秒。 直接跑评测要 626.91 秒。 快了 91.6 倍。 延迟估算器叫 FMC。 只拿少量真实 profile 校准。 TTFT 的预测误差从 78.5% 压到 24.8%。 搜法叫 BandPareto。 逐层混精度不再乱试。 按带状结构走。 A6000 上。 答得出配置的请求从 48% 涨到 92%。 严格满足延迟的从 32% 涨到 48%。 放宽 10% 容忍后是 84%。 Thor 边缘卡上。 答得出从 16% 涨到 76%。 这篇值得深读：跟你的 AI 自动调参想法正对口。 质量代理加延迟代理加结构搜索。 这三招可以直接抄。 精读笔记随后上站。 来源：https://arxiv.org/abs/2611.07570

SpecCTMC：扩散模型也能投机解码

扩散语言模型一次能写好几个词。 但各写各的会打乱词之间的关系。 这篇不用单独的草稿模型。 拿之前算过的预测直接提候选。 再并行验一遍。 验不过的纠正回来。 分布一点不走样。 数学上证明了保真。 LLaDA-8B 和 Dream-7B 上。 顺序算的次数少了 1.73 到 4.38 倍。 来源：https://arxiv.org/abs/2611.08362

Measured Coupling：扩散模型并行解码，哪些词能一起交

扩散模型每步要挑哪些词一起定稿。 老办法看两个位置的预测像不像。 这篇直接量真东西。 定一个词会让另一个词的信心变多少。 探针藏在正常前向里。 不用训，不用加模型。 三个模型四个 benchmark 上。 步数比老办法少得多。 多数设置下更快。 精度平均只掉 1.1 个点。 来源：https://arxiv.org/abs/2611.08307

NUMA-Torch：CPU 读题，内存别跑错插槽

大模型在多插槽 CPU 上读题。 瓶颈不在算力，在内存带宽。 PyTorch 默认不管 NUMA 拓扑。 权重经常跨插槽去取。 这篇让编译器认路。 每个插槽当一个独立的张量并行分片。 权重按插槽切好。 计算和内存都锁在本地。 双插槽 Haswell 上读题快 2.63 倍。 四插槽 Haswell-EX 上快 2.27 倍。 来源：https://arxiv.org/abs/2611.07105

ServerBench：让 coding agent 自己设计 serving 系统

coding agent 不光能写代码。 也能设计整套推理服务。 这篇出了个 benchmark。 目标是每块钱 GPU 挣回多少延迟合格的 token。 Claude Sonnet 5.5 拿了 2.97。 是 vLLM 参考实现的 4.87 倍。 33 次里 22 次交出能验证的系统。 13 次超过最强基线。 来源：https://arxiv.org/abs/2611.06841
