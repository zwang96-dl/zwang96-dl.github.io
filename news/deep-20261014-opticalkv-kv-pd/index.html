Optical KV：给 PD 解耦修一条光专线传草稿纸

  • 原文：https://arxiv.org/abs/2610.18444
  • 作者：Seongwon Yoon、Shimeng Yu
  • 日期：2026-10-13 提交（arXiv 10/14 批次公布）

一句话人话

PD 解耦有个隐形账单。 prefill 算完，草稿纸要搬家。 草稿纸就是 KV cache。 它搬去 decode 卡才能开写。 现在搬运走普通分组网络。 网络超订一挤，首字就迟到。 这篇给搬运单独修了条光专线。 专线开通慢，就把等待藏进计算里。 仿真里性能打平 400G 普通网络。 成本只要对手的五成五到七成八。

核心方法

  1. 网络分工：请求走老路，KV 走光路。
  2. 请求、输出和控制信号不动。
  3. 它们继续走主机网卡和老网络。
  4. 每张 GPU 的 RDMA 网卡改接光交换机。
  5. RDMA 就是绕过 CPU 的直传通道。
  6. 光交换机行话叫 OCS。
  7. 每张卡用一对光纤接入。
  8. 一根光纤上用不同波长分多路。
  9. 这招行话叫波分复用，缩写 WDM。
  1. 预约调度：算之前先把线路订好。
  2. 光专线的好处是独占不抢道。
  3. 坏处是机械光开关动作慢。
  4. 重新配置要几十毫秒。
  5. 作者让调度器提前下单订线。
  6. prefill 一开算就订头段线路。
  7. 最后一个分块时再订尾段。
  8. 行话叫 last-chunk commit。
  9. 等待时间全程压在计算底下。
  10. KV 算完那一刻，线刚好通。
  1. 选目标卡：挑最早空出来的。
  2. 订线时先看 decode 端口。
  3. 哪个端口最早空闲就订哪个。
  4. 已有现成线路的优先用。
  5. 省掉一次重新配置的等待。

关键数据

  • 对照组是 400G 分组网络。
  • 对方开了自适应路由。
  • 光网络性能跟它打平。
  • 成本是 2:1 超订网络的 0.55 到 0.78 倍。
  • 扛得住 384 端口机械光开关。
  • 那种开关重配置要 50 毫秒。
  • KV 有多重？先感受一下量级。
  • Llama-3.1-70B 用 BF16 存。
  • 每个 token 的 KV 是 320 KiB。
  • 6.4 万 token 上下文约 20 GB。
  • 智能体一轮就搬这么多。
  • 图 1 里那次迁移搬 6.67 万 token。
  • 实验底子要说清，不是线上实测。
  • prefill 时间是 H100 实测的。
  • 他们测了 33 次 vLLM 运行。
  • 拿实测拟合出一个成本模型。
  • 模型中位误差 4.6%。
  • 集群层面的结果来自仿真。
  • 仿真喂的是真实服务轨迹。
  • 规模点有 128 卡和 256 卡。

术语表

  • PD 解耦：prefill 和 decode 分卡干。
  • KV cache：算过的注意力草稿纸。
  • TTFT：等到第一个字的时长。
  • OCS：光电路交换机，给连接修专线。
  • EPS：普通电分组网络，走共享道路。
  • WDM：波分复用，一根光纤多路并行。
  • RDMA：绕过 CPU 的内存直传。
  • 超订：总需求大于总带宽的配比。
  • 预约调度：提前订线路，等待藏进计算。
  • SLO 达标率：请求按时完成的比例。
