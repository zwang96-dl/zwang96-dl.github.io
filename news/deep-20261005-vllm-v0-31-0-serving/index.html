vLLM v0.31.0：大规模 serving 更新精读

原文链接：https://github.com/vllm-project/vllm/releases/tag/v0.31.0 发布时间：2026-10-04 23:44 PDT（本轮窗口内发布） 版本规模：717 个提交，307 位贡献者（96 位新人）

人话解读

  • vLLM 发了个大版本，核心就一句话：大模型上云 serving 更快、更稳、更好管了。
  • 对你最直接的三块：prefill 并行混搭数据并行。
  • MoE 通信换了更均衡的后端，调度器多了新旋钮。
  • 运维向的：引擎重启不用重新读权重了，秒级回来。
  • 这篇笔记只挑 serving 相关的讲，模型支持和纯 bugfix 略过。

核心更新

大规模 serving

  • 新增 MoonEP：更均衡的专家并行通信后端。
  • MoE 推理时，专家之间要交换 token 数据。
  • 以前的后端负载不均，有的卡闲有的卡排队。
  • MoonEP 把这份通信摊得更平，长尾延迟下来了。
  • 用法就是一行参数：--all2all-backend moonep。
  • prefill 的上下文并行，现在能跟数据并行组合。
  • 上下文并行是把长 prompt 切段分给多卡一起读。
  • 数据并行是多份请求复制模型同时跑。
  • 以前两者难兼得，现在可以叠起来用了。
  • DeepEPv2 也支持了序列并行。
  • EPLB 加了共享专家重叠，通信和计算错开跑。
  • KV 卸载加了背压检测。
  • KV 往 CPU 搬时如果下游跟不上，会提前告警。
  • 以前是默默变慢，现在能感知到瓶颈在哪。

调度器新旋钮

  • --max-num-active-seqs：单独限制"正在跑"的请求数。
  • 以前的 max_num_seqs 管的是总数。
  • 新参数把"排队"和"在跑"分开管，更精细。
  • --long-prefill-token-threshold 改成自适应。
  • 以前长 prompt 超固定阈值就被切块。
  • 现在看排队里有多少 prefill，再动态定阈值。
  • 类比：以前食堂按固定人数开窗口。
  • 现在看排队长度动态加减窗口。
  • 等待队列改写：已占着 KV 块的请求优先调度。
  • 占着位置的先上车，省得 KV 块反复分配释放。
  • 修了一个死锁：KV connector 配 MTP 时。
  • KV 压力下一度会卡死，这版修好了。

快速重启

  • 新命令 vllm preload：起一个权重缓存守护进程。
  • 权重经过量化、切分后常驻 GPU 显存。
  • 引擎重启时通过 CUDA IPC 直接映射。
  • CUDA IPC 是同机 GPU 进程间共享显存的机制。
  • 不再从磁盘重新读权重。
  • 以前重启要几分钟，现在秒级回来。
  • 这轮还加上了数据并行和 MTP 草稿模型支持。
  • 新增 /health 端点和就绪等待，方便编排。
  • 实验性功能：vllm snapshot。
  • 用 CRIU 给初始化好的引擎拍快照。
  • CRIU 是 Linux 下给进程拍快照恢复的工具。
  • 快照恢复是整机状态还原，适合 TP1 小引擎。

推测解码

  • Model Runner V2 上支持了草稿模型推测解码。
  • Model Runner V2 是 vLLM 新一代执行引擎。
  • 推测解码就是小模型先打草稿、大模型改。
  • 新增 LiLiCorr drafter，一种新的草稿模型。
  • DFlash 支持异步调度。
  • 草稿的上下文 KV 预计算进了 CUDA 图。
  • DSpark 自适应验证支持 Gemma4。
  • Kimi-K3 支持变长 decode。
  • MRV2 做内存估算时把 MoE 内存也算进去了。
  • 以前 WideEP 部署容易 OOM，现在提前算准。

多模态相关

  • 视觉 tower 支持了编码器 CUDA 图。
  • CUDA 图是把一串 kernel 调用录下来一次下发。
  • 省的是 kernel 调度开销。
  • 多模态前缀缓存改成增量式块哈希。
  • 前缀缓存就是"算过的 prompt 片段不用重算"。
  • 新加了 Triton 写的 mm_input_norm kernel。
  • SWA 滑动窗口的 KV 不再进前缀缓存。
  • 滑动窗口注意力只看最近一段。
  • 缓存它没意义还占地方，干脆不进缓存。

安全与 breaking change

  • 每个请求的多模态参数默认被拒绝。
  • 可信部署要在启动时加 --trust-request-mm-kwargs。
  • 前缀缓存的 key 现在按来源打标签。
  • 以前 LoRA 名字和 cache_salt 可能撞车。
  • 现在分开了，LoRA 路径也进了块哈希。
  • tokenizer_mode="slow" 被删了。
  • 在线量化 fp8 改名 fp8_per_tensor。
  • Quark 的静默在线量化被移除。
  • AllSpark INT8 后端被移除。
  • 升级前先在 staging 测一遍，别直接升生产。

跟你研究方向的关联

  • 你在评估 SGLang 的 P/D 解耦。
  • vLLM 这版就是"对照组"的进度条。
  • prefill 上下文并行加数据并行：prefill 侧多了一种姿势。
  • 评估时可以对比 SGLang 的对应能力。
  • MoonEP：MoE 大规模 serving 的通信瓶颈。
  • SGLang 那边也有 DeepEP，值得横向看。
  • 调度新旋钮：--max-num-active-seqs 和自适应阈值。
  • 都是 SLA 内调 throughput 的现成抓手。
  • 跟你想做的 AI 自动调参系统直接相关。
  • vllm preload：生产滚动升级的停机大头是权重加载。
  • 这个能力上线后，可以重新测重启开销。
  • SWA 的 KV 不进前缀缓存：滑动窗口模型的前缀缓存策略。
  • 跟 RR-Evict 笔记里的淘汰策略可以对照看。

术语表

  • SM100：Blackwell 架构的流多处理器代号，B200 用的就是。
  • NVFP4：4 位浮点格式，NVIDIA 的低精度量化格式。
  • MXFP8：8 位微缩放浮点，微软主导的格式。
  • FlashMLA：DeepSeek 开源的高效注意力实现。
  • MoE：混合专家模型，每次只激活一部分专家。
  • EP：专家并行，MoE 专家分到不同卡上。
  • all2all：集合通信的一种，互相都要发数据。
  • DP：数据并行，多份数据同时跑。
  • TP：张量并行，一个算子切到多卡。
  • MTP：多 token 预测，一次前向猜多个 token。
  • SWA：滑动窗口注意力，只看最近一段上下文。
  • EPLB：专家并行负载均衡。
  • WideEP：专家并行规模很大的部署形态。
