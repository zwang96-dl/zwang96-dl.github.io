树形投机解码装进 DeepSeek-V4：压缩注意力下的分支一致性

原文：Adapting Tree-Structured Speculative Decoding to DeepSeek-V4 for Efficient Inference
作者：Changxu Liu, Zhaogeng Li（百度 Baige AI Team + 复旦）
链接：https://arxiv.org/abs/2609.24698

人话解读

树形投机解码不是新东西，难的是把它塞进 DeepSeek-V4 里。 V4 的注意力会把历史在线压缩，树分支一多，压缩状态就对不上。 这篇把三件事做对了：验证看分支、中间状态隔离、最后只提交被接受的路径。 说白了：先把几条候选路并行试一遍，选中的那条才写进档案。 在 DeepSeek-V4-FLASH 上测的，预算 D=5 到 8。 D=8 时树形接受长度 2.83–3.41，单链只有 2.39–2.84。 吞吐最高 +18.5%，小到中等 batch 上最香。

核心方法

三大挑战：

  • 分支感知的因果验证和隔离。

不同分支的 token 一起验，物理顺序不等于逻辑依赖。 attention mask 必须按树拓扑来，兄弟分支互相看不见。

  • 压缩状态一致性。

CSA/HCA 在线压缩，分叉后的分支会压出不同的压缩状态。 token 级验对了还不够，压缩状态也得跟被接受路径一致。

  • 动态树执行开销。

建树、元数据、临时状态、路径刷新都是额外开销。 多接受的 token 得盖住这笔账，吞吐才真涨。

三阶段投机前向（图 1）：

  • Draft Extend：把已接受前缀展开成候选树。
  • Draft Decode：按树拓扑算草稿表示，复用 V4 的 FlashMLA 树 attention。
  • Target Verify：先跑 verify preprocess 生成验证计划。

再做分支感知因果验证，候选链共享前缀复用、分支后独立压缩。

状态管理：

  • token 级 KV 和压缩状态分开管，CSA/HCA 比滑动窗口难搞得多。
  • 候选分支的状态先写进 scratch pad（临时草稿纸），不污染持久缓存。
  • 接受路径选出来后才刷新：token 历史、KV、CSA/HCA 压缩状态一次刷齐。
  • C4 压缩频繁要及时刷，C128 压缩少可以攒一波再写。
  • 整体直接写进 SGLang 的投机推理管线，CUDA Graph 按树形配置限定覆盖。

关键数据

DeepSeek-V4-FLASH，8 卡 NVIDIA，batch 1–64，三个数据集（GSM8K/MBPP/ShareGPT）：

  • 接受长度：树形在全部配置下都赢单链。D=8 时 2.83–3.41 对 2.39–2.84。
  • 相对增益随预算走高：D=5 约 +11.0%，D=6 +14.4%，D=7 +17.1%，D=8 +18.6%。
  • 增益增量递减：+3.4%、+2.6%、+1.6%，草稿的可靠预测视野是天花板。
  • 吞吐增益：D=5 只有 +3–5%（小预算下勉强打平）。D=6 到 +8–9%，D=7/8 停在 +9–10%。
  • 同预算下"浅而宽"和"深而窄"接受长度只差 2% 以内。

draft 不够强时，加深不如加宽。

  • batch 维度呈倒 U 形，峰值在 batch=4 附近。

小 batch 访存 bound，多接受 token 直接砍前向次数。 大 batch 计算 bound，候选反而抢算力。

  • 最难预测的 ShareGPT 增益最高，全局峰值 +18.5%（s3_k2_d6，bs=4）。

单链最容易早崩的地方，树形的宽度最能救场。

关键图表

术语表

  • CSA（Compressed Sparse Attention）：DeepSeek-V4 的压缩稀疏注意力，把历史在线压成短表示。
  • HCA（Heavily Compressed Attention）：更重压缩的注意力变体，跟 CSA 搭配用。
  • 接受长度（accepted length）：一轮验证平均接受多少个 token，衡量候选质量。
  • 验证预算 D（verification budget）：目标模型一轮验证的候选 token 总数。
  • EAGLE/MTP：主流的草稿+验证投机解码框架。
  • scratch pad：临时草稿纸，分支状态先存这里，选中才转正。
  • CUDA Graph：把 GPU 算子序列预录成图，避免重复调度开销。
