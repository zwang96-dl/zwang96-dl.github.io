vLLM：Kimi-K3.1-Pro 的 B300 P/D 配方来了

#67722 是本轮最值得看的一条。

它给 Kimi-K3.1-Pro 加了 B300 预设。

预设走 AgentX 的拆分部署。

拆分部署就是 prefill 和 decode 分开跑。

像流水线分工，各干各的活。

这条跟你研究的 P/D 解耦直接相关。

#64574 修的是 MoRIIO 的端口冲突。

MoRIIO 是搬运 KV 缓存的工具。

KV 缓存就是模型的草稿纸。

多卡并行时端口会撞车。

撞车就连不上，现在修好了。

#65186 跟 GDN 的检查点有关。

prefill 的检查点能导出来了。

检查点就是中途的进度存档。

以后能接着跑，不用从头算。

#67072 是 AMD 的小优化。

MoE 的输出投影融进 topk 排序。

跑 M3.1 decode 更快一点。

#62590 调了 Qwen4Exp 的稀疏预热。

#49700 让 EPLB 的状态覆盖更细。

EPLB 是专家负载均衡的调度器。

来源：https://github.com/vllm-project/vllm/pull/67722 来源：https://github.com/vllm-project/vllm/pull/64574 来源：https://github.com/vllm-project/vllm/pull/65186

SGLang：14 条，NPU 和 Kimi-K3 占大头

#50097 给 NPU 加了 FP8 KV。

FP8 就是把草稿纸的字写小一半。

用在 DSA 的 decode 上下文并行。

DSA 是把超长上下文切开分卡算。

省显存，长上下文 decode 更划算。

#46022 是调度器的小修。

共享前缀去重，省一次重复计算。

前缀就是很多请求共用的开头。

#46063 也跟调度器有关。

给 encoder 的重放行预留位置。

多模态请求排队更稳。

#40732 补了个 PD 测试。

覆盖 decode 回撤后的重启路径。

#50839 修 Kimi-K3 的空闲 rank。

attention DP 下空闲的卡不再捣乱。

KDA 检查点的类型也对齐了。

#50526 和 #50524 是 inkling2 的新核。

#50882 让每台服务器都记 GC 日志。

GC 就是内存回收，卡顿了能查到。

#50870 修 AMD 的 DSA 内核。

token 偏移改成 64 位。

#50725 修 NPU 的 prefill 崩溃。

#50470 修多模态的张量匹配。

#49481 让 prefill 图能断点续跑。

#50869 和 #49409 是 RL 方向的。

sglang-miles 的输出缓存更稳。

来源：https://github.com/sgl-project/sglang/pull/50097 来源：https://github.com/sgl-project/sglang/pull/46022 来源：https://github.com/sgl-project/sglang/pull/40732

TRT-LLM：Kimi K3 上 SM107，混合 KV 缓存升到 V2

#22175 是本轮最实在的一条。

Kimi K3 的运行时上了 SM107。

SM107 就是 B300 那代卡的代号。

混合 KV 缓存也升到 V2。

KV 缓存就是模型的草稿纸。

#21711 修的是拆分部署的停止判断。

生成服务器接手后，第一 token 就要查停。

以前可能漏查，现在补上了。

#22408 扩了 DSpark 的草稿页。

DSpark 是投机解码的草稿器。

投机解码就是先让实习生打草稿。

再让专家一次性改完。

#21887 让采样方式能选。

CUDA 图捕获时挑要用的采样变体。

#22286 是重构，#22320 和 #22226 是测试。

#22039 修了个安全漏洞。

Qwen3.8-Flash-Next 自托管指南更新了

这篇讲自己搭服务器跑 Qwen3.8。

Qwen3.8-Flash-Next 是通义的新模型。

vLLM 配方要 v0.30.0 以上。

SGLang 配方覆盖 H200 到 GB300。

TP8 还能上 AMD 的 MI350X。

单张 RTX PRO 6000 也能跑 NVFP4。

DGX Spark 也行，n-gram 表放 NVMe。

你手里有 H100 和 MI350X。

照着配方能直接抄作业。
