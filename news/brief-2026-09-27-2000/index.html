新技术与论文

1. EAServe：多模态推理的"三段式"解耦

  • 多模态推理是三段流水线：先编码图片，再理解，最后逐字输出。
  • 编码这段最尴尬：每请求必经它，GPU 却常年吃不饱。
  • EAServe 让编码当"交通指挥"：管放行节奏，也管去哪算。
  • GPU 怎么分块，它也一并说了算。
  • 实测覆盖图像、视频、音频三种模型。
  • 达标吞吐最高 4.3 倍，干掉了 Dynamo。
  • 对比 vLLM 也有 1.7 倍，配置还能自动搜最优。
  • 这篇跟你手头的事直接对口：你在看 SGLang 的 P/D 解耦。
  • 它把同一套思路搬到多模态，多了编码这一段要管。
  • 精读笔记已生成：EAServe-多模态Encode感知解耦。
  • 原文：https://arxiv.org/abs/2609.31551

2. KV Cache 新"内存墙"：一篇把五大门派重考一遍的综述

  • 长上下文越跑越慢，卡的不是算力，是显存带宽。
  • 作者把 KV 优化分成五派：量化、扔 token、分页。
  • 剩下两派：复用前缀、搬去异构存储。
  • 同一套考卷重考：128k 上下文，Llama-3-70B。
  • 关键结论分三段：短了拼权重，长了拼 KV，再长拼的是网卡。
  • 4-bit 以下量化，精度掉得越来越快。
  • 分页和前缀复用不掉精度，但只解决"装不下"，不解决"搬不动"。
  • 硬件给了三档：H100、B200、MI300X。
  • 你手里的 MI300X 也在表里。
  • 选型有现成规则：看硬件、看长度、看精度预算。
  • 原文：https://arxiv.org/abs/2609.30854

3. ActKV：给 agent 的 KV 瘦身，先保"动作记忆"

  • agent 一步步干活，KV 越堆越多，显存先顶不住。
  • 这篇的思路：压缩别瞎压，先保住跟"下一步动作"有关的记忆。
  • 长任务实测：精度保住 98.53%，显存只用 25.98%。
  • token 吞吐涨到 3.97 倍，任务吞吐 3.58 倍。
  • 搞 agent 服务的话，这套"动作优先"值得借鉴。
  • 原文：https://arxiv.org/abs/2609.31395

4. FragToken：tokenizer 的"一字多写法"能拿来偷算力

  • 同一句话，tokenizer 能切出长短两种写法，攻击者专挑长的。
  • 效果：解码步数翻倍，账单翻倍，但你看到的回复长度没变。
  • 实测 token 膨胀 1.99–2.46 倍，质量几乎不掉。
  • 这是供应链投毒的新姿势：不用刷请求，悄悄多烧钱。
  • 做推理服务计费的话，得盯着这一手。
  • 原文：https://arxiv.org/abs/2609.31552
