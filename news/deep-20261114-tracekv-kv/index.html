TraceKV：推理模型的草稿纸，压 5.64 倍还不掉分

  • 原文：Ke Li、Zishan Shao、Yiran Chen，杜克大学
  • 论文：arXiv:2611.15569，2026-11-11 提交
  • 论文链接：https://arxiv.org/abs/2611.15569
  • 代码地址：https://github.com/AK-DREAM/TraceKV
  • 说明：数字全是作者自报，没有第三方实测

一句话

会推理的视觉语言模型，草稿纸特别占地方。

这篇把它压到原来的六分之一，推理还不跑偏。

人话解读

视觉语言模型现在不只看图答题。

它要一步一步想，像做数学题那样推理。

想得越久，草稿纸越厚。

图片的 token 加上推理过程的 token。

全都要存在 KV 缓存里，等着后面接着用。

KV 缓存就是模型的草稿纸。

存的是每一步算好的键和值。

低秩压缩是省纸的老办法。

只存主要的几条信息，细节扔掉。

以前的办法有个毛病。

校准用的都是输入的图片和问题。

模型自己想出来的推理过程，没拿去校准。

结果压完之后，模型越想越偏。

答案开始跑偏，严重的还会死循环。

这篇先找出两个病根。

第一，校准数据和真实推理对不上。

第二，不同位置的 KV，压坏的代价不一样。

然后三招一起上，把两个病根都治了。

核心方法

方法分三步，都围着一个原则转。

原则叫保策略：压完之后，模型的答案分布别变。

不是只看数字像不像，而是看它想说什么别变。

第一步，在线校准。

先让没压缩的模型自己生成推理轨迹。

拿图片加问题，让它一步一步想。

把输入和想出来的过程都收起来。

一起做校准数据。

这样校准用的数据，跟推理时遇到的一样。

第二步，敏感度加权的 SVD。

SVD 是一种矩阵分解，把大矩阵拆成小块存。

先量每个 KV 位置有多敏感。

敏感度用策略 KL 散度来算。

策略 KL 散度是衡量答案分布变了多少的尺子。

采样下一词的预测，算分数梯度。

敏感的位置多留，不敏感的位置少留。

第三步，全局分配 rank。

rank 就是低秩压缩后留多少维度。

所有层、所有 KV 投影，共用一个总预算。

按每个奇异成分的重要性来分。

重要的多分，不重要的少分。

三步都不用训练，校准完直接就能用。

关键数据

实验覆盖 4 款会推理的视觉语言模型。

主表列了三款。 Qwen2.5-VL-7B、InternVL3-8B、Qwen3-VL-8B。

另外 Qwen3-VL-32B-Thinking 在实验设置里提及。

评测用三个视觉推理基准。

ScienceQA 考科学推理。

MathVista 考数学推理。

MMMU 考多学科视觉推理。

先看只做低秩压缩，rank 留 70%。

三组模型平均分 73.33 分。

没压缩是 73.58 分，基本没掉。

同档基线只有 69.47 到 71.33 分。

rank 留 50% 时，差距拉得更大。

这篇 70.28 分，基线掉到 53 到 63 分。

再看低秩加量化，rank 留 70% 加 4 位量化。

压缩 5.64 倍，平均分 73.41 分。

没压缩是 73.58 分，等于没掉分。

同档最强的基线 Palu 只有 70.59 分。

压得更狠也还能打。

rank 留 70% 加 3 位量化，压缩 7.44 倍。

平均分 72.24 分，只掉 1.34 分。

rank 留 50% 加 3 位量化，压缩 10.24 倍。

平均分 68.49 分，掉 5.09 分。

纯量化基线翻车很明显。

RTN 4 位量化只压 3.20 倍，平均分 57.79 分。

KIVI 2 位量化压 5.33 倍，平均分 72.18 分。

系统效率在 Qwen2.5-VL-7B 上测。

batch 设 16，上下文从 4K 到 32K。

16K 上下文，注意力模块快 1.53 倍。

端到端快 1.38 倍。

再加 4 位量化，注意力快 2.42 倍。

端到端快 1.83 倍。

显存峰值从 32.13GB 降到 18.57GB。

32K 上下文时，没压缩的模型直接爆显存。

消融实验里，在线校准的贡献最大。

换校准集也还稳。

用 ScienceQA 校准，去测 MathVista 和 MMMU。

仍然赢过所有基线。

同域校准更好，ScienceQA 上多 2.33 分。

MathVista 上多 2.10 分。

还有个细节值得记。

开头的 sink token 误差一直很低。

sink token 是注意力天生盯住的那几个位置。

因为它们敏感度高，方法自动多留了预算。

跟研究方向的关联

这篇跟 PD 解耦评估直接对口。

推理模型的 KV 缓存，是解码池子最大的显存开销。

压 5.64 倍还不掉分，等于同等硬件多接请求。

有三招能直接进评估清单。

第一，压缩质量别只看重建误差。

要看策略 KL 散度，也就是答案分布变了多少。

重建误差小，不等于推理不跑偏。

第二，校准数据要拿在线推理轨迹。

静态输入校准，会漏掉推理过程的状态。

agent 会话的长推理轨迹，也是同理。

第三，rank 预算按敏感度分。

一刀切的均匀压缩，浪费在不敏感的位置上。

另外，解码加速那组数也值得记。

16K 上下文端到端快 1.83 倍。

显存峰值从 32.13GB 降到 18.57GB。

长推理场景下，解码池子的容量和延迟都能受益。

局限与提醒

数字全是作者自报，没有第三方实测。

评测是离线基准，不是线上服务。

batch 16、单模型、lmms-eval 框架下测的。

并发一高，收益可能不一样。

代码地址已给出，但论文写的是即将放出。

用之前先确认仓库是不是真的能跑。

优化过的低秩注意力内核是定制的。

还没进 vLLM 或 SGLang 的主线。

想直接用，得自己接。

校准要先让密集模型生成推理轨迹。

这是一次性成本，但不是零成本。

Qwen3-VL-32B-Thinking 只在设置里提及。

主表没列它的大模型数。

32B 那档的效果，还得看附录或复现。

术语表

  • KV 缓存：模型的草稿纸，存每一步算好的键和值
  • 低秩压缩：只存主要的几条信息，把矩阵拆小了存
  • SVD：矩阵分解，把大矩阵拆成几个小矩阵相乘
  • rank：低秩压缩后留多少维度，越小压得越狠
  • 策略 KL 散度：衡量压缩前后答案分布变了多少的尺子
  • 在线校准：拿模型自己生成的数据去校准，不是拿现成数据集
  • sink token：注意力天生盯住的几个位置，动不得
  • 量化：把数字用更少的位数存，4 位就是 4 个比特
  • 推理视觉语言模型：会看图、会一步步推理的模型
  • lmms-eval：评测多模态模型的常用框架
