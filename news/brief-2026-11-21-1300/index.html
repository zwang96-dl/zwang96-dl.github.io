vLLM：Inkling 2 在 GB10 上更快了

#69021 是 #69028 的后续。

Inkling 2 是 Thinking Machines 的新模型。

之前为修 SM12x 崩溃绕开了 TMA。

TMA 是 GPU 搬数据的高速通道。

这次确认 64 宽分块加两级流水能跑。

还比绕路的核快两成多。

N 等于 256，2048 个 token 时 120 微秒变 90。

4096 个 token 时 216 微秒变 174。

8192 个 token 时 475 微秒变 380。

只改了 4 行，Hopper 和 SM100 没动。

来源：https://github.com/vllm-project/vllm/pull/69021

vLLM：Rubin 构建换上新版 PyTorch

#68036 是纯构建改动。

Rubin 是英伟达下一代 GPU。

构建镜像换成 PyTorch 的 cu135 夜版。

还记下了 ptxas 13.5.37 的坑。

它在 SM107 上会悄悄算错数。

来源：https://github.com/vllm-project/vllm/pull/68036

SGLang：昇腾上搬 KV 更省了

#44320 是 NPU 上的扩展优化。

扩展就是读新 token 那一步。

以前总按 query 那头搬数据。

这次先算哪头搬得少，再选方向。

新 token 超过 4096 个也走这条路。

说白了就是搬东西挑轻的那头搬。

这是给 DeepSeek 模型在昇腾上做的优化。

不过这是昇腾专属实现。

你手里是 H100 和 MI350X。

思路能借鉴，代码不能直接搬。

来源：https://github.com/sgl-project/sglang/pull/44320

SGLang：多卡等不到人就别硬撑

#52030 修了扩散多卡并行的超时处理。

以前等超时的那单照样返回残缺结果。

下一单反而先报错，冤得很。

现在超时那单直接失败，不再硬撑。

流水线等待也加了上限。

来源：https://github.com/sgl-project/sglang/pull/52030

SGLang：撞不上层的 LoRA 现在直接报错

#51783 堵住了悄悄失效的 LoRA。

LoRA 是给模型打的小补丁。

以前对不上层的照样显示加载成功。

请求照跑，跑的却是底模型。

抽查 826 个热门 LoRA，116 个 0 层加载。

现在加载时就直接拦下来。

来源：https://github.com/sgl-project/sglang/pull/51783

SGLang：外挂平台能自己提供分段图后端

#50150 是给非 CUDA 平台开的口子。

分段图后端是把一次前向拆成多段图。

以前只能用内置的 CUDA 版。

NPU 这类平台想自己实现就得改源码。

现在能直接接自己的实现进来。

来源：https://github.com/sgl-project/sglang/pull/50150
