ShelfKV：多轮推理里，图片 KV 别扔、要时再读

  • 作者：Ziyi Wang、Xiyue Zhang、Bing Hu、Guangmin Song、Chenyi Zhang、Li Wang
  • 单位：浙江大学、浙江科技大学、坎特伯雷大学、温州商学院
  • 文章：Keep the Reasoning, Read the Image: On-Demand Visual KV for Multi-Turn Reasoning VLMs
  • 提交时间：2026-11-18（arXiv:2611.23769v1）
  • 原文链接：https://arxiv.org/abs/2611.23769
  • 说明：数字全是作者自报，没有第三方复现。只测了两个推理视觉模型。

一句话

推理视觉模型边想边删图。

第一轮想完，图基本被删光了。

第二轮再问图里的事，答不上来。

这篇把图全留进 CPU 内存。

用到哪块，再临时搬回显存读。

人话解读

推理视觉模型有个毛病。

它回答前要先想几千个 token。

想的过程越长，草稿纸越满。

草稿纸就是 KV cache。

旧的缓存策略有个固定预算。

每张图、每段推理、每句提示词，共用一个预算。

新 token 不停进来，老内容就得删。

问题是，图和推理抢的是同一份预算。

推理越想越长，图就被越挤越少。

等用户第二轮追问图里的细节，图已经不在了。

这篇先量了这个损失有多大。

用 Qwen3-VL-8B-Thinking 跑图表问答。

第一轮问推理题，第二轮问同一张图的描述题。

直接问描述题，压缩缓存只比全缓存差 8.3 个点。

先想一轮推理再问，差距拉到 24.3 个点。

三倍。

再看缓存里还剩什么。

每头平均留下的视觉条目，从 184.5 个掉到 12.5 个。

到追问来的时候，97.9% 的视觉条目已经被删了。

关键发现是：缺的不是容量，是保护。

把同样多的位置从共享预算改成图片专属保留区，追问分数涨 17.7 个点。

而把共享预算直接加大同样多位置，只涨 10.0 个点。

说白了，图不是没地方放。

是没有人替它留位置。

核心方法

方法叫 ShelfKV。

不用训练，叠在现有缓存策略上面用。

它把“留住图”和“读图”拆成两件事。

架子：图全放 CPU，永不删除

所有视觉条目都留在 CPU 内存里。

作者管这叫 shelf，架子。

不管推理多长，图一份都不少。

CPU 内存便宜，整张图的 KV 全留也放得下。

桌子：显存里只摆当前要读的

每步真正进注意力的，是一张小桌子。

作者管这叫 desk，桌子。

桌子大小不变，跟原来策略的预算一样。

每步桌上摆的是当前问题最需要的视觉条目。

不用的视觉条目，下桌回架子。

草图：先用 4 位小钥匙挑候选

每步都比一遍全架子，太贵了。

所以先做一份 4 位量化的候选钥匙。

作者管这叫 sketch，草图。

每隔几步，用上一步的问题给全架子打分。

挑出分数最高的候选，搬到显存。

打分只用 32 维、4 位，精度损失几乎没有。

实测证明，草图挑的和精确打分挑的，分数一样。

成对换位：图进桌，文字先让位

候选视觉条目和桌上文字条目，按同一把尺子比分数。

分数用当前问题的注意力打分算。

视觉条目分数高的，进桌。

被顶掉的文字条目，不删除，只停放。

作者管这叫 parked，停放。

停放的文字还在策略的保留集合里。

下一轮没人顶它，它就回桌上。

每步最多换 Rmax 对，默认门槛是 0。

只要视觉分数更高，就换。

换位每步、每层、每个 KV 头都重算。

提示词和最近 W 个生成 token，永远不参与换位。

关键数据

  • 追问差距：先推理一轮再问图，DBTrimKV 比全缓存差 24.3 个点。直接问，只差 8.3 个点。
  • 视觉条目流失：每头平均 184.5 个，推理一轮后剩 12.5 个。97.9% 被删。
  • 保护胜过加容量：128 个视觉保留位，追问涨 17.7 个点。共享预算加同样多位置，只涨 10.0 个点。
  • 主结果：对话场景里，ShelfKV 比最强现有策略 DBTrimKV 高最多 20.3 个点。显存用量相同。
  • 对方显存翻倍也不够：DBTrimKV 预算翻一倍，ShelfKV 还领先 8.7 个点。
  • 比固定保留区更好：同等显存下，比最优固定图文分配高 12.7、5.0、3.0 个点。预算越紧，赢得越多。
  • 小保留区就够：每头留 32 个视觉条目，图表追问就从 61.3% 涨到 74.3%。留 64 个，涨到 81.0%。
  • 五轮对话：ShelfKV 比 512 预算的 DBTrimKV 高 11.6 到 15.0 个点。
  • 代价是时间：A100 上，批 1 时每步 48.3 毫秒，宿主是 41.0 毫秒。批 64 时 103.2 毫秒，宿主是 41.8 毫秒。
  • 峰值显存差不多：批 64 时 20.8 GB，宿主是 21.1 GB。省的是显存里的缓存位，不是总显存。
  • 草图可以后台跑：批 64 时，后台算草图把每步从 126.8 毫秒压到 103.2 毫秒。

跟研究方向的关联

这篇跟多模态 P/D 评估直接对口。

三点可以抄进评估清单。

第一，视觉 KV 的账要单列。

多轮对话里，图和推理抢同一份预算。

只报总缓存命中率，会把图被挤掉的事藏起来。

以后报数，视觉条目留存率和追问分数要分开报。

第二，保护比加容量值钱。

同样多的位置，给图留专属保留区，比加大共享预算多涨 7.7 个点。

PD 拆分里，编码器节点的 KV 策略可以照这个思路改。

读题节点上，视觉条目先划一块保留区。

第三，按需读是省显存的新姿势。

图全放 CPU，用时再搬回。

代价是每步变慢，批 64 时从 41.8 毫秒涨到 103.2 毫秒。

这笔账要进 PD 评估。

解码节点如果也用这招，词间隔会涨。

但要注意三点限制。

数字全是作者自报，只测了 Qwen3-VL-8B-Thinking 和 4B。

只在 A100、A800 上测过。

总内存没省，只是把图挪到了 CPU。

术语表

  • KV cache：推理时的草稿纸。每个 token 的键和值，留着后面算注意力用。
  • Retention policy：缓存保留策略。草稿纸满了，决定删谁留谁的规则。
  • DBTrimKV：这篇用的最强宿主策略。给每个头学一个保留门，预算紧的时候还能保住分数。
  • Host：宿主。ShelfKV 叠在上面的那个原有缓存策略。
  • Shelf：架子。CPU 内存里放全部视觉条目的地方，永不删除。
  • Desk：桌子。显存里真正进注意力的条目集合，大小固定。
  • Sketch：草图。4 位量化的候选钥匙，用来快速挑出值得搬上桌的视觉条目。
  • Parked：停放。被视觉条目顶掉的文字条目，没删，只是暂时下桌。
  • Rmax：每步最多换位对数。换位次数的上限。
  • CharXiv：图表问答基准。300 张图表，先问推理题，再问描述题。
  • MMMU-Pro：多模态推理基准。300 道带图的大学水平选择题。
  • MMDU：多图多轮对话基准。110 段对话，1645 个问题。
