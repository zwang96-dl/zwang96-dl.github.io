SGLang v0.5.23 发布说明精读

人话解读

  • v0.5.23 的说明终于写出来了。
  • tag 早打了，正文拖到今天才发。
  • 一个版本装了 1007 个 PR。
  • 三大块：快、省、稳。
  • 快：DeepSeek-V4.1 全线提速。
  • prefill 就是读题先算一遍。
  • decode 就是逐个往外吐词。
  • 省：MoE 也能塞进消费级单卡。
  • MoE 就是混合专家模型。
  • 稳：PD 解耦修了一堆实战坑。
  • PD 解耦就是两阶段拆机器跑。

核心方法

低延迟模式

  • opt-in 模式，自愿开启。
  • NVIDIA 侧叫 megakernel（融合大内核）。
  • AMD 侧叫 monokernel（单内核插件）。
  • 把 V4.1-Flash 的解码步打成一个融合持久内核。
  • 持久内核就是常驻 GPU 不退场。
  • 省掉反复启动内核的开销。
  • GB300 上单用户解码快 44%。
  • MI350X 上单用户解码快 75%。
  • 你手里正好有 MI350X。
  • 插件仓库：sgl-nvidia-mega / sgl-amd-mono。

DeepSeek-V4.1 在 GB300 上

  • 高负载下 prefill 吞吐最高 1.5 倍。
  • 32K 到 64K 长提示，首字延迟降约 28%。
  • 配套 PR：#44403、#45059、#45107。
  • 手法是 breakable prefill CUDA 图重放。
  • CUDA 图就是把算子序列打包预录。
  • 长短上下文都能直接重放。

MoE 首字更快

  • 7 个 MoE 模型，8K 提示首字早到 30% 到 58%。
  • 在 H200 上测的。
  • 名单：V4.1-Flash、GLM-5.3-Flash、gpt-oss 等。
  • 手法是 MoE autotune 覆盖 prefill 块。
  • PR #43363。

Paged Experts

  • opt-in 功能。
  • 大到装不进单卡的 MoE 模型。
  • 也能在消费级单卡上跑。
  • 比 CPU offload 快 30 倍。
  • CPU offload 就是权重放内存、算时再搬。

LoRA 上量化 MoE

  • FP8 和 NVFP4 量化模型也能挂 LoRA 了。
  • LoRA 就是低秩微调适配器。
  • 用的是新 LoRA 引擎。
  • opt-in 开启。

HiCache 文件级 L3

  • MLA 做解码上下文并行时。
  • 前缀缓存能存到文件级 L3 存储。
  • HiCache 就是多层缓存。
  • PR #41187。

TPU7x

  • 通过 SGLang-TorchTPU 插件上 TPU7x。
  • PyTorch 原生，不走 JAX。

新模型

  • Muse Spark Open、Beam-1.0。
  • MiniMax-M3.1-Flash、MiniCPM-V 4.7。
  • Kev。
  • 扩散类：Cosmos3-Nano-Sim、FastH3 Omni。
  • FLUX.3 Image Klein、HY-Nomas、MOSS-Image。

PD 解耦专章

  • 这一章全是跟 PD 相关的。
  • 每条都翻译成大白话。

搬运加速：

  • #44740：NIXL 传送引擎支持 prepared dlists。混合模型的 KV 搬运更快。NIXL 就是 PD 搬运的高速通道。dlist 就是提前备好的描述符列表。
  • #38955：解码侧 KV 预分配走 pinned 内存。pinned 内存就是锁页内存，搬运不经过 CPU 换页。
  • #44029：KVShard 的 0SM KV cache allgather。0SM 就是不占流处理器，纯靠拷贝引擎。
  • #44598：预构建的解码批输入直接拷 GPU。免掉 CPU 同步。
  • #45492：prefill 的 KV 分块发送免 CPU 同步。调度线程直接发。
  • #44622：调度器的 MLP 同步行改用 gather 加 broadcast。走 gloo 后端。

正确性修复：

  • #39729：KV 校验和实现清理加优化。搬运时少一笔计算。
  • #42702：解耦下 decode 撤回请求跟在飞前向撞车。修了竞态。
  • #44605：传送后端可以跳过不可比对端的校验和。省掉无效校验。
  • #45453：延迟的 decode KV 释放在 TP 各卡间同步。TP 就是张量并行。
  • #45973：NIXL 或 Mori 写失败时给延迟的 abort 确认下毒。防止错放行。
  • #44386：延迟 KV 释放被按住时，PD decode 不许闲置。调度器别偷懒。
  • #45922：丢了的 prefill 心跳计数重启。断线重连的账别算错。
  • #46423：解码侧 radix 缓存下也做 KV 校验。

布局与握手：

  • #45075：PD 默认走 MegaAttention。KV 布局写进 PD 握手里。
  • #43482：NIXL 支持按 GPU 选 UCX 网卡。#45722 保留手动选择。
  • #44140：只传 decode 前缀长度之后的 DSA 索引器状态。少搬一点是一点。
  • #44215：运行时 PD 角色切换支持 DP 和 DP attention。
  • #43760：PD 角色切换时复用启动时的解码图。少重建一次。

KVShard 系列：

  • #38473：KVShard 的 PD 传输加端到端测试。KVShard 就是 KV 缓存分片。
  • #40929：KVShard 支持 MTP 的 KV 缓存分片。MTP 就是多词元预测。
  • #42973：GLM 的 DSA/MTP 接 PD 和 CPU HiCache。

多模态相关：

  • #45440：prefill 异常重排队时，多模态输入不再丢。
  • #44952：V4.1 的编码器 SWA 有界重放在 PD prefill worker 上跑。SWA 就是滑动窗口注意力。

数字彩蛋：

  • #46463：按 NVML fabric 状态识别 MNNVL 设备。Kimi-K3 双节点 TP8/DCP8 解码从 379 涨到 485 词/秒。DCP 就是解码上下文并行。MNNVL 是 NVLink 级互联。

术语表

  • prefill：读题阶段，先把提示算一遍。
  • decode：吐字阶段，逐个往外生成词。
  • PD 解耦：读题和吐字拆到不同机器跑。
  • KV cache：注意力草稿纸。
  • NIXL：PD 搬运的高速通道。
  • DCP：解码上下文并行。
  • SWA：滑动窗口注意力。
  • HiCache：多层 KV 缓存。
  • megakernel：融合大内核。
  • monokernel：AMD 侧单内核插件。
  • MoE：混合专家模型。
  • MNNVL：NVLink 级互联 fabric。
  • pinned 内存：锁页内存。
  • opt-in：默认不开，手动启用。
  • TTFT：首字延迟。
  • TPOT：词间延迟。
