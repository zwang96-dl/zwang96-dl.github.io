vLLM v0.32.0：短请求与低精度 KV 精读

原文链接：https://github.com/vllm-project/vllm/releases/tag/v0.32.0 发布时间：2026-10-17 23:50 PDT（本轮窗口内发布） 版本规模：814 个提交，363 位贡献者（121 位新人）

人话解读

  • vLLM 发了新大版本。
  • 这版不是只加新模型。
  • serving 的三处都动了。
  • 前端接待、草稿纸、执行器。
  • 草稿纸就是 KV 缓存。
  • 它记着算过的中间结果。
  • 对你最值钱的是短请求。
  • 还有 H100 的低精度草稿纸。
  • 和 AMD 的默认引擎切换。
  • 下面按你的硬件拆开讲。
  • 不是你的卡的，我会标明。

核心更新

短请求：前端不再傻排队

  • 以前请求先进一个前端。
  • 前端忙时，后面只能等。
  • 现在可以多开几个前端。
  • 参数是 --api-server-count。
  • 设成大于 1 才生效。
  • 新连接去最闲的那个前端。
  • 像超市多开几个收银台。
  • 还按哪台空着来分流。
  • 官方说短请求涨幅不小。
  • 每秒请求涨 43% 到 85%。
  • 这是官方自报的数字。
  • 没有独立复测，别当定论。
  • 你的请求正好偏短。
  • 输入大约 250 个词元。
  • 这条值得你第一个实测。

低精度 KV：草稿纸写小字

  • KV 缓存很吃显存。
  • 精度降下来，纸就变小。
  • 同显存能装更多请求。
  • 这版把低精度铺得更广。
  • NVFP4 是一种 4 位格式。
  • 它现在能在 SM90 上跑。
  • SM90 就是 H100 的架构。
  • 还能在更老的卡上跑。
  • 也能在新消费卡上跑。
  • 另一个格式专治稀疏注意力。
  • 名字叫 fp8_ds_mla。
  • 它在 SM90 上有成绩。
  • 模型是 GLM-5.3-Flash。
  • 输出吞吐最高涨 31%。
  • 注意只测了这一个模型。
  • 还有一条别误读的。
  • GLM-5.x 默认开 FP8 草稿纸。
  • 这条只限 SM100 架构。
  • SM100 是 Blackwell 的卡。
  • 不是你的 H100，别套用。
  • 那条官方数是涨 2.3% 起。
  • 最高到 5.5%，跟你无关。

AMD：新执行器转正

  • MRV2 是新一代执行器。
  • 全名 Model Runner V2。
  • 它在 ROCm 上成了默认。
  • ROCm 是 AMD 的软件栈。
  • 以前要手动开，现在不用。
  • 你的 MI300X 和 MI350X。
  • 升级后默认就走新路。
  • 行为变了，升级先测一轮。
  • AMD 还多了 4 位草稿纸。
  • 名字叫 ultraquant_4bit。
  • 密度约是 FP8 的两倍。
  • 草稿纸更小，并发能更高。
  • AMD 区还有两条小账。
  • Kimi-K3 长题首字快约 20%。
  • 靠的是 prefill 检查点。
  • GLM 小版解码间隔降了。
  • 降幅是 5% 到 15%。
  • 两条都只测了指定模型。
  • 另有一条只限 MI355X。
  • 那是比 MI350X 新的卡。
  • 正文没把它算到你头上。

投机解码：实习生上 GPU

  • 投机解码是先猜再验。
  • 像实习生先打一版草稿。
  • 专家只改错的地方就行。
  • MRV2 新增 GPU 词元猜测。
  • 猜的长度还能变长变短。
  • 不再是固定猜几个词。
  • 弹性专家并行也来了。
  • 名字叫 Elastic EP。
  • 专家能先排空再扩缩。
  • 流水线并行也能混搭。
  • 能叠 prefill 上下文并行。
  • 这给解耦部署多一种拼法。

多模态：传图只拷一份

  • 大图大视频很占内存。
  • 以前传给每个工人一份。
  • 工人是干活的执行进程。
  • 现在一份共享内存搞定。
  • 名字叫共享内存张量场。
  • 默认已经打开，不用配。
  • 编码器输入会按类排序。
  • 图片和视频不再乱穿插。
  • 同类扎堆，机器更顺手。
  • 官方说每秒请求涨约 7%。
  • 准确说是 6.5% 到 8.2%。
  • 新模型多了 MiniCPM-V。
  • 版本是 4.7，看图说话。
  • 还有全模态向量模型。
  • 名字是 EmbeddingGemma 2。
  • 图文音视频都能转向量。
  • 用不上的编码器可跳过。
  • 靠 --limit-mm-per-prompt 控制。

P/D 解耦与 KV 搬运

  • KV 连接器这轮修了多处。
  • NIXL 的主机拷贝会合并。
  • Mooncake 的搬运也会合并。
  • 合并就是少跑几趟腿。
  • DeepSeek 新版有个细节。
  • 解耦时可跳过一段重放。
  • 前提是 KV 已经加载好。
  • 这些都是边角优化。
  • 没有端到端大数字公布。
  • 别指望解耦凭这版翻盘。
  • 你评估 SGLang 时可对照。
  • 看它那边搬运账怎么算。

安全与 breaking change

  • 默认不再放行所有来源。
  • CORS 是跨站调用的门禁。
  • 以前默认谁都能来敲门。
  • 现在默认只放行可信源。
  • 老部署升级可能被拦。
  • 先在测试环境验一遍。
  • 这轮修了三个安全洞。
  • 一是聊天模板耗尽资源。
  • 二是分词器编号越界。
  • 三是点对点套接字耗尽。
  • 不可信图片只准光栅格式。
  • 共享缓存的句柄要签名。
  • JSON 嵌套超 64 层拒绝。
  • Python 3.10 已不再支持。
  • 环境太老会直接装不上。
  • 级联注意力已被移除。
  • 还有 max_tokens 语义变了。
  • 它不再从上下文里预留。
  • 升级前把这几条过一遍。

术语表

  • KV cache：模型的草稿纸，存算过的中间结果。
  • SM90：Hopper 架构代号，H100 用的就是它。
  • SM100：Blackwell 架构代号，B200 用的就是它。
  • NVFP4：英伟达的 4 位浮点格式。
  • FP8：8 位浮点格式，精度和体积居中。
  • MRV2：vLLM 新一代模型执行器。
  • ROCm：AMD 的 GPU 软件栈。
  • EP：专家并行，专家分到不同卡。
  • MLA：一种省草稿纸的注意力结构。
  • CORS：网页跨站调用的门禁规则。
  • NIXL：英伟达的高速数据搬运库。
  • Mooncake：一个 KV 搬运与缓存系统。
