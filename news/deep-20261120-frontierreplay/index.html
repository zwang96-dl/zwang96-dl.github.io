FrontierReplay：混合模型的前缀缓存，读题不用切了

原文：Zekun Wang、Yizhuo Wang，北京理工大学，arXiv:2611.26020v1，2026-11-19 提交。

原文链接：FrontierReplay（arXiv:2611.26020）

一句话人话版

混合模型的前缀缓存一直很难做。

递推层的状态不能随便截断。

以前想在中间存一个检查点。

就得把读题切成两段。

FrontierReplay 不切了。

读题一口气跑完。

事后只把递推层那段重放一遍。

检查点就有了，代价还很小。

这篇讲了什么问题

混合模型把注意力和递推层混着用。

Qwen3.5、Falcon-H1 都是这种结构。

Kimi-K3、GLM-5.3-Flash 也是。

递推层不用每 token 存一份 KV。

它只留一个固定大小的状态。

长上下文便宜，就是这个原因。

但这个状态是边算边覆盖的。

想复用，只能在当初存过的位置。

vLLM 存得很粗。

Qwen3.5-9B 每 528 个 token 存一个。

Falcon-H1-7B 每 1568 个 token 存一个。

两个存点之间的前缀，全都白白重算。

实测：Qwen 漏掉 2–8% 的可复用前缀。

Falcon 漏掉 6–20%。

更细的缓存也不是办法。

Marconi、SPC 都要在中途切断读题。

切一次就多一次调度。

负载一高，省的还不够付切的代价。

近似重建更不行。

SuffixReplay 靠猜，输出会变。

长上下文能掉 13–17% 的准确率。

核心方法：三招

  • 第一招：读题不切，事后只重放递推层
  • 读题一口气跑完，不切断。
  • 边跑边记一小段输入日志。
  • 只记递推层的输入，不记别的。
  • 跑完后，一个跨层重放核接手。
  • 它只算递推层的状态转移。
  • 注意力、MLP、输出层全跳过。
  • 从之前存过的状态出发。
  • 沿着日志走到目标位置。
  • 写出来的检查点跟真算的一模一样。
  • 每 token 的代价比重算便宜 6–37 倍。
  • 一个检查点只要 1–3 毫秒。
  • 不用跟 host 同步。
  • 窗口上限 1024 个 token。
  • 超过就提前切一刀兜底。
  • 也不用改原生算子。
  • 原来的前向核一个都不动。
  • 第二招：复用点提前猜得到
  • 复用几乎都结束在结构边界上。
  • 回合结束、分支点，都是能提前看见的。
  • 四种负载下，79–100% 的复用 token 都这样。
  • 规划器只看入队时能看到的信息。
  • 聊天模板的结尾、已完成的回合。
  • 还有以前请求已经分叉过的位置。
  • 提前定好目标，不用等未来的请求。
  • 每个目标都在 16 个 token 的边界上。
  • 第三招：检查点按前沿留，死的借给 KV
  • 一个检查点 49–147MB，很占地方。
  • 缓存里只能放几百个。
  • 淘汰按四档排优先级。
  • 正在跑的请求锚点，最先保。
  • 已经证明有用的分支点，其次保。
  • 被更深的检查点取代的祖先，先扔。
  • 纯猜的检查点，再扔。
  • 死掉的槽位不空着。
  • 直接借给注意力 KV 池用。
  • 缓存紧的时候，照样不浪费。

关键数据

  • 实验平台：1 张 A800 80GB，vLLM 0.30.0。
  • 模型：Qwen3.5-9B、Falcon-H1-7B。
  • 还有 4B 到 34B 的缩放实验。
  • 负载四种：多轮对话、SWE-agent、长文档问答、树搜索。
  • 缓存预算 32 GiB。
  • 达标线：首字 500 毫秒，均词间隔 50 毫秒。
  • 8 组模型加负载，全是最好的精确缓存。
  • 好吞吐比 vLLM 高 1.11–4.26 倍。
  • Falcon SWE-agent 那组，4.26 倍。
  • 首字中位数降 16–89%，最多快 8.9 倍。
  • Falcon SWE-agent：首字 1.1 秒降到 125 毫秒。
  • 80% 达标容量涨 1.05–1.73 倍。
  • 34B 树搜索，好吞吐 3.67 倍。
  • 跟近似方法 SuffixReplay 比。
  • 对话和智能体 trace 打平。
  • 高负载下赢 1.10–1.54 倍。
  • 准确率一分不掉。
  • RULER 长上下文：跟 vLLM 一样。
  • SuffixReplay 在 24K–32K 掉 13–17%。
  • 切读题的代价：调度步数多 1.05–1.86 倍。
  • 重放杠杆：模型越大越划算。
  • Qwen3.5-9B 是 13.8 倍，Falcon-34B 是 36.9 倍。
  • 每次重放的额外显存：1.76–1.79 GiB。
  • 缓存压到 16 GiB，照样保住 98.7% 的收益。

跟研究方向的关联

  • 前缀缓存加混合模型，先确认这篇的结论。
  • Qwen3.5、Kimi-K3、GLM-5.3-Flash 都是混合结构。
  • 读题节点上，递推状态是复用的瓶颈。
  • 评估里加一档：混合模型的多轮复用。
  • 只看纯注意力模型，会高估复用率。
  • 检查点 49–147MB 这个账要进显存预算。
  • 16 token 边界这个粒度，可以抄进对照组。
  • 重放核 1–3 毫秒，进首字预算里算。
  • 淘汰策略那四档，可以抄进缓存管理。
  • 近似重建掉准确率，评估里要单测长上下文。

局限与提醒

  • 数字均为作者自报，没有独立复现。
  • 用的 vLLM 0.30.0，版本有点老。
  • 实测只在 1 张 A800 上。
  • 34B 的张量并行只测了首字和好吞吐。
  • 重放窗口上限 1024 个 token。
  • 更长的跨度还是要切。
  • 每组配置跑没跑多次，论文没写。
  • 评测只用了四种公开负载。
  • 真实生产流量可能不一样。

术语表

  • 混合模型：注意力和递推层混着用的模型。
  • 递推层：Mamba、GDN 这类层，状态固定大小。
  • 前缀缓存：算过的开头不用重算。
  • 检查点：递推层在某个位置存下来的状态。
  • 读题：prefill，读提示词、算 KV 的那一步。
  • 首字：TTFT，第一个词吐出来要多久。
  • 词间隔：TPOT，平均每个词要多久。
  • 好吞吐：goodput，达标的请求每秒几个。
  • SLO：服务等级目标，比如首字 500 毫秒。
  • RULER：长上下文准确率评测集。
  • GDN：门控 DeltaNet，一种递推层。
  • Mamba-2：一种状态空间递推层。
  • SWE-agent：让模型修代码库的智能体框架。
  • 树搜索：ToT，模型分叉试多条路的推理方式。
