Jev 与 SGLang /v1/decisions：不生成文字的决策推理

人话解读

这篇拆解了一个反常识的发现：做决策，不一定要让模型"说话"。

TypeSafe 的 Jev 是个闭源决策服务。你给它一份共享的证据（state），再给一堆问题。每道题它只回每个选项的概率，一个字都不生成。

研究者 Archer Hume 花了约一万次 API 调用，从外面把它摸了个透。结论是：Jev 大概率是个因果解码器（causal decoder），但只跑 prefill，不跑 decode。prefill 结束、接上 readout（读数头）就收工。token-by-token 的生成链整条消失。

SGLang 在 9 月底把同一套思路做成了开源实现 /v1/decisions。任何 chat 模型都能用。不用训练，不用特殊 checkpoint。渲染一次问题，读答案位置上几个选项 label 的 next-token 概率就行。

核心方法

Jev 这边的逆向手段（Archer Hume，约 9392 次调用，全部黑箱）：

  • 延迟扫描：固定一题拉长 state，对比固定短 state 加题数到 1500。看延迟曲线在哪转折。
  • Token 账目：1 题 268 tokens、2 题 276 tokens。加法完全可加，说明是"共同前缀 + 各题后缀"结构。
  • Tokenizer 指纹：415 个探针对 192 个公开 tokenizer，全不匹配。最接近 Qwen，命中 348/415。
  • 信息可见性探针：某题塞密码"ZEBRA-7741"，另一题问"其他题提到的密码是什么"。答对概率 0.00。同一句话移到 state 里，概率跳到 0.90–0.92。题目之间完全隔离。
  • 随机化 block 加配对对照：同一个请求重复跑，吸收请求噪声，再看选项顺序/无关选项的影响。

SGLang /v1/decisions 这边的实现思路：

  • 把问题渲染成一次 prefill。选项标成 A/B/C 等 label。
  • 直接读答案位置上这些 label 的 next-token log-probability。
  • 不生成任何文字，不解析输出。/v1/systemone 上 output_tokens 直接是 0。

关键数据

  • 选项顺序效应：只把选项调换顺序，正确答案概率从 0.84–0.89 跳到 0.93–0.96。阈值设在 0.9 附近的话，if 会走向不同分支。
  • IIA 违反：加一个明显无关的第五选项（"坏天气造成的"），原两选项 log-odds 从 +0.38 掉到 +0.11。十个随机化 block 每一个都下降，平均 −0.28（95% 区间 −0.36 到 −0.19）。模型把整张选项表当有序整体读。
  • confidence 是算术：TypeSafe 官方 adapter 公式是 c = (p_max − 1/K) / (1 − 1/K)。三选项、最高概率 0.8，得到 0.7。它衡量"领先答案比均匀分布高多少"，不是学出来的正确性估计。
  • 校准：1200 题 MMLU 上十桶 ECE = 0.031，相当不错。但 990 题挤在 0.9–1.0 这一桶，ECE 被高分桶主导。
  • 新鲜数学题（避 benchmark 污染）：三位数乘法平均概率 83.0%、实际正确率 86.7%。两步文字题 30.4% 对 32.0%。模指数运算 34.9% 对 56.0%，明显低估自己。
  • 延迟：100 题以内 server time 几乎不动。1500 题的请求几百毫秒内回来。单 branch 上限约 32768 tokens（2 的 15 次方），整个请求上限约 65536 tokens（2 的 16 次方）。23k tokens 的 state 配 5000 个问题是合法请求。30k tokens 约 160ms，推测是 ~10B active 参数的稀疏 MoE。
  • SGLang 官方文档的实测警告：冷启动和 prefix cache 命中之间、不同 batch 组成之间，概率最多飘 0.07，label_mass 最多飘 0.14。要完全一致就得关掉 radix cache，代价是失去 prefix 重用。超过 26 个选项得用 AA、AB 双字母 label，先验概率不相等，顺序效应更明显。
  • 生态：llm2jev（SGLang/Transformers/MLX 三后端，支持图文输入，9/20 加 SGLang scoring 后端）。diffusion-jev-sglang（DiffusionGemma 做图像决策，"Jev 加眼睛"，单卡 A100）。s1decide、ruling、Kev-0.5B（Qwen2.5-0.5B 冻结 + 9.3M LoRA + pointer 读数头）等复刻。

跟你研究方向的关联

  • prefill-only 推理是 P/D 解耦的极致形态。P/D 解耦把 prefill 和 decode 分到不同卡上。这套直接把 decode 整个砍掉，延迟和成本再降一档。
  • 共享 state 的 KV cache 加并行 branch，就是 prefix caching 的另一种形态。一桌人共用一份菜单，各人点各人的菜。radix tree 在这里天然适用。
  • 分类、路由、打分、审核这类 workload，本来就不需要生成文字。用 chat completion 硬套，等于为每个决策多付一整轮 decode 的钱。这个接口把价格打下来了。
  • 校准这件事值得单独看。ECE 0.031 的数字背后，是用 proper scoring rule（log loss / Brier loss）对着真实结果训练。你的 serving 评估里如果涉及决策类 SLO，可以借这套评估思路。
  • 坑要记住：选项顺序会动概率，batch 组成会动概率，confidence 只是算术。做阈值决策前，先在自己 workload 的标注数据上验证。

术语表

  • Jev：TypeSafe 公司的闭源决策模型服务。只出概率，不生成文字。2026-09-15 发布。
  • RLCD：Reinforcement Learning for Calibrated Decisions。TypeSafe 训练决策概率的方法，配方未公开。目标是用真实结果把概率校准。
  • readout（读数头）：把最后一层 hidden vector 接一个小线性层加 softmax，直接输出选项概率。z = Wh + b，p = softmax(z)。
  • branch（分支）：共享同一份 state 下的一道独立题目。题目之间互相看不见。
  • IIA（无关选项独立性）：理性选择理论的假设。加无关选项不该改变原有选项的胜负比。Jev 违反了它。
  • ECE（期望校准误差）：所有标成 0.8 的案例里，是不是真的大约 80% 成真。越小越好。
  • proper scoring rule（严格评分规则）：log loss、Brier loss 这类损失函数。期望上，只有回报真实条件分布时损失最小。
  • /v1/decisions：SGLang 的原生扩展接口。把 chat 模型变成决策模型。不是 OpenAI API 的一部分，要走 HTTP 直接调。
