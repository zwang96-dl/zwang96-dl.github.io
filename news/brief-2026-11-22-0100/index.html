vLLM：KV 卸载现在能分读写了

#67961 给多层 KV 卸载加了个开关。

开关叫 access_mode，有三种值。

只读、只写、读写都行。

用处是两条路可以同时走。

一条路把 CPU 缓存写进文件系统。

另一条路直接从文件读进 GPU。

GDS 是 GPU 直读磁盘的通道。

以前整条链路只能一个方向。

现在读写分开配，层级更灵活了。

来源：https://github.com/vllm-project/vllm/pull/67961

vLLM：图片参数被悄悄忽略，token 账算错了

#68317 修的是 OpenCUA 处理器。

你传 min_pixels 这些参数，它全当没听见。

图像大小的上限设了也白设。

后果是 token 预算对不上。

按 512 平方算，预算 334 个 token。

实际一张 1920×1080 的图要 2691 个。

多出来的 token 全是隐性开销。

现在参数会正常传给图像处理器。

来源：https://github.com/vllm-project/vllm/pull/68317

#68667 把离线接口的报错分了类。

以前六处都直接抛 ValueError。

现在分清是输入错还是状态错。

来源：https://github.com/vllm-project/vllm/pull/68667

SGLang：推测解码三件套，代码合一了

#52174、#52164、#52159 是一组重构。

推测解码就是先让小模型打草稿。

大模型再逐个核对，错了就改。

EAGLE、NGRAM、DSpark 各写了一套验证流程。

三套流程做的事其实一样。

现在抽成同一套验证环，共用。

验证结果也一次提交，不再分四次。

逻辑判断也只留一份定义。

行为不变，纯粹为了以后好维护。

来源：https://github.com/sgl-project/sglang/pull/52174

来源：https://github.com/sgl-project/sglang/pull/52164

来源：https://github.com/sgl-project/sglang/pull/52159

SGLang：扩散请求卡住了，健康检查终于会报警

#52012 加了个请求看门狗。

看门狗就是盯着请求别卡死的定时器。

以前内核卡住，/health 还报 200。

编排器以为实例活着，继续往里送请求。

现在请求超时，看门狗就让 /health 报 503。

流量会被切走，不再往死胡同里送。

来源：https://github.com/sgl-project/sglang/pull/52012

SGLang：图生图编码器卸载后，出图变了

#51187 修的是 Qwen-Image-Edit。

同一条编辑指令，同一个种子。

编码器放 CPU 上，出的图不一样。

8 条提示，没一条像素完全相同。

RoPE 是给位置编号的办法。

以前这张表在 CPU 上建。

现在改到 GPU 上重建这张表。

卸载和常驻，出图终于一致了。

来源：https://github.com/sgl-project/sglang/pull/51187

SGLang：低内存卸载不再每次全量拷权重

#36727 修的是组件卸载。

组件就是扩散模型里的 VAE 这类零件。

以前每次换出，都要全量拷一份权重。

权重本身从来不变，白白浪费一次拷贝。

MiniMax-H3 的 9.7 GiB 视频 VAE 实测。

第一次换出 4.85 秒，现在 0.37 秒。

来源：https://github.com/sgl-project/sglang/pull/36727
