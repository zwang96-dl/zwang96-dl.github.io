NVIDIA 官方博客：什么时候该用 EPD 解耦加速多模态推理服务

原文：When to Use Encode-Prefill-Decode Disaggregation to Accelerate Multimodal Model Serving
作者：NVIDIA 技术博客（Alexandre Milesi、Ayush Agarwal、Guan Luo 等；致谢 Inferact 联合创始人 Roger Wang）
发布时间：2026-09-09
原文：https://developer.nvidia.com/blog/when-to-use-encode-prefill-decode-disaggregation-to-accelerate-multimodal-model-serving/

一句话人话版

多模态推理里，看图经常比读题还费时间。看图就是 ViT 编码。读题就是 LLM prefill。NVIDIA 这篇博客用 GB200 实测。把"看图"从推理 worker 里拆出来，独立扩缩容。这就是 EPD 解耦。TTFT 最快能快 5 倍。端到端快 7 倍。但只在特定条件下划算，博客给了张"什么时候该拆"的决策表。

它解决什么问题

先说背景。多模态请求在 LLM prefill 开始前，要先做两件事：

  1. 媒体预处理。下载、解码图片/视频；
  2. ViT 前向。视觉 Transformer 把像素变成 embedding。再投影到 LLM 的 token 空间。

聚合部署：编码、prefill、decode 全挤在一个 worker 里。它们共用一个调度域。请求里只有一两张小图时，这没问题。但请求变成多图、高清图、视频时，ViT 编码能吃掉几百毫秒甚至更久：

  • 它堵住自己的 prefill。图还没看完，LLM 干等着。
  • 它还跟同机上其他请求的 prefill/decode 抢 GPU。
  • 更糟的是，纯文本请求也会被排在多模态请求后面干等。明明它根本不需要看图。

这就是 EPD（Encode-Prefill-Decode）解耦要解决的问题。把"看图"拆成独立的 worker 池。编码、prefill、decode 各自独立地 batch、调度、扩缩容。

原文关键图

图 1 人话解读。TTFT 被拆成三段：媒体预处理、ViT 前向加投影、LLM prefill。单图请求里编码只占一小块。多图和视频请求里，编码直接变成 TTFT 的大头。博客还提到一个诚实的数据。TTFT 里 43% 的时间，花在"ViT 还没开始"之前。也就是下载、解码这些阶段。EPD 解决不了这部分，得用别的手段（见文末"其他抓手"）。

核心方法：EPD 解耦与三种部署拓扑

NVIDIA Dynamo 是开源分布式推理框架。它是这么实现 EPD 的。encoder worker 只管产出 vision embedding。PD worker 只管消费 embedding 跑 LLM。两者之间用 NIXL 传 embedding。

图 2 人话解读。左边聚合部署：一个 worker 从头到尾包办"看图加读题加答题"。右边 EPD：encoder worker 池专门看图。算完 embedding，经 NIXL 甩给 PD worker。核心洞察。解耦的代价，是多一轮跨 worker 协调。多一轮 embedding 传输。只有当被隔离出来的编码工作量足够大、大到能覆盖这笔开销时，拆分才划算。

encoder worker 可以跟 PD worker 挤同一块 GPU。也可以独占另一档 GPU。由此分出三种拓扑：

图 3 人话解读。

拓扑怎么摆什么时候用
Aggregated（聚合）每块 GPU 一个 worker，编码+prefill+decode 全包图少、输出长、编码占比小的时候；最简单
Colocated（同机共存）每块 GPU 上 encoder worker 和 PD worker 共存（经 CUDA MPS 共享 GPU），队列和 batch 相互独立同构集群的首选。ViT 相对 LLM 很轻，单独给它一块同档 GPU 会闲置；共存既隔离了调度，又不浪费卡
Disaggregated（异构分层）encoder 跑在便宜卡上（如 RTX 6000D），PD 跑在高端卡（GB200）上，embedding 经 NIXL 跨机器传集群里本来就有高低两档卡的时候。注意：同构集群上强行分层，效果永远不如 colocated，别折腾

关键实验数据

测试环境：Qwen3.5 122B A10B NVFP4。MoE：122B 参数，每 token 激活 10B。4× GB200（异构拓扑另加 2× RTX 6000D 跑 encoder）。NIXL 走 UCX RC/TCP 以太网传 embedding。实测峰值 20 Gbps。goodput 的 SLO 定义为 ITL（token 间延迟）< 100 ms。

决定 EPD 收益的四个因素（原文 Table 1 中文版）

因素为什么影响 EPDEPD 什么时候划算
输入媒体量图越多 → visual token 越多 → 编码工作量越大；EPD 可以单独给 encoder 加卡，防止编码变成瓶颈多图、高清图、视频输入
输出长度 OSL输出越长，总延迟越被 decode 主导；TTFT 的收益还在，但端到端收益被稀释短输出：端到端收益成立；长输出：收益被侵蚀
模型大小 / 精度ViT 的计算量基本固定，LLM 的计算量随激活参数和精度下降而下降；小模型、MoE、量化模型的 ViT/LLM 计算比更高小模型、MoE、低精度模型收益大；大 dense 模型收益小
混合流量混合 batch 里纯文本请求会被迫等 ViT；EPD 把编码隔离后，文本请求可以直接 prefill多模态流量 + 对延迟敏感的纯文本流量混跑时

代表性数据：10 图/请求的负载

10 张图/请求、OSL 1024：

图 4 人话解读。TTFT 上 colocated 降 58%、异构分层降 50%。端到端提升不大。OSL 1024 意味着 decode 要吐 1024 个 token。这部分时间 EPD 根本动不了。真正的信号是 goodput。异构分层在同样 SLO 下，多扛了 70% 的流量。因为 encoder 的容量是"白加"的，没动 GB200 的预算。

图像量 × OSL 全扫描：TTFT 提升 25%–93%

图 7 人话解读。这是"什么时候该拆"的量化答案。两张热力图（上：colocated，下：异构），全格子都是正收益 25%–93%。最重的格子（50 张图）达到 92%–93%。注意收益几乎不随 OSL 变化，因为 TTFT 本来就不含 decode。

图 8 人话解读。端到端就要挑食了。图多加输出短的右下角是深红，大收益。图少加输出长的左上角收益缩到很小。colocated 在"5 张图 × OSL 2048"这个格子栽了。倒亏 2.5%。embedding 传输的开销没赚回来。OSL 从 128 拉到 2048。异构 EPD 的端到端优势，从 20.3% 缩到 5.2%。

模型越大，EPD 越不划算

图 9 人话解读。Qwen3.5 4B/9B/27B 上，ViT 参数占比一路走低。从 7.2% 降到 4.7%，再降到 1.7%。colocated EPD 的 goodput 倍数也一路走低。从 2.62× 降到 1.50×，再降到 0.65×。27B 直接跌破盈亏线。博客强调：参数占比只是表象。真正的北极星指标，是"ViT 前向在请求总耗时里的占比"。ViT 固定，LLM 越大越重，编码越不值得单独拆。

量化放大 EPD 收益

图 10 人话解读。ViT 保持 BF16 不动。只把 LLM 的激活权重从 BF16 量化到 NVFP4。colocated EPD 的 goodput 倍数涨了。从 1.78× 涨到 2.64×。逻辑很直白：量化把 LLM 的 prefill/decode 变快了。请求总时间里编码的占比被动抬高，EPD 就有更大的施展空间。量化加 EPD 是乘法关系，不是加法。

混合流量：纯文本请求也被解救

50/50 图文混合流量，OSL 128。纯文本请求的 TTFT：92.3ms → 53.3ms（-42.2%）。图片请求从 289.9ms → 200.6ms（-30.8%）。文本请求收益更大，因为它彻底跳过了等 ViT 的队。

文末还给了三个"EPD 管不着"的抓手

博客很诚实：TTFT 里 43% 花在 ViT 启动之前。EPD 对这部分无能为力，得用：

  1. 前端并行媒体解码（--frontend-decoding）。把下载/解码挪出 worker，放到 Dynamo 前端。encoder-only 测试里延迟降 26%。从 281.3ms 降到 207.0ms。
  2. Embedding cache。算过的图存 CPU 内存。重复出现的图直接复用 embedding，不再跑 ViT。
  3. 多模态 KV 路由。按媒体内容哈希做路由。让共享同一张图的请求，落到已经有对应 KV 的 worker 上。不然每张图在路由器眼里都长一个样。

另外提到：vLLM 和 SGLang 的 EPD 功能都在 roadmap 上。Dynamo 只是先交卷的那个。

跟你研究方向的关联

  • 先 profile，再决定拆不拆。博客的北极星指标是"ViT 前向在请求总耗时里的占比"。你在 4090 上跑 Qwen-VL/InternVL。第一步：把 TTFT 拆成三段看。媒体预处理、ViT、prefill。如果 ViT 占比不到 20%，EPD 大概率不划算，别急着上架构。
  • 单机同构用 colocated 思路。你只有 4090，异构分层不适用。但思路可以借鉴。encoder 和 PD worker 同挤一块卡，用 MPS 隔离调度。本质是用进程隔离换调度自由。
  • 量化是放大器。你本来就在玩 FP8/量化。这篇博客证实了量化加解耦是乘法关系。实验顺序。先量化，再评估要不要拆。
  • 混合流量的队头阻塞。如果你以后做图文混跑的 serving，纯文本被 ViT 堵住是最隐蔽的延迟杀手。EPD/请求分流值得单独测一组数据。
  • 低成本先手。embedding cache 和前端并行解码，是"不动架构也有收益"的优化。可以先做。等 SGLang v0.5.19 的 EPD 重构出来。对照这篇博客的决策表做实验。

术语表

  • EPD disaggregation。编码-预填充-解码解耦。把推理拆成三个可独立扩缩容的阶段。本文只拆了 encode，P/D 还在一起（P/D 解耦是另一个话题）。
  • TTFT（time to first token）。首 token 延迟。用户"看到第一个字"要等多久。
  • ITL（inter-token latency）。token 间延迟。衡量生成过程"卡不卡"。
  • goodput。有效吞吐。只算满足 SLO 的请求，比 raw throughput 诚实。
  • OSL（output sequence length）。输出序列长度。
  • NIXL。NVIDIA Inference Transfer Library。跨 worker、跨机器传 tensor 的库。这里传的是 vision embedding。
  • NVFP4。NVIDIA 的 4-bit 浮点量化格式（microscaling）。
  • Colocated。同机共存。多个 worker 进程共享同一块 GPU（经 CUDA MPS）。但队列和 batch 各自独立。
  • Dynamo。NVIDIA 开源的分布式推理服务框架。
  • ViT。Vision Transformer。负责"看图"的模型部分。
