DeepSeek-V4.1-Flash：把 KV Cache 压到 890 字节/token 的"瘦身架构"

原文：deepseek-ai/DeepSeek-V4.1-Flash · Hugging Face（DeepSeek-AI model card，2026-09-10）
⚠️ 阅读前说明：所有架构数字和基准分数都是 DeepSeek 自报的（model card + API changelog），尚未经过第三方独立复测。技术原理值得学，但性能数字先打个折听。

人话解读

这是个"看着胖、用着瘦"的模型。总参数 552B（加上记忆模块 Engram 约 748B）。但干活时只唤醒一小部分：处理输入激活 8B，生成输出激活 16B。以前是"每个员工都得来打卡"。现在是"只叫值班的人来，其余人待命"。

真正的杀招不在参数，而在 KV Cache 的极限压缩。KV Cache 就是推理时的"草稿纸"。每个 token 的全局 KV cache 只要 890 字节。是上一代 V4-Flash 的 1/4，初代 V1 的 1/437。

为什么这对你重要？做推理 serving 时，长上下文的成本大头不是算力，而是显存。KV cache 就像服务员手里越写越厚的点菜单。菜单越长，占的桌子越大，能同时接待的客人就越少。DeepSeek 这次把"记菜单"这件事重新设计了一遍。

核心思路就一句话：解码器不再自己记笔记，而是直接"复印"编码器的压缩版笔记。这叫 Causal Encoder-Decoder 架构。再配上稀疏注意力和 FP4 量化。1M 上下文的 serving 成本被砍到以前的零头。

核心方法

1. Causal Encoder-Decoder（CED）：把 40 层切成"读题组"和"答题组"

传统 decoder-only 模型是"一边读题一边答题"。每层都要给每个 token 存自己的 KV。CED 把 40 层 Transformer 切成两半。20 层因果编码器 + 20 层解码器。

  • 编码器负责"读题"（处理输入），只算一次。
  • 解码器的全局 KV cache 直接从编码器最后一层的隐状态投影出来。不再从解码器各层自己的隐状态推导。相当于解码器不维护自己那套厚账本，直接复用编码器的压缩版。

效果：prefill 阶段只激活 8B 参数（只跑编码器）。decode 阶段激活 16B。input-heavy 的 agent 工作流最受益。读大量文档、代码库、对话历史都算。DeepSeek 说这种负载下 prefill 算力几乎减半。

2. Compressed Sparse Attention 2（CSA2）：注意力也"分级记笔记"

CSA2 给每个注意力层指派三种静态模式之一：

  • Full：全量注意力，照单全记。但只有第一层这么干。
  • Reindex：复用别的层选出来的"重点位置索引"。不自己重新算。
  • Reuse：直接复用别的层的 KV。相当于"抄作业"。

另外还配了个 Hierarchical Sparse Indexer。中文叫分层稀疏索引器。深层的索引层，只能在第一层 Full 模式圈定的候选池里找。索引成本跟上下文长度脱钩：上下文从 64K 拉到 1M，索引开销不涨。

3. SWA Bounded Replay：滑动窗口的 KV 不再落盘

滑动窗口注意力（SWA）的 KV 以前要持久化到 SSD。V4.1-Flash 换了个做法。缺失的 SWA KV 直接重播（replay）。把最近 n_win 个 token 现场重算。不存 SSD。持久化 KV cache 体积降到 V4-Flash 的 1/8。解码器的 KV 放主机 DRAM 里就行。全局 KV 生命周期 72 小时。

4. FP4 主 KV 缓存：E2M1 格式 + 每 16 通道一个缩放因子

主 KV 用 FP4（E2M1）格式存。每 16 个通道配一个 E4M3 缩放因子。打个比方：以前用"高精度天平"称每一克。现在用"厨房秤"称大宗，只在关键处校准。精度损失可控，体积砍半再砍半。

5. 其他组件（了解即可）

  • Engram 条件记忆：196B 参数。1600 万条目的 n-gram 查询表。按 token 稀疏查表。像给模型配了本"速查手册"，不用全背下来。
  • DSpark 投机解码：半自回归草稿生成，加按置信度调度的验证。跟 SGLang/vLLM 的投机解码是同类技术。
  • 多模态原生：DeepSeek-ViT 视觉编码器。从零训练，2D-RoPE + 3×3 pixel-unshuffle 下采样。再加两层 MLP 投影器。图片和文字从预训练第一天就一起训，不是后期贴上去的。
  • 推理力度连续可调：reasoning_effort 1–100 整数档。拿算力换准确率。serving 时可以根据请求 SLA 动态调"思考深度"。

跟你的研究方向的关联

  • KV cache 压缩是 serving 成本的第一性原理。decode 池的并发上限，几乎完全由 KV cache 大小决定。你在评估 SGLang P/D 解耦时，对这点应该最有体会。890 字节/token 意味着：同样显存能塞 4 倍并发。这是"架构级"的降本，不是"调参级"的。
  • CED 天然适配 P/D 解耦。编码器只跑 prefill，解码器只跑 decode。跟"prefill/decode 分离部署"是同一套分工哲学。评估 SGLang disaggregation 时，可以把 CED 当参照系。模型侧也在做解耦。
  • FP4 KV cache 跟 SGLang 的 mxfp8 KV 传输同源。SGLang v0.5.19 刚加了 mxfp8 KV 传输。P/D 解耦搬运 KV 时，就用这个压缩格式。DeepSeek 这边是 FP4 落盘。低精度 KV 是全行业的共同方向。值得跟踪哪种格式先成为事实标准。
  • 多模态原生 vs 后贴。V4.1-Flash 的 ViT 从预训练第一天就跟文本一起训。你之前看的很多方案是"视觉塔外挂"。做多模态 serving 评估时。想知道 EPD 对这种原生多模态模型的 TTFT 影响。可以直接套用 NVIDIA 那篇 EPD 博客的决策表。
  • 可复现性提醒。checkpoint 已在 HF。地址是 deepseek-ai/DeepSeek-V4.1-Flash。vLLM/SGLang/Transformers 均可跑。注意官方没给 Jinja 聊天模板。prompt 编码要用仓库里的 encoding/encoding.py。或者 Rust 版 deepseek-recipe。直接套旧模板会错位。

术语表

  • KV Cache：推理时缓存的 Key/Value 中间结果。避免每个新 token 都重算历史。长上下文 serving 的显存大户。
  • Prefill / Decode：prefill 处理输入 prompt。算力密集。decode 逐个生成 token。访存密集。P/D 解耦就是把这两阶段部署到不同机器上。
  • CED：因果编码器 + 解码器。Causal Encoder-Decoder 的缩写。两段式架构。本文 20+20 层。解码器 KV 从编码器投影而来。
  • Sparse Attention 稀疏注意力：只关注"重要位置"的注意力。计算量从平方级降到近线性。
  • SWA（Sliding Window Attention）：滑动窗口注意力。只看最近一个窗口的 token，省显存。
  • FP4 / E2M1：4 位浮点格式（2 位指数 + 1 位尾数）。本文用来存 KV cache。E4M3 是 8 位浮点的一种。
  • MoE（Mixture-of-Experts）：混合专家模型。每 token 只激活少数专家。本文 384 路由专家激活 6 个。
  • Reasoning effort：可调的"思考深度"档位（1–100）。档位越高越准，也越贵。
  • Engram：本文的 196B 条件记忆模块。1600 万条目 n-gram 查询表。按 token 稀疏访问。
  • TTFT（首字延迟）：从发请求到看到第一个字的时间；input-heavy 场景下主要由 prefill 决定。
